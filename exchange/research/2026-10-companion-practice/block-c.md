## 1. 别人怎么做（三种）

| 做法 | 谁 | 一行证据 |
| --- | --- | --- |
| **① 只增不删，靠检索排序**：新事实和旧事实并存，召回时按相似度挑 | mem0 v3、SillyTavern Vector Storage、AIRI FlowChat 实验 | mem0 v3 迁移文档：「新事实和旧事实并存」，排序信号只有语义、BM25、实体，**没有时间**，去重只认 MD5 完全相同；没有过期 / 衰减 / 遗忘 [文档，直读]。后果在 issue 里：#4956「v3 ADD-only 会让可变属性的旧事实和新事实一起浮上来」（换工作例子，2026-04 开，**至今 open、无维护者回复**）、#4896（docs 承诺最新为准但只有哈希去重，关为 not planned）、#5867 [帖子，#4956 直读，另两条为搜索摘要]。ST 向量库：取相似度 ≥25% 的前 3 条，**文档明说无遗忘 / 衰减，手动清** [文档，直读]。AIRI：所有记忆每轮拼进系统提示词，作者自己说「会越来越长，还没想好」[文档，直读] |
| **② 数值衰减 + 强化 + 冻结**：每条有强度，按时间指数衰减，被提起则回升，低于阈值冻结再清理 | MaiBot `A_memorix`（关系记忆）、MemoryBank（论文）、naturel_gpt（2023） | MaiBot：强度按 `2^(-Δh/半衰期)` 衰减，**半衰期默认 24 小时**，被召回 +0.05（1 小时冷却），强化 / 削弱事件的系数 0.5，低于 0.1 冻结、回到 0.15 复活，冻结满 24 小时后进入清理（软删还是硬删没核实），每小时跑一轮；全按墙钟时间算，**停机后重算结果一样** [代码：`memory_lifecycle_policy.py:25-140,198-335`；`memory_maintenance_service.py:22-57,303-330`；默认值取自代码，线上配置可能覆盖]。MemoryBank：受艾宾浩斯遗忘曲线启发，按时间和重要度遗忘 / 强化，评测是 SiliconFriend 的定性 + 模拟对话，**摘要里没有数字** [论文]。naturel_gpt：bot 可主动记 / 忘，且有「记忆强化」延长有效期 [文档] |
| **③ 带来源、带有效期、旧的留着不删**：新事实取代旧事实的方式是「给旧的标失效时间」，写入要有出处 | Graphiti、MaiBot `person_fact_verifier`、Letta Code | Graphiti：LLM 先挑出与新事实矛盾的旧边，再由确定性规则设 `旧.invalid_at = 新.valid_at`、`旧.expired_at = 现在`，**旧边保留**；每条派生事实可追溯到原始片段 [代码：`edge_operations.py:717-790`，LLM 挑矛盾在 `:992-1030`]。MaiBot：自动抽出的人物事实默认只是「不确定笔记」，只有**能在同一个人自己的原话里逐字找到、且不含「今天 / 可能 / 打算」这类临时词、不是问句、是独立一句**才升为稳定事实；有批处理按新规则重新晋升旧事实 [代码：`person_fact_verifier.py:30-79`，`person_fact_reverification.py:49-90`]。Letta Code：智能体自己改写记忆，MemFS 用 git 记历史，`/sleeptime`「dreaming」在后台复盘最近对话、合并去重；**文档里没有写怎么发现并删除错记忆，也没有遗忘** [文档，直读] |

评测办法（有出处的）：LongMemEval（ICLR 2025）测五种能力——信息抽取、跨会话推理、**知识更新**、**时间推理**、**拒答**，500 题，商用助手在持续互动下准确率掉约 30% [论文]；mem0 README 自报 LongMemEval 94.4、BEAM(1M) 64.1，且注明数字含托管平台的专有优化 [文档]。**没找到**专门评「遗忘得像不像人」的公开基准。

## 2. 我们现在在哪

- **记什么**：Hindsight 长期记忆，写入说明要求每条写清谁说的、关于谁、绝对日期；**否定和更正各单列一条**；重要的事标【重要】、一直成立的事标【长期】（ADR 0012 决策 4、0018）。她自己的经历走另一条线：日记、周记、阶段总结（0017、0018 决策 3），以及 ≤7 天内直接按事件账重算那一天（0032）。
- **怎么忘**（ADR 0018，`packages/bot/src/memory/fading.ts`）：召回之后、进提示词之前，按「最后一次沾到它」算——7 天内清楚、7–30 天加「记不太清了」、30 天以上不进提示词，**除非他这次的话里提到了这条的某个实体名（一提就想起）**；提过 2 次以上期限翻倍；【长期】【重要】不淡。**是召回时按日期算的纯函数，不删库里的东西**；「刚想起的」不存内存，从聊天记录往回推（0039），所以重启前后一样。
- **不做**（用户 10-06 定）：她无缘无故自己想起旧事；带情绪的记忆。公共记忆「有线索才想起」（0017）。
- **记错了怎么纠正**：靠三样——① 写入说明让更正单列；② 离线审计脚本 `memory-date-audit.mjs`（10-09 查出 3 条凌晨「明天」算错的，用户同意后 `PATCH` 改了两条、作废一条）；③ 人工在 Hindsight 面板里改事实 / 作废（`docs/memory-editing.md`，作废可恢复）。
- **文档里没写、我也没验证的**：同一个可变属性（工作、城市、分手）的**新事实是否让旧事实失效**——ADR 0012 / 0017 / 0018 和 `memory-editing.md` 里没有这一条，Hindsight 的整合怎么处理矛盾我没查。这正是 mem0 #4956 的那类问题。

## 3. 各做法对我们的代价

| 做法 | 实现量 | 风险 | 和哪些 ADR 冲突 |
| --- | --- | --- | --- |
| ① 只增不删 | ≈0（Hindsight 本来就是库里只增，我们在召回层变淡） | 可变属性的新旧事实并存、排序无时间信号；我们靠日期变淡缓解，但变淡是按**提起的日子**，不是按**事实是否过期**，「换了工作」后旧事实只要被提过仍可能被召回 | 无 |
| ② 数值衰减 + 强化 + 冻结清理 | 中（把 0018 的三档改成连续强度 + 定时任务） | 清理若是硬删则不可逆；MaiBot 默认半衰期 24 小时对「很多天前的小事」太快；我们现有三档已含「提过 2 次翻倍」＝强化，增量主要是连续性和清理 | **0018**（想不起来≠删除，要保留「一提就想起」）；`memory-editing.md`（作废可恢复）|
| ③ 来源 + 有效期 + 准入 | 中～大（要在 Hindsight 之外加一层「事实有效期」，或确认 Hindsight 是否支持） | 抽取与矛盾判断仍靠 LLM，会误判；MaiBot 的「必须逐字在本人原话里」会漏掉大量真事实（它自己就分了稳定 / 不确定两层）| 0012（写入说明）、0027（覆写带来源）；不与 0018 冲突 |

## 4. 与终极目标冲突的做法（只列不推荐）

| 做法 | 出处 | 为什么冲突 |
| --- | --- | --- |
| **什么都不忘，每轮把记忆全塞给模型** | mem0 v3 的 ADD-only（官方宣传「持续学习」）、AIRI 的全量拼接、ST 向量库无衰减 [文档] | 真人会淡忘；全知会让她读起来像有数据库的助手（目标第 2 条）。外部反应：HN「我关了 ChatGPT 记忆」帖里有人因为「creepy」关掉，也有人抱怨旧上下文被塞进无关问题（「context pollution」）、「不想被我以前的想法问责」[帖子，直读]；对浪漫陪伴 AI 的 Reddit 研究（2,909 帖、79 个子版块）把「不可逆、持久、用户负担」列为反复出现的模式 [论文，只读摘要] |
| **不分线索地主动翻旧账 / 靠记忆换黏性** | 用户 10-06 已明确不要（ADR 0018）；ChatGPT 记忆帖里的「无关问题里带出旧事」同类 [帖子] | 目标第 4 条；也违反「有线索才想起」|
| **记错了不让人看、不让人改** | 摘要里出现于「保留用户对记忆的控制」的建议（PAIR 长期研究，19 人 14 天）[论文，只读摘要]；Letta 文档没写错记忆怎么删 [文档] | 我们有面板和作废，不冲突；列在这里是因为它是别人的常见缺口 |

## 5. 一句话建议（Claude 代做的看法，由用户定）

我们「淡化 + 一提就想起」比读到的所有项目都更贴近目标，不需要换成别人的衰减模型；真正没覆盖的缺口是**「新事实让旧事实失效」**（换工作、搬家这类）和**「他当场纠正后她是否记得」**，建议先用 LongMemEval「知识更新」题型的思路做一个小测试量一下，再决定要不要加有效期层。
