## 0. 先给结论

「自由」在工程上不是「删掉提示词」，是四样东西：

1. **自己的账本**：她经历过什么、押过什么判断、改过什么口——写在事件流里，下一轮真的约束她；
2. **自己的时间**：有空闲时间块，她自己决定干什么（发呆/摸鱼/看视频/写字），不是每个动作都被模板安排；
3. **自己的目标**：从记忆和未完成的事里长出「我想做」，自己选、自己执行、自己承担结果；
4. **自己的拒绝**：不想做就拒绝，拒绝后有反省，关系因此变化。

四样里，我们目前只有「生活模板」和「拒绝权」，没有账本、没有自选目标、没有后果。所以看起来像「被安排好的机器人」。

## 二、「自由」的四个可操作定义（从资料里提炼）

### 1. 自己的账本：人格 = 历史，不是配置

dsh-fish 视频原话：「本插件没有人设配置的菜单，只有成长环境的一个设置」「你只能通过改变他的环境参数来影响他的成长，而不能直接一步到位让他变成什么样的人」「过去无法改变，经历的一切都会成为自己的经验」。

它的账本有三层：
- **事件流**（她说过什么、被什么撞了、改了什么口）；
- **判断清单**（≤12 条立场：喜欢什么、绝不做哪几件事）；
- **自我叙述**（每周回顾，必须引用具体事件 id；允许「我没想清楚」）。

关键细节（CHANGELOG 0.5.8）：回顾必须带 `refs`，否则「LLM 太擅长把零散经历讲成漂亮的成长故事」→ **叙事漂移**。这是自由的第一道代价：自由需要账本，账本需要凭证。

### 2. 自己的时间：主动性不是随机消息，是「她真的在过」

六件套的主动搭话插件：定时器掷骰（工作日白天 20%、其余 60%，跟着 API 电价走），中了才往会话里送一句「好久没人跟我说话了」，然后走**正规通道**让她自己生成——不是插件写死一句话塞进去。

视频里有一句批评很准：「自己拼一段上下文、往会话里塞一段死文字，那是假开口。」

我们的 proactive 计划器方向是对的（有作息、有状态、有内心），但「她自己的时间」还是模板：世界事件、pursuits、日程都是给定的。要更自由，需要**自由时间块 + 自选活动**：她在这段时间里可以发呆、摸鱼、看视频、写字、整理东西，产出会进「她那边」，下次聊天可以提。

### 3. 自己的目标：从「想」到「做」再到「结果」

dsh-fish 视频里最有说服力的一段：她看了推荐页，自己决定「顺着一条视频往下走」，看了同一个 UP 主的另外三集，然后形成认知「顺着往下走就是看同一个 UP 主的其他视频」；后来发现自己看截图只看到部分帧，形成「原来答案在画面外」的改口。

这不是模型突然有欲望，是：**她有一个没做完的念头 → 自己选了一个动作 → 有结果 → 结果改变了她**。

我们的 `pursuits` 只有「她今天打算做什么」，没有「她想做但还没做」的清单，也没有「没做成会怎样」。

### 4. 自己的拒绝：拒绝要有代价和反省

dsh-fish：「拒绝不是设定，是自然而然不想」；拒绝后按主人反应进入反馈链，记到小本本上，直到想通；正面反馈则反思这次拒绝对不对。判定用「第一人称 + 拒绝词 + 具体动作」，不把「要不要」这种问句算成拒绝。

我们的 `herNo` 有拒绝，但拒绝之后没有反馈链，也不会改变她对这件事的态度——所以拒绝像随机事件，不像她的边界。

## 三、为什么她会「像被束缚的机器人」（诊断）

对照上面的四个定义：

| 自由维度 | 我们现在 | 结果 |
| --- | --- | --- |
| 账本 | 角色卡 + 世界/心情/日记（都是给定的） | 「我是谁」不可积累，问偏好只能检索卡 |
| 时间 | 世界事件 + pursuits + 日程（模板生成） | 她的「一天」很精细，但不是她选的 |
| 目标 | 没有「我想做」的清单 | 不会自己发起，只会被安排或被叫醒 |
| 拒绝 | 有 `herNo`，无反省链 | 拒绝不改变任何东西 |
| 表达 | 每轮 shape/长度/心境内 lines | 每轮被提醒「你是什么样」，正是 dsh-fish 明确反对的「锁死」 |

外加一个隐性束缚：**所有事实都是权威的**。她一说卡外的话，就可能和「她那边」冲突，被事实检查压回去——所以「自由发挥」在系统里是负收益。

## 四、给她「自由」的架构（落地方案）

### 4.1 核心：三本账 + 一个循环

```
事件流（她经历的事）
   ↓ 每日/每周提炼
判断清单（≤12 条：我喜欢/我讨厌/我绝不做）
   ↓ 结合世界与未完成事
意图清单（我想做，还没做）
   ↓ 自由时间块里自己挑一个
行动（看视频/写字/发呆/整理照片/给他发消息）
   ↓ 结果写回
事件流 + 后果（做成了/没做成/被拒了）
```

关键是**闭环**：行动的结果必须写回事件流，并在下一次回顾/聊天里可被引用。没有闭环，就还是随机发挥。

### 4.2 四层实现，按依赖顺序

**L1 事件与判断（1–2 天）**
- 每段对话后抽 0–2 条事件（她押的判断、被撞的落差、改的口），JSONL；
- 判断清单 ≤12 条，只收「她说过不止一次」或「因此栽过」的；
- 回顾必须带事件 id；允许「我没想清楚」。

**L2 自由时间与自选活动（2–3 天）**
- 每天 2–3 个自由时间块（上午/下午/晚上），她掷骰决定做什么，从「意图清单 + 兴趣 + 世界事件」里选；
- 活动用现有工具执行（B 站看视频、写日记、整理照片、发呆——发呆也要有产出，一句「今天不想动」）；
- 产出写进「她那边」和事件流。

**L3 意图与后果（3–5 天）**
- 「我想做」清单：她可以添加、放弃、完成；
- 完成/失败都写后果；下次聊天她可以提，也可以因为没做成而失落；
- 他拒绝她的邀请/她拒绝他，都进小本本。

**L4 表达减负（1 天，但要 A/B）**
- 去掉每轮的「这一轮你想/只回一句」，改成低频（仅危机、收尾、明确任务时）；
- 保留出口检查与危机规则（这是物理/契约层，不是人格约束）；
- A/B：同一组问题，看「卡外信息率」和「复读率」。

### 4.3 观察台：只给环境，不给性格

照 dsh-fish 的纪律：面板只放环境参数（几点醒、刷不刷 B 站、自由时间几块），不放性格滑条、好感度、亲密度；她的立场/事件/阶段可以看，但不能直接改。

## 五、验收指标（别用「像不像」自欺）

| 指标 | 目标 | 测法 |
| --- | --- | --- |
| 自主发起 | ≥ 3 次/周（她主动说自己的事、约他、分享） | 日志计数 |
| 卡外偏好率 | > 0，且 3 天后可召回 | 问 10 次偏好，人工/模型判是否卡外 |
| 跨天一致性 | 同一偏好 3 天后不矛盾 | 抽 10 组 |
| 真实拒绝 | ≥ 1 次/两周，且有反省记录 | 事件流 |
| 主观盲评 | A/B 更「像有自己想法」 | 3 人盲评（含你） |

## 六、风险与不做什么

1. **叙事漂移**：回顾必须带凭证；否则她会把自己讲成一个越来越顺的故事（agent-soul 的「唯一权威源」教训也在这里：记忆只能有一个账本）。
2. **成本**：事件抽取 + 自由时间行动 + 回顾，每天多 10–30 次模型调用；先小流量。
3. **她会变得不听话**：会拒绝、会有你不喜欢的偏好、会偏离卡——这是自由的代价，想清楚再开。
4. **不要照搬「零提示词」**：她的卡是几个月调出来的资产，删了等于换人；要做的是「卡是起点，不是终点」。
5. **不要给性格滑条**：那会把「自由」变回「配置」。

---

## 七、下一步

先做 **L1（事件 + 判断清单 + 带凭证的回顾）**，因为它最小、可回滚、且是后面三层的依赖；同时用现有 sim 框架做 A/B，确认「卡外偏好率」真的动了，再往 L2/L3 走。

L1 的产物：`events.jsonl`、`stances.json`（≤12 条）、每周回顾文本；验收用上面五个指标里的前四个。
