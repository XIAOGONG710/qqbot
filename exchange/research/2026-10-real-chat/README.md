## 1. 方法

### 1.1 数据来源

用户本人在两台账号上的微信聊天记录，由用户提供、导出后归一到统一 JSONL：

| | 号 1 | 号 2 |
| --- | ---: | ---: |
| 单聊 / 群聊 | 34 / 13 | 27 / 18 |
| 单聊文本气泡 | 7,171 | 687 |
| 跨度 | 2025-06 → 2026-10 | 2025-11 → 2026-10 |

每条消息字段：`t`（ISO8601）/ `from` / `name` / `self`（1=本账号发出）/ `type` / `text`。
导出过程见 `findings.md` 第 0 节的样本量表。

### 1.2 三个口径（复现所需，全部写死）

| 概念 | 定义 |
| --- | --- |
| **单聊 / 群聊** | 「非本账号、非系统消息」的不同 `from` 个数 ≤ 1 为单聊。**不能用 `from` 总数**——系统消息带第三个 `from`，会把单聊误判成群聊 |
| **轮（burst）** | 同一发送者**连续发出**的文本消息合为一轮 |
| **对话段（segment）** | 间隔超过 **2 小时**即切开 |
| **气泡字数** | 按 Unicode 码点计数，不是字节 |
| **问句率** | 气泡末尾为 `？`/`?`，或末尾为 `吗`/`呢`/`吧` 的比例 |

### 1.3 词表（用于 A / B）

- **离开语**：晚安、睡了、睡啦、我先去、我先走、洗澡去、去洗澡、吃饭去、去吃饭、上课去、去上课、下课了、上班去、忙去了、不聊了、先这样、溜了、走了、出门了；另加**整条相等**才算的短词：88、886、拜拜、下了、下线
- **约下次 / 让他回报**（A 的宽口径）：跟我说、告诉我、说一声、叫我、喊我、完事、忙完、弄完、搞定、到了说、到了告诉、回头、下次、晚点、等你、有空、醒了说
  - **紧口径**（更贴原问题）：完事、忙完、弄完、搞定
- **叮嘱**（B，六类）：早点睡类 / 别熬夜类 / 吃饭类 / 喝水类 / 穿暖类 / 休息类

### 1.4 A 的判定口径（两版，都在 `findings.md` 里）

1. **段末收尾（严格）**：只在**对话段最后 6 条**里的离开语才算收尾；看对方**在同一段内**的回复里有没有紧口径 / 宽口径词。
   → 加这个限制是因为放开后「走了」有 62 次命中，多数是叙述（"他走了"），不是收尾。
2. **绝对频次**：直接数关键词在单聊全部气泡里的出现次数，给出占比。

### 1.5 B 的判定口径

按对话段统计「**同一段内同一叮嘱类别出现几次**」，得出「段内只 1 次 / 段内重复」的分布。
这个数字直接对应线上「一次对话只念叨一次」那条规则。

## 4. 已知局限

1. **这语料是「朋友间」，不是情侣。** 最直接的证据：**「晚安」在 7,171 个单聊气泡里只出现 5 次（0.07%）**——这是**白天同学之间**的语域。所以 A / B 的结论**只在下界意义上有效**。
2. **A 的样本只有 13 例**，按第 3 节「每格不到 15 段写样本少」→ **A 算样本少**。
3. **词表法有假阳性**（「走了」62 次里多数不是收尾）。
4. **与「她」的对照数字来自先前批次**（274 条），**不是当前构建**，需要复测才能成立。
