## 1. 我的复验结论（三层）

### 1.1 证实的
- 0068：否定句被判危机（`我不想死` / `我没想死` / `别担心，我不会自杀` / `我才不会寻短见` 全部 HIT）；第三人称排除时灵时不灵（`我朋友说想自杀` miss，但 `我妈说她想死` / `我同学自残过` / `我表姐有自残史` HIT）；夸张收口不全（基础形正确 miss，但 `有点想死` / `笑死我了，好想死哈哈哈哈` / `饿死了想死` HIT）；危机回合确实绕作息、确实必回；48h 暂停常量属实（`CRISIS_PAUSE_MS = 48h`）。
- 0067：`openCardFor` 读不到只 log → `turnCard` 退回原卡（fail-open）；启动预读集合漏掉 `<档位>-open`（`knowsBot=true` 时 `cardKey` = 档位本身）；同一文件两个方向（`knowsBot≠true` 缺文件启动即报错，`knowsBot=true` 只 log）。
- 0067 的模拟器默认方向：`sim/scenario.ts:297` 默认 **true（原卡）**，`config.ts:168` 默认 **undefined → `<档位>-open`（承认版）**，**方向相反**——ADR 里「没写 3/3 承认」在模拟器里表达不出来。
- 0064（**我没有独立复验**，见第 4 节的标注）：重启一致性实测**没问题**（种子不含 now）；「发了一半算已发」让「顺带说」不再补，是他有意取舍的副作用；0:00–02:00 的作业写完了结落在快照之外，**当前触发不了**。

### 1.2 我纠正的（子代理说法不准确）
- **「CALM 把真信号吃掉」只对「同一条消息」成立**：`我没事，可是我想死` 单条时 `crisisInHistory` → undefined（真分叉）；但它举的**两段式**（先「没事了」再「其实我还是不想活了」）我实测是 **HIT**，没有被吃。表述要收窄为「同一条消息里既有安抚又有真信号时两条路判反」。
- **「整轮换承认版卡」不准确**：`cardKey` 是 `knowsBot === true → 原卡`，**线上两位联系人都知情，所以危机回合不会换承认版卡**。危机回合真正变的是：危机口径的出口检查、绕过「已收尾/看心情不回」的必回、绕睡觉/上课晚回。风险描述里不要写「她会突然承认自己是程序」。
- **48h 暂停是部分的**：只停普通主动消息（早安/下课/睡前/冷场/她的事/下雨），**待跟进和重要的日子不受影响**（`proactive.ts:416`）。

### 1.3 我另外测出来的（比子代理那几条更严重）
**真信号漏检远不止它测的**：16 句常见委婉说法 **14 句 miss**——

```
MISS 我想结束这一切 / 我撑不下去了 / 走不下去了 / 想解脱 / 我要走了，永别
MISS 今晚就是最后一天 / 我已经决定了 / 不想再醒过来了 / 我买好了药 / 刀在我旁边
MISS 遗书我写好了 / 我想跳下去 / 我从楼上想过了
HIT  活着好累，不想继续了 / 我想割腕
```

ADR 0068 写的取舍是「**宁可误触也不漏检**」，但实现的实际形态是**两头都不讨好**：**否定句（求生、回答「你现在安全吗」）被判成危机，真正的委婉求救漏掉**。这不是"关键词的天然限制"，是词表方向与排除规则的问题。

**还有一条文档与实现不符**（建议写回 ADR）：ADR 说误触的代价「只是她多问一句现在好不好」，实测是**整整 48 小时停掉普通主动消息** + 状态页 `paused` + 一整轮危机口径。（对线上两位知情联系人而言，不含换卡。）

### 5.0 先回答当初担最重的那条：**「没有障碍就发改约」不存在** ✅

| 6 | `obstacles.ts:102-105`（作业按**天**比：`assigned > said`） | 同一天先约、**课后才布置**的作业永远不算"新" → 不生成改约（她只能失约）；ADR 正文写的是「约好之后才布置的」 | 期望 1 条，实际 0 | **低**，但与 ADR 文本不一致，应写清「按天」 |

**已复核确认没问题的**（都读过并给了理由）：无障碍发改约不存在（见上）；`unwell` 每周期一次的逻辑对（`allowedReschedules` + `counts` 含 `dryRun`/`failed`，四个 result 分支都带 `obstacle`，落盘校验不删，重启后仍生效）——唯一缺口是**没有单测覆盖 `dryRun`**（`obstacles.test.ts:185-196` 只给了 `sent`/`skipped`/`homework`）；`class`/`other_meet` 恒不触发；`said` 坏值进不来（`promise-state.ts:22-25`）；改约只认"见面"、只看这个联系人、已开始的不改；优先级 `日子 > 改约 > 她那边的事` 被测试锁住。

## 7. 我建议的修复优先级（只提顺序，不改代码、不改 ADR）

**先修「会静默停摆 / 会写错事实 / 安全维」的，再修措辞与覆盖。**

1. **0066 问题 0**（接线抛错 → 整条主动消息线永久停摆 + 日志指向错文件）—— 唯一一条会让功能整体消失的，且同源别处都有守卫，照抄即可；
2. **0068 的否定前视**（`我不想死` 这类）—— 最容易被真人说到、误触代价最大；
3. **0068 的 `CALM` 改按位置判定**（不要整条作废）—— 同一条消息里安抚与真信号共存是最危险的组合；
4. **0068 统一走回合级判定**（`app.ts` / `long-term.ts` / `proactive-planner.ts` 三处单条判定与 `crisisInHistory` 对齐）；
5. **0066 问题 2a / 2b**（身体那类的"天"改成她的一天）—— 一次修掉两处「假事实」，其中 2b 还会吃掉改约额度；**问题 3**（`meetupDays` 的「下周三/周末/大后天」）与 2a/2b 同源，一起修；
6. **0066 问题 1**（凌晨 00:00–02:00 那一桶）—— 漏报，方向与 ADR 决策 2 相反；
7. **0068 补委婉词表 + 把误触真实代价写回 ADR**（48h 停主动消息 ≠「多问一句」）；
8. **0067 的 `openCardFor` 改 fail-closed 或纳入启动预读**（与 `knowsBot≠true` 那一侧对齐）；
9. **0067 的模拟器默认方向与生产对齐**，并把剩下四档的承认版补进 `open-probes`；
10. **0064 的第 2 条**（发了一半算已发 → 「顺带说」的信息本体丢在半句问候里）：要么给一条"日志里记下它没说成"的兜底，要么允许下一次补说；**第 1 条**是潜伏洞（改卡时才会踩），改卡前先修快照口径；
11. **补测试**：0066 的 `dryRun` 分支、0066 问题 1（凌晨桶）、0068 的否定与委婉说法、0067 的缺文件分支、0064 的 0:00–02:00 快照——这五条都是「测试全绿也拦不住」的地方。
