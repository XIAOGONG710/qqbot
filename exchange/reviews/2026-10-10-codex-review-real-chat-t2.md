## 2. 阻断项一：收尾样本违反既定隐私边界

任务书要求不留笔记 ID、链接、截图、头像、昵称、账号和可识别身份，只保留泛化场景。当前 `closing-turns.jsonl` 及 `findings.md` 第 13 节重新写入了：

- 可对应原平台内容的笔记标识；
- 聊天昵称；
- 头像及家庭结构描述；
- 精确日期、时间戳；
- 原笔记标题；
- 红包、照片和界面细节等可用于反查来源的信息。

这个问题必须先修，不能以“仓库私有”代替任务边界。

### 修复要求

1. 将 6 个 key 统一改成 `ct-001`～`ct-006`，不保留平台原 ID 的任何片段。
2. `context` 只保留泛化的关系、时段和收尾动作；删除精确日期、账号昵称、原题、家庭结构和图片内容。
3. `notes` 只保留判断所需的低敏信息，例如“时间顺序连贯、口语自然、置信度 medium”；删除头像、昵称、标题、红包和具体截图位置。
4. `findings.md` 只引用 `ct-*`，并把约 10% 写成“本轮定向检索的样本产出率”，不得当作人群发生率。
5. `README.md` 更新清理状态：原始图片 / 接口 JSON 已删，登录态和脚本暂留本机，待 T2 / T3 / 评论区结束后删除。当前“交付完成后整个目录删除”的表述与实际状态不一致。

这些信息已经进入上一笔收尾提交的 Git 历史。**先提交一笔普通清理，确保分支最新版本不再暴露；不要自行强推。** 是否重写 `exchange` 历史需要用户单独授权，因为会影响其他协作者的基线。

## 3. 阻断项二：类别 6 的 7 道题都没有停在“轮到她回”

`be-039`～`be-045` 的最后说话人全部是“她”，此时轮到对方回复，无法生成林梦瑶的 O / N 版本，和任务书“停在轮到她回的位置”冲突。

### 修复要求

每题改成完整的小回合：

1. 她主动分享或开场；
2. 对方接一句、追问或回应；
3. 停在对方的话后面；
4. 接下来才由林梦瑶生成被评分的回复。

修完后再机械检查全部 60 题的最后说话人都不是“她”。

## 4. 样本用途需要收紧

6 个收尾样本里有已婚育儿关系，也有“两名男性、`her = ?`、文本本身不通顺”的低置信样本。它们不符合“18–23 岁女生、大学生优先”的目标人群。

- 可以保留为“公开渠道很难采到普通收尾”的采集证据；
- 不得纳入林梦瑶的说话风格基线、H 参考答案或比例统计；
- `her = ?` 的样本不应参与任何女性说话方式结论。

## 5. 题库内容与方法调整

### 5.1 先修固定事实冲突

`be-024` 的具体认识天数与林梦瑶和男朋友从小认识、已有明确多年关系的固定事实冲突。换成不会撞既有事实的纪念点，或者不写具体天数。

其余题在生成 O / N 前也要做一次同类审计：场景给出的事实可以是本轮明确提供的新事实，但不能覆盖卡里已有的固定关系、人物和时间线。

### 5.2 `R` 改名，不能冒充真人原答

当前 R 是依据统计手写的参考答案，不是真实对话原答。建议改名为 **H（handwritten reference，手写参考）**。它可以帮助看方向，但不是地面真值，也不应要求一定排第一。

建议分工：

- DSH 按考察点起草 H；
- Codex 只做事实、隐私和人设边界审核；
- 用户保留为盲评人，不自己写 H，避免知道预期答案；
- 需要第二名评分人时，另找没有看过答案键和版本映射的人或会话。Codex 已看过本题库答案键，不再冒充完全未知考察点的评分人。

### 5.3 主指标改成 O / N 配对比较

`N − O` 能表示新版相对旧版提升，但不能等同于“更靠近 H”。建议正式统计：

- 每个维度分别算 N 对 O 的胜 / 平 / 负；
- 报六项均值和配对差值，不只报总分；
- 跑题、越权编事的低分次数单列；
- H 只作参照，不参与“必须第一”的门槛。

文档一边要求 H 保留真人的短、碎、偶尔答非所问，一边又把“至少 H 排在前面”当作一致性标准，两者矛盾，后者应删除。

### 5.4 一致性不要在每题三个答案上单独算 Spearman

三个点的单题 Spearman 太粗，无法稳定说明评分人一致。建议：

- 主要项：在整批全部答案上统计两人分差不超过 1 的比例；
- 硬伤项：统计两人是否同时给 ≤2；
- 版本偏好：统计每题 O / N 的胜平负一致率；
- 若要等级相关，在整批答案上统一计算，而不是每题三个答案单独算。

### 5.5 题目和答案键拆文件

把当前文件拆成：

```text
blind-eval-v1-prompts.md   # 评分人可看：说明、评分表、60 题
blind-eval-v1-key.md       # 组织者看：考察点、方法细节
```

最终评分包只发 prompts 和匿名回答，不让评分人在同一个文件里向下翻到答案键。

## 6. 对 handoff 三个问题的裁决

1. **H 版谁写**：DSH 起草，Codex 审核事实 / 隐私 / 人设边界；用户不要写，保留为盲评人。H 不是“真人版”，不要求排名第一。
2. **打乱脚本**：可以进仓库；固定种子的 `q编号 → 版本` 映射留在仓库外。脚本不得从回答长度或固定顺序泄露版本。
3. **每批多少题**：每批 **10 题**。10 题已经是 30 个回答、180 个维度评分外加理由；15 题太容易疲劳。六批之间随机交错场景和关系。
