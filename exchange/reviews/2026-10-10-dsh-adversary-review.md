### 1.3 flash 在被审查方没测的画面里会退化（这是我要加的限制）

被审查方测的"聊天截图"是**程序生成、字体规整**的。我换成中文手写/毛笔感字体 + 旋转 + 模糊 + 低对比（`vision-report3.md`；真值 5 句：`你今天去医院了？/ 嗯 刚回来 大夫说没大事 / 那就好 吓我一跳 / 晚上想吃啥 我买回去 / 随便 你看着买吧`）：

```
simkai(楷体) 30px 干净                      → 5/5 逐字全对
STXINGKA(华文行楷) 34px + 旋转4° + 高斯0.8  → 5/5 逐字全对
FZSTK(方正舒体) 28px + 旋转8° + 高斯1.6 + 低对比 → 3/5
        第 2 句读成「刚回来 大夫说没事」（掉「嗯」，「没大事」→「没事」）
        第 4 句读成「晚上吃啥 我买回去」（掉「想」）
simkai 22px + 缩到 0.6 + 高斯1.4            → 4/5
        第 1 句读成「你今天去医院了吗」（「？」→「吗」，**加了图上没有的字**）
```

三点必须写进结论：

1. **会丢字、也会加字**。`？→吗` 不是"读不准"，是**替换成另一个字**——这跟被审查方抓到的「没大事→没事」是同一类错的另一个方向，被审查方只报了"掉字"。
2. **它会否认自己没看清**。最糊的那个变体（方正舒体+8°+1.6 模糊+低对比）它的思考链写「**清晰度很高，没有旋转或模糊问题**」，然后照读错字。**过度自信**比掉字危险：调用方按"它说清楚"来判断可信度会被骗。
3. 被审查方给的限制（"看懂图够用、逐字 OCR 不够"）**方向对，程度偏轻**：干净程序图也会掉字（我 640×900 Arial 28px 那次 4/5，掉的正是同一个"没大事→没事"）。

> 我承认并已排除一个我自己的假阳性：第一版退化图我用的是 `Ink Free` / `Segoe Script`，**它们没有中文字形**，PIL 画出来是一排空心方框（`shot_b_hand_30_rot5_blur1.2.png` 已存证），flash 答"文字都被方框替代"**其实答对了**。我换成 `simkai/STXINGKA/FZSTK` 重做，才有上表。这条写出来是给后来人省一步。

### 1.4 `[Unsupported Image]` 到底是谁说的？——是 **API 塞进去的**，不是 v4-pro 的自述

这是被审查方那条被点名质疑的证据，我把它坐实了，**结论反而更硬**：

```
（vision-report.md 第三节）token 计数判别
  deepseek-flash    ：纯文本 prompt_tokens=73  ｜ 文本+64×64 图 prompt_tokens=257   （图 = +184 tokens）
  deepseek-v4-pro   ：纯文本 prompt_tokens=126 ｜ 文本+64×64 图 prompt_tokens=131   （图 = +5 tokens）

（vision-report.md 第四节）让它原样复述收到的消息
  v4-pro  → content 就是：「[Unsupported Image]」（prompt_tokens=30）
  flash   → 拒答
```

+5 tokens 正好是 `[Unsupported Image]` 这个占位符本身。也就是说：

- **HTTP 200**（不是 400/报错）——"API 有没有拒绝图片"的答案是：**没拒绝，是静默把像素换成了一串占位文本**。
- **图确实没到 v4-pro**：+5 tokens 对比 flash 的 +184 tokens，像素根本没进上下文。它有 1M 上下文、`max_output_tokens` 也够，不是截断。
- v4-pro 思考链里的「图片是 [Unsupported Image]」，是它**读到了 API 塞进来的那串字**再转述。所以**提问里那条攻击假设（"那是模型自己说的，是被审查方误读"）不成立**；被审查方的结论对，只是它没给出这层证据（也没有 `GET /models` 那条声明）。
- 补一条被审查方没测的：**坏 URL 上两者行为不同**（`vision-report4.md`）
  ```
  flash   + https://example.invalid/nope.png  → HTTP 400  「Failed to download image from …」
  flash   + http://127.0.0.1:9/nope.png       → HTTP 400  「Failed to download image from …」
  v4-pro  + https://example.invalid/nope.png  → HTTP 200，prompt_tokens=46，答「没有形状。」
  ```
  → v4-pro **连"图没下下来"都不报**，照样给一个确定答案。这是"不要用它看图"的又一条理由。

### 1.5 「关思考后它会编」能不能区分"收到了没解析"还是"纯编"？——能，答案是后者

`thinking: {"type":"disabled"}` 下，v4-pro 对同一张 64×64 红底白方块答（`vision-report.md` 第二节）：

```
图里有：
- 一个大的深蓝色矩形，占据画面中间偏左，边缘不规整。
- 一个浅灰色矩形，位于深蓝色矩形右上方，略微重叠。
- 一个橙色小块，位于浅灰色矩形左上方。
- 一个红色方块，位于深蓝色矩形左侧中部。
…（共 9 行）  prompt_tokens=52
```

判别实验（**这是被审查方缺的那一步**）：同一个问题、**完全不附图**，看它会不会编。

```
（vision-report2.md 第一节）
v4-pro 无图 thinking=default  → 「我没有看到图片，无法描述。」        ← 诚实
v4-pro 无图 thinking=disabled → 「抱歉，我无法查看图像。请提供图像…」 ← 诚实
flash  无图 thinking=default  → 「没有形状」
flash  无图 thinking=disabled → 「这张图里没有任何形状或图案，整体是纯白色的空白画面。」 ← 编了一张白图（1 次；vision-report4.md 用同款问题重跑 3 次都得「没有形状」/「图片没有显示出来」，所以是 1/4 的偶发，**不足以定性**）
```

合起来：**v4-pro 关思考时是"纯编"**——因为 `prompt_tokens=52` 低于它带图时的 131、也低于它纯文本时的 126，说明那串占位符在关思考这条路径下**不再出现在上下文里**，模型只看到"请描述这张图"的题面在诱导它补全画面，它就补了一整幅不存在的画。**不是"收到了图没解析"**：它连占位符都没拿到。

所以被审查方那句「关掉思考后它会【编】」**复现了**，但归因要改：**不是这个模型爱编，是"题面预设了图、而图被静默丢掉"造成的编。** 同样机制作用在 flash 上会怎样，我的 1/4 次观测不足以回答——**这一点我认为应该写"未证实"，而不是"flash 不会编"**；被审查方把它归成 v4-pro 的专有毛病，范围说大了。

### 2.2 ⚠️ 硬伤：H 是按「意图 / 考察点」写的，而被测模型**看不到**意图

- **停在半路**（`audit-H.txt` 第 5 节）：
  ```

「咋」开头 4 条：be-017「咋了 我听着呢」、be-019「咋了 我醒着呢」、be-020「咋岔气了 还疼吗」、be-021「咋被打回来的」
多气泡题相邻气泡的间隔：{5, 6, 7, 8, 10} 秒，其中 **15/19 正好是 6 秒**
所有 after 首值全是 5 的倍数（20×9、25×5、30×22、40、45、50、60、90、600）
```

**没有"风格出格"的条目**（攻击方向失败），但 `咋了 我听着呢` / `咋了 我醒着呢` 是同一个模板换两个字，19 个气泡间隔里 15 个正好 6 秒，`行` 开头 6 条——这是"一个人一口气写完 + 机械补间隔"的指纹。评分表里有一项就是「真人｜1 分＝一眼 AI：工整」，H 作为**参照物**带着这种指纹，风险是被审查方没说到的：它会把"工整"训练成合格而非不合格。

## 结论 C：她现在的日常是三层、第三层（`autonomousLife`）没开

**判定：部分推翻。**

- 「三层结构」「第一二层＝状态行」「第三层只记账、状态行来自规则」→ **站得住**。
- 「**第三层没开**」→ **被推翻**：`origin/main` 自己的文档说它 **2026-10-09 15:07 就显式打开了**。
- 「线上跑在虚拟机上 → 服务全停是正常的」→ **无法判定（未证实）**，而且和 `origin/main` 里同一件事的记录互相矛盾。

### 3.1 「第三层没开」站不住：被审查方用的是自己刚否掉的那份文件

### 3.2 但"状态行来自规则、第三层只是记账"是对的（这部分攻击打不穿）

```

`blind.ts` 里状态行也是同一个函数（`status-line.ts` 注释第二行：「contact.ts 拼提示词和模拟器的状态行影子比对使用同一个函数，避免对外状态和生活事件账各算一套」）→ **对外状态行与事件账是刻意分开算的**。这条**站得住**。

**但「事件账不进提示词」这句要加限定**（我按攻击方向的"别的路径"查到了）：

```
world.ts:782   let actions = projectWorldActions(events);        // 账 → 世界动作投影
world.ts:786   const state = worldAt(world, schedule, now, actions);   // 世界读它

app.ts:279     ...(sharedWorld ? { onWorldActions: sharedWorld.record } : {})

action-queue.ts:195  record: (contact, episode, drafts) => world.record(...)   // 关掉开关也直通

两点结论：

- 「不进提示词」只管 **ADR 0040 / 0044 的"类型化行动"**（sleep/eat/study/…）。**世界动作（喂猫、取快递、交作业…）一直是"事件账 → 世界 → 状态行/提示词"**，从来就在提示词里。被审查方那句「第三层只是『记账』」在"类型化行动"这个范围内对，说得太满会误导。
- **有第二条写入口**：`worldState.record`（`app.ts:279` 的 `onWorldActions`）会把**聊天里她说"做过的事"**写进同一本账，而 `sharedWorld` 在开关关掉时**直接落回 `ledgerWorld`**（`app.ts:196-198`），所以这条口子**不跟 `autonomousLife`**。→ 「没开就等于『她自己过日子』没发生」要限定成「**没人聊天时自主排**的那部分不发生」。

### 3.4 「线上跑在虚拟机上 / 服务全停是正常的」= **未证实**

被审查方的全部依据是用户的一句话，**它自己在 `archive/handoff/2026-10-10-2320-dsh.md:9` 引的原话**：

> 「记忆该不该开？…这个我来回答，**可以开**，但是**对方在虚拟机上运行，内存不够，所以暂时不开**。」

它自己在同文件 `:40` 也承认：「**上面的推断是从「对方在虚拟机上运行」这一句推出来的**」。独立证据我找了，**找不到，而且找到的是反证**：
