3. `qzoneBrowse: on` + 重启一次 → 看 48 小时：她会不会自己提起「刚才翻空间看到…」，会不会编别人的话。
4. `qqControl: read`（只读）→ 盘点稳定后；`qqControl: on` + 允许清单先只放宝宝和鸽鸽 → 再单项试资料类（签名 / 群名片），最后才谈社交类；`qqDangerous` 单独一次、单独看。

回滚：把对应开关改回 `off` 重启；`qzoneBrowse` 的草稿和 `presence.json` 里的 `browse` 一行可以留着（不影响行为）。

## 没做 / 风险

- **全都没在真 QQ 上试过**：空间动作名、好友申请字段、改头像走的接口，按 NapCat 源码和文档写，线上可用性由第 1 步回答；读不到就只记一行，不假装。
- **空间点赞 / 评论没接**：动作名没法在本机验证，错了是公开动作；等探针确认后再按 `social` 档接。
- **自动同意好友申请没做**：同意谁、拒绝谁该由用户定，先盘点再谈规则。
- 封号风险由用户承担（10-25 明说）。控制面本身不改变她跟他聊天的方式；它只是把「账号级动作」放进一个能审计、能限流、能一键关掉的盒子里。

## 下一步（这版还差的一步，先写在这里免得当成已经做了）

这版交付的是**能力 + 闸 + 审计 + 盘点**：`account.run(...)` 能调那些动作，但**还没有任何对话决策去调它**——现在她自己在聊天里做不了「加好友 / 改名片 / 群公告」，这些要下一步接成独立开关再谈（建议顺序：好友申请 → 群名片 → 资料类 → 最后才碰群管理）。空间那条是完整接进去的（`qzoneBrowse` 会自己读、自己归纳、进提示词），只差线上验证。

## 第 2 版（14:3x，`431fcce`）：接进机器人，「完全控制」变成可执行

- **好友申请自动处理**（新开关 `qqFriendGate`）：插件把 `friend-request` 事件交给 `app.receiveFriendRequest`；`allow` = 名单内自动同意、其余留着；`all` = 名单内同意、名单外驳回；`off` = 不碰。要 `qqControl: on`。动作是 `set_friend_add_request`，名单是 `qqAllowFriends`。
- **动作表扩到 54 个**：读 19（含群文件 / 群荣誉 / 群系统消息 / 好友分组 / cookies）/ 资料 8（含改群名、群头像、好友备注）/ 社交 17（含转发、发文件、群签到、群待办）/ 危险 10（含删群文件、群头衔、群发转发）。
- **命令行 `scripts/qq-admin.ts`**：`inventory` / `actions` / `run <动作> --params '<json>'`；默认只读，写动作必须 `--mode on --yes`，照样过允许清单、限流、危险闸。
- 测试：`app.test.ts` 75 项（新增好友申请 2 项）、`account.test.ts` 10 项；插件 config 28；类型检查干净。
