## 四条来源怎么处理（详见 ADR 0167）

| 来源 | 处理 | 理由 |
| --- | --- | --- |
| 人格自检 | **做了**（只读 CLI） | 我们有出口检查、humanness、rough-edges、consistency，但缺一个「十条对照设定」的入口 |
| 群里量出的数字（7 字 / 无主语） | **不新做代码** | `rough-edges` / `humanness` 已经在量同一件事；值钱的是「每改一版复量」的流程 |
| 梗百科 memewiki | **采纳方向，等数据** | 它强在离线 6600 条 + 先查再回；我们 `memes.ts` 依赖 B 站热榜、条目少。方案：把它的数据导进 `memes.json`（词 / 意思 / 用法 / 来源），保留我们的敏感词过滤与 45 天过期；**数据要用户提供** |
| bili-cli | **不引入** | 和我们 `bilibili-account` 同层且更全（能投稿）；引入等于把她的 B 站号交给外部 CLI，绕过我们自己的风控/熔断/开关。只借鉴「全 JSON 输出」的接口形态 |
| retcon-form（可证伪记忆） | **采纳到记忆账本，下一版** | 「写记忆时必须写清什么情况下它是错的」和 `identityLedger` / `memoryAudit` 互补；要改 schema 和旧条目迁移，先记候选 |
| 显式沉默 / >5 秒转后台 | 已有 / 不适用 | `moody` + `readReceipts` 就是显式沉默；我们没有「会跑 5 秒的命令」入口 |
