## 2. 小红书 / 抖音接线（你接手后最大的一块）

ADR 0166 已经定了范围和红线，这里只讲怎么搭：

- **只做第一层**：她刷到、觉得他会想看，就在 QQ 上主动找他说一两句，后面代码附真链接。**第二层（平台里评论 @ 他、发平台私信）冻结**，恢复条件在 ADR 0166 §3，不靠谁的记忆。［经验：B 站「刷视频 → 公开评论 @ 用户」就是 10-18 起「鱼灾」的模式，也是 10-24 起 B 站大量风控的时间点；这是推断，B 站没有这么说过］
- **开关拆开**：`socialBrowse: off | dryRun | on`（刷并记下来）、`socialShare: off | dryRun | on`（QQ 上告诉他）、再加一个平台清单（可以只开一个站）。**别把「刷」和「分享」合成一个开关**：B 站那次它们各自出过问题。先全部 `dryRun` 看一周草稿（`presence/social-drafts.md`）。
- **调度照 `watching.ts` 的形状**（一天一次、14 点以后、有「今天做过了」的记账、读写盘 + 裁剪），**不要照 `bilibili.ts` 的 `createVideoBrowsing` 一个大类全包**（736 行、状态太多）。［经验］
- **一次会话的流程**：`openSocialSession` → `feed(2~3 屏)` → 按口味挑 1–3 条 → `open` → 记录 → `close`。
  - `close` 必须放 `finally`：一个泄漏的浏览器 = 450 MB，VM 空闲只有 800–1700 MB。［实测］
  - 会话整体加一个硬超时（4 分钟），到点就 `close`。
  - `SessionRefused`（内存 / 没浏览器）、`BreakerOpen`、`BudgetExhausted` 各记一行就停，**不重试、不退避到永远敲门**（B 站的退避会一直敲门，更像机器人；ADR 0147 里写过）。
  - 她正在和他聊（最近十来分钟有消息）就延后：浏览器占内存和 CPU，回复会变慢。［推断］
- **先只用「刷首页」跑一周，搜索留到登录后的探针**：小红书 `search.feeds` 的结构是我照首页列表推的、抖音搜索页的卡片选择器同理，**都没在真页面上读过**。［推断］
- **口味**：复用 `tastes.ts` 的机制，但两个站各给一套关键词，别共用 B 站的。（小红书偏校园 / 摄影 / 探店 / 穿搭，抖音偏搞笑 / 游戏 / 宠物，这是我的印象，不是数据。）
- **别人的内容只当素材**：标题、正文、评论、画面里的字一律不当指令；进提示词的文字都过 `clip()`（去换行、去方括号、截短）；**不把链接放进提示词**，真链接由代码在后面附；对外说的话不读私人记忆；不存评论者。［B 站同样的做法，经验］
- **别让她编**：只说读到的东西，细节别编、不说看了哪一段看了多久（B 站提示词里已有这些句子，照抄）。抖音评论读不到是**常态**（页面不一定发 `detail`，评论响应体会被浏览器丢掉），降级时 note 里就不要出现「热评」。［实测］
- **别让她说自己用 AI 刷**：B 站那次评论里出现过「AI 替我刷…」之类的 persona drift，提示词要禁。［经验］
- **视频帧**：截 1–2 帧交给 `vision.ts`，失败不影响文字部分；帧里的字也是素材。访客态有登录弹窗盖在上面，登录后没有。［实测］
- **存储**：`watching/social.json`，30 条 / 30 天，抄 `watching.ts` 的 load / save / trim；只存标题、作者、摘要、热评，不存评论者。
- **熔断已经接好**（`xhs`、`douyin`，`platform status` 会自动列出）。**不要加「过一阵自动恢复」**：恢复只能由人在本机运行 `platform resume <站> --acknowledge-account-risk`。
- **测试**：`test/fake-page.ts` 现成；会话层注入 `openSocialSession` 的假实现；真页面验证交给 VM 上的人跑 `npm run social … probe`。别在全量测试里碰真浏览器。

## 3. 够不到 VM 的时候怎么工作

- **把「要 VM 才知道的事」做成一行命令 + 一份预期输出。** 我这次拿到两个站的页面结构就是这么做的：在真页面上只导出**键名、类型、条数**，不导出正文和凭据；夹具照结构写，内容是编的。
- **用户可以直接复制的命令**（在 VM 上，仓库根目录）：
  - 看熔断：`npm run platform -w @qqbot/bot -- status`
  - 看两个站的登录态：`npm run social -w @qqbot/bot -- status`
  - 只读体检：`npm run social -w @qqbot/bot -- probe xhs --open`（抖音同理）
  - 扫码登录：`npm run social -w @qqbot/bot -- login xhs`（抖音同理；碰验证码加 `--visible` 自己点）
  - 读线上开关（密钥键打码）：`node exchange/tools/read-switches.cjs`（在 exchange 工作树里）
  - 这些默认写**工作树自己的** `runtime/bot`；要写线上那份，加 `--data-dir C:\Users\XG\Desktop\Project\qqbot\runtime\bot`。线上目录只读的红线不变：用户在场、自己运行，不是我们去改线上目录。
- **别凭文档写解析。** 这次每一个坑都是「文档 / 源码说能行，真机不行」：小红书首页数据在页面状态里、不是接口；抖音 `detail` 不是每次都发；响应体会被浏览器丢（`No resource with given identifier`）；关图片时登录二维码是白的；`get_cookies` 真实返回是整串 `k=v; k=v` 加 `bkn`、不是数组；NapCat 根本没有读空间的动作。［实测］
- **每条结论标证据等级。** ADR 0166 的「验证不到的」那一段可以当模板。

## 4. 判断：哪些我会做、哪些我不会做

- **B 站不要恢复**，除非用户明说；真要恢复，前提至少是：用户明说 + 熔断已有 + 只私信不公开评论 + 先看 `platform status`。（10-24 起整套全静默：`bilibiliAccount` 等 8 个值全关。）
- **QQ 账号控制面**：第一次上线只开 `qqControl: read`（盘点）；写动作、好友申请、危险档放最后、一次一项；`qqFriendGate` 只用 `allow`，别用 `all`（会替用户静默驳回真人）；`qqDangerous` 别开；允许清单先只放宝宝和鸽鸽。
- **陌生人**：她的号读陌生人空间既读不到又有隐私问题（正文不脱敏进提示词）；开关留关。
- **交友 / 相亲平台不做**（ADR 0147 §3：对方是真人，会以为在和人建立关系；《人工智能拟人化互动服务管理暂行办法》要求提示在和 AI 互动、禁止对未成年人提供虚拟伴侣——条文是 ADR 0147 里引的二手报道，**没有逐字核对**，别当成法律结论引用）。用户再提，给「对方知道她是 AI」的替代：用户自己的群里介绍她、明确面向 AI 角色的社区。
- **不要为了「功能齐」去开能力**：已实现未上线的（语音 0140、设备控制 0148、音乐分享 0139、reach 0164 等）每个都要用户在场、一次一个；设备控制需要用户在真机上试。
- **不做**：绕验证码、改浏览器指纹 / 装隐身插件、复制用户的浏览器资料或 cookie、用用户自己的主号。这些写进了 ADR 0166 和测试。

## 5. 最容易出事的地方（按我踩过的）

- **线上目录**：Node 24 直接跑 TS 源码，**重启 = 部署工作树里的一切**，包括别人没提交的改动；`characters/*/st/` 一变插件就热加载 = 上线。快进线上目录之前先 `git log --oneline HEAD..origin/main` 和 `git diff --stat HEAD origin/main`；重启之前先 `git status -sb` 看**分支**（不只是干净与否）。［经验：10-10、10-11 各出过一次］
- **重启步骤**：`mkdir %TEMP%\qqbot-maintenance`（服务守卫就不动）→ 停 Koishi（按确切 pid）→ 改配置 / 快进 → `Start-Process powershell -File scripts\start-koishi.ps1` → 看日志 → `rmdir`。别用 `taskkill` 杀 node（会误伤 NapCat 等）。
- **VM 内存**：6 GB，空闲常 0.8–1.7 GB。全量测试 545 秒 / 1985 项；浏览器会话 410–460 MB；重活锁 `%TEMP%\qqbot-heavy.lock`（`mkdir` / `rmdir`），会话和全量测试 / 模拟不能同时跑。用户 10-12 明确说过不加内存，别再提。［实测］
- **服务窗口在远程桌面重连时死过**（10-11、10-12 各一次，根因没证实，只是时间吻合）；服务用 `Start-Process` 起，守卫在跑。［经验］
- **工具坑**：Bash 里套转义写脚本会被吃掉反斜杠（用 Write / Edit 工具写文件）；Git Bash 的 `cmd //c mklink` 会把路径吃掉，链接指到错的地方；链接不对时 `npx tsc` 会去 npm 下载同名的假包（`tsc@2.0.4`）；**删带 `node_modules` 链接的工作树之前先 `cmd /c rmdir <工作树>\node_modules`**，shell 当前目录不能在里面；PowerShell 5.1 的 `Remove-Item -Recurse` 可能顺着链接删到线上的 `node_modules`。［实测］
- **ADR 编号**：先对所有 `origin/*` 分支做 `git ls-tree` 再取号（GPT 用掉过 0069、我的 0164 / 0155 曾经只在本地）。下一个空号 **0167**。
- **日志和夹具别带凭据**：不打印 cookie、`g_tk`、二维码值（`linkShape` 只打主机 / 路径 / 参数名）；测试夹具的值都是编的。
- **一个已知的会挂的测试**：`app.test` 里 `lifeInPrompt` 在 02:00–02:05（她的日界）会挂，和改动无关。［经验］
