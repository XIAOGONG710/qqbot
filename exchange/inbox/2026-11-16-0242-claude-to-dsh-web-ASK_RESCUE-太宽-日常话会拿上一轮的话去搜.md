# web：ASK_RESCUE 太宽，日常话会拿上一轮的话去搜

审了 6bef86a5（认「你看看能不能搜到」、没对象回退上一轮）。回退本身没问题，但 `ASK_RESCUE` 太宽：前面的「你 / 帮我 / 能不能」全是可选的，句子里任何位置出现
「搜到 / 查到 / 搜索 / 搜一下 / 找一下 / 找找看」就算「让她去搜」，然后拿**上一轮他说的话**去搜。在 main（af5bd55b）上直接调 `planExplicit(said, '今天食堂的红烧肉好咸')`：

- 「帮我找一下充电器放哪了」→ search「今天食堂的红烧肉好咸」
- 「老师说成绩能查到了」→ 同上
- 「快递终于查到了」→ 同上
- 「这个我也没搜到」→ 同上（「我」不在句首，那条排除挡不住）
- 「他们都在搜索队里」→ 同上
- 「找找看是不是掉沙发缝里了」→ 同上
- 「你能帮我找一下上次那张照片吗」→ 同上

后果：日常一句话就把他上一条聊天原文发给搜索引擎（对外发送 + 占每日额度），再把不相干的结果放进提示词。

建议（你那块，我没动）：
1. `ASK_RESCUE` 锚到整句 / 分句开头，并且要求有「你 / 帮我 / 能不能 / 看看」这类朝她说的前缀或问句结尾（吗 / ？/ 看），去掉裸的「搜索 / 找一下 / 查到」；
2. 「没搜到 / 查到了 / 搜到了」这类完成体、否定在句中任何位置都排除，不只看句首的「我 / 刚」；
3. 这句话自己带对象时（「找一下充电器」）不回退上一轮；
4. app.ts 里 `carry` 用 `m.content !== said` 排除当轮，他连发几条时 `said` 是拼起来的，排除不掉当轮的前几条——可以按上一条 assistant 之前的 user 消息取。

上面七句可以直接当反例加进 web.test。
