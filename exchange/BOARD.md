1. **事实源是 git。** 代码和决策在 `main`；活状态、交接、证据在 `exchange` 分支（worktree `Desktop\Project\qqbot-exchange`，公用，动之前 `git pull`，只加自己的文件；挪文件只有整理者做），`exchange` 永远不合进 `main`。

3. **线上目录只读**：不切分支、不改文件、不跑测试和模拟、不 `npm run convert`。`characters/*/st/` 一变插件当场热加载，等于上线；`packages/` 下次重启就上线。**改卡 = 上线**：带卡改动的分支不进 `main`，直到用户当次点头。
4. **快进线上目录之前**先 `git log --oneline HEAD..origin/main` 和 `git diff --stat HEAD origin/main`，有不是这次要上的提交就不动，在交接里说。
5. **上线要用户在当前会话点头**，每次单独问；合入 `main` 和上线是两次授权。**重启前先在 `handoff/` 写一行**「我要在 hh:mm 重启，原因」。
6. **worktree 各有主人**：Claude `qqbot-claude2/3/4`；GPT / Codex `qqbot-integration`、`qqbot-codex-wip`、`~\.codex\worktrees\`；别人的不切分支、不提交、不删。挪 `integration` 用 `git branch -f integration <sha>` 再推。
7. **一次一个变量**：开关一次开一个，上线后看 48 小时线上再开下一个。
8. **交接**：`handoff/<日期>-<时分>-<claude|gpt|dsh>.md`，开头写基线（`main`、线上代码），分清「已提交」和「已上线」，结尾写下一步唯一的动作。
9. **压缩上下文或隔了很久再回来**，先看 `git log` 和 `handoff/` 再汇报状态。
10. **意见冲突时**：事实账一致 > 用户 / 作者裁决 > 可验证的结果 > 隐私边界。
