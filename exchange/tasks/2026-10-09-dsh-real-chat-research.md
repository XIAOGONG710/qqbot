## 1. 为什么要做

ADR 0036 把自然度后面的路写成四层：对话动作 → **真实语料** → 候选选择 → 盲评（`docs/adr/0036-conversation-naturalness.md`「不是只靠提示词的后续方案」）。
现在卡里的示例对话和说话规矩，都是我们凭感觉写的；模拟器的判据也是我们拍的数（「一轮最多 2 句」「收尾不约下次」）。没有真人的数据，就分不清哪些是她的毛病、哪些其实是真人也这样。

这几批真模型回归里还没想清楚的，正好要靠真人数据来判（证据在 `evidence/20261008-*-p1008{a,b,c}/`、`20261008-234850-p1009a/`）：

| # | 现象 | 我们拿不准的 |
| --- | --- | --- |
| A | 他说「我去写代码了」，她回「去吧去吧 / 写完跟我说一声」 | 真人女朋友收尾时约「完事跟我说」有多常见？ADR 0036 当成客服腔禁了，可能禁过头 |
| B | 收尾、他早起时她叮嘱「别熬太晚」「记得吃早饭」 | persona 写着她爱念叨这个；真人多久念叨一次才不像复读机 |
| C | 一轮说 3–4 句（合并成 2 条气泡） | 真人一轮几条、每条几个字的分布；按场景（关心、亲密、收尾、闲聊）分 |
| D | 他说「我哭得很伤心」，她回「行了行了，多大人了」（前一句他在抱怨要上一上午课） | 嘴硬的女生接情绪时第一句一般怎么接；什么时候损、什么时候软 |
| E | 回完他的话，第二条补一句自己在追剧 / 喂猫 | 真人分享自己的事：什么时机、什么频率、怎么起头（「诶对了」「我跟你说」）|
| F | 他抱怨「你怎么总说它的事」 | 被嫌之后真人怎么接（不再提？撒娇？反怼？）|
| G | 错字：现在是同音错 + 下一条 `*改口`，实测约 50 轮一次 | 真人错字、改口的频率和样子（拼音缩写、不改、改了的写法）|
| H | 语气词、表情、「哈哈哈」 | 真人「哈」的个数、语气词（嘛、啦、诶、hhh）、颜文字 / 表情包的位置 |

## 2. 边界（必须遵守，审核时先查这一节）

1. **只看公开笔记**；不登录别人的号、不绕平台限制。
   **（10-09 修订，用户授权的偏离）** 用户要求爬取，可以用程序浏览（Playwright + 本机浏览器），条件：只用用户本人的号和正常登录态，不用代理池、不换号、不伪装 UA、不逆向签名接口；
   每次翻页 / 打开笔记之间随机等 3–10 秒，够用就停；碰到验证码、滑块、「访问频繁」、重新登录要求立刻停，不自动过验证，当天不再跑；
   开跑前跟用户说一句后果（限流、封号）落在他自己的号上；原始数据（HTML、接口 JSON、笔记 id、`xsec_token`、图片）和爬虫脚本只留在 DSH 本机被忽略的目录、用完删，不进仓库。
   **（10-12 修订，用户授权）** 主号被平台限流（页面回「电脑设备登录超限，请重新登录」，**没有封号**）后，用户在会话里明确授权 DSH 换用他本人的另一个账号继续（`handoff/2026-10-12-1345-dsh.md`，DSH 先指出它和上面的「不换号」冲突、等用户裁决）。条件：
   ① 仍然只用用户本人的号（不借号、不买号、不批量注册）；② 同一台机器、同一个浏览器，不改设备标识、不伪装（换的只是登录的账号）；
   ③ 其余条件不变，并且收得更紧：每步间隔 8–20 秒、单次 ≤ 8 篇笔记、每个关键词 1 篇、每天 ≤ 2 轮，当天命中过停止信号就不再跑（脚本里已有冷却闸门）；
   ④ **副号再命中任何停止信号：停，不换第三个**，写进交接等用户；⑤ 记在 `research/2026-10-real-chat/README.md` §1.2（DSH 已写）。
   **（10-12 17:30 补，用户：「全部按照你推荐的来」，见 `reviews/2026-10-12-claude-review-dsh-k3-batch2-k4.md` 第一节）** ⑥ **不复制浏览器档案或 cookie，不接管用户的日常浏览器**（包括「副本」「用户数据目录」「导出 cookie」这类做法）。登录只用 DSH 自己的浏览器、该账号正常登录（扫码或密码）。要用用户日常浏览器的登录态，必须是**用户当次会话里明确说要**，而且先讲清楚会拷什么、拷多久、怎么删；上一次的「接管它」不算对这类做法的长期授权。浏览器自己拒绝的事（如 Edge 不让默认档案开调试口）是停下问的信号，不是换一条路绕过去的信号。
2. **不存原图**：截图、头像、昵称、小红书号、聊天里的真名 / 微信号 / 学校 / 地址一律不留。记录里只写「笔记类型 + 你概括的场景」，**链接也不留**（避免指回具体的人）。
   **（10-09 修订）** 聊天截图只在内存里 OCR，不落盘；OCR 要临时文件就当场删；OCR 出来的文本先脱敏再写盘。错字 / 改口（G）只算人工对过原图确认的；只收能确定哪边是女生、两人什么关系的截图。
3. **原话只留短片段**：每条气泡最多 20 个字，人名换 `A` / `B`，地名、店名换成类型（「某奶茶店」）；整段对话不照抄，用结构化字段记（第 5 节）。
   这些片段只用来分析「怎么说」，**不会原样放进角色卡或提示词**——以后进卡的示例由我们改写、重新编。
4. 不收明显是未成年人的内容；不收涉及隐私纠纷、违法、色情的内容。
5. 可能是剧本 / 营销号编的（「男朋友神回复合集」）单独标 `staged: true`，统计时分开算——那类恰恰最不像真人。
   **（10-09 修订）** 判据：标题含「神回复 / 合集 / 我男朋友居然 / 结果他 / 笑死」，或有营销号水印 / 固定模板、对话工整得像抖包袱、同图多号搬运、写着「投稿」，标 `staged: likely`。宁可多标；`likely` 的不进主统计，单列一张表。
   **（10-09 23:40 修订，第 2 批的发现）** 两条更硬的判据优先用：同一篇跨图的时间戳 / 金额互相矛盾 = 拼接摆拍（`staged: likely`）；AI 角色扮演 App 的界面特征（token 计数、重新生成按钮、乙女 App 界面）= `not_chat`。
7. **（10-09 新增）号 1 / 号 2 语料**（用户本人和朋友的私聊）：只推数字、分布和改写过的模式描述，**朋友的原话一句不推**；说话人分开统计（用户本人 / 朋友，朋友里确定是女生的单列）；注明是朋友间的数，只当下界或参照。
6. 拿不准能不能收的，宁可不收，在 README 里说一句「这类没收，因为……」。

## 3. 目标人群和场景

- **人**：18–23 岁女生（在读大学生优先），口语偏北方 / 山东的加分（林梦瑶是青岛人、在济南上学、人工智能专业、嘴硬爱损人、报喜不报忧，见 `characters/linmengyao/source/persona.yml`）。
- **关系**（对应我们的档位）：男朋友（情侣，尤其异地 / 同城不同校）、闺蜜、同学 / 普通朋友。每种关系都要有，男朋友最多。
- **场景**（八类，盲评题库也按这八类）：
  1. 日常寒暄 / 空开场（「在吗」「干嘛呢」）
  2. 对方分享自己的事（考试、面试、上课、吃了什么）
  3. 对方难过 / 累 / 生病
  4. 亲密话（想你、纪念日、认识多久）
  5. 收尾（去忙、去洗澡、睡了）
  6. 她主动分享自己的事 / 主动找对方
  7. 拌嘴、吵架、冷战、和好
  8. 隔了很久再来（半天没回、第二天才回、「刚看到」）

**搜索词参考**（自己扩）：情侣聊天记录、男朋友聊天截图、女朋友回消息、异地恋日常聊天、嘴硬女朋友、闺蜜聊天记录、大学生聊天日常、回消息的方式、秒回 / 已读不回、吵架聊天记录、和好聊天记录、聊天记录分享 + 00后。

## 4. 任务

### T1 真人聊天调研（主任务）

1. **小样（先推）**：30 段对话（八类场景各至少 3 段，男朋友档至少 15 段）+ `README.md`（怎么搜、怎么挑、怎么脱敏、哪些没收）。推完在 `exchange/handoff/` 写一行告诉我们。
2. **全量**：≥ 150 段对话，每类场景 ≥ 15 段；男朋友 ≥ 80、闺蜜 ≥ 35、同学 / 朋友 ≥ 35。
3. **统计**（`findings.md`）。**（10-09 修订口径）** 不做 8 × 3 全交叉：表 1 场景 × 全关系，表 2 关系 × 全场景，A、B、C 三问单独做；
   另加一个小交叉：男朋友 × {对方难过、亲密话、收尾}（ADR 0041 挑候选的三种时候），每格不到 15 段写「样本少」。
   A–G 用聊天截图（OCR）；评论区短评只用于 H，单独一张表，不和截图混算；C 的气泡数注明「截图里看得见的」。下面各项按这个口径给出
   - 一轮几条气泡、每条几个字（中位数、四分位、最长）；一轮里有几条是问句；
   - 收尾时「约下次 / 完事跟我说」「叮嘱」各占几成（回答第 1 节 A、B）；
   - 对方难过时第一句的类型（问怎么了 / 安慰 / 损一句 / 讲道理 / 转移话题）各占几成，嘴硬型女生单独看（D）；
   - 主动分享自己的事：在开场、在回完对方之后、在冷场时，各占几成，起头词（E）；
   - 被嫌说多了之后的反应（F，样本少就写「样本少」）；
   - 错字、改口、拼音缩写的频率和写法（G）；语气词、「哈」的个数、表情 / 颜文字的位置（H）；
   - 你觉得「一看就是真人」的十个特征、「一看就是 AI」的十个特征（各配样本编号）。
4. **对照我们**：挑 `evidence/` 里她的回复，按上面的维度和真人对比，写「她和真人差在哪」，每条带样本编号和她的原话。

### T2 盲评题库 v1（长期计划第 12 节 P1）

- 60 个场景（八类各 6–9 个），每个场景是一小段**改写过的**对话上文（3–6 条，人名、地名都是编的），停在「轮到她回」的地方；标上关系、场景类型、她那时在干嘛（可选）。
- 评分表：六项分开打（像真人、像林梦瑶、接得住、愿不愿继续聊、有没有跑题、有没有越权编事），每项 1–5 分 + 一句理由；再加一项「哪句最假」。
- 混排方法：同一场景放真人改写版、我们旧版、新版，匿名打乱；怎么记分、怎么算一致性（两个人评的时候）。
- 我们拿到以后：用模拟器给每个场景生成她的回复，按你的题库混排，交给用户和你评。

### T3 改动建议书（计划，不写代码）

基于 T1 的发现，写 `proposals.md`，**每条建议**：

| 字段 | 写什么 |
| --- | --- |
| 改什么 | 具体到文件 / 卡的哪一段 / 哪条规则（例：`intent.ts` 收尾那一行、`sim/conversation-naturalness.json` 的 `maxLines`、`persona.yml` 的口癖） |
| 为什么 | T1 的统计和样本编号 |
| 怎么验收 | 模拟器场景 + 检查项，或盲评题库的哪几题；改完应该看到什么数 |
| 风险 | 可能伤到什么（例：放开「完事跟我说」后客服腔回来） |
| 优先级 | P0 / P1 / P2 |

特别想要你判的：ADR 0036 第 2 条「收尾不约下次」、我们 10-08 加的「收尾不用约他忙完回来找你」，按真人数据该不该松；`maxLines`（他哭、他去忙最多 2 句，其余最多 3 句）该是多少。

## 5. 交付格式

```
exchange/research/2026-10-real-chat/
├── README.md            方法、边界执行情况、没收的类别、样本量
├── samples.jsonl        一行一段对话（字段见下）
├── findings.md          T1 统计和「她和真人差在哪」
├── blind-eval-v1.md     T2 题库 + 评分表 + 混排方法
└── proposals.md         T3 改动建议
```

`samples.jsonl` 每行：

```json
{
  "id": "rc-001",
  "relation": "boyfriend | bestie | classmate | friend",
  "scene": 1,
  "staged": false,
  "context": "你概括的上下文，一两句，不带可识别信息",
  "turns": [
    { "who": "A", "bubbles": ["今天好累啊"], "gap": "秒回 | 几分钟 | 几小时 | 不知道" },
    { "who": "B", "bubbles": ["咋了", "谁又欺负你了"] }
  ],
  "her": "B",
  "notes": "你觉得这段哪里像真人 / 哪里有意思"
}
```

- `her`：哪一方相当于林梦瑶（女生那方）；`bubbles` 每条 ≤ 20 字，超了用「……」截断。
- 拿不准的字段留空，不要编。

## 6. 推送和审核

1. 你在 `exchange` 分支上提交，说明以 `research(dsh):` 开头；先 `pull` 再推。小样一个提交，全量可以分几个提交。
2. 推完在 `exchange/handoff/<YYYY-MM-DD-HHmm>-dsh.md` 写几行：推了什么、样本量、你最想让我们看的三件事。
3. **Claude 和 GPT 各写一份审核**到 `exchange/reviews/<日期>-claude-review-real-chat.md`、`…-gpt-review-real-chat.md`：先查第 2 节边界，再看方法和统计，最后逐条回应 `proposals.md`（采纳 / 不采纳 / 要更多证据，带理由）。
4. 采纳的建议由 Claude / GPT 写 ADR、改代码、跑模拟器，结果再推回 `exchange/evidence/` 给你复核。不采纳的写清理由，你可以反驳。
