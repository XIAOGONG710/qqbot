## 5. 协作协议（三方都照这个）

1. **事实源是 git。** 代码和决策在 `main`；活状态、交接、证据在 `exchange` 分支（worktree `Desktop\Project\qqbot-exchange`，公用，动之前 `git pull`，只加自己的文件），`exchange` 永远不合进 `main`。
2. **线上在 VM**（192.168.139.138）的 `C:\Users\XG\Desktop\Project\qqbot`。DSH 在联想主机上，够不到 VM，它那里看到的一律不算线上证据。
3. **线上目录只读**：不切分支、不改文件、不跑测试和模拟、不 `npm run convert`。`characters/*/st/` 一变，插件当场热加载，等于上线；`packages/` 下次重启就上线（守护自己拉起也算）。
4. **快进线上目录之前**：`git log --oneline HEAD..origin/main` 和 `git diff --stat HEAD origin/main`，有不是这次要上的提交就不动，在交接里说。
5. **上线要用户在当前会话里点头**，每次单独问；合入 `main` 和上线是两次授权。推到 `main` 但不上线的，提交说明和交接里写「未上线，别快进线上目录」。
6. **worktree 各有主人**：Claude `qqbot-claude2`、`qqbot-claude3`；GPT / Codex `qqbot-integration`、`~\.codex\worktrees\`；别人的不切分支、不提交。挪 `integration` 用 `git branch -f integration <sha>` 再推。
7. **一次一个变量**：开关一次开一个，上线后看 48 小时线上再开下一个。
8. **交接**：`exchange/handoff/<日期>-<时分>-<claude|gpt|dsh>.md`。开头写基线（`main`、线上代码），分清「已提交」和「已上线」；结尾写下一步唯一的动作。
9. **意见冲突时**：事实账一致 > 用户 / 作者裁决 > 可验证的结果 > 隐私边界。
10. **隐私**：key、token、cookie 不进仓库；QQ 号和聊天原文按用户授权可以进 `exchange`。
