# 任务：真人聊天的回复延迟基线（只出数字）

- 日期：2026-10-18（Claude 起草）。给 DSH（有那份微信聊天导出的那台电脑）。**只出数字，不推任何一句对话原文**（同 `research/2026-10-real-chat/README.md` 第 1 批的规矩）。
- 为什么要：线上她回他的消息，第一条离他最后一条的延迟**中位 6.3 秒、p10 4.5、p90 12.7**（10-09 起 339 次热聊），回 ≤8 字 6.0 秒、回 ≥20 字 7.9 秒——不管回多长都差不多快、又准时。我做了一个候选（`claude/rhythm`：打字时间按字数、回之前加一段「看 + 想」，偶尔隔十几秒），但**参数是我凭经验定的，没有真人数据**；有了数据才知道该快还是该慢。

## 要统计什么（用第 1 批的两个账号的单聊文本气泡）

「一轮」= 同一个人连着发的气泡（间隔 ≤ 20 秒的算一轮，和 `exchange/tools/live-chat-stats.mjs` 一致）。「热聊」= 上一条（任意一方）离这条不到 2 分钟。

1. **第一条延迟**：对方最后一条气泡 → 本人这一轮第一条气泡，的秒数。只看热聊里的。给：个数、p10 / p25 / 中位 / p75 / p90 / p95 / p99。
2. **按本人这一轮第一条的字数分组**：1–3 字、4–8 字、9–17 字、18 字以上，各组同上的分位数。（看延迟和回多长有没有关系，我猜有：长的更慢。）
3. **条间隔**：本人同一轮内，上一条气泡 → 下一条气泡的秒数，按**下一条**的字数分组（1–3 / 4–8 / 9–17 / 18+），分位数同上。
4. **长尾**：热聊里延迟超过 30 秒、超过 60 秒的占比（「看别的去了」有多常见）。
5. 本人和朋友（两个账号各自的对方）分开出一份，看差别大不大。
