# GPT 任务书：先量「她像不像真人」、再把「活着」的底线补上（用户 10-13：「把这些交给 GPT 进行」）

- 日期：2026-10-13，Claude（主窗口）写。起因：用户让我对整个过程做一次对照终极目标的锐评（见本文第 0 节），再说「把这些交给 GPT 进行」。
- 和 `tasks/2026-10-13-next-phase.md` 的关系：那份是「窗口（10-13 13:17 → 10-15 13:17）里不开新开关、不重启」的观察计划，**本文每一项都只推分支、不上线**，不违反窗口；上线要等窗口结束再问用户。GPT 开工提示词 `prompts/2026-10-13-gpt.md` 里的事（独立复核 0064 / 0066 等）仍然有效，**本文是追加**，排序见第 6 节。

## 0. 为什么要做这些（锐评的结论，和本任务相关的几条）

1. 引擎很重、真人使用很轻：10-12 他发来 73 条，约 69 条是表情，她只回了 3 句；真有对话的日子 10-09 到 10-11 三天，每天她回 30–44 句。所有「更像真人」的判断几乎都来自合成题目和模拟。
2. 目标的四条验收没有一条每天在量；现在每天量的是表层（一轮几条、1–3 字占比、问句率）。「说话更短」三批盲评、30 次判断，只把 1–3 字占比从 8% 推到 10%。
3. 评判者几乎全是模型；唯一的人是用户一个人。**最直接的信号——用户在聊天里觉得哪句假——今天没有采集通道。**
4. 「活着」的可靠性：10-11 19:57、10-12 09:45 两次整体被杀，没有告警；守护脚本的重启很可能从没生效过。
5. 一天重启 6 次（5 次上线），「一次一个开关、看 48 小时」被我们自己破了；上线前没有机器可查的检查。

## 1. 总原则（所有项都适用）

- **不改她说什么、什么时候说**（不碰提示词、意图、出口检查、时机、角色卡）。这些项是「量」和「保底」，不是新行为。唯一的例外是 T1 里「收到一条形如『假』的反馈消息就不把它当聊天」，见 T1 的说明。
- 线上目录只读；在自己的 worktree（`qqbot-integration`、`~\.codex\worktrees\`）里做；分支 `codex/<事>`，基于 `origin/main`（先 `git fetch`，看最新是哪个提交）。
- **不重启、不改 `koishi.yml`、不开新开关**（新增的配置项默认关；开不开、什么时候开是用户的决定）。
- ADR 编号：`0069` 空着（0065 的结果出来了：不做有效期层），留给 Claude 的下一份 ADR；**你用 `0070` 起**；写前 `git fetch` 看 `origin` 有没有更大的号。
- 只用纯虚构的对话做真模型模拟；真实聊天内容不进仓库、不进交接、不贴给别的窗口。
- 全仓测试（`--test-concurrency=1`）要过；报数字。
- 交付：分支、提交号、测试结果写进 `exchange/handoff/<日期>-<时分>-gpt.md`；重启前的通告规矩不变（本文不需要重启）。

## 2. T1 反馈通道：用户在 QQ 里对某句话回「假」或「像」（最高优先，最小）

**目标**：把「哪句话像机器人」这个最直接的信号采下来，成本是用户 2 秒。每周看一次「最假的 10 句」，比盲评便宜两个数量级。

**做法**：
- 配置新增 `feedbackCommands: boolean`，**默认 false**；只对 `boyfriend` 档的联系人有效。
- 触发：收到的消息**只有**「假」或「像」两个字之一（允许前面带一个 `/`，后面带标点或一个小黄脸；**「假的」「太假了」「真假」不算**），带不带 QQ 的「回复」引用都行：
  - 带引用：目标是被引用的那条她的消息（按 OneBot `reply` 段的 id 找，历史里她发出去的消息有 `messageId`）；
  - 不带引用：目标是她最近那一轮（最后一串她发的消息），要在 30 分钟内，否则忽略（当普通消息处理）。
- **消耗掉**：不 `append` 进聊天记录、不交给回复器、不进长期记忆、不触发主动计划器的 `poke`；也不回复任何东西。可选：用 NapCat 的 `set_msg_emoji_like` 在用户那条上点一个赞表示「记下了」——先查当前 NapCat 版本有没有这个接口，没有就算了。
- 记录：`<数据目录>/feedback/YYYY-MM.jsonl`，一行一条 `{ at, label: 'fake' | 'real', herMessageId, her: [那一轮的气泡], context: [前面最多 6 条（角色 + 文字）], tier }`。**这个文件只在 `runtime/`（被忽略）里，不进仓库、不进日志正文**；日志里只写一行「反馈：假（第 N 条）」，不写内容。
- 工具 `scripts/feedback-digest.mjs --days 7`：读 jsonl，输出 markdown：每天几条假 / 像、按天列出最假的句子（带前面两条上下文）。只在终端打印，不写仓库。

**验收**：
- 单元：命令解析（「假」「/假」「像」命中；「假的」「太假了」「你真假」不命中）、30 分钟窗口、引用定位。
- `app.test.ts`：开关关着时「假」当普通消息；开着时被消耗、写了 jsonl、**没有回复、不进历史**；非 boyfriend 档不生效。
- 写一份短 ADR（`0070`）：说明这是「工具而不是行为」，并写清隐私（文件位置、不外传）。

## 3. T2 每日「像不像」报告（只读，不调模型）

`scripts/daily-realness-report.mjs <日期>`，读线上数据**副本**（聊天、主动记录、事件账、feedback jsonl），输出一页 markdown（打印到终端，也可以 `--out`）：

1. **量**：他发来几条、她回复几条、她主动几条；表情、图片、文字分开数。
2. **表层**（沿用 `exchange/tools/live-chat-stats.mjs` 的口径）：每条中位字数、1–3 字占比、一轮一条占比、问句率。
3. **断联指标**（对应终极目标第一条）：当天事件账里她过的事有几件；她说的话里**提到了几件**（按事件类的关键词表匹配：拍照 / 修图 / 调色 / 相机；作业 / 报告 / 截止；课 / 上课；猫 / 土豆；吃饭……关键词表放在文件顶部，容易改）；两个数字的比。**他一条都没发的日子也要有这一项**（那种日子这项最有意义）。
4. **反馈**：当天「假 / 像」各几条。
5. **服务**：当天日志里 `错误`、`模型正文是空的`、`被截断`、`危机信号` 各几次；Koishi 启动了几次（`名单：` 行）。

**验收**：用 10-09 到 10-12 的线上副本跑一遍，结果贴进交接（只贴数字）；对 10-13 这种他没发消息的日子不崩。**不要加任何「评分」或「像真人指数」**——只给原始数，判断留给人。

## 4. T3 「活着」的底线：心跳 + 告警 + 上线前检查

三小项，按顺序，**额度紧时只做 3a**。

**3a 上线前检查脚本** `scripts/golive-check.mjs --to <分支或提交>`（只读，不重启）：逐条打印 PASS / FAIL，任何一条 FAIL 退出码非 0：
- 线上目录：分支 `main`、工作区干净、`--to` 是 `HEAD` 的子孙（能快进）；
- 最后一条聊天时间距现在 ≥ N 分钟（默认 30，`--quiet-minutes` 可改）；
- `exchange` 分支的 `handoff/` 里近 30 分钟内有一行「我要在 hh:mm 重启」且提到这个 `--to`（两个窗口的锁）；
- 上一次重启的时间和改了什么：读/写 `runtime/bot/restarts.log`（一行一次：时间、`--to`、原因、谁）；**距上一次「行为变化」的重启不足 48 小时就 FAIL**，除非 `--safety "<理由>"`（修故障 / 安全）；
- 维护标记 `%TEMP%\qqbot-maintenance` 存在（说明有人准备停机）；
- `--tests <日志路径>` 里全仓测试通过的汇总行。
另有 `scripts/restart-log.mjs` 追加一行。**把「一次一个开关、看 48 小时」从口头约定变成脚本能拦的事。**

**3b 心跳**：Koishi 插件每分钟写 `<数据目录>/heartbeat.json`（`{ at, pid, ref }`，原子写，插件卸载时清掉定时器）；`scripts/heartbeat-watch.mjs` 读它，超过 15 分钟没更新（且没有维护标记）就告警。告警通道做成可插拔：默认写 `runtime/bot/ALERT.txt` + 控制台输出；推送（ntfy / Bark / 邮件等）留空，**用哪个通道由用户定，不要自己挑一个服务去注册**。

**3c 不依赖桌面会话的拉起**：写好 `scripts/install-services-tasks.ps1`（用 Windows 计划任务启动 NapCat / Hindsight / Koishi / 看门狗，和现有 `start-*.ps1` 同一套参数），**只写、只测语法，不执行**——「不管用户是否登录都运行」要用户的 Windows 密码，上次试 Interactive 类型的任务失败（0x800710E0）。README 里写清楚怎么装、怎么回滚、需要用户做什么。

**验收**：`golive-check` 对「现在的 `main`」打印出合理结果（所有 PASS / FAIL 的原因都对）；`heartbeat-watch` 对一个人为写旧的 `heartbeat.json` 告警、对新的不告警；3c 只交脚本和说明。
