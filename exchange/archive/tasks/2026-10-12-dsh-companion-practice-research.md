## 0. 终极目标（调研的靶子，用户可以改一个字）

> **让林梦瑶像一个真实存在的 20 岁左右的女大学生那样活着：她有自己连续的日子，没人找她时也在过；有人找她时像同龄人那样回，不像随叫随到的助手。**

这句话怎么验收（调研时拿它当尺子，凡是和它冲突的做法，只列、标「与目标冲突」，不推荐）：

1. **断联三天回来**，她有三天的事可说，而且和账对得上、重启不改史；
2. **盲测里**读起来像手机对面的人，而不是靠「我今天做了什么」来证明自己有生活；
3. **她会因为自己的事**晚回、拒绝、改约，而且有原因（身体、日程、关系），不是为了「像人」而随机冷淡；
4. **不追参与度**：不用让人上瘾的手段（连续打卡、情绪勒索、制造焦虑）换黏性；不宣称有意识（`docs/plans/2026-10-08-long-term-execution.md` §2）。

## 3. 证据规则（调研的质量全靠这个）

1. **每条事实写来源**：链接 + 访问日期 + 证据等级——`代码`（读了源码）/ `文档`（官方文档）/ `论文` / `帖子`（论坛、博客、评论，只当线索）/ `没找到`。**没找到就写「没找到」**，不要推断补上。
2. 区分「它宣称的」和「我读代码确认的」。开源项目尽量读核心文件，别只看 README。
3. 只看公开资料。**不登录任何账号，不用浏览器档案 / cookie（任务书第 2 节 ⑥）**，不下载可执行文件，不推个人聊天原文。
4. 每块**不超过两页**；每个做法一行：谁 + 怎么做 + 证据等级。
5. 不抄台词和人设文本，只记**机制**。

## 4. 交付和流程

1. **A 先交**（`inventory.md`）：交了在交接里说一声，**停下**，等 Claude 看一眼方向对不对再做 B–E。
2. B–E 各一份 `block-b.md` … `block-e.md`：每份固定五段——
   - 别人怎么做（A / B / C 三种以内，每种一行证据）；
   - **我们现在在哪**（引 ADR 编号，别重复造）；
   - **各做法对我们的代价**：实现量、风险、和哪些 ADR 冲突；
   - **与终极目标冲突的做法**（只列不推荐，写明为什么冲突）；
   - **一句话建议**（最多两句，标明是 DSH 的看法，由用户定）。
3. **`options.md`**：把 B–E 压成**一页**「选项 + 代价」给用户挑（每块 ≤ 3 个选项，每个一行代价）。Claude 先核对事实和冲突再给用户。
4. 用户挑完 → **Claude 写 ADR**（DSH 不碰 `docs/adr/`）→ 再进实现。
5. 交接照旧：`exchange/handoff/<日期>-<时分>-dsh.md`，写：推了什么、最想让我们看的三件事、没找到的。
