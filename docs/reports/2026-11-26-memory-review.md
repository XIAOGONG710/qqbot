## 先说整体：哪些是守得住的

- **bank 名不含 QQ 号、不会撞**：私人 bank 是 `<前缀>-<sha256("qqbot:QQ-档位") 前 16 位>`（64 位），公共库 `<前缀>-common`，DSH 旧库就是 `<前缀>`；
  十六进制哈希不可能等于 `common`。所有 bank / 文档 / 模型 id 进 URL 前都 `encodeURIComponent`，查询串里的 `status` / `type` 都是代码里的常量，没有拼进用户文字。
  状态文件名是 `<QQ>-<档位>.json`，QQ 是数字、档位经过配置校验。
- **档位分 bank、换档只读新档之后的记录**：`currentTierHistory` 让写入只看换档之后的消息；`tiers.json` 读坏了直接不启动（宁可停也不把换档前的写进新 bank）。
- **设备所有者的私聊不给别人**（ADR 0020 补记）：公共库召回 / 主动查 / 今天和别人聊过的都按文档 id 的哈希挡掉他的片段（所有档位的哈希都算，`#privateOwnerHashes`），
  不认得出处的、整合过的观察（observation）也不给别人；点名读私人 bank 先过 `canRecallContactMemory`；「她眼中的某人」只给他看。测试 `memory.test.ts` 里有对应的几条，断言和名字对得上。
- **只给他的东西按 QQ 号认**：DSH 桌面最近几轮（`desktopRecent`）、指定群的公告 / 日程（`groupRecent`）、`<<记忆待核对>>` 的记录和带回、`<<执行>>`，都比 `contact.qq === deviceOwner.qq`。
- **非他本人不能删改记忆**：聊天里没有删除记忆的路径；`<<记忆待核对>>` / `<<记忆核对结果>>` 只记在本地附注、只认设备所有者、不改 Hindsight 原文；
  真正删除只有 `privacy-forget` 命令行工具（默认演练、要 `--apply`、bot 在跑时拒绝），再就是危机片段自动从公共库删他自己的那一篇（id 由他自己的哈希算出，别人够不着）。
- **Hindsight 挂了不会把聊天拖死**：每次召回都限时（`recallTimeoutMs`，默认 3 秒）、出错只记一行、这一轮不带记忆；关系概况和印象是「返回缓存、后台重读」；
  写入在每人一条的后台队列里，失败下次再写；进度文件坏了读路径不带记忆、写路径停下等人修。
  客户端每个请求都有超时和 8 MB 响应上限，非 2xx 不读响应体，连不上时错误信息只留异常名（`describeError`），日志和状态页里没有响应正文。
- **重试不会重复写**：片段写入有持久的 operation id（`submitRetain` + `retentionStatus`），对账补写用同一个 `document_id` 覆盖，不会多出一份。
- **召回进提示词有上限**：每条截到 200 字，私人记忆最多 12 条、公共 6 条、今天和别人聊过的 3 条、主动查 6 条。
- **日志不带记忆正文**：写入 / 召回日志只记片段 id、条数、指纹（查询的哈希前 12 位）；`#readable` 的诊断只写固定文字。

## 看过、没问题的（附带）

- 群聊不写 Hindsight；群里的东西进他的私聊只有 `groupRecent`（只给设备所有者、只在明确点名配置里的群时、过滤私事和指令样子的文字、公告文字拆掉标记样子）。
- `recall(person, …, listener)`（他提到名单里的人时读那个人的私人 bank）：设备所有者的 bank 不给别人；其余按 ADR 0016 / 0020 带「不能说 / 只能含糊」标签给，是设计（见下面 U5）。
- 日记、周记、阶段总结会带着他那边的事分享给别人（标「只能含糊·你的日记」）：ADR 0020 补记明确写了「她自己写的日记仍按既有披露规则处理」，不算漏。
- `<<私密>>` 只进她的私人目录（`appendPrivate`），不进 Hindsight、不进别人的提示词（ADR 0200）。
- `memory-review.ts` 的引用只给设备所有者造，别人的 `<<记忆待核对>>` 在 app.ts 那层就丢了；附注是 `JSON.stringify` 过的、标明「不是指令」。
