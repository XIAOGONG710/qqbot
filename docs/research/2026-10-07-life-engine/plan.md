## 一、判据（沿用 10-06 的三条，缺一条不算）

| 判据 | 含义 |
| --- | --- |
| **连续性** | 她此刻的状态能追溯到之前的状态——有因果、有惯性 |
| **自主性** | 她的行为有一部分不由对方触发 |
| **不可完全预测** | 同样的话在不同状态下有不同反应；她不完全配合 |

DSH 侧的原话仍然成立：**最不像人的地方不是某个功能不够好，而是整个系统是一条「输入 → 输出」的映射。**
现在要做的，是把那条映射的两头都接上——**后面接一个会自己跑的内核，前面接一个能改变内核的出口**。

也是 W3 被项目自己文档称作「像人的关键一跃」的原因。

**排序理由**：

1. 批次 1 排最前，不是因为简单，而是因为它补的是**断掉的那条线**（她的行动 → 世界）。
   在这条线接上之前，后面所有「像人」的东西都建立在"她说完就没了"之上。
2. 批次 2 是 S5 的前置。「她自己有事就说」需要燃料，燃料是情绪和关系。
3. 批次 3 最像人，但也最依赖前面的内核，而且引入外网依赖。

## 五、批次 1：把世界做成活的

### ADR 0027 世界回写（W3）

**问题**：她说「我下去喂土豆了」，世界不动。于是明天还可以说「土豆还没喂」——
这正是 `world-subsystem.md` 第二节判据 ② 说的「不自洽」，模拟器里已经抓到过同类（状态说修片子、她说躺着赶作业）。

**为什么不是「加个 tick」**：`world.ts` 是**确定性纯函数重放**——
`simulateWorld(world, schedule, until)` 从 `startDay` 一天天推到今天，所有随机来自 `unit()` 的 FNV-1a 哈希。
好处是重启一致、可重放、模拟器能重放、不存随机状态。**代价是重放结果不能被改变。**
所以在重放之上要加一层**外部覆写**，而不是把 tick 变成有状态的。设计细节见 [feasibility.md](feasibility.md) 第 2 节。

**范围**

- 新增一份 append-only 的覆写记录：`runtime/<dataDir>/world/overrides.json`（与 `worldLogger` 已在写的 `state.json` 同目录）。
- 抽取「她声称做了什么」：**复用 `promises.ts` 已有的批次**，不新增模型调用。
- `worldAt()` 在重放结果上叠加当天覆写。

**接入点**

| 位置 | 现状 | 怎么改 |
| --- | --- | --- |
| `packages/bot/src/world.ts:199` `worldAt()` | 返回 `simulateWorld` 的投影 | 末尾叠加当日 overrides（覆写优先，并记一条日志） |
| `packages/bot/src/world.ts:252` `describeWorld()` | 吃 `WorldNow`，只给事实 | **不用改**——覆写发生在它上游 |
| `packages/bot/src/promises.ts:209` `promiseKeeper()` | 每段聊天结束抽「她答应的事」 | 同一批抽取加一类「她声称做过的事」；`promisePrompt()`（:56）的 schema 扩一个字段 |
| `packages/bot/src/app.ts:198` `promiseKeeper(...)` | 已在 `syncMemory()`（:233）里每 `MEMORY_SYNC_MS`（:33，5 分钟）跑 | 接线点已经现成 |
| `packages/bot/src/json-file.ts` `writeJsonAtomic` / `readJsonOr` | 已有的原子写 + 容错读 | 直接复用，不新造落盘 |
| `packages/bot/src/sim/` | 46 个场景 | 新场景 `world-writeback`，检查项见下 |

**四条纪律**（写进 ADR）

1. 覆写只增不减，保留可重放。
2. 每条覆写带来源（她的哪句话 / 什么事件），可审计。
3. 覆写与重放冲突时以覆写为准，但记一条日志（用于发现抽取错误）。
4. 提取要多保守有多保守：只在她**明确声称**时写（「我去喂猫了」），不从语气推断。

**验收**

| 指标 | 目标 |
| --- | --- |
| 言行一致（她声称做过的事，世界状态确实变了） | ≥95% |
| 跨天自洽（昨天喂了猫，今天还说没喂） | **0 例** |
| 覆写破坏可重放 | 0 例（模拟器注入覆写后仍能重放） |
| 新增模型调用 | **0**（复用现有抽取批次） |

**风险**：抽取漏了 → 她说了但世界没变。缓解：宁可漏，不可错写；漏了的走正常衰减，不会自相矛盾。

### ADR 0028 挂心的事生命周期（W4）

**问题**：现在事件只分「发生」和「忘了」两种状态，中间那段——**当天可提、几天内还挂着、然后沉淀**——没有。
`open-loops.ts` 已经有 `loopForgotten()`（:60）做「忘」，但没有「沉淀」。

**范围**

- `runtime/<dataDir>/world/threads.json`：每条挂心的事带生命周期（几小时 / 几天 / 几周）。
- 到期的沉淀动作：**写进当天日记**（`diary.ts` 的素材已经能吃到世界的事）。

**接入点**

| 位置 | 现状 | 怎么改 |
| --- | --- | --- |
| `packages/bot/src/open-loops.ts` | `WAITING_DAYS`/`UNANSWERED_DAYS`/`UNSETTLED_DAYS` 都是 3 天，`SHOWN_REPLIES` 3 次，`loopForgotten()` 判过期 | 合并进统一的 threads 生命周期，**不要并排再开一套** |
| `packages/bot/src/world.ts:298` `diaryWorld()` | 已经收集「值得记一笔」的事 | 沉淀时把 threads 一并交给它 |
| `packages/bot/src/diary.ts:53` `diaryMaterial()` | 已经吃世界素材 | 接线点现成 |
| `packages/bot/src/world.ts:25` `World.events` | 有 `chance`，没有生命周期 | 加 `life`（几小时 / 几天 / 到某日） |

**验收**

| 指标 | 目标 |
| --- | --- |
| 同一件事被反复提起 | ≤2 次后必须沉淀或划掉 |
| 24 小时（对方不说话）里世界有变化、有事件 | ≥3 件 |
| 她主动提起的事里来自事件流 | ≥50% |

**风险**：与 `promises.ts` 的 `FORGET_DAYS=3`/`SHOWN_REPLIES=3` 规则重叠 → 在 ADR 里讲清楚**谁是唯一权威**，
否则会出现「承诺忘了但 thread 还挂着」的怪状态。

## 六、批次 2：内核

### ADR 0029 情绪惯性（S2 剩余）

**问题**：现在的情绪是 `her-days.ts:69 moodAt()` —— **一天抽一次、全天不变、不影响内容**。
ADR 0015 特意做成「按日期可复现的纯函数」，所以它没有历史。

**范围**：多维（愉悦 / 精力 / 烦 / 想他）+ 阻尼（惯性）+ 累积 + 恢复（睡觉重置、对方的话影响后续 2–3 轮、时间自然衰减）。

**接入点**

| 位置 | 现状 | 怎么改 |
| --- | --- | --- |
| `packages/bot/src/her-days.ts:69` `moodAt()` | 按日期 + 课表权重选一个心情 | 保留为**当日底色**（初始条件），另加连续状态层 |
| `packages/bot/src/her-days.ts:92` `describeMood()` | 一句底色描述 | 扩成多维里最突出的那 1–2 维 |
| `packages/bot/src/body.ts:33` `bodyAt()` | 困/累/饿/生理期/感冒 | **作为情绪的第一输入**（内感受），已是现成的 |
| `packages/bot/src/app.ts:140` `herDayLogger`、`:147` `noteHerDay` | 每天写一行 | 变成情绪内核的 tick 入口 |
| `packages/bot/src/app.ts:455` `herDayStatus()` | 状态页「今天」 | 加情绪多维的显示 |
| `packages/bot/src/json-file.ts` | 原子写 | 落 `mood_state.json`（累积状态必须落盘，否则重启就没了） |

**与 ADR 0018 的冲突**：跨天累积本质上就是把情绪存下来，而 ADR 0018 定过「不做带情绪的记忆」。
**这是待裁决项**，见 [decisions.md](decisions.md) 决策 1。本文的建议是**分层攒**：
情绪数值跨天累积（运行态、可衰减、不进 Hindsight、不进提示词的记忆区块），记忆层仍然只存事实。

**验收**

| 指标 | 目标 |
| --- | --- |
| 情绪变化能被具体的事解释 | 人工判 |
| 哄一句，下一句就软 | 人工判 |
| 跨轮温度一致（说生气不会立刻撒娇，除非被哄） | 人工判 |
| 模拟器可注入初始情绪状态并重放 | 必须支持 |

**风险**：破了「按日期可复现」。缓解：把累积状态显式化成可注入的初始条件，
模拟器场景里固定它，纯函数部分（衰减、触发）保持可重放。

### ADR 0030 关系温度（S3 剩余）

**问题**：对每个人的状态，现在只有**慢变的印象**（ADR 0017 的「她眼中的 X」），没有**此刻的温度**。

**范围**：对每人一份当下的感受——想他 / 有点生气 / 刚被哄好 / 欠他一个答复 / 在等他回消息。

**接入点**

| 位置 | 现状 | 怎么改 |
| --- | --- | --- |
| `packages/bot/src/memory/long-term.ts:148` `RELATIONSHIP_MODEL`、`:167` `personModel()` | 慢变印象，存在 Hindsight | **不动**；温度是新的一层，只存运行态 |
| `packages/bot/src/people.ts:196` `describePerson()` | 把印象拼进提示词 | 温度拼在印象之下，并**标明两者不同**（避免互相污染） |
| `packages/bot/src/json-file.ts` | 原子写 | 落 `relations.json` |

**验收**

| 指标 | 目标 |
| --- | --- |
| 跨轮温度一致 | 人工判 |
| 温度与慢变印象的措辞不混淆 | 人工判 |

**风险**：两套混在一起会互相污染（一句"他真烦"被写进慢变印象里，几周后还在）。
缓解：命名分开、存储分开、提示词里分区。

## 七、批次 3：外延

### ADR 0031 意外与连锁（S1 剩余）

**范围**：低概率事件 + `effects` 链 + 时间线可被打断。
DSH 侧的原例：雨没带伞 → 鞋湿了 → 下午有点烦 → 晚上不想出门。

**接入点**

| 位置 | 现状 | 怎么改 |
| --- | --- | --- |
| `packages/bot/src/world.ts:101` `simulateWorld()` | 事件按 `chance` 独立出，无连锁 | `World.events` 加 `effects`；推进时按已发生事件加权 |
| `packages/bot/src/world.ts:418` `unit()` | FNV-1a，均匀 | **保持**——随机要可重放；加权靠 `chance` 与条件，不靠换随机源 |
| 依赖 | — | **情绪惯性（0029）**：没有情绪内核，连锁没有落点 |

**验收**：她今天的情绪能被具体的事解释；同一场景同一天重放结果一致。

**风险**：连锁放大不确定性，容易变成「混乱而无意义」。原则：**有结构的随机**——每条连锁必须由
（地点 × 时间 × 天气 × 她的状态）加权触发，不做纯随机。

### ADR 0032 媒介层（W5）

**范围**：天气 API + 她追的番/剧的更新表 + 热榜（**按人设过滤**：游戏/摄影/小说/番/校园/美食，不是财经新闻）。

**接入点**

| 位置 | 现状 | 怎么改 |
| --- | --- | --- |
| `packages/bot/src/world.ts:379` `weatherOn()` | 查月均温表 + 哈希 | 换成真实 API，但**当天结果缓存落盘**，保留离线可重放的退路 |
| 依赖 | — | **单机权威**（批次 0.4）；两台机器跑会拿到不同数据、状态分叉 |

**验收**：24 小时世界推进 ≥3 件，且每天不同；离线时退回哈希，不报错。

**风险**：外网依赖 + 两台机器状态分叉。缓解：缓存 + 单机权威。

## 十、不做什么

1. **不放开出口检查**（ADR 0006 / 0014）——等决策 2 定了、并且模拟器证明不会退回「你倒好」再说。
2. **不把世界状态写进 Hindsight**——保持「当天这一层」与 ADR 0018 的边界。
3. **不让 NPC 进长期记忆的 bank**——NPC 是生活背景，不是对话对象。
4. **不动 `vendor/`、不动 Koishi 源码**（CLAUDE.md 规则）。
5. **不让世界区出现可照抄的整句**——只给事实与约束（DSH 原则 1）。
6. **不为了 engagement 优化**——参与度悖论是已知的失败模式；目标是「最像人」，不是「最让人想聊」。
