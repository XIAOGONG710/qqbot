## 二、它是什么

一个 AstrBot 插件，自称「独立持续型 AI 陪伴核心」（`metadata.yaml:5`）。它不替换 AstrBot 的主人格，只在主回复前后注入动态生活上下文、关系状态，并负责主动消息的编排（`README.md:36-38`）。平台是 aiocqhttp（OneBot）和 QQ 官方机器人。

- **规模**：约 270 个非测试 `.py` 文件、30 万行。超大文件有：`page_api.py` 3.2 万行、`main.py` 2.1 万行、`proactive_message.py` 2 万行、`daily_state.py` 1.9 万行、`proactive_engine.py` 1.1 万行、`user_memory.py` 1.1 万行。
- **生态**：长期记忆、生图、创作、识屏、通话 / 共同观影、现实设备都拆成了独立插件，这里只有适配层（`README.md:83-99`、`572-579`）。
- **docs/ 下大多是 V2 新框架的设计稿**：契约、状态机、回放夹具。设计稿自己写着「不能将文档完整度理解为实现完成度」（`docs/FRAMEWORK_DESIGN.md:3`），执行契约的运行断言「全部 not_run」（`docs/contracts/execution/v1/README.md`）。下文每条机制都标了「已实现」还是「设计稿」。
- **命令很多**：`陪伴 …` 有六十多条（`metadata.yaml:17-88`）。和我们「不再新增指令」的规矩相反，这部分不学。

## 三、核心机制（带路径）

路径都相对它的仓库根目录。

### 1. 她自己的生活

- **日程分两级（已实现）。** 每天由大模型生成一次粗日程（`planning.py:755-980`），生成后过 5 轮质检，不合格就带纠偏重试；失败时退回昨天的日程。某一段开始前 3 分钟，才把这一段细化成小事件、地点和状态（`planning.py:71-244`）。
- **聊天改她的日子（已实现）。** 只认主要用户的话。识别出的调整带强度、有效期（6 / 10 / 18 小时）和影响范围，写进当前段，并让这一段的细化失效重算（`daily_state.py:12255-12391`）。
- **计划和实际对账（已实现）✓。** `schedule_reconciler.py:560-837`：
  - 只有显式引用这条计划的证据才能改它的状态，时间或标题相似只算待核实的候选（`:640-651`）；
  - 聊天和计划时段重叠，记成 `possible_interruption`，「plan completion remains unproven」（`:653-700`）；
  - 时段过去还没有证据，状态是 `unknown`，「never complete」（`:795-805`）。
  读取时按用途给不同视图：此刻、过去、将来、主动、写记忆（`agenda_disclosure_policy.py:76-119`）。「此刻」只返回有证据的条目，不把原计划的文字当成事实（`agenda_runtime.py:767-835`）。
- **日记防编造（已实现）✓。** 写之前先建证据账，每条分四级：已确认 / 原计划 / 运行推演 / 状态底色（`dreaming.py:762-870`；`:866`「原计划，不能直接声称已经完成」）。写完再质检，「把未确认计划或推演写成了已完成经历」就打回重写（`:974`）。生成提示词里也写明，只有「已确认发生」能写成经历（`:1022`、`:1203`）。
- **她的时间线（已实现）。** 他问「你几点在做什么」时，才去日程、细化、日记、主动、创作、QQ 空间里检索；检索不到就让她说记不准（`self_timeline.py:110-133`）。
- **睡眠是 7 态状态机（已实现）。** 7 态是：清醒 / 入睡中 / 浅睡 / 被叫醒 / 临时晚睡 / 继续睡 / 自然醒（`daily_state.py:11706-12003`）。被叫醒后有 30 分钟缓冲，没人说话就睡回去。他说「陪我到一点」会生成一条临时晚睡约定，有上限，最晚到次日 06:00（`:11799-11927`）。
- **梦（已实现）。** 素材来自带权重的碎片池，权重每天 ×0.72 衰减，另加近期日记、有证据的历史、昨天聊天的余味和天气；原计划不能当梦的素材（`dreaming.py:295-481`）。
- **多出口共用一份生活（已实现）✓。** 日程和睡眠全局只有一份。外部插件（通话、共同观影）开始、续期、结束时各报一次「正在一起做某事」：`notify_external_activity_*` 带 TTL，默认 240 秒、限 30–3600 秒，过期自动删（`extension_api_scheduler.py:40-153`）。
  - 活动进行中，无关的主动消息暂缓（`busy_reply_gate.py:387-413`）；
  - 提示词写「实时共同活动（最高优先级事实），固定日程已被覆盖」（`scene_context.py:867-874`）；
  - 结束时插件交回一份 6 小时有效的短期连续性摘要，最多 8 条，分私聊版和群聊版，不写长期记忆（`extension_api_memory.py:49-103`）。
  - 这两份登记只在内存里，重启丢失（未核实）。
- **设计稿**：活动进程带 checkpoint 和版本号，暂停期间不长进度；共处会话走 requested→active→ending→ended，结束只产出摘要提案（`docs/DOMAIN_STATE_MACHINES_V0.md` §3、§7–11，全部 not_run）。

### 2. 主动消息

README 的说法是「候选生命周期」（`README.md:288-319`）。

- **候选与评分（已实现）。** 生活、新闻、天气、备忘、待跟进等模块都往里投候选，事件 id 稳定（`proactive_engine.py:852-899`），分 7 条路线，各自有间隔倍数和偏置（`proactive_routes.py:136-539`）。打分主体是 salience + urgency×0.9 + warmth×0.7，再叠加：按来源的回复率反馈（±0.18）、老化、过了最佳窗口扣分、犹豫一次加 0.035（`proactive_engine.py:1712-1825`、`3565`）。
- **没回就降速（已实现）。** 最小间隔 ×(1+0.35n)，上限 2.2 倍，不压每日额度（`proactive.py:2339-2373`）。
- **他说要休息就静默（已实现）✓。** 「睡了 / 别打扰 / 明早聊」静默到次日 08:30，且不少于 6 小时；午休 90 分钟；「休息」2 小时（`user_rest_gate.py:229-252`）。他一开口就解除（`:134-149`）；「睡了」不挡早安（`:223`）；引用别人的话、「不用回这条」之类不算（`:23-66`）。
- **对话中不插话**：ConversationOccupancy、revision 失效是**设计稿**（`docs/ARCHITECTURE_RESET.md:583-596`、`1231-1264`）。代码里是近似实现：他刚活跃过就顺延；她说了收尾的话后有 45 分钟宽限，他再开口就释放（`proactive_engine.py:1481-1610`）；他问「在干嘛」时清掉待发的状态分享（`:705-764`）。
- **人格判断（已实现，但大多被降成软建议）。** 单独一次模型调用，输出 send / rewrite / defer / drop，每天最多 12 次（`proactive_engine.py:2711-3034`）。defer / drop 默认降为软建议，只有语义拦截或理由里含特定关键词才真拦（`:2517-2585`）。
- **发送前复核（已实现）。** `proactive_message.py:5702-5917` 做确定性检查：内部残留和工具回执泄漏、像在回复刚发来的话、混进别人的私聊、重新承诺提醒却没建任务、外界分享缺来源。之后可选模型终审（`:6790` 起）。
- **额度取最小值（已实现）。** 全局、用户、关系阶段、当前互动档四者取最小；回避或受伤时为 0（`proactive.py:1611-1662`）。
- **审计（已实现）。** 每条主动都记：状态、拦截原因、路线、语义分、原文和终稿预览；同签名合并计数，留 160 条；24 小时内他回了，就把结果回填（`proactive_engine.py:5946`、`6073-6152`、`6247`）。
- **两个出口共用一本账（已实现）。** `proactive_chat_runtime_bridge.py` 包住另一个主动插件的整条发送链：生成前用同一套闸预检，含共用每日额度和 90 秒碰撞窗（`proactive_message.py:688-798`）→ 锁内取发送租约（`:932-945`）→ 生成后走同一套复核（`:961-1056`）→ 平台确认送达才记账，用 attempt_id 防重记（`:1058-1143`）→ 没送达就释放租约（bridge `:584-601`）。「别处说过了」只有话题签名的模糊去重，4 小时内相似的不发（`daily_state.py:2842-2877`），没有事件回执。

### 3. 记忆、情绪、关系

- **写记忆：实际是关键词打分后直接写（已实现）。** `user_memory.py:3402-3504`，最多 36 条。底下的权威存储层做 operation_id 幂等、逐字段 CAS、删除留墓碑（`authoritative_private_memory.py:252-366`），只保证写得可靠，不判断该不该写。「提议 → 权威写入」、禁止写入表和反例验收都是**设计稿**（`docs/MEMORY_CONTRACT_V0.md:44-195`、`docs/MEMORY_COUNTEREXAMPLE_EVAL_V0.md`）。
- **纠正（已实现）。** 正则识别「说反了 / 明明是」，30 分钟或 2 轮内作为当前纠正生效，旧事实不关闭（`user_memory.py:8106-8204`）。
- **情绪事件账（已实现）。** 每条事件有：稳定哈希 id、revision、status（observed / revised / applied / ignored / expired）、`correction_of`、来源分类（interaction / memory_recall / system_condition），不存原文（`domains/affect/emotion_event_contract.py:12-147`）。限长 64 条，按 id+revision 去重（`emotion_event_ledger.py:13-48`）。情绪惯性按半衰期 8 小时加权，提示词要求「单个新事件最多让外显情绪移动一档」（`user_memory.py:8206-8280`）。
- **回忆余波（已实现）。** 记忆插件产生 memory_recall 类事件（触到伤疤、温暖回忆、脆弱共鸣），这边拉来转成半衰期 30 分钟的短期状态，用完 ack（`memory_companion_adapter.py:3192-3316`）。
- **关系账（已实现）。** 防刷：30 分钟内同理由去重，单次 +4 / −12，每日 +12，高分段加分打折（`relationship_ledger.py:231-338`）。3 天宽限后正分只向 0 回落（`:441-515`）。八阶段，阶段间有 20 分迟滞（`relationship_policy.py:24-279`）。越界分轻 / 中 / 重扣分，道歉有限恢复，再犯追回（`user_memory.py:6747-7088`）。
- **表达决策共用（已实现）。** 一个纯函数给出不可变的 ExpressionDecision（七档，含 tts_style、主动预算、reason_codes），被动回复、主动消息、TTS 三处读同一个结果（`companion_interaction_expression.py:56-676`；调用点 `user_memory.py:1207`、`proactive.py:2475-2534`、`tts_enhancement.py:2888`）。
- **她的生活写进记忆时带两个标签（已实现）。** `reality_level` 区分 bot_action / observed_context / real_user_fact，`sayability` 区分 direct / indirect（`memory_companion_adapter.py:2724-3184`）。但写法是第三人称「Bot 梦境碎片：…」（`:3371`），正是 ADR 0347 第 5 层要修的毛病。
- **身份归并（已实现）。** 必须带显式 operation_id，只预览冲突、不自动合并（`unified_person_registry.py:1341-1432`）。

### 4. 提示词编排、发送、多端、诊断

- **注入计划（已实现）✓。**
  - 每段有 key、source、优先级、位置和合并规则。位置分四种：稳定 system / 动态 system / 回合末尾 / 工具契约（`conversation_injection_plan.py:45-54`、`214-627`）。
  - 同一个 key 来了两份内容不同的，记一条冲突，保留先到的（`:280-306`）。
  - 排序是稳定段在前、动态段在后，为的是保护 prompt cache（`:574`）。
  - 冻结前生成一份**不含正文的清单**，每段只记 key、source、位置、字数、sha256（`:188-211`，`main.py:19180-19209`）。
- **时效、可见性、证据元数据（设计稿 / 接入未核实）。** `companion/injection.py:401-447` 的上下文贡献结构有 lane、max_age_seconds、visibility、evidence、revision 等字段，但没找到它进主对话注入。
- **送达才入历史（已实现）。** 平台没返回失败，才记进送达账；工具步骤中途发的话和最终回复分开；后台补发余段的任务收尾后才写历史；进会话历史和外部记忆的只有确认送达的那几段（`final_response_persistence.py:51-494`）。补发余段时，上下文割裂、触发消息被撤回或命中禁词就停，并落一条结构化记录（原因、预期几段、实际几段；`main.py:12148-12275`）。
- **给外部插件的状态与主对话同源（已实现）。** 共处插件拿实时上下文用的是主链路同一个场景段函数（`scene_context.py:833`），用 `purpose` 参数显式标出去处不同的差异，比如给生图用时去掉「状态余波」（`:865`；`extension_api_diagnostics.py:44-104`）。桌宠桥只是把送达的主动消息文本 POST 出去（`desktop_pet_bridge.py:176-184`），拿不到角色状态。
- **扩展协商，对不上就当不可用（已实现）。** 描述字段集合、api 版本、实例代次（instance_generation）、能力，任一项对不上就算不兼容；对方报降级也算不可用（`companion/integrations/optional_plugin.py:79-126`）。
- **诊断。** 「答疑」读持久化的未回复原因（`command_handlers.py:600`、`2303-2325`）。Token 按来源、任务、天、小时记账（`token_budget.py:394-648`）。**反例**：「查看提示词 回复注入」是另外手工重拼的一份（`main.py:20140-20156`），不读冻结清单，和真实请求会对不上。

### B. 两边都有，它做得更好的

- **主动审计**：我们只记 result / reason（`proactive/proactive-planner.ts`）；它还记原文和终稿对照、评分因子、24 小时内回没回，周报能直接按路线看效果。
- **收尾留白**：我们是固定的 `RECENT_MS = 1 小时`（`proactive/proactive.ts:220`）；它从「她说了收尾」开始算，他一开口就释放。
- **给外部的状态按去处显式裁剪**：第 2 层方案里 SELF 的中性心境和 QQ 的 melt 版不一样，只在方案文字里「如实说明」；它把这种差异做成 `purpose` 参数，比对时能按标签豁免。
- **交回摘要分档**：第 3 层方案只计划「不放原文」的一句概述（`layer3-writeback.md:89`）；它分私聊版和公共版，各自带有效期。
- **复核的确定性检查项**更多（泄漏工具回执、混进别人私聊、承诺了提醒却没建任务）。我们的主动消息靠「生成时可以说不发」加「提交前重跑 blockReason」，回复侧另有审稿，两者没逐项对比过（未核实）。

### C. 我们更强的

- 生活是规则推出来的、可重放、有幂等事件账（`life/schedule.ts`、`world/world.ts`、`world/action-queue.ts`），不靠模型每天现编，也不会退回「昨天的日程」。
- 召回第二人称、带日期、会变淡、带当时的感觉和护栏（`memory/long-term.ts`、ADR 0218）；它写记忆靠关键词，召回第三人称。
- 动机先于时钟（`proactive/agency.ts`），模型说「不发」就真不发；先记后发、提交前重查闸（ADR 0329）。
- 不存会漂移的分数，数值从事实重算（`human-values.ts`）；它的好感分经济不适合我们只有一个男朋友档的场景。
- 「此刻的她」导出走同一批模块渲染（第 2 层方案），行为基线逐字比对（`test/baseline/`）；它的回放夹具没真跑过。
- 不新增指令，一切从对话里来。

### 不学的

- 大模型每天现编日程、失败就退回昨天的日程：和我们「世界账是唯一事实来源、可重放」相反。
- 关键词打分直接写长期记忆、第三人称写她的经历（「Bot 梦境碎片：…」）。
- 好感度分数经济（八阶段、扣分、道歉返还）：我们只有一个男朋友档，数值从事实重算（`human-values.ts`），别扭用 `emotion/grievance.ts`，比扣分更像人。
- 「人格判断」说 defer / drop 却默认照发：我们让模型说「不发」就真不发。
- 「查看提示词」另拼一份：诊断必须读真实那一份。
- 六十多条命令、2–3 万行的单文件、大量未实现的契约设计稿：我们不加指令，ADR 只写要做和已做的。

## 六、最该先化用的一项

**提示词指纹清单（建议 1）。** 理由有三：

- 不改她的任何言行，按规矩可以直接做；
- 第 2 层验收的「一字不差」现在只能开敏感日志、拿全文比，有了清单就能不碰正文地逐槽比对；
- ADR 0336 后面还有好几步拆模块，清单能在每一步看出哪段变了。

做完再做建议 2（桌面在场租约），它是第 3 层多处判断的共同地基，跟第 3 层的开关一起上线。
