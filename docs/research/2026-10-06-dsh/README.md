## 三、规划（最高标准、世界子系统、自传）

**总体**：方向和用户要的一致（「像一个存在的人」，不只是说话像人），分析扎实，很多根因带了行号，核对下来基本属实。
但它是一整套新的范式（内核 + 七个子系统），比 ADR 0014–0018 加起来还大，要拆成几个 ADR，一个一个确认、一个一个验证。

### 和已有决定的冲突（要用户明确定）

### 文档里和现状对不上的地方

- 早期稿写「主动消息现为 off」：10-05 起是 on（已改）。问题清单里写的是对的。
- 「表达层现在完全没做」：已有分条发送、最多 5 条气泡、打字时间、看心情不回、收尾后的附和不回（ADR 0007 / 0013），缺的是长度方差、错别字、改口这些。
- 「未完成的事」：ADR 0018 第 4 步做的是她答应的事，「她想知道结果的」「悬而未决的」还没有，这一点 DSH 侧说得对。
- 验收指标（真问句占比、短气泡占比、主动开口比例）可以做成模拟器报告里的统计数，但不宜当成通过 / 不通过的硬门槛：样本少，会逼着去凑数字。

### 建议的先后

1. ADR 0018 第 6 步（真模型批次）→ 第 7 步（问过用户再上线）。不变。
2. **ADR 0019「当天这一层」**（S0，纯提示词和数据措辞）：状态行只写约束（和 ADR 0014 的证据做 A/B）、意图层、心情写底色、对照结构进出口检查、热聊多等 2 秒、`pinExamples` A/B。逐条给用户确认。
3. **ADR 0020 披露分级 + 主动说别人的事**（问题 6 + 9）。
4. **ADR 0021 世界子系统 W0–W2**（`world.yml`、状态推进、进提示词）。动手前要用户定三件事（世界子系统文档第十三节）：室友 / 同学起不起名（自传已经定了两位闺蜜）、相机基金的数、媒介层接不接真实数据。
5. **自传接进来**：先把自传里的硬事实同步进 `persona.yml`（见下一节，有几处要用户定），再做 `biography.yml` 切块、有线索才召回。
6. 身体状态、情绪惯性、W3 回写（说完「去喂土豆了」世界跟着变）放在后面。

## 五、两处运维改动

- **`scripts/run-napcat-ascii.ps1`**：给仓库在中文路径的机器用，从 `C:\napcat-ascii\` 启动 NapCat，账号密码读 `C:\napcat-ascii\data\napcat_cred.txt`（明文，在仓库外，没进库）。
  本机仓库是纯 ASCII 路径，照旧用 `scripts/start-napcat.ps1`。再说一次：两台机器不能同时登这个 bot 号。
- **`docs/hindsight.md`「本机安装记录」**：防火墙放行、pg0 数据目录不能是中文路径、Hugging Face 和 PyPI 走镜像、嵌入模型实际约 2.2 GB、`pg0 start` 不能接管道。
  都是实测出来的坑，保留。数据目录那一条按 `2ab139a` 改成了现在的选法。
  那台机器的仓库在中文路径，照样落到 `%LOCALAPPDATA%`，行为不变；以后要是把仓库挪到纯 ASCII 路径，先设用户环境变量 `QQBOT_PGDATA` 指向现有的数据目录，不然会换成仓库里的空目录。
