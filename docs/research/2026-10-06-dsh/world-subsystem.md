# DSH 侧：世界子系统 —— 详细构建方案（2026-10-06）

> 归档（2026-10-06）：原 `docs/DSH侧-世界子系统构建方案-2026-10-06.md`。审批意见见 [README](README.md)。

**这份解决什么**：最高标准方案里第 ⑤ 项「世界」写成「没有」。本文把它拆成可施工的三层（资料 / 状态 / 规则）、五块内容、七个阶段。
**标准**：一律按最高标准，以最像人为方向，难度不作取舍依据。
**怎么用**：不替代 ADR。要动手的先写 ADR；本文给结构、数据草案、接入点和验收判据。

---

## 一、起点：她的世界**已经存在**，只是没有状态

**世界构建必须从她已有的事实长出来，不能新发明。** 她资料里的原话：

| 事实 | 出处 | 现在的形态 |
| --- | --- | --- |
| 宿舍**楼下有只三花流浪猫**叫「土豆」，她起的名字，**每天下楼喂**，拍它照片存手机，**会拿给他看**（低档位去掉「给他看」） | `persona.yml:377` / `:394` | 只是**描述**，没有状态 |
| **宿舍 8 人间**；最怕数学；追剧、游戏、食堂和奶茶外卖、**穿搭化妆**、熬夜的黑眼圈、**痛经** | `persona.yml:500` | 只是**场景举例** |
| 在**攒钱买相机**——在拍照修图，「想要个真的」 | `persona.yml:252` | **没有进度** |
| 「中午食堂去不去」「这老师点名好烦」「**我快递到楼下了，帮我拿一下**」「今晚一起追剧？」 | `persona.yml:489` | 只是**例句** |
| **她会主动分享**：刷到的好玩视频、土豆的照片、自己拍的照片、今天吃了什么、追剧的吐槽 | `persona.yml:436` | **没有来源** |
| 日记写日常流水：今天吃了什么、**剧追到第几集**、土豆又干了什么、他今天说了什么 | `persona.yml:432` | 同上 |
| 青岛人，独生女，爸妈都在体制内，**每周和家里视频**；专业是人工智能与大数据应用（她自己感兴趣） | `persona.yml:107` `:110` `:117` `:171` | 半静态事实 |

> **关键结论**：她**该分享什么、日记里写什么、平时会碰到什么**，资料里已经定了；缺的是**这些东西的状态、推进规则，和"说出去之后世界要跟着变"**。
> 所以这不是"给她一个新世界"，而是**把已有的世界从文字变成活的**。

## 二、世界的定义与四条判据

**定义**：她所处的、**会变化、可被提及、有边界**的环境。

| 判据 | 含义 | 反例（现在） |
| --- | --- | --- |
| **① 自己会变** | 你不说话时它也在推进 | 土豆「每天喂」只是句子，没有"今天还没喂" |
| **② 自洽** | 昨天/刚才的状态约束现在 | 状态说「修片子」，她说「躺着赶作业」（模拟器已抓到） |
| **③ 可被提及** | 能变成对话内容，且是她**主动**提得起的 | 她会分享的东西没有来源，只能现编 |
| **④ 有边界** | 她只知道她该知道的 | 现在没有"信息边界"这一层 |

## 三、世界 = 资料 + 状态 + 规则

**三者缺一不可**，而且必须分开存放（否则会互相污染）：

| 层 | 是什么 | 放哪 | 谁改 |
| --- | --- | --- | --- |
| **资料（什么存在）** | 地点、物、人、常去的店、习惯 | `characters/linmengyao/source/world.yml`（**新增，走控制台编辑页 + 隐私检查**） | **人**（用户/控制台） |
| **状态（现在怎样）** | 土豆饿不饿、快递到没到、作业写到哪、室友在不在 | `runtime/<dataDir>/world/state.json` + `events/<date>.jsonl` | **运行时**（tick） |
| **规则（怎么变）** | 每小时/每天怎么推进、什么条件下触发什么 | 写在 `world.yml` 的每件东西上 | **人**（资料层） |

> ⚠️ **决策点（要用户确认）**：资料里的 **NPC（室友、同学）目前没有名字**（她资料里只有"室友"这个群体）。给她起名字 = **扩展人设**。
> 按你们已有的规则「设定里没写到的自己的事含糊带过、不现编」（roadmap 里那条 `discreet`），**这些名字必须写进资料层，不能让模型现编**——不然后面会前后不一致（参考之前"老家答南方一个小地方"那类问题）。
> 建议：**先给 2 个室友 + 1 个同学起名**（够用且不臃肿），其余的用「室友」「同班那个」这类群体称呼。

## 四、五块内容

### 块 1：环境（她身处的空间与自然）

- **固定地点**：宿舍（8 人间）、知行楼（上课/机房）、图书馆、一食堂/二食堂、超市、快递驿站、**楼下猫窝**、回家路上
- **自然**：济南的天气/气温/季节/日照（→ 直接接真实天气 API）
- **每个地点挂"可提及的物"和"会发生的事"**：食堂 → 新窗口/排队/菜不好吃；机房 → 键盘坏/老师讲得快；驿站 → 排队/取件码

### 块 2：物（有状态、会自己推进）—— **这一块是核心**

| 物 | 状态 | 推进规则 | 可提及（示例，注意不是台词模板） |
| --- | --- | --- | --- |
| **土豆**（三花流浪猫） | 饥饿 / 猫粮存量 / 今天见没见到 / 心情 | 饥饿每天 +0.35（分早晚两次喂）；她**没课且不下雨**时会下楼 | 饿 → 蹲在脚边叫、扒东西；见到 → 蹭腿；没见到 → 有点失落 |
| **快递** | 在途 → 到驿站 → 取件码（3 天过期）→ 已取 | 下单后 T+2 到，T+5 过期 | 「补光灯终于发货了」/「到了但我不想下楼」 |
| **相机基金** | 已攒金额 / 目标 | 每周 +一点（省下的钱） | 「攒到 X 了，还差一半」——**这是"进度感"的来源** |
| **作业/实验报告** | 名称 / deadline / 完成度 | deadline 越近完成度推进越快 | 「写一半写不下去了」——**但只有在完成度真的卡住时才能说** |
| **奶茶/外卖券** | 张数 / 过期日 | 过期自动消失 | 「我的券明天过期，今天必须喝一杯」 |
| **手机电量 / 充电宝 / 伞** | 短期状态 | 按一天的活动推 | 「手机只剩 5%」/「伞还在宿舍」 |
| **身体相关** | 痛经周期、感冒、黑眼圈 | 按周期/睡眠质量推 | 痛经那几天会改变情绪基线和说话方式（**这是"身体"子系统的主要输入**） |

### 块 3：人（社会关系）

**分两类**：

| 类 | 谁 | 已有？ |
| --- | --- | --- |
| **名单里的人** | 宝宝（boyfriend）、鸽鸽（classmate） | ✅ ADR 0016/0017 已有（bank、印象、公共库） |
| **世界里的 NPC** | 室友 ×7（8 人间）、同班同学、老师、妈妈/爸爸、楼下阿姨、快递小哥 | ❌ **要新建** |

每个 NPC 要有：**称呼 / 关系 / 印象 / 最近状态 / 未完成的事**。
例：妈妈 → 每周视频 → 最近在催她穿秋裤 → 可提及「我妈刚发消息问我冷不冷」。

**NPC 与名单里的人的区别**：NPC **不在 QQ 上**，她**不能说"我刚跟鸽鸽聊了"就当 NPC**——她的世界和 QQ 名单是两个圈，但**可以互相提到**（这正是"她主动说起别人的事"那条边界管的）。

### 块 4：事件流（世界在发生什么）—— **她主动开口的燃料**

| 类别 | 例子 | 触发方式 |
| --- | --- | --- |
| **日常节律** | 上课、吃饭、午睡、洗漱、喂猫、取快递 | 由时间线（作息）驱动 |
| **周期事件** | 周一大扫除、周三值班、周末留校/回家、每月那几天 | 按周期表 |
| **校园事件** | 社团招新、讲座、查卫生、运动会、评奖、调休 | 日历 + 随机 |
| **突发** | 下雨、停电、停水、猫吐毛球、快递丢件、室友吵架、老师点名 | 低概率随机 + 条件触发 |
| **媒介** | 热搜、短视频、群聊、朋友圈、**番剧/小说更新** | **外部真实数据**（块 5） |

**每件事的生命周期**：发生 → 当天可提 → 几天内还挂着 → 沉淀（进日记/记忆）。
**不能永远挂着**（这正是 ADR 0014 那条「说明里的话她会每句都照做，不能一直挂着」的同一条道理）。

### 块 5：媒介（外部世界进入她脑子的入口）—— **最高标准下必须有**

她的世界不止宿舍和猫。她**每天刷手机**：

| 渠道 | 内容 | 来源 |
| --- | --- | --- |
| 短视频/社交 | 刷到的好玩视频（**她资料里明写了会主动分享这个**） | 热搜/热榜 API |
| 追的番/剧/小说 | **更新了** → 今天有新一集/新章 | 更新表（或人工维护她追的那几部） |
| 群聊/朋友圈 | 别人发了什么 | 可人工或半自动 |
| 游戏 | 今天打到哪、输了赢了 | 规则生成 |

> **这是"她主动提起"最大的来源**，而且**天然每天不同、不需要编**。
> 注意信息边界：**刷到的内容要符合她的人设**（游戏/摄影/小说/番/校园/美食），不是财经新闻。

## 五、世界怎么跑：tick + 三类事件

```
tick（每 5 分钟，事件驱动可提前）
 ├ 1. 推进「物」：按各自的速率/规则更新状态
 ├ 2. 到点了没：检查今天时间线里排定的事件
 ├ 3. 掷骰子：按（地点 × 时间 × 天气 × 她的状态）加权的随机事件
 ├ 4. 写入事件流：events/<date>.jsonl
 └ 5. 回写她的状态：世界 → 情绪 / 身体（这是世界影响她的唯一通路）
```

**加权而不是均匀随机**：下雨天才可能触发"没带伞"；deadline 前才可能触发"通宵赶作业"；她在宿舍才可能触发"室友吵架"。

## 六、三个世界，和它们之间的信息边界

**最高标准必须把这三个圈分开**，否则会不像人（像神）：

| 圈 | 内容 | 她怎么知道 | 能不能主动提 |
| --- | --- | --- | --- |
| **她的世界** | 宿舍、猫、课、室友、她刷到的东西 | 亲身经历 | ✅ 可以（这是她的一天） |
| **你们共同的世界** | 一起经历过的、约好的事 | 聊天记录 + 记忆 | ✅ 可以，但**只对他/对参与过的人** |
| **你的世界** | 你在青岛的事、你的同学、你的日常 | **只能通过他得知** | ⚠️ 只知道他告诉过的；**不能"猜"到** |

**边界规则**：
1. 她**不能知道**你没告诉她的关于你的事（不能"我感觉你今天很累"这种超能力）
2. 她的 NPC 和你的世界**不共享**（她室友不知道你是谁，除了她主动说）
3. **共同世界要按档位抬出来**：和同学档聊天时不能提"我们一起去的那个地方"

### 运行态 `runtime/<dataDir>/world/`

```
state.json                 # 当前世界状态（快的、几小时内有效的）
events/2026-10-07.jsonl    # 当天发生的事（每行一件：时间/来源/内容/影响）
threads.json               # 挂心的事（几天到几周，带生命周期）
```

**持久化 + 可回溯** 带来三件好事：跨天连续、可审计（为什么她今天这么说）、可复现（模拟器能重放）。

## 八、世界 ↔ 她 的三条通路（第三条最关键）

| 通路 | 方向 | 说明 |
| --- | --- | --- |
| **① 世界 → 状态** | 事件影响情绪/身体 | 下雨没带伞 → 烦躁 +0.2、体力 −0.1；土豆生病 → 焦虑 +0.4 |
| **② 世界 → 表达** | 她说的内容来自事件流 | **不是编的**——今天真发生了才能说 |
| **③ 表达 → 世界（回写）** | 她说的话改变世界 | **她说完「我去喂土豆了」→ 土豆的 hunger 归零、seen_today = true** |

> **③ 是现在完全缺的一环，也是"言行一致"的实现方式。**
> 没有回写，就会出现：今天说喂了猫，明天还能说「土豆还没喂」——**模拟器里已经抓到过同类不一致**（状态说修片子、她说躺着赶作业）。
> 回写不需要模型参与：从她的回复里抽"她声称做了什么"（可以用已有的抽取通道，和 promises 同一批），比一下就能更新。

## 九、与现有模块的接入点

| 现有 | 怎么接 |
| --- | --- |
| `schedule.yml` | 世界的**骨架**（时间线）——已经有了，不用重做 |
| `her-days.ts` | 现在是"她的日子"（心情/书），升级成**世界 tick 的入口** |
| `persona.yml` 的土豆 / 相机 / 快递 | 从"设定里提到"升级成"有状态的物"（**资料要抽到 `world.yml`，persona 里留引用**） |

| Hindsight | 事件流 → 记忆素材；**但世界状态本身不进记忆库**（保持"当天这一层"的边界） |
| 控制台「林梦瑶」页 | 加一个「世界」分页（物、人、事件源）——沿用 ADR 0010 的编辑页 + 隐私检查 |

## 十、分阶段（W0–W6）

| 阶段 | 内容 | 依赖 | 难度 |
| --- | --- | --- | --- |
| **W0 资料层** | 写 `world.yml`（物 / 人 / 事件源 / 规则）+ 档位可见性 + 隐私检查 + 控制台分页 | 无 | 小 |
| **W1 状态推进** | `world.ts` 的 tick（物推进 + 计划事件 + 加权随机） | W0 | 中 |
| **W2 接进提示词** | 「此刻的世界」作为独立区块（⚠️ **只给约束，不给可照抄的句子**） | W1 | 中 |

| **W5 媒介层** | 外部真实数据：天气、热搜、追的番更新表 | W1 | 中 |
| **W6 模拟器** | 能重放、跨天自洽检查（见下节） | W1–W5 | 中 |

> **W0 是纯资料**，可以立刻开始；**W3 是"像人"的关键一跃**（说完的话世界要跟着变）。

## 十一、验收指标

| 指标 | 判据 | 目标 |
| --- | --- | --- |
| **跨天自洽** | 昨天喂了猫，今天不能说没喂 | **0 例矛盾** |
| **言行一致** | 她声称做过的事，世界状态确实变了 | ≥ 95% 被回写 |
| **世界在推进** | 你不说话的 24 小时里，物状态有变化、有事件发生 | ≥ 3 件 |
| **主动素材** | 她**主动**提起的事里来自事件流的比例 | ≥ 50% |
| **不重复挂账** | 同一件事被反复提起 | ≤ 2 次后必须沉淀或划掉 |
| **信息边界** | 她说出"你没告诉过她的关于你的事" | **0 例** |
| **不可照抄** | 回复里出现世界区的原句 | **0 例** |

**W6 的自洽检查（建议做成模拟器检查项）**：
```
给定世界状态 W 和她的回复 R
  → R 里声称的事实是否与 W 相容？
  → R 声称做了的事，回写后 W' 是否自洽？
  → 跨天：W(t) 与 W(t+1) 的差是否能被事件流解释？
```

## 十二、禁忌与边界

1. **不要写成可照抄的句子**（最高标准方案里那条原则 1）——世界区只给**事实与约束**，不给措辞。
   ❌「一个人待着也挺自在」 ✅「在宿舍，他在青岛」
2. **不要给她上帝视角**——她不能知道你没告诉她的关于你的事。
3. **不要让她现编世界细节**——资料里没写的（室友名字、店里的事）**要么写进 `world.yml`，要么含糊带过**。
4. **不要让她永远挂着同一件事**——每条事件有生命周期，过期要沉淀。
5. **世界状态不进记忆库**——保持「当天这一层」与 ADR 0018 的边界（不进记忆、不带情绪）。
6. **NPC 不进长期记忆的 bank**——NPC 是她的生活背景，不是需要被记住的对话对象。
7. **媒介内容要符合人设**——她刷到的是游戏/摄影/小说/番/校园/美食，不是财经新闻。

## 十三、要用户定的三件事

1. **室友/同学要不要起名**（现在是"室友"这个群体）。起了名字就要写进资料层，不能现编。建议先起 **2 个室友 + 1 个同学**。
2. **相机基金的目标金额和攒钱速度**（例：攒 320 / 目标 1200 / 每周 +30）——这决定她的"进度感"。
3. **媒介层要不要接真实数据**（热搜/番剧更新表），还是先用规则生成。接真实数据最像人，但需要维护她"追的那几部"的清单。
