## 按调研方案补齐（ADR 0004）

按 [ADR 0004](adr/0004-time-scheduling-memory.md)，依据 [调研与调试方案](research/2026-10-03-companion-research-and-debug-plan.md)。
顺序：时间 → M2（上一节）→ 消息调度 → 长期记忆。口吻、时间承接这类用例必须在 QQ 上实测，单元测试不能代替。

- [x] 角色表达：示例对话（`mes_example`）按 ST 实现；男朋友档的语气修正（不再怼人、不乱许诺）
  - 背景：10-04 探索分支（已删除）加了情感底色和示例对话后，用户实测她不再怼人、不再胡言乱语；这里按同样的效果重写（`cad4a27`），
    所有档位共用的输出规则只写对谁都成立的话，情感底色和示例只给男朋友档
  - 验证：`npm test`（69 项）。示例对话的拆块、`name`、预算挤出与 `pinExamples` 对照 `openai.js` `parseExampleIntoIndividual` / `populateDialogueExamples`；
    后处理里示例名字变成「名字: 」前缀对照 `prompt-converters.js` `mergeMessages`。
    实测（模拟器，ADR 0005）：重写后的卡 T02 6 次全是反话或埋怨，`6d40b04` 再改男朋友档的人设后通过，见下文「实测」一节
- [x] 时间：每次生成算出当前时间、星期和距上一组消息的间隔，放在聊天记录之后；ST 时间宏
  - 验证：`npm test`（78 项）。`time.test.ts`：时间宏的格式与 `humanize` 阈值对照 `time-macros.js` 和 moment 默认值；
    `idleDuration` 连发时只有「1 分钟」，运行时的提示按这一组第一条算出「3 天」；昨天、停机后补回、第一次聊天几种情况。
    用一位联系人的真实记录干跑：时间提示排在聊天记录之后、末尾指令之前。实测：QQ 上答对星期几（10-04 20:09）；模拟器里星期、T10、T11 各 3/3 通过，见下文「实测」一节
- [x] 消息调度：连发合并（静默约 2 秒、最长约 6 秒）；拆条发送中途来新消息时不发过时的剩余部分
  - 验证：`npm test`（84 项）。假时钟测试：三条间隔 0.5 秒的消息在最后一条之后 2 秒一起生成；一直在发时第 6 秒生成；补回后的 catchUp 不等；
    发送三条的第一条之后对方插话，后两条不发、接着回复。实测：QQ 上 T07、T08 通过，T09 手动来不及；模拟器里 T07–T09 各 3/3 通过，见下文「实测」一节
- [x] 长期记忆：Hindsight，按片段写入、生成前召回、关系概况（Mental Model）
  - 环境与来源核对见 [docs/hindsight.md](hindsight.md)（hindsight-api 0.10.2，依赖按哈希锁定；PostgreSQL 与 onnxruntime 需要 14.40 以上的 VC++ 运行库）。
  - 验证：`npm test`（98 项）。`memory.test.ts` 把建库、写入、召回、关系概况的请求体逐字段对照 0.10.2 的 OpenAPI（探索分支的错误写法会被查出来）；
    片段切分、只写结束了的或攒够 30 条的片段、失败下次重写、同一联系人串行、召回出错不注入、当前片段不重复注入。
    端到端（本机 Hindsight，虚构联系人与编造的对话）：中文绰号、偏好变化、否定句、相近事件、相对时间的召回都排第一，测试 bank 已删。
    离线全链路（假 NapCat、假模型接口、本机 Hindsight、虚构联系人）：启动补回后写入两个旧片段 → 收到消息等 2 秒 → 召回 4 条 → 生成 → 拆两条发出；
    发给模型的提示词依次是示例对话、聊天记录、召回的记忆、时间提示、末尾指令。测试 bank 已删。
    实测：QQ 上写入、召回都在跑（10-04 晚上），模拟器里 T13、T14、T19、T20、T23 通过；实测发现中文绰号召回不到，换成 PGroonga（`7647578`），
