# 生活模块第二轮深入复核

首轮 16 项及 #17 模型错误日志泄漏已修复，完整检查记录见 [持续进度](optimization-progress.md)。本轮在用户授权后使用三个子代理并行检查，主代理整合验证。下面只列有合成数据复现的新增问题，编号接续首轮；具体修复状态以持续进度为准。

## #18 [P1] 身体配置允许无限回看，阻塞同步状态投影

位置：`life/body.ts` 的 parseBody、coldOn。

合法 JSON 中的数值 `1e309` 在解析后为 Infinity。旧校验只要求 cold.days >= 1，因此接受该值；coldOn 从 Infinity 逐日递减，永远不会推进。隔离复现子进程在 1500ms 超时后被终止，主进程没有挂死。此外，无效日历日期、零/负/倒置/字符串周期及越界概率也被接受。

修复：严格校验形状、日期、正安全整数周期及长度、有限概率和月发生率；感冒天数上限 366 用于保证计算量有界，不是医学判断。直接调用 coldOn 的路径同样检查，防止绕过配置解析。新增 6 项回归覆盖非法值及合法端点。

## #19 [P2] 开放会话取消约定未及时释放日程

位置：`life/promises.ts` 的提前约定抽取。

模型已返回旧约定 ID 的 resolved，提前抽取只处理 add，旧约定仍进入 appointmentsBetween。合成复现为 12:00 明确取消 12:10 的见面，近未来日程仍被占用。需要在成功的提前抽取中处理取消，并验证重启后仍取消；失败抽取不能改账。

## #20 [P2] 跨会话改约仍保留旧地点

位置：`life/promises.ts` 对 pending 同时间约定的去重分支。

首轮 #3 修复了同一开放片段的 earlier。另一个会话的旧约定仍被 pending 匹配后直接跳过。第二个关闭会话明确把东门改西门，抽取结果正确但账里仍是东门。需要统一见面约定更新：先按同一联系人的日期/时间匹配，再更新内容并保留稳定 ID，不能依赖模型必定同时返回 resolved。

## #21 [P2] 数组形日记进度在序列化时消失，重复生成与入库

位置：`life/diary.ts` 的状态读取。

written:[] 被当日期映射使用，日期属性写进数组后 JSON 序列化仍为 []。连续两次 catchUp 会生成并保存六篇最近三日的日记，进度始终丢失。需要校验映射形状、日期、字数和原文类型，兼容旧版缺省字段；坏状态应明确失败并保持原文件。

## #22 [P2] 未来经历提前生成并持久化偏好

位置：`life/tastes.ts` 的 reflect 经历过滤。

只过滤时间 >= since，没有时间 <= now。app 传入全账时，六条未来经历足以在今天形成偏好。需要在反思入口截断未来及无效时间。

## #23 [P2] strength 对象仍能使合法 JSON 提案崩溃

位置：`life/tastes.ts` 的提案 strength 转换。

首轮排除了 null 提案，但 `Number(p.strength)` 仍会对 JSON 对象 `{valueOf:null,toString:null}` 抛出 TypeError。需要只转换允许的原始数值类型，并确认有限值，避免任意对象强制转换。

## #24 [P2] 乱序平台回复破坏近期相遇历史

位置：`life/acquaintances.ts` 的 observe 摘录追加与淘汰。

回复按到达顺序 append/slice，而 last 取时间最大值。历史补抓或乱序回复可把旧摘录放到最后并淘汰真正的近期摘录，提示词中的“上一次”与最后相遇时间矛盾。需要按事实时刻排序后保留近期记录。

## #25 [P2] 未来相遇出现在今天的熟人提示

位置：`life/acquaintances.ts` 的 promptLine。

只判断 now-last < 三天，未来 last 产生负差值也能通过。未来两次观察直接进入今天提示。需要排除尚未发生的观察，并让展示摘要与当前截止时间一致。

## #26 [P2] 熟人与偏好状态只校验数组，不校验元素

位置：`life/acquaintances.ts` 和 `life/tastes.ts` 的 #load。

people:[null] 或 tastes:[null] 作为合法 JSON 通过读取，promptLine 随后 TypeError；调用链会进入提示词回调。需要严格校验持久状态，在数据不可确认时明确失败，保留原文件，禁止把坏数据静默重置为空后覆盖。

## 验证边界

复现使用合成文件、假模型和隔离子进程，没有调用真实 QQ、B 站或记忆服务。新增修复必须有正确行为回归，并由主代理再次检查调用链、执行适用检查后提交。此清单不保证模块不存在其他缺陷。
