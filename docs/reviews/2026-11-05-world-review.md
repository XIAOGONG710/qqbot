# 世界账模块深入审查

基线：`bbe9df96`。登记的九个文件分为四路并行检查：主代理审查事件账、行动队列与选择器，三个子代理分别审查世界投影/写回、天气/节日、NPC/邀请/障碍。仅使用合成数据、假供应商和故障注入，不调用真实服务或读取运行时隐私资料。当前模块仍在审查，不能以局部检查通过宣告全部完成。

## 已确认缺陷与建议

| 编号 | 优先级 | 位置 | 证据与影响 | 修复方向 |
| --- | --- | --- | --- | --- |
| W01 | P1 | action-queue.ts 的 replace/drop/settleDue | 原子写入失败后内存已变化，同 ID 重试假成功，重启丢计划；结算清理失败也会提前移除队列或发布死信 | 先成功持久化，再发布内存；清理/确认失败保留计划并允许幂等重试 |
| W02 | P2 | life-events.ts 的 validLifeEvent | 不存在的日历日、自动滚动的时间、空身份及不安全金额/contact 通过持久校验 | 严格日历/ISO 时间和安全整数边界，坏账失败关闭 |
| W03 | P2 | life-events.ts 的 readLifeEvents | 同 ID 冲突事件作为多条独立事实被读取，消费者可能不一致 | 校验事件 ID 唯一，保持原文件并明确失败 |
| W04 | P1 | life-events.ts 的读取异常 | JSON 解析异常带事件正文片段进入普通错误信息 | 对外保留错误分类，不包含私密正文；保留瞬时 IO 错误语义 |
| W05 | P2 | life-selector.ts 的 targetForMeal | 全天晚饭事件被当午饭同伴，晚饭和迟到吃饭却未关联实际 NPC | 按实际饭点匹配事件及举行的约，覆盖午饭/晚饭/迟到分支 |
| W06 | P1 | world.ts 的 persist | events A 已写成功、兼容 actions 写失败，下一次 B 基于旧内存覆盖主账并丢 A | 主账写成功立即发布，兼容投影失败保持 dirty，可重试同 ID 修复 |
| W07 | P2 | world.ts 的相机购买 | 13:00 礼金可倒填成 12:00 出门、12:30 已购买 | 固定出门时刻的资金前置检查，不能用未来资金改写已发生购买 |
| W08 | P2 | world.ts 的猫粮投影 | 补给 12:20 才取，11:00 在驿站的猫粮已加进可用库存 | 按真实取件时刻计算可用粮，不按整日提前计入 |
| W09 | P2 | world.ts 的作业投影/完成前置 | 当天 08:20 尚未上课，07:00 作业已可见且可声明完成 | 至少到实际课程开始后才布置/可完成，不猜课内具体分钟 |
| W10 | P2 | world.ts 的 nextLesson | 同名课程在周四/周五两个条目，截止却按原条目 ID 推到下周四 | 待引入跨披露档稳定且不泄密的课程分组身份后修复；不先引入高低档 due 分歧 |
| W11 | P2 | weather.ts 的 wetSlot/dayFrom | 回放 14:00 读取 15:00 才可知的前小时累计降水 | 观测键同时受 until 截止限制 |
| W12 | P2 | weather.ts 的缓存读取 | 坏形状、字符串温度等合法 JSON 缓存产生 NaN 结果 | 严格校验、明确降级错误、保持原文件，修好后可重读 |
| W13 | P2 | weather.ts 的请求超时 | 供应商忽略 AbortSignal 时永久锁住 inFlight | 独立截止竞速、释放锁与监听，迟到结果不能覆盖新缓存 |
| W14 | P2 | festivals.ts 的活动合并 | 覆盖作者 free.on，关闭模式也未撤销已注入的未来活动 | 来源标记区分生成项，保留作者与已开始时段，可逆重建未来项 |
| W15 | P2 | festivals.ts 的日历合并 | notes/greet/off 因 name/year 去重无法更新已生成模式 | 只更新有来源的未来生成项，旧无标记条目保守保留 |
| W16 | P1 | npc.ts / parseWorld | 无限或巨量月发生次数进入同步循环，隔离子进程超时确认 | 解析与直接投影都校验有限有界参数 |
| W17 | P2 | obstacles.ts 的作业障碍 ID | 同一 due 不同课程/结束时刻被 Map 合并，丢整段占用 | 用不含正文的稳定复合身份，保留同一障碍去重 |
| W18 | P2 | npc-asks.ts / world.ts | 多个 NPC 独立答应，图书馆与视频 held 时间互相重叠 | 按通知时间线与稳定优先级协调已答应时段，保留拒绝事实及理由 |

## 不是本轮缺陷的既定行为

ADR0048 明确允许已有足够覆盖的过去预报补为实况，并要求已观测小时不被覆盖。初步怀疑的“昨天全预报可补实况”因此撤回，不修改该政策或已有兼容测试。改变该政策需独立决策，不能借审查顺手改变历史规则。

## 校验与边界

正确行为回归分别放在 `world-queue-review`、`world-ledger-review`、`world-selector-review`、`world-state-review`、`world-weather-review`、`world-festivals-review`、`world-npc-review` 测试文件。各组先证明失败再修复，覆盖失败写入、重启、同 ID 重试、时间因果、超时、坏缓存和跨 NPC 冲突。当前提交与最终验证状态见 [持续进度](optimization-progress.md)。W10 仍待稳定身份依赖，世界账模块不能据此标记全部审完。
