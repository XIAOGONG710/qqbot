## 接手顺序

**先核对 GitHub 仓库可见性。** 11 月 27 日的交接记录显示远端为公开。确认改为私有后再发布内部交接材料。详见[过夜小结](../reports/2026-11-27-overnight.md)。

1. 先同步 `main`、检查 Git 信箱和工作区。读取当前 Koishi / DSH 加载版本、监听和开关状态，确认 `oneDiary` 仍关闭。把仓库提交与运行版本分别记录。
2. 授权上线前做一次只读预检。重点核对配置旧键能否迁移、设备控制配置及当前数据库和状态包是否完整。语言和跨联系人记忆的部署取舍沿用既有决定单，避免把上一轮授权用于新变更。
3. 有当次授权后，再按部署手册操作。DSH 插件安装或重载与 Koishi 部署分别验收。QQ 入口、召回、桌面在场、跨端回写和留话按顺序核对，先用合成数据。
4. 需要回退时先保全数据。特别检查 `outbox-state.json` 中的待发队列、未决投递与未补写回执。旧版本只读 `OUTBOX.jsonl`，不能把投递不明的内容原样转回旧队列。
