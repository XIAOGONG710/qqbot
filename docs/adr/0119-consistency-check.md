# ADR 0119：前后一致性检查（只读工具，不进运行时）

- 状态：**已实现**（2026-10-22；工具 `node src/ops/consistency-cli.ts`；没有开关，不改运行时行为）
- 日期：2026-10-22
- 关联：[ADR 0118](0118-weekly-report.md)
- 用户提出：2026-10-22「把 A 全部做完」（A12）

## 为什么

一天上线十几个改动，模拟都是几轮的短场景，看不到“跨天”的毛病：下午说在上课其实没课、说下雨其实没下、同一句话三天里说了三遍。

## 做了什么

`consistency.ts` + `ops/consistency-cli.ts`：把她说过的话和**当时的账**（作息 / 假期、世界账的下雨钟头）对一对，**只用规则（正则 + 账），不调模型**。命中的只是“该人工看一眼”的线索，不是定论（比如“等下课”说的是将来，不算在上课）。

规则：
1. 说在上课，账上这会儿没课（排除等下课 / 刚上完 / 要上课 / 去上课……）；
2. 说在宿舍，账上这会儿在放假；
3. 说在下雨，账上这个钟头没下；4. 说没下雨，账上这个钟头在下（要世界账；没有就不查这两条）；
5. 问候和钟点对不上（她先开口时中午以后说早安 / 白天说晚安；回他的不算）；
6. 同一句话（去标点空白后 ≥ 5 个字）在 3 个不同的日子都说过（口头禅 / 复读；发图的记录不算）。

输出：每条规则命中几次 + 每条最多 4 条例子（时间 + 她那句的前 24 个字）。她的话可以出现（她是机器人），他的话一个字不出现。

## 数据

对线上 676 条她的话（10-05 起）跑：规则 1 命中 1 处（一句“别在课上睡”其实说的是他，属误报）、规则 2 命中 2 处（10-05 / 10-06 国庆假期她说“在宿舍修片子”——放假期间的真问题，后来作息改了）、规则 3 命中 2 处（10-09 雨的钟头）、其余 0。**她前后不一致的地方很少，主要是假期里的说法和个别下雨钟头。**

## 没做 / 要注意

- 规则靠关键词，漏的不少；它的用处是随时间看趋势（上线新东西以后有没有变多），不是抓全。
- 没有“吃了什么 / 钱 / 猫粮”这类数字的核对（要对接具体的账，之后再说）。

## 验证

`consistency.test.ts`（5 个）：上课（真在上 / 没课 / 将来过去不算）、下雨（不给账不查）、问候（回他的不算）、复读（同一天不算、太短不算、发图记录不算）、汇总文字（每条规则一节、他的话不出现）。
