# ADR 0226：DSH 桌面动作进入 QQ 时间线和世界账

状态：已实现，跟随 `dsh.enabled`；默认关闭，不启动新的网络服务。

## 决定

DSH 插件提供两个最小工具：

- `timeline_record`：桌面动作完成后追加脱敏摘要到 `~/.dsh/linmengyao/timeline-inbox.jsonl`；
- `world_event`：桌面上确实完成的生活动作追加到 `~/.dsh/linmengyao/world-inbox.jsonl`。

QQ 每 30 秒读取一次收件箱。时间线事件以 `desktop` 渠道写入现有 `Timeline`；世界事件以 `source: external` 交给现有 `WorldState.recordEvents`，所以世界事件仍经过时间、事件类型、前置条件和持久化闸门。两边都用独立状态文件按 `id` 去重，坏行、过期行和未知事件类型跳过，不把 DSH 的原始文本直接带进 QQ。

## 边界

- DSH 工具只允许短动作类型和脱敏摘要，不接收文件路径、令牌、账号、原文或任意 shell 指令；
- 只有“已经完成”的动作才允许记录，计划、猜测和模型回复不算事实；
- 收件箱是只追加协议，QQ 不回写、不删除 DSH 文件；
- `dsh.enabled` 关闭时不启动同步定时器；重新打开后仍只消费时间窗内、尚未去重的行；
- 世界事件只接受 QQ 世界已认识的生活动作类型，成功的 `feed_cat`、取件、作业等仍由世界账检查前置条件；
- 收件箱仅保留最近 30 天可消费，时间戳未来超过 1 分钟或字段超限直接跳过；
- 这不是 DSH 直接修改 QQ 状态的接口，也不授予设备控制、文件读写或网络权限。

## 为什么不做 HTTP

DSH 与 QQ 已经共享本地灵魂目录，收件箱足够表达“完成了一件事”。文件协议不需要新增端口、令牌和服务生命周期；后续若迁移到 WebSocket，仍应复用同样的字段校验、幂等键和 QQ 侧裁决，而不是把闸门复制到 DSH 插件。
