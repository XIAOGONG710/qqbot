# ADR 0010：控制台里的「林梦瑶」页面——角色资料改成可编辑的来源，页面上改、保存时检查

- 状态：已采纳（2026-10-05：待定问题与用户确认，见文末「确认记录」）
- 日期：2026-10-05
- 关联：[ADR 0009](0009-console-usability.md) B 部分（方向已定：控制台页面 + 新的可编辑资料）；[ADR 0003](0003-contact-tiers.md)（档位与隐私）、
  [ADR 0007](0007-schedule-and-reply-timing.md)（作息）、[ADR 0008](0008-koishi-runtime.md)
- 修改：ADR 0003 的数据流（`legacy/` + `tiers.toml` → 转换器 → `st/`）改为（新的可编辑资料 → 转换器 → `st/`）

## 背景

ADR 0009 确认记录：B 部分做控制台页面 + 新的可编辑资料；要能改人设各段和每段给哪些档位、世界书场景、作息 / 课表 / 假期调休、
各档说话方式 / 示例对话 / 禁用词；运行状态也放进这个页面。

### 取证（2026-10-05，两个只读的子代理 + 核对）

**角色资料现在怎么来的**（只记结构，不记内容）：

| 来源 | 结构 | 转换器用到的 |
| --- | --- | --- |
| `legacy/persona.toml` | `persona` 23 个键：4 个整段字符串、`traits` 3 条、13 个分段共 58 个字段、`redlines`、`social`、`social_extra`；另有旧引擎参数 | 13 个分段、`traits`、`social` 里 4 档、`social_extra`。不用：旧引擎参数、`social.group/secret/warmth`、`daily_moods`、`him`（存占位符） |
| `legacy/speech_library.toml` | 118 个场景，每个有 `id, family, kind, tier[], trigger[], examples[], avoid[], source, sources[]` | `id, kind, tier, trigger, examples, avoid`；5 个场景不属于任何生成世界书的档位 |
| `legacy/schedule.toml` | 7 个作息分段 | 只用睡觉那一段的时间 |
| `legacy/timetable.toml` | 学期、5 个节次、起床、2 个假期、2 个调休、14 门课、12 个空闲活动 | 大部分；不用课的老师 / 简称 / 备注 |
| `legacy/books.toml`、`interests.toml`、`followed_ups.toml` | 书、兴趣、关注的 UP 主 | 都没用到 |
| `tiers.toml`（365 行，47 行注释） | `discreet`；`[visible]` 58 条（字段 → 档位代码串）；`[[rewrite]]` 15 条（按原文逐字替换，`why` 不解析）；`[schedule]`（课名给哪些档、每档「他在哪」、课型、空闲活动给哪些档、假期、调休）；`[tier.<档>]` 7 个（`code, user_is, knows_him, social / social_text, discreet, scenes, drop_scenes, demeanor, examples, banned`） | 全部 |

- 现在 `st/` 下的 14 个文件和这些来源生成的逐字节相同（子代理在内存里重新生成后比对过，没有运行转换器，也没有写文件）。
  所以 `st/` 没有在 SillyTavern 里手改过，迁移时不会丢东西。
- 隐私靠「不写进去」：每档一张卡、一本世界书，按 `[visible]` 过滤字段，用 `[[rewrite]]` 去掉提到他的话。
  转换器对写错的地方都会报错（字段没登记、可见性漏了字段、改写的原文对不上、作息引用了不存在的课或假期等），测试检查每档卡里的提示词字段和作息没有本档禁用词。
- **缺口**：世界书没有检查禁用词。known、classmate、stranger、unlisted 四本世界书里，各有 2、3、4、4 个本档禁用词。
  大多在触发词里，触发词不进提示词；但每档有 1–2 条经由场景的 `kind` 标签进了正文，stranger、unlisted 另有 2 条经由「不要说的话」（`avoid`）进了正文。
  正文会注入提示词。这和 ADR 0003「低档位也不写『别提你有男朋友』」的原则不符。出口检查（ADR 0006）拦的是她说出口的话，拦不到这里。
- 改写是对原文逐字打补丁：原文一改，补丁就对不上，转换器会报错。在页面上改字段时，这套机制没法用。
- 测试里有一段按 `legacy` 的字面值断言（`convert.test.ts` 196–230 行），资料一改就会失败。

**Koishi 控制台的页面怎么加**（`@koishijs/console`、`plugin-console` 5.30.11，核对过源码）：

- 插件调 `ctx.console.addEntry({ dev, prod })` 注册一个前端入口；生产模式下浏览器加载 `prod` 目录里的 `index.js` 和 `style.css`。
  官方插件（config、logger、auth）都这样做，`dist/` 里只有这两个文件。
- **不用构建**：控制台在发出 `index.js` 时，会把 `import … from 'vue';`、`'@koishijs/client';` 等裸导入改写成它自带的那几份（`plugin-console/src/node/index.ts` 的 `transformImport`）。
  所以手写的 ES 模块就能用 Vue 3.5 和控制台的客户端接口，Element Plus 和 `k-form`、`k-schema` 这些组件已经全局注册。
  Vue 是只有运行时的那份：不能写模板字符串，要用 `h()` 写。
- 要构建的话，需要 `@koishijs/client`（AGPL-3.0，没装）、vite、`@vitejs/plugin-vue`、sass 等一套开发依赖。
- 前后端通信用 `ctx.console.addListener(名字, 函数, { authority })`（前端用 `send`），实时数据用 `DataService`。
  装了 `plugin-auth` 时，`authority` 要求登录且权限够；**页面本身和入口文件不受登录保护**，真正的检查要放在监听器和数据服务上。
- 坑：
  - 入口文件的路径里不含 `node_modules`、又不在控制台目录下时，返回 403。所以要按 `node_modules/koishi-plugin-qqbot/…` 这条路径注册（这是工作区的链接）。
  - 入口挂在注册它的插件上：插件失败时页面跟着消失。
  - 监听器在插件停用时不会自动删掉，旧的回调还能被调到。

**运行状态有哪些数据**：回复器内部已经有「几点看到、原因」，只是没往外暴露；换档时间在 `tiers.json`；NapCat 在线状态插件拿得到。
Hindsight 没有现成的连通性接口，要另加探测。

## 需求

1. 在「林梦瑶」页面里改：
   - 人设各段，以及每段给哪些档位；
   - 世界书场景：触发词、例句、不要说的话、给哪些档；
   - 作息、课表、节次、假期、调休、空闲活动，以及这些内容给哪些档；
   - 各档的「对方是谁」、说话方式、示例对话、禁用词。
2. 保存时生成全部档位，在内存里做检查。检查不过就不写，并指出是哪一档的哪一句；检查通过就写资料文件、重新生成 `st/`，插件按现有的文件监听自动重读。
3. 运行状态：
   - 名单里每人的档位和换档时间；
   - 现在在等什么：几点看到和原因、生成中、发送中、几分钟后再试；
   - NapCat 和 Hindsight 连没连上；
   - 作息开关，以及她此刻在干什么。
4. 只有登录控制台后才能看、才能改。
5. 不改 Koishi 和控制台的源码；`legacy/` 不动；迁移那一步生成的 `st/` 和迁移前逐字节相同；`st/` 仍能导入 SillyTavern。
6. qqbot 插件配置有误（红点）时，页面仍能打开，资料仍能改。
7. 改动写进仓库里的文件；提交仍由我在会话里做，推送前问用户。

## 决策（提议）

### 1. 新的可编辑资料：`characters/linmengyao/source/`

- 分 4 个文件：人设、场景、作息、档位。格式见待定问题 1（倾向 YAML：多行文字按原样分行，git diff 好读；js-yaml 4.3.2 是 MIT，仓库里已经装着）。
- 用一个迁移脚本从 `legacy/` + `tiers.toml` 一次性生成，之后转换器只读这份资料。`legacy/` 留作原件不动。
  `tiers.toml` 迁移后删除（git 历史里还在），注释里写的理由搬进资料的「备注」字段或 ADR。
- 数据模型：
  - **人设字段**：`{ 文字, 给哪些档, 各档改写后的文字?, 备注? }`。15 条改写在迁移时套用一遍，直接存成各档的最终文字（待定问题 2），`why` 变成备注。
    页面上看到的就是每一档实际用的那句。
  - **场景**：`{ id, 标签, 给哪些档, 触发词[], 例句[], 不要说的话[], 来源? }`。保留来源，因为「线上原话」和隐私有关。
  - **作息**：睡觉时间；课表那几项；`tiers.toml` 里 `[schedule]` 的各档设置（课名给哪些档、每档「他在哪」、课型、空闲活动给哪些档、假期）。
  - **档位**：`tiers.toml` 里 `[tier.*]` 的全部字段，加上全局的 `discreet`。档位的顺序照旧（它决定输出顺序）。
  - 不迁移：转换器没用到的内容，以后要用再从 `legacy/` 迁；存占位符的 `him`；旧引擎参数。
  - 写在代码里的常量照旧留在代码里：段落标题、字段标签、输出规则、`system_prompt`、正则脚本、空闲时段的边界。

### 2. 检查（保存前跑，CLI 和页面共用一个函数）

- 转换器现有的全部报错。
- 现有测试里的隐私断言改成运行时检查：
  - 每档的提示词字段和作息里没有本档禁用词；
  - 不出现占位符；
  - 只有允许的档位有「他是你男朋友」的介绍；
  - 男朋友档以外没有示例对话和 `demeanor`。
- 世界书正文也查禁用词（不查触发词）。现有的命中怎么处理，见待定问题 4。
- 检查结果逐条列出：档位、在哪（字段、场景 id 或作息项）、命中的词。
- **实现时的调整**：
  - 保存时真正拦下的只有两类：每档会进提示词的文字（卡的提示词字段、作息、世界书正文）里出现本档禁用词，以及脱敏占位符（`build.ts` 的 `checkPrivacy`）。
    「他是你男朋友」的介绍由 `knows_him` 决定；「只有男朋友档有示例和 `demeanor`」只是现在资料的写法，以后可能给别的档位加示例。这两条留在测试里，不作为保存时的检查。
  - `st/` 只是生成结果，CLI 每次都按资料覆盖，不再要求 `--force`；检查不过就什么都不写。内容没变的文件不写，免得插件无谓重启。
  - 世界书原有的 4 处命中按用户确认的改法改了（10-05）：
    - 两个场景的标签「问有没有男朋友」「追问男朋友是谁」改为「问感情状况」「追问感情上的事」；
    - 两个场景的「不要回」去掉了她的本命英雄名（「我貂蝉带你飞」改为「我带你飞」，另一处删掉，留下已有的「带你飞」）。

### 3. 页面

- **注册**：页面注册一次，挂在根上下文上，qqbot 插件失败或重启时页面仍在；状态里显示「插件没在运行」。
  监听器在插件停用时手动删掉旧的。所有监听器和数据服务都要求登录（`authority: 4`，和 plugin-config 一样）。
- **写法**：不构建，手写 ES 模块（待定问题 3），用 `h()`、Element Plus 和控制台的 `k-form`。
  表单尽量由服务端发 Schema、前端用 `k-form` 渲染，和插件配置页一个样子，手写的界面代码少一些。
  文件放在 `packages/koishi-plugin-qqbot/client/`，按 `node_modules/koishi-plugin-qqbot/client` 这条路径注册。
- **布局**：标签页「状态 / 人设 / 世界书 / 作息 / 档位」。
  - 场景、课这类多条的内容用「列表 + 选中一条编辑」，世界书列表能按档位和关键字筛选。
  - 每个标签页有自己的「保存」：写对应的资料文件，再跑一遍全部检查和生成。
- **实现时的调整**：
  - 编辑表单的 Schema 写在前端（`client/schemas.js`、`client/scenes.js`，用 `@koishijs/client` 导出的 `Schema`），不由服务端发：
    资料的形状是固定的，前端自己搭就够了，插件启动失败时编辑页也照样能用。服务端保存前用 `checkSource` 再校验一遍。
  - 入口、监听器、数据服务每个 Koishi 进程只在根上下文注册一次（`src/console.ts`），插件重启不会重复注册，所以不用在停用时删旧的。
  - 页面声明 `fields: ['qqbot']`：数据服务有了数据（登录完成）才显示，避免自动登录完成前调监听器被拒（试验结果第 2 条）。
  - 人设、作息、档位三页是「左边选一段、右边 `k-form`」；世界书是「列表 + 选中一条编辑」，能新建、删除。
  - 每页「保存 / 检查 / 还原」：只发这一页的那份资料，服务端和其余几份合起来校验、生成全部档位、做隐私检查；
    「检查」只到这一步，不写。保存成功后只重读这一份，别的页没保存的草稿不受影响；生成的文件都没变时提示「生成的卡没有变化」。
    没有改动时「保存」是灰的。
  - 浏览器里验证时发现（10-05）：控制台断线重连时会把页面重新挂载，组件里的状态全丢，但模块不会重新加载。
    所以草稿、当前标签、选中的段落和场景放在模块里，侦听器挂在不随组件卸载的 `effectScope` 上，重连后接着用；
    关掉或刷新浏览器页时还有没保存的修改，浏览器会先问一句。
  - 「保存 / 检查 / 还原」那一条固定在页面顶上（表单很长）。Element Plus 标签页的内容区是 `overflow: hidden`，会让 sticky 失效，页面里改成 `visible`。

### 4. 运行状态

- **回复器**加只读的 `status()`：空闲 / 等到几点看到（原因）/ 生成中 / 发送中 / 几分钟后再试，以及连续失败次数。
- **app** 汇总每个人的状态，加上档位、换档时间、最后一条消息的时间（不显示聊天内容）、NapCat 在线状态。
- **Hindsight**：每分钟探一次 Hindsight 的健康接口，再加上最近一次写入是成功还是失败。
- 作息开着时显示她此刻的状态行（`schedule.ts` 现有的那句）。
- 数据有变化就推给页面，最多每秒一次。
- **实现时的调整**：插件启动、停下、启动失败时立即推；另外每 5 秒推一次，因为「几点看到」「她此刻在干什么」随时间变。
  Hindsight 的 `/health` 每分钟最多探一次，最近一次写入、召回的成败由长期记忆模块记下。

页面只写文件，不碰 git。改动由我在会话里看过后提交，推送前问用户。

## 验收

- 三个包的测试全过。迁移那一步 `st/` 逐字节不变。检查函数覆盖：每种检查各有一个会失败的例子。
- 临时实例端到端：
  - 每类资料各改一处并保存，`st/` 重新生成，插件自动重读；
  - 故意写进一个禁用词，保存被拒，并指出档位和位置；
  - 插件红点时页面仍能用；没登录拿不到数据。
- 截图给用户确认好用；真实例重启后照常运行。

## 待定问题（一次问完）

1. **资料格式**：YAML（倾向）/ TOML（smol-toml 写出时多行文字会变成一行带 `\n`）/ JSON（同样的问题）。
2. **改写怎么存**：直接存各档的最终文字（倾向）/ 保留「原文 + 逐字替换」的补丁。
3. **页面写法**：不构建，手写（倾向）/ 用 vite 构建（多一套 AGPL 的开发依赖）。
4. **世界书里的禁用词**：
   - 迁移后我把命中的几句列出来、给出改法，你确认后在新资料里改，之后检查覆盖世界书正文（倾向）；
   - 先只加检查，现有的命中先放行；
   - 以后再说。

下面这些我按倾向做，你不同意再说：状态页不显示聊天内容；`tiers.toml` 迁移后删除；`legacy/` 里没用到的内容不迁移；提交由我做。

## 备选方案

| 方案 | 不选的原因 |
| --- | --- |
| 保留 `legacy/` + `tiers.toml`，页面的改动另存一层、转换时叠加 | 用户选了新的可编辑资料（ADR 0009 确认记录第 2 条） |
| 页面直接改 `st/` 下的生成文件 | 每档一份，要改 7 遍，还跳过了档位过滤 |
| 资料放进 `koishi.yml`，用插件配置的表单改 | `koishi.yml` 不入库；一百多个场景放进一个表单也没法用 |
| 自己起一个独立网页（不进控制台） | 要另做登录；控制台的登录、样式、组件都现成 |

## 后果

- 角色资料的来源变了：改人设不再是「改 `tiers.toml` + 跑转换器」，而是在页面上改，或者直接改 `source/` 里的文件再跑转换器。`CLAUDE.md` 里没有写这条；会话提示词里「改人设用 `tiers.toml` 的 rewrite，再用 `cli.ts --force` 重新生成」那条作废，以本 ADR 为准。
- 转换器的输入换了，测试要改；`st/` 的格式不变，SillyTavern 仍能导入。
- 页面是手写的前端代码（几百行），没有构建，也不新增依赖；用到的 `@koishijs/client` 接口跟着控制台的版本走，升级 Koishi 时要检查。
- 改写从「补丁」变成「各档的最终文字」后，改一句通用的话时，各档的改写版本不会跟着变，要分别改。页面上会把同一字段的各档版本放在一起显示。
