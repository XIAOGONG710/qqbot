# ADR 0165：断网时也用她的号告诉能动虚拟机的人（net-alert helpers）

- 状态：**已实现，未上线**（分支 `claude/net-alert-helpers`；不是 Koishi 开关，是 `runtime/bot/alert.json` 的一项 + 重启服务守护进程）
- 日期：2026-10-26
- 关联：[外网断了，用她的 QQ 告诉你](../net-alert.md)（10-18 上线的断网提醒）、[ADR 0067](0067-disclosure-per-contact.md)
- 用户提出：2026-10-26「以后断网的话用她的号发送简短的通知给鸽鸽，他是可以修改虚拟机的」；随后「给鸽鸽的通知简短一点，就只需要说明断网即可，用林梦瑶的口吻发，先模拟让我看看情况」

## 现状

10-18 起，外网断了 / 恢复了，服务守护用她的号给**用户**发一条「【运维提醒】……」。但用户自己看不到宿主机（10-17、10-18 两次都是这样），能动虚拟机 / 宿主机的是鸽鸽（联系人名单里：同学档、知情、网络运维），他并不知道断了。

## 做法

`alert.json` 多一项 `helpers`：一组 QQ 号（要是她号的好友）。外网**断了**的那一次，除了用户，helpers 也各收到一句她自己的话：

> 鸽鸽，我这边断网了，连不上外网，现在回不了消息。

- **只说断网**：不求他做什么、不带分钟数 / 域名 / 机器人细节；**恢复时不打扰他**（用户那条照旧）；
- **她自己的口吻、没有「【运维提醒】」前缀**：断网时模型也连不上，所以是固定的一句，不是现写的；因为是她对他说的话，补回漏掉的消息时会记进和他的聊天记录，之后她知道自己说过（给用户的那条仍带前缀，不进记录）；
- 每次断网最多发一次（判定规则不变：最近 10 次里 7 次不通）；先发用户、再发 helpers，**各自独立**（鸽鸽不是好友、发失败不影响用户那条）；`network: false` 时都不发；`helpers` 去重、去掉用户自己和非正整数、最多 3 个；日志只写「已通知帮忙看虚拟机的人 / 没发出去（原因）」，不写 QQ 号。

代码：`ops/alert-qq.ts` 的 `dispatchNetworkAlert`（统一分发，守护脚本和测试共用）、`networkDownHelperText`；`scripts/services-watchdog.mjs` 的 `notify` 改成调它。

## 模拟（10-26，真的状态机 + 真的分发函数 + 假的发送，什么都没真发）

干净的断网（正常 20 分钟 → 断 25 分钟 → 恢复）和时好时坏的断网（像 10-18）：各只在判定断网那一刻发一次，用户收到「【运维提醒】……」，鸽鸽收到上面那一句；恢复时只有用户收到。断 3 分钟就好的抖动：什么都不发。

## 不做

- 不重启任何服务，不给他别的告警（NapCat 掉线、整套停了这些仍只给用户，也没有发出去的办法）；
- 虚拟机整个停了、NapCat 没了、QQ 本身连不上时，这条路发不出去（和原来一样，需要宿主机侧的办法）；
- 他回这条消息，会被当成普通聊天（断网期间模型连不上，她多半回不了；恢复后会接着回）；不自动做任何事。

## 上线

1. 线上目录快进到这个分支（只多脚本和 `ops/` 下一个不被 Koishi 加载的文件，**不重启 Koishi**）；
2. 在 `runtime/bot/alert.json` 加 `"helpers": [鸽鸽的 QQ]`（该文件不进 git；他的号在联系人名单里，不在日志里写）；
3. 重启服务守护进程（它才会读到新代码）；
4. **不发测试消息**也行（那会让他收到一句「断网了」却没断）；要测的话先和他说一声。

回退：删掉 `helpers` 那一项。

## 测试

`alert-qq.test`：helpers 的解析（去重 / 去自己 / 最多 3 个 / 不是数组当没有）、先用户后 helpers 且各自独立（包括 send 抛错）、恢复时只发用户、`network: false` 不发、给 helpers 的话（鸽鸽开头、≤30 字、不含运维提醒 / 求助 / 域名）。
