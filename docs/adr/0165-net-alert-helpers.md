# ADR 0165：断网时也用她的号通知能动虚拟机的人（net-alert helpers）

- 状态：**已实现，未上线**（分支 `claude/net-alert-helpers`；不是 Koishi 开关，是 `runtime/bot/alert.json` 的一项 + 重启服务守护进程）
- 日期：2026-10-26
- 关联：[外网断了，用她的 QQ 告诉你](../net-alert.md)（10-18 上线的断网提醒）、[ADR 0067](0067-disclosure-per-contact.md)
- 用户提出：2026-10-26「以后断网的话用她的号发送简短的通知给鸽鸽，他是可以修改虚拟机的」

## 现状

10-18 起，外网断了 / 恢复了，服务守护用她的号给**用户**发一条「【运维提醒】……」。但用户自己看不到宿主机（10-17、10-18 两次都是这样），能动虚拟机 / 宿主机的是鸽鸽，他并不知道断了。

## 做法

`alert.json` 多一项 `helpers`：一组 QQ 号（要是她号的好友），**只收外网断了 / 恢复的两条**，文字更短、不带她的聊天细节：

- 断了：「【运维提醒】虚拟机 12 分钟连不上外网（解析不了 api.deepseek.com），梦瑶回不了话。NapCat 还在跑，多半是宿主机或虚拟机网络，麻烦看下。」
- 恢复：「【运维提醒】外网恢复了（断了大约 40 分钟），不用再看了。」

规则（和给用户的那两条一样，只是多发给 helpers）：每次断网最多各发这两条；先发用户、再发 helpers，**各自独立**（鸽鸽不是好友、发失败不影响用户那条）；`network: false` 时都不发；`helpers` 去重、去掉用户自己和非正整数、最多 3 个；发送本身不进她的聊天记录（前缀 `【运维提醒】`，`backfill.ts` 认它）；日志只写「已通知帮忙看虚拟机的人 / 没发出去（原因）」，不写 QQ 号。

代码：`ops/alert-qq.ts` 的 `dispatchNetworkAlert`（统一分发，守护脚本和测试共用）、`networkDownHelperText` / `networkUpHelperText`；`scripts/services-watchdog.mjs` 的 `notify` 改成调它。

## 不做

- 不重启任何服务，不给他别的告警（NapCat 掉线、整套停了这些仍只给用户，也没有发出去的办法）；
- 虚拟机整个停了、NapCat 没了、QQ 本身连不上时，这条路发不出去（和原来一样，需要宿主机侧的办法）；
- 他回这条消息，会被当成普通聊天（同学档的她回他一句）；不自动做任何事。

## 上线

1. 线上目录快进到这个分支（只多脚本和 `ops/` 下一个不被 Koishi 加载的文件，**不重启 Koishi**）；
2. 在 `runtime/bot/alert.json` 加 `"helpers": [鸽鸽的 QQ]`（该文件不进 git）；
3. 重启服务守护进程（它才会读到新代码）；
4. 第一次先发一条「【运维提醒】测试」给他确认收得到，**要先和他说一声**。

回退：删掉 `helpers` 那一项。

## 测试

`alert-qq.test`：helpers 的解析（去重 / 去自己 / 最多 3 个 / 不是数组当没有）、先用户后 helpers 且各自独立、`network: false` 不发、给 helpers 的文字（≤80 字、不提主动消息 / 聊天）。
