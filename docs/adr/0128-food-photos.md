# ADR 0128：吃的照片（配置 `foodPhotos`，默认关，要 `photos` 和 `menu` 开着）

- 状态：**已关闭**（上线于 2026-10-23 夜，2026-10-25 用户看了货架里的 5 张吃的照片说太假，`foodPhotos` 改回 false，不再发；10-24 午饭 / 晚饭两次发图都因 NapCat 超时 retcode 1200 失败，只发出去了文字）。货架里的图是 Commons 上别人拍的，同一道菜总是同一张，餐具和场景对不上她的食堂 / 外卖，不再启用，等作者提供真照片再说
- 日期：2026-10-23
- 关联：[ADR 0109](0109-photo-shelf.md)（照片货架）、[ADR 0110](0110-photo-shares.md)（`cat_photo`——同一个 news 的新一类做法）、[ADR 0125](0125-menu.md)（每顿吃什么）
- 用户提出：2026-10-23「菜单每天随机，照片直接找没事博主的那些第一视角的照片就行」（B18 的后一半）

## 来源试了哪些（有数据）

用户要的是“博主发的第一视角随手拍”。先实测，再定来源：

| 来源 | 结果 |
| --- | --- |
| 小红书、微博 | 要登录 + 请求签名，程序走不通（不试） |
| 必应图片、搜狗图片 | 匿名请求被拦（302 到验证页 / `forbid`），返回里没有图片地址 |
| **B 站图文（专栏）**，用她自己登录的号 | 搜 “今日午饭 / 今日晚饭 / 食堂 午饭” 都有结果，但绝大多数是 B 站“笔记卡片”（蓝色横线底 + 文字 + 咖啡杯插画）、菜谱教程、带平台水印的图；搜索结果里的 `image_urls` 只是封面小图（20–60 KB）。看图把关 **23 张里只有 1 张能用** |
| **Wikimedia Commons**，按菜名搜 | 热门的菜每道有 30 张以上；全是普通人拍的碗和盘，许可是 CC BY-SA / CC BY / CC0 / 公有领域。看图把关 **24 张里收 16 张**（兰州拉面 3/6、麻辣烫 4/6、煲仔饭 6/6、炒饭 3/6），每张 370 KB – 1 MB（宽 1600） |

所以选 Commons。它的照片是普通摄影爱好者随手拍的生活照，和“博主第一视角”风格接近，但不是博主平台的图——这一点要在这里写明。

## 做了什么

1. **货架按菜名收**（`photos.ts`）：新的一类 `food`，条目带 `dish`（哪道菜）；`discoverFood(dishes)` 给指定的几道菜各找 `FOOD_PER_DISH`（2）张，一道菜一轮最多看 4 张，看过的不再看，搜不到的菜 6 小时内不再搜，被限流 / 断网同样过一会儿再来。`has('food')` / `prompt('food')` **必须给菜名**，只返回这道菜的——没给就是没有，绝不拿别的菜的照片说是这一顿。
2. **来源**（`photo-sources.ts`）：Commons 按菜名搜（`FOOD_QUERIES`：默认菜单里 38 道菜每道都有英文搜索词，有测试守着），宽 ≥ 1500、jpeg、许可只收 CC0 / 公有领域 / CC BY / CC BY-SA（不收带 NC / ND 的）；出处、作者、许可存进索引（作者要署名时查得到）。
3. **看图把关**（和聊天同一个看图模型，每次带上这道菜名）：人脸、叠加的文字 / 水印 / 相框 / 拼图、清晰可读的店名招牌必须**明确回答“没有”**；必须明确回答“是这道菜（或很像的同类）”“主体是装在碗 / 盘 / 锅里的一份做好的饭”“普通人随手拍的实拍（宣传图、海报、插画、菜谱步骤图不算）”“清晰”；说明 6–40 个字、不带地名 / 品牌 / 外文。规则在代码里，不让模型自己定。
4. **什么时候找**（`app.ts`）：启动时和之后每 2 小时，给今天、明天要吃的菜（`dishesBetween`，从 `menu-from.json` 那天起）各找，货架里够了就不动。
5. **他说“拍给我看看你吃的 / 午饭吃的啥发我看看”**（`photoWanted` 新认 food）：发她**最近吃的那一顿**那道菜的照片（`lastMealDish`），意图行：说是哪一顿、吃的什么（看“你那边”吃的那一行），先带一句再另起一行放照片；可以说是吃饭时拍的。原来的“看看你”（要她本人）仍然不放行，但“看看你吃的”是看饭，放行。没有这道菜的照片就照旧不发（她那顿“没拍”）。
6. **主动**（`food_photo`，news 的新一类）：每顿约 18% 在饭点开始后 6–18 分钟想起来拍了张发给他，只对男朋友档；没有这道菜的照片 / 刚发过 / 今天发够了就不发；那之后聊过了不发；不留到后面的睡前 / 早安里。
7. 状态页：照片货架那一行多一个“吃的 N 张”。

## 没做 / 要注意

- 不是博主平台的图（见上表）。Commons 的许可大多是 CC BY-SA：**私下一对一聊天里用**，不转发、不公开；这比 ADR 0109（只收 CC0 / 公有领域）宽松，是用户这次的裁决。
- 有的菜 Commons 上没有或很少（黄焖鸡搜不到、酸辣粉 0 张），那几天她“没拍”。想补：用 `photo-cli` 手动加（`add <图片> --kind food --dish "黄焖鸡米饭" --caption "…"`）。
- 菜名是通用的，Commons 上的饭不一定是山东的做法（比如兰州拉面是兰州的）；说明里不带地名，她说“吃的兰州拉面”和照片一致就够。
- 第一次开 `menu` 要到第二天才有菜名，所以吃的照片也要到第二天才开始；货架里的照片会提前找好。

## 验证

`food-photos.test.ts`（11 个）、`food-shares.test.ts`（6 个）：许可（CC BY / BY-SA / CC0 / 公有领域收，NC / ND / 不认识的不收）、尺寸 / 比例 / 地址检查；看图规则逐条（人脸、水印、招牌、不是这道菜、不是一份饭、不是实拍、不清晰、说明太短 / 太长 / 带地名）；货架：每道菜收到 2 张为止、没给菜名 = 没有、重新打开还在、看过的不再看、一轮最多试 4 张、搜不到 6 小时内不再搜、限流返回 retry；`photoWanted` 认得“拍给我看看你吃的”等、自拍照旧不放行；`lastMealDish`；`food_photo`：约 18% 的顿数、菜名对得上、时间在饭点后 6–18 分钟、没开 menu 没有、货架里没有 / 聊过了不发。真模型模拟（10-23）：`sim/food-photo.json` 4 次 × 10 项检查全过——他说「拍给我看看你中午吃的」，她发的是账上那道菜（兰州拉面）的照片，不说成别的菜，再要一张不连着发；`sim/food-share.json` 4 次 × 8 项全过——12:31 她先说一句「午饭吃的青椒肉丝盖饭」，另起一行放照片。端到端（真 Commons + 真看图，临时货架）：煲仔饭收了 2 张、小笼包 1 张、兰州拉面这轮 4 张都没过把关；照片是普通人手机拍的，有的偏糊，「清晰」只是看图模型的自述。
