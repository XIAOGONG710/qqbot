# ADR 0038：行动先排队，结束后才成为事实

- 状态：模拟器增量已实现、已验证（2026-10-08）
- 关联：[ADR 0029](0029-life-event-ledger.md)、[ADR 0037](0037-typed-life-actions.md)、[长期执行计划](../plans/2026-10-08-long-term-execution.md)

## 问题

类型化行动裁判能判断一个动作是否合法，但动作通常有持续时间。若计划一开始就写进 `events.json`，未来的结束时刻会被当成已经发生的事实；若只存在内存里，Koishi 重启后行动会消失或重复结算。

## 决策

新增原子文件 `action-queue.json`，保存已经由世界裁判确定、但尚未结束的行动。队列里的 `event.at` 是预计结束时刻；只有虚拟时间到达该时刻以后，事件才交给统一事件账。

结算严格按以下顺序：

1. 将同一个稳定 ID 的事件提交给 `WorldState.recordEvents()`；
2. 重新读取事件账，确认该 ID 已经存在；
3. 再从行动队列移除并原子写盘。

若进程在第一步后、第三步前退出，重启后仍会再次提交同一个 ID；事件账幂等去重，然后队列安全清除。写事件失败或事件没有真的进入账本时，队列保持不动。

模拟器新增 `action` 步骤。场景只提交动作意图、目标和期望时长，不能直接声称 `succeeded`；裁判失败会立刻留下失败事件，成功或中断则排队，时间推进到结束以后才入账。旧的 `life` 步骤继续兼容。

## 验证

- 行动裁判、队列与模拟器定向测试 24 / 24；
- 覆盖：排队落盘、结束前无事实、结束点结算、重启恢复、同 ID 幂等、写账失败保留、写账静默失败保留、损坏项目过滤、模拟场景重放；
- 全仓测试 525 / 525（bot 465、character-tools 37、Koishi 插件 23），三套 TypeScript 类型检查通过；
- 本增量只接模拟器，不启动线上自主行动，不改变当前聊天和作息行为。
