## 差距

聊着聊着她那边发生了一件小事（室友喊她、食堂排队、宿舍查卫生），真人会当场说一声“等下，……”。原来这些小事只在“你那边（今天到现在的事实）”里排着，她自己想起来才会提，所以聊到一半从来没有被打断过。

## 做了什么

`interruption.ts` 的 `interruptionNow`：不存状态、不加新事实——世界账里每件日常小事都有发生的时刻（`events[].at`）。这一轮如果有一件小事**恰好发生在这场聊天正在进行时**：
- 聊天正在进行：最近一条（任何一方）在 5 分钟内；
- 小事发生在她**上一次回话之后**、此刻之前、不超过 6 分钟；
- 她自己没说过它；
- 约 60% 的情况真打断（按小事 id 和他最后一句取哈希，同一句每次一样）。

提示词里多一行：「你正聊着，N 分钟前你这边发生了一件小事：X。先接他的话，顺带说一声你刚被这件事岔了一下（像当场说的：“等下，……”）；事情的细节只用这一句写的，没写的别编；要花点时间的可以说一声“等下”再去弄，别写成长段」。**这一轮不带“先直接回答他刚问的”之类的意图、不套形状 / 长短提示**——它们和这一行冲突，模型会按更紧的那条来、把打断吞掉（第一版模拟 5 次都没提）。他难过 / 危机 / 小别扭 / 主动找他 / 她在想事情时不打断。只对男朋友档；日志只记“被打断了”，不记内容。

和 ADR 0112 配合：她说了“等下”、他没接话，过几分钟她自己回来。

## 数据

- 模拟（真模型，`sim/interruption.json`：10-28 22:16 世界账“宿舍查卫生”，22:20 他问“你在干嘛”，5 次）：改前 0/5 提到；改后 **3/5** 提到（「等下，刚宿舍查卫生，……」「在写概率论作业，等下，刚被查卫生岔了」）。有 1 次在“查卫生”后面添了世界账里没有的“交了个表”——提示词要求不编，模型仍偶尔加细节，这是已知的残留。

## 没做 / 要注意

- 能被打断的只有世界账里有“发生时刻”的小事；今天这类小事一天最多 3 件，所以打断一周也就几次。
- 剩下 2/5 没提的，是模型更看重“他在问我在干嘛”。没再加码（再加码会把每个回答都变成先讲打断）。

## 验证

`interruption.test.ts`（4 个）：什么时候算（正在聊 / 她上一次回话之后 / 窗口内；约 60% 真打断；同一句每次一样）；不算（回话之前 / 太久 / 还没发生 / 聊天没在进行 / 她已经说过 / 没有小事）；取最近的一件；提示词行。
