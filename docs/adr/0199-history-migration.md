# ADR 0199：把 VM 时期的素材并进她现在住的机器（一次性的迁移工具）

- 状态：**工具已实现并测过；DSH 已在他那台机器上跑完（10-30 18:43）**。不是开关，不是常驻功能
- 日期：2026-10-30
- 关联：[ADR 0004](0004-time-scheduling-memory.md)（片段 `ep-<首条时间戳>`）、[ADR 0017](0017-long-term-memory-like-a-person.md)（她的日记写进公共库）、[ADR 0018](0018-memory-fades-and-promises.md)（周记、阶段总结、`diary.json`）、[ADR 0158](0158-memory-ledger.md)（记忆账本）、[ADR 0176](0176-same-her-shared-memory.md)（同一个她）
- **用户决定（2026-10-30）**：「素材迁移过去吧，自己学习是各方面都自我学习」。

## 起因：她在新机器上只有 4 天的记忆

10-27 00:27 她的运行时从 VM 搬到 DSH 的机器，当时**没有带数据**（交接里写过）。10-30 DSH 回答追问时才对上：`runtime/bot-shadow` 建于 10-27 00:38，聊天记录只有 681 行，真正连续的从 10-26 起；Hindsight 里的 bank 也是另一批。VM 上留着 10-05 → 10-27 00:15 的 1494 行、她写的 23 篇日记 / 4 篇周记 / 1 篇阶段总结，以及整个 `runtime/bot`（约 54 MB，其中照片和贴纸占 52 MB）。她在 DSH 那边是从 10-26 起重新认识他的；10-30 下午那段怪对话又赶上 Hindsight 停了 79 分钟（召回失败，回话不带记忆）。

「自己学习」要有素材可学：翻日记（ADR 0194）、总结说话习惯（ADR 0193）、聊完回想（ADR 0197）都吃她自己的历史。所以先把素材接上。

## 搬什么、不搬什么（原则：素材迁，运行状态不迁）

| 东西 | 做法 | 为什么 |
| --- | --- | --- |
| 他的聊天记录（`chats/<QQ>.jsonl`） | **并进**新机器已有的那份：同一个人、同一句话、时间差 3 秒以内算同一条（一对一匹配，两条一模一样的「嗯」仍是两条）；已有的行一个字不改；按时间排好 | 片段 id 是 `ep-<首条时间戳>`，聊天并进去，机器人按平常的写入路径（`LongTermMemory.sync`，到了安静 45 分钟的片段就写）会自己把这几周的记忆重新写进新机器的 bank，不用另搬 |
| 她自己写的日记 / 周记 / 阶段总结 | **原样**写进新机器的公共库（`document_id`、事件时间、标签、元数据、实体都照旧）；新机器上同 id 已有的不覆盖（内容一样就跳过，不一样就列出来） | 这是她当时写的原话，用模型重写一遍就不是她的了。聊天片段能从聊天重新生成，这些不能 |
| `memory/diary.json` | 并进「写过的日记 / 日记原文 / 周记 / 阶段总结」记录；新机器已有的键不动 | 不并的话，补写日记的流程会把这些日子当成没写过，用模型重写并**覆盖**她当时写的原文 |
| 身份账本、世界事件、承诺、主动记录、成语、观看记录、各联系人的写入进度…… | **只存档**到新机器的 `vm-archive-<日期>/`，不启用 | 它们是有时效的运行状态，搬过来会让她重提早就过去的事（比如三周前的「带你去吃火锅」）；写入进度是绑旧 bank 的，覆盖了新机器的会让它以为已经写过 |
| Hindsight 里的事实 / 观察 / 关系概况 | **不搬**（聊天并进去后自己重新生成） | 两台机器的 bank 前缀不同（VM `linmengyao-1006-…`，DSH `linmengyao-…`）；强行搬库要碰 embedding 和实体表 |
| 别的联系人的聊天（VM 上另一位同学 52 行） | **默认不进素材包**（`--chats` 只点名他） | 是第三个人的话；DSH 那边有没有这个联系人也不知道。要搬再单独导 |
| 配置、密钥、cookie、照片（38 MB）、贴纸（14 MB） | 不搬；名字像密钥的文件、超过 2 MB 的文件存档时也跳过 | 照片货架和贴纸货架可以在新机器上重新攒 |

## 工具（`ops/history-migrate.ts` + `history-migrate-cli.ts`）

1. **`export`**（旧机器上，只读）：读旧数据目录 + 用 GET 读旧 Hindsight 公共库里她自己写的文档 → 一个素材包目录；`manifest.json` 记每个文件的字节数和 SHA-256，只记旧目录的目录名，不记本机路径。
2. **`plan`**（新机器上，只看不写）：每份聊天会并进多少条、`diary.json` 多几个、要写几篇文档、有什么挡路（`bot.lock` 里的 PID 还活着 = Koishi 没停）。
3. **`apply`**（新机器上，Koishi 停着；不带 `--yes` 就只是 plan）：拿数据目录的锁 → 备份要改的聊天和 `diary.json` 到 `migration-backup-<时间>/` → 并聊天（先写临时文件再改名）→ 并 `diary.json` → 写文档 → 存档 → 留 `migration-done.json`。**什么都不覆盖，再跑一遍结果一样。**
4. **`verify`**（Koishi 跑一阵之后）：把聊天按 45 分钟切成片段，算出该有的 `ep-…`，和 Hindsight 里实际有的比，缺的列出来（缺的会在下一次同步补）。

素材包读的时候会核对哈希，拷贝时坏了或被改过直接报错。

## 迁完之后会发生什么（要提醒 DSH）

- Koishi 一启动，`sync` 发现几十个「已结束但没写过」的片段，会按顺序写进新机器的 bank（他的 bank 约 86 个，公共库约 93 个）；Hindsight 为每个片段调一次模型抽事实，所以要几分钟到十几分钟，期间召回的是还没写完的记忆。**最好在他不在的时候重启。**
- 之后 Hindsight 自己整合成观察、关系概况会自己刷新。
- `diaryInsights`（ADR 0194）从此有 23 篇日记可翻；`speechNotes` 的语料多三周。是否打开仍然一次一个、等用户点头。

## 回滚

- 聊天和 `diary.json`：把 `migration-backup-<时间>/` 里的文件放回原位。
- 写进公共库的 28 篇文档：`DELETE /v1/default/banks/<公共库>/documents/<id>`（`document_id` 就是 `diary:<日期>`、`week:<周一>`、`phase:…`）；它们是新增的，删掉不影响别的。
- 存档目录 `vm-archive-<日期>/`：直接删。`migration-done.json` 删掉即可。
- 聊天并进去之后写进 Hindsight 的片段是平常的写入，不用特别回滚；要重来就删对应 `ep-…` 文档并把该联系人的写入进度文件里的条目去掉。

## 验证

- `history-migrate.test.ts` 21 项（聊天并入的去重 / 一对一 / 排序 / 不改已有行、`diary.json` 并入、文档按原参数再写、导出 / 读取 / 哈希核对 / 密钥和别的联系人不带、`plan` 只读、`apply` 的备份 / 锁 / 幂等 / 冲突不覆盖 / 存档不启用、`verify` 的片段推算）；变异检验 26 处全红（第一遍 2 处没红，补了断言和修正了变异本身）。
- 用 VM 上真实数据导出素材包（1494 行聊天 + 23 / 4 / 1 篇文档 + 28 个存档文件，406 KB，扫描过没有密钥 / cookie），在一个带重叠的合成目标目录上做了 `plan`：并进 1491 条、3 条重复不动；再用真的 `LongTermMemory.sync` + 假的 Hindsight 接口模拟迁移后第一次启动：写进他的 bank 90 个片段（该有的 90，缺 0、多 0），第二次同步新写 0 条。
- **现场结果（DSH，10-30 18:43）**：新机器已有 712 条，并进 1477 条（17 条重复不动），现在 2189 条；`diary.json` 并进 20 篇日记记录、3 周记、2 阶段总结；文档写进 28 篇、0 篇冲突。启动后 `verify`：他的 bank 98/101——3 个片段进度里记着写过、Hindsight 里没有（异步受理后后台处理失败，进度却记成完成），DSH 把它们从进度里删掉后重写，101/101。这个洞由 [ADR 0201](0201-memory-reconcile.md)（记忆对账）补上。公共库 97/101 里至少有一个是危机相关的片段本来就不写（ADR 0068），`verify` 加了 `--common` 把它们去掉。
- 这台机器上的素材包没有放进任何 git 仓库（里面是他的聊天原文和她的日记），怎么送到 DSH 那台由用户定。

## 没做

- 不搬 Hindsight 的库本身；不搬照片 / 贴纸；不搬另一位同学的聊天；不处理 DSH 桌面那一侧（`~/.dsh`）的任何东西。
- 没有合并两边的「写入进度」——新机器会把并进来的旧片段当作没写过的重新写，这正是想要的。
