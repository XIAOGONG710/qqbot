# ADR 0064：她账里的事成为开口的理由（0057 的推广）

- 状态：**提议**（2026-10-12 用户在 `options.md` 里选了 B1；下面「待确认」回答后进入实现，实现前不改代码）
- 日期：2026-10-12

- 调研依据：`exchange` 分支 `exchange/research/2026-10-companion-practice/block-b.md`、`options.md`

## 背景

终极目标是她像一个真实的 20 岁女大学生那样活着：**因为自己的事开口**，而不是因为钟点或对方沉默。10-12 的调研（B 块）给出两个事实：

1. 别人的主动消息绝大多数是「钟点 / 对方沉默 N 秒」；只有 private_companion 把候选建在状态和日程上。我们的护栏（没回就停、先记后发、错过不补、种子化时刻）比读到的项目都严。
2. **我们线上发出去的主动消息，大多不是她自己的事**：`runtime/bot/proactive/` 唯一一份记录（一个联系人，10-05 至 10-12，只数条数）共 27 条记录，发出 11 条——睡前 5、待跟进 3、下课 2、早安 1；下雨、重要的日子没发出过；0057 的相机那条遇上 10-11 DNS 掉线，没发成。

0057 已经证明「她那边刚有件事 → 主动告诉他」这条路径能走通，但事实源是写死的：`world.ts:182` 的 `worldNews(now)` 只认 `cameraFund.camera` 一件事。要让「因为自己的事开口」成为常态，要把这个函数推广成**由既有事实源投影的事件类**。

取证（`main` `9f1b81c`，只读）：

| 要用的 | 在哪 | 现状 |
| --- | --- | --- |
| 事的结构 | `world.ts` `WorldNews { id, at, what }`；`proactive.ts` `NewsItem`（加了 `day`）| 一件一条，id 稳定；`proactive.ts:272-275` 按 `item.id` 排候选（id 带事情的 id）|
| 到点核实 | `proactive.ts:409-415` | 事情没发生不发；那之后两人聊过不发 |
| 没说成的顺带说 | `proactive.ts` `CARRIES_NEWS`、`untoldNews` | 问候类时机顺带说 |
| 课程作业 | `WorldNow.homework: { course, due, done, doneAt }`；ADR 0056 的 `projectPortfolio` 给出「24 小时内到期」的紧急程度 | 已有，事实层 |
| 身体 | `body.ts` `bodyAt` / `unwell`（痛经、感冒），同一天对所有人一样，按档位裁剪说不说得出口 | 已有，纯函数 |
| 身边的人 | `WorldNow.people`（ADR 0033）| **不用**：第三方私事，ADR 0020 规定不主动说 |
| 考试出分 | — | **没有事实源**（世界里只有作业，没有考试），这一类现在做不了 |

## 决策

1. **`worldNews(now)` 的签名不变，内部改为「事件类」投影**：每个类是一个纯函数 `(WorldNow) => WorldNews[]`，只读 `WorldNow` 里已有的事实，**不新增状态文件**；同样的输入同样的输出，所以重启前后一样（ADR 0039 的纪律）。
2. **准入原则**（一件事同时满足才算「值得第一时间说」）：
   - 已经了结（有明确的 `at`）；
   - 有结果或有代价（买到了、交了、不舒服）；
   - 事实来自确定性世界或事件账，不是模型临时想的；
   - 这一档看得到（沿用 `tiers.yml` 的 `proactive.occasions` 里的 `news`，现在只有男朋友档开；ADR 0003 / 0020 的可见性不变）。
3. **第一批三个类**（其余类要改本 ADR）：
   - `camera`：已有，不动；
   - `homework_done`：`WorldNow.homework` 里**24 小时内到期**的那份（ADR 0056 的紧急口径）已经写完交了：id `homework:<作业 id>`，`at` = `doneAt`，`what` 例如「把〈课程〉的作业写完交了」；课名只给能知道专业的档位（男朋友档可以）；
   - `unwell`：当天**第一次**身体不舒服（`unwell(bodyAt(...))` 当天由假变真）：id `body:<日期>`，`what` 例如「肚子疼 / 有点感冒」，说得出口的程度按 `BodyNow.period.detail` 裁剪；**只在她醒着、不在上课时算**。
4. **说明（occasionNote）只给事实和方向，不给台词**（ADR 0036 调整的教训）；并且每个事件类都写死一句：**只说这件事，不要对方回应或关心，不抱怨对方没找她**（ADR 0011 调整 5 的同一条）。`unwell` 另加：不写成「需要你哄」——不是求安抚（调研 D 块把「焦虑求安抚」类触发列为与目标冲突）。
5. **总量不变**：仍受每天≤2 条、没回就停、睡觉 / 上课不发、10 分钟内聊过不发（`NEWS_RECENT_MS`）、那之后聊过就不单发（0057 决策 4）。同一天有多件事时：优先级 `camera` > `homework_done` > `unwell`，只有排得上的单发，其余走 0057 调整的「顺带说」（`CARRIES_NEWS`）。
6. **逐类开关**：`tiers.yml` 的 `proactive` 加可选 `news_kinds: [camera, homework_done, unwell]`；没写按只有 `camera` 处理，所以旧卡行为不变。新类先试运行一天（`proactive: dryRun`）再开。
7. **日志可审计**：到点发或不发都写事件类和 id（`主动：她那边的事（homework:xxx）…`），沿用 0011 §7。
8. **不做**：身边人的事（0020）；考试出分（无事实源）；让模型自己判断「这件事值不值得说」（0011 备选方案已否掉）。

## 实现步骤

1. `world.ts`：把 `worldNews` 拆成 `newsCamera`、`newsHomework`、`newsUnwell` 三个纯函数，`worldNews` 合并；单元测试覆盖每类的有 / 无、跨零点（herDay）、档位裁剪。
2. `proactive.ts`：`NewsItem` 加 `kind`；优先级和「顺带说」按类排；`occasionNote` 按类给说明。
3. `character-tools`：`tiers.yml` 的 `proactive.news_kinds` 进卡（`extensions.qqbot.proactive`），旧卡忽略。
4. 模拟器：场景 `proactive-news-homework`、`proactive-news-unwell`，各 3 次真模型，检查：只说这一件、不要求回应、不抱怨、不出现禁用词、第二天不再为同一件事单发。
5. 线上：试运行一天看日志，再开；每开一类问用户。

## 验证

- 单元：每类准入（了结、有结果、可见、醒着）、优先级、id 稳定、重启后候选一样。
- 模拟器：同一天两件事时只单发优先级高的，另一件走顺带说；他已经聊到的不再单发。
- 真模型：说明里不带引号台词；`unwell` 的三次输出没有「你哄我 / 快关心我」类说法。
- 线上：先 dryRun。

## 备选方案

| 方案 | 不选的原因 |
| --- | --- |
| 让模型每隔一段判断「有没有值得说的事」| 难验证、费钱（0011 备选方案已否掉）；事要从账里取不让模型编 |
| 一次推广到所有事件（快递、猫、小事）| 小事天天有，会变成「今日汇报」；也会占满每天 2 条 |
| 把身边人的事也算新闻 | 第三方私事，ADR 0020 规定不主动说 |
| 只加 `unwell`、不加 `homework_done` | 调研 B 块要的是「事」成为常态，一类不够；但每类单独开关，可以先开一类 |

## 后果

- 每开一类，主动消息里「因为她自己的事」的比例上升；发送量不变（仍受每天≤2）。
- `unwell` 是第一个涉及身体的主动消息，说得出口的程度必须跟着档位走（生理期细节只在能说的档位）。
- 考试出分等没有事实源的类，要先有世界层的事实才能做，另开 ADR。
