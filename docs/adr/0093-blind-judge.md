# ADR 0093：让模型当鉴别员做盲评——量“内容”像不像真人

- 状态：**已实现**（工具 `ops/blind-judge-cli.ts`，不进运行时）；“顺着说”那句提示词的新措辞随这次上线
- 日期：2026-10-21
- 关联：[ADR 0091](0091-reply-shape.md)（形状控制和只看写法的尺子）、`exchange/research/2026-10-real-chat`（真人聊天样本）
- 用户提出：2026-10-21「现在长短什么的已经和真人相似了，但内容还是差距有点大」（此前：盲评要他一条条打分没什么用）。

## 为什么

ADR 0091 的尺子只看**写法**（长短、标点、逗号）：字数配平后 AUC 0.73，长短追上之后它基本读不出差别了，可用户仍觉得内容差得远。内容层面的 AI 味（太会接话、爱反问、过于得体）脚本读不出来，要用户一条条打分又太累、噪声也大。办法：让**模型**当鉴别员，做盲评——同一句话，一个是真人女生当时回的，一个是她回的，顺序随机，问哪个是真人、凭什么；鉴别员的理由正好是要改的地方。

## 做了什么

`ops/blind-judge-cli.ts`：`--cases cases.json --hers hers.json`。cases 来自真人情侣聊天样本里 `relation = boyfriend` 的 24 段（不含摆拍的）：女方每一轮回复男方上一轮的话，共 72 对（刺激 = 男方这一轮的气泡，真人回复 = 女方当时回的）。她的回复：每个刺激单独开一个只有这一轮的模拟场景生成（男朋友档、不带记忆、`shortReplies` 开着，新代码另加 `--shape`）。鉴别员（DeepSeek，温度 0）输出 A / B 和一句依据；最后把“认出她”的依据归类。输出“挑中真人 N%”：50% = 分不开，越高越露馅。

## 量出来的（72 对 × 每个版本 1–2 份样本，每份约 3 分钟生成 + 3 分钟鉴别）

| 版本 | 鉴别员挑中真人 |
| --- | --- |
| 旧代码（线上 `shortReplies`，没有形状控制） | 61%、65%（平均 63%） |
| 形状控制 + 顺着说（`ffc77ac`，含“问一个字”） | 51%、57%（平均 54%） |
| 同上，去掉“问一个字 / 一句反问”、加“别用反问句回他” | 61%、57%（平均 59%） |

标准误大约 ±4 个点（每个版本 144 条判断），所以：旧 → 新（63% → 54–59%）方向对、没到统计显著的程度；两个新措辞之间分不出高低。

**认出她的依据**（鉴别员给的理由，按关键词数）：“接话太完整 / 顺滑 / 得体 / 太会接”占约 80%（最稳定的一条）；“反问 / 追问”旧代码占 62%、新措辞两份样本 50% 和 41%（说明那句提示起了作用，只是被“完整顺滑”接替）；“解释、安抚、关心”很少（5 / 44 以下）。归类里反复出现：“刻意反问追问”“句句完整顺滑”“巧妙反驳、俏皮反问像设计过”“解释安抚太标准”“重复附和像模板”。真人那边的特征：不完整、跳跃、只应一声、答非所问。

## 局限

- 鉴别员也是模型，容易把“更得体”的判成 AI；“被她骗过 40–46%”不等于真人会被骗。
- 她的回复是单轮、没有上文、没有记忆生成的，真人那条有上文——这是偏严的测法；反过来，单轮看不出跨很多轮才暴露的毛病（人设细节反复出现、句式一模一样、没有自己的议程）。
- 真人样本只有 72 对（小红书情侣聊天截图，已脱敏），来源是公开的，人设不是她的；每个版本的样本量小。
- 结果没有让用户本人确认过。

## 接下来

最有用的校准是用户自己：给他 10 条“他真实说的话 → 她现在的回复”，让他标哪些假并改成他觉得像的——比任何自动尺子都准，也能补上单轮测不到的东西。鉴别员的头号依据“太完整太顺滑”可以试：偶尔接半句、应一声、答非所问（真人样本里很常见），要和“她认真听了”的感觉平衡，需要再测。
