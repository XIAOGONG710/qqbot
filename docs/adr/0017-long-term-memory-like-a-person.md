# ADR 0017：像真人一样的长期记忆——有线索才想起、她的日记、对每个人的印象

- 状态：已采纳（2026-10-06 与用户确认，见文末「确认记录」）
- 日期：2026-10-06
- 关联：[ADR 0016](0016-people-she-knows.md)（名单里的人互相认识、公共记忆库）、[ADR 0012](0012-hindsight-tuning.md)（Hindsight 调优、关系概况）、
  [ADR 0015](0015-her-own-days.md)（她自己的日子：心情、在读的书）、[ADR 0007](0007-schedule-and-reply-timing.md)（作息）

## 背景

用户要她「像真人一样拥有长期、不同人不同经历的记忆」。ADR 0016 之后：每个人一个私人 bank（和他的聊天），一个公共 bank（名单里除陌生人档以外所有人的聊天），
提起写了介绍的人时给介绍和他的私人记忆。对照真人的记忆还差：

1. **想起来的时机**：公共记忆每轮都放（模拟器里「在干嘛呢」也带 3 条鸽鸽的事）。真人是被线索勾起来的。
2. **她自己的经历**：她自己的事只有「说给某人听过」才进记忆；没说出口的那一天（上了什么课、干了什么、心情）过了就没了。
3. **对人的印象**：对鸽鸽的了解只有手写的一句介绍，不会随着聊天变。
4. **是谁说的**：公共记忆里看不出是和谁聊的。
5. **计划里的日期**：「10月12日：鸽鸽下周要去杭州出差」——计划的事标的是计划那天，读起来像已经发生。

取证（10-06，只读；真实例公共库 `linmengyao-1006-common` 补写 6 段之后，只看计数和分数）：
- 83 个节点（事实 43、观察 40）、45 个实体，名单里的称呼「鸽鸽」「宝宝」和「林梦瑶」都成了实体。
- 召回分数分不出相关和无关：本机没开交叉重排（`reranker` 为空），`final` 只按名次（每次都是 1.100、1.076、1.053）；
  向量相似度在 0.83–0.87 之间，「哈哈哈」反而最高；关键词分数「在干嘛呢」和「鸽鸽最近在忙啥」一样。所以不能用 `min_scores` 设门槛，要自己判断线索。
- Hindsight 0.10.2 有实体列表（`GET /entities`）、写入时指定实体（`MemoryItem.entities`）、心智模型（关系概况用的那种，`source_query` 可以点名一个人）。

## 决策

### 1. 有线索才想起公共记忆

- 公共记忆不再每轮都查，下面任一条成立才查：
  - 他这次的话里提到了公共库里的人和事：Hindsight 抽出的实体名（至少 2 个字，去掉「林梦瑶」和他自己的称呼），实体列表每 10 分钟重读一次；
  - 他问到她过去的事：同一句里有时间（今天、昨天、上次、最近……）和经历（干嘛、去哪、在忙……），并且是问她的（有「你」，或者是问句）；
  - 他提到了名单里写了介绍的人（ADR 0016 决策 2）。
- 日志写线索：`召回公共记忆 3 条（线索：鸽鸽）`。

### 2. 她的日记

- 她的每一天（到 02:00）结束后，写一段第一人称日记存进公共库（`document_id` 是 `diary:<日期>`，标签多一个 `diary`）。
  材料：那天的作息（课、空闲活动）、心情和原因、在读的书和进度，加上她那天在名单里每个人那儿说过的话（连同对方的话，每人截一段）。
- 说明写「怎么写」：聊天里你说过自己做了什么，就是你那天做过的，照写；作息里的课和活动照写；和谁聊了什么一句带过；不编新的大事；150–300 字。
- **没聊天的日子也写**（用户定），只按作息、心情、书。bot 停过的，下次启动补最近 3 天。每天多 1 次模型调用 + 1 次写入。
- 日记只进公共库（名单里除陌生人档以外的人有线索时想得起来），不另放进提示词。

### 3. 对每个人的印象

- 名单里除陌生人档以外，每个人在公共库里有一份「她眼中的 X」（Hindsight 心智模型，`source_query` 点名这个人，跨所有人的聊天整理：他是谁、做什么的、最近在忙什么、
  你们之间重要的事和没聊完的事；150 字以内，写具体日期），整理之后自动刷新（最短 30 分钟）。
- **只在写了介绍的人被提起时用**（用户定）：放在介绍下面、他的私人记忆上面。「宝宝」这种常用词称呼不会误触发，介绍仍然是开关。

### 4. 记得是谁说的、计划的日期

- 公共记忆每条标出是和谁聊的（document_id 的哈希对回名单里的称呼；日记标「你的日记」）：`- 10月5日（和鸽鸽聊的）：……`。
- 召回的事发生在现在之后的，标成「打算」：`- 10月5日说（打算 10月12日）：鸽鸽要去杭州出差`。
- 写入公共库时把聊天对象的称呼和她的名字作为实体（`entities`，类型 PERSON），实体对得更准。

## 实现步骤（小步提交，每步能运行、测试通过）

1. ADR、路线图（本文件）。
2. 是谁说的、计划的日期、写入时的实体；单元测试。
3. 有线索才想起：实体列表、问过去的判断；单元测试。
4. 对每个人的印象；单元测试。
5. 日记：材料、生成、写入、补写、日志；单元测试（假模型、假 Hindsight）。
6. 模拟器：跨天时也写日记；新场景（线索、日记），回归 `people-mention`、`people-common`、`classmate-probes`；各 3 次。
7. 真实例：重启 Koishi，打码查日志（日记、印象、线索），推送。

## 备选方案

| 方案 | 不选的原因 |
| --- | --- |
| 公共记忆用召回分数设门槛 | 本机的分数分不出相关和无关（见取证） |
| 每轮都查公共记忆，交给模型判断用不用 | 现状；占 token，也容易无缘无故说起别人的事 |
| 日记只在聊过天的日子写 | 用户要没聊天的日子也写 |
| 日记直接放进提示词（最近 3 天） | 每轮多几百 token；有线索时从公共库召回就够 |
| 印象用那个人私人 bank 里的关系概况 | 只看他自己的聊天，别人说起他的事不在里面；关注点是「你们的关系」不是「他是谁」 |
| 没写介绍的人也用印象认出来 | 用户定只在写了介绍时用（常用词称呼会误触发） |

## 后果

- 公共记忆的召回从每轮一次变成有线索才查；日记每天多 1 次模型调用和 1 次写入；印象每人一个心智模型，整理后自动刷新（Hindsight 调 DeepSeek）。
- 日记会把她那天说过的话整理成「做过的事」，以后跟谁说起都一致；也会把说过的玩笑当真（比如随口说「我今天跑了十公里」），这和真人一样，记下了就是说过。

## 确认记录（2026-10-06）

1. 公共记忆：有线索才想起。
2. 日记：写，没聊天的日子也按作息写。
3. 印象：名单里每个人都整理，只在写了介绍的人被提起时用。
4. 是谁说的、计划的日期、写入时的实体：明显的改进，直接做。
