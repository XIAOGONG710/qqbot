# ADR 0144：刷陌生人的空间（「空友爱看」那种推荐流），用来观察人怎么说话

- 状态：**已实现，未上线、未在真 QQ 上验证**（分支 `dsh/qq-control`；开关 `qzoneStrangers`，默认 `off`）
- 日期：2026-10-25
- 关联：[ADR 0143](0143-qzone-peek.md)（好友的空间）、[ADR 0083](0083-presence.md)（她自己的说说和「空友爱看」）、[ADR 0142](0142-qq-account-control.md)（控制面）
- 用户授权：2026-10-25「做看陌生人的，正好可以让她观察学习人是什么说话的」

## 背景

「空友爱看」是 Qzone 把陌生人的优质说说混进推荐流的模块（ADR 0083 查过报道）。用户要的不是「看谁」，而是**看平台推上来的陌生人在怎么说话**——这是语料，不是社交。所以这版和 ADR 0143 是两套策略：

| | 好友的空间（0143） | 陌生人的推荐流（0144） |
| --- | --- | --- |
| 看谁 | 名单里的具体人 | 平台推的，不知道是谁 |
| 身份 | 用她的号读（对方可能看到访客） | 用她的号读（平台侧有登录态，但没有「谁的页面」） |
| 留什么 | 一句提示词 | 一句提示词 + 正文样本（观察用） |
| 名字 / QQ 号 | 提示词里会说「是谁的空间」 | **一律不留** |

## 决策

1. **只读、不互动**：不点赞、不评论、不关注、不加人。这一层只有 GET，拿到的正文进提示词和样本文件。
2. **不做「谁的」**：推荐流里不记录昵称和 QQ 号。样本只留 `{at, text, images}`（正文 ≤160 字）。
3. **接口按候选试**：推荐流没有公开文档，且换过几次。`qzone-remote` 只提供登录态和 `g_tk`，这里按三条候选逐个试——
   `emotion_cgi_re_feeds`、`qzone_recommend`、`feeds3_html_more`，哪个返回条目就用哪个（名字记进状态，排障用）。
   全都不行返回 `undefined`：日志只记一行「刷陌生人：推荐流读不到（接口变了 / 登录态过期 / 风控）」，本次运行不再试。
4. **解析是「找像说说的对象」**：在 JSON 里找带 `content / summary / text / title` 的对象，去掉 HTML 标签、压空白、去重，
   跳过 `commentlist`、`replyList`、`rtlist` 这些评论/转发链——不把别人的评论当成一条说说。
5. **节奏**：09:00–23:00、醒着、两次之间至少 3 小时（每跳 60 秒，`attemptAt` 落盘，重启不重来）。
6. **落到她身上的方式**：6 小时内 `describeSelf` 里多一句「你刚才刷了会儿空间，看到几条陌生人发的：「…」「…」（平时的人就是这么说话的）」，
   最多 3 条、每条 ≤40 字；样本另追加到 `presence/strangers.jsonl`，将来要做「她的语感从哪来」的统计有原始料。
7. **`dryRun`**：只写 `presence/drafts.md`，不进提示词、不写样本。

## 验证

- `qzone-strangers.test.ts` 5 项：认说说（去标签 / 压空白 / 去重 / 跳过评论链 / 截断）、候选逐个试（403 换下一个）、全失败返回 undefined、摘要不带名字和号、样本只留正文和时间。
- `qzone-browse.test.ts` +2 项：开着时进提示词 + 样本落盘两行；`dryRun` 只写草稿；读不到只试一次。
- 类型检查（bot + 插件）干净；`modules.test.ts` 覆盖新文件。

## 没做 / 要注意

- **接口名是猜的**：三条候选都来自 Qzone 网页端的历史接口，2026 年还认不认、要不要 `qzonetoken` 之类的新字段，**只能在线上跑一次才知道**。所以先 `dryRun`，读不到就只记一行。
- 推荐流里如果混进带手机号 / 学校名 / 真名的内容，摘要会照原文进提示词（不脱敏）；`extractPosts` 只截长度，不做内容审查。介意的话把 `qzoneStrangers` 关掉，或先只开 `dryRun` 看草稿。
- 样本文件只增不删；将来要做统计再写一个清理/去重脚本，不在这一版。
- 不做「学到的说话方式」的自动迁移：这一版只让她「看到」，怎么用是提示词和 ADR 0097/0098/0131 的事。

## 2026-10-25 补记：探针实测——这条路在她的号上读不到陌生人（Claude，只读）

- 候选接口：`qzone_recommend` HTTP 404（不存在）；`emotion_cgi_re_feeds` HTTP 200 但 `ret:1034 非法请求`（接口在，缺参数，没有再去猜）；`feeds3_html_more` HTTP 200、`code:0`，但它是**好友动态**，里面只有她自己的 6 条说说 + 1 条腾讯广告，没有陌生人。本 ADR 的通用解析器会把广告当成「陌生人说的话」收进去，所以 `feeds3` 的返回不能直接喂给它。
- H5 版（`h5.qzone.qq.com/mqzone/index`，用同一份登录态，1 个 GET）：HTTP 200、104 KB，页面里内嵌了登录后首屏数据（`FrontPage.data.vFeeds`，6 条，全是她自己的说说）。每条 feed 的 `comm` 里有推荐标记 `recomtype` / `recom_show_type` / `recomreportid` / `recomlayout`，**全是 0**；`stMapABTest` 是空对象（没有被分进任何实验组）。页面里没有推荐内容，也没有暴露 `getActiveFeeds` 之类的接口路径（在外部 JS 里，没去抓）。`qzonetoken` 在页面的 `window.shine0callback` 里，没再去用。
- 用户补充（10-25）：「空友爱看在 QQ 客户端上」。综合起来：**「空友爱看」是客户端内测，没有灰度到她这个号（无实验组、无推荐标记），网页和 H5 版都看不到。** 在她的号被灰度到之前，`qzoneStrangers` 保持 `off`；若以后要再试，先看 H5 首屏里有没有 `recomtype ≠ 0` 的 feed，有了再谈接口。
- 不继续的原因：再往下就是猜参数、翻 JS 去抓接口，对腾讯的请求会越来越像爬虫，而她的号是用户实名担着风险的；而且没有证据说明有东西可读。
