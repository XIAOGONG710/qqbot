# 0242：AI 生活照先过质量门，只登记非人物视觉参考

日期：2026-11-04

## 背景

生图接口返回了图片文件，不代表这张图适合进入审核区。常见问题包括文件损坏、分辨率过低、画面突然出现人物或手、招牌乱码、水印、著名地标、过强的棚拍感，以及菜品、天气、时段和当天世界事实不一致。土豆、书桌、餐具和窗景如果每张都换样子，也无法形成连续的生活环境。

## 决定

图片进入人工审核前先经过两层质量门：

1. 本地按实际文件签名和格式结构解析 PNG、JPEG、WebP 的尺寸；拒绝损坏文件、短边不足 512 像素、异常比例、超大尺寸和超过 12 MB 的文件。
2. 可注入的视觉审查器检查人物、人脸、手、可读文字、水印、著名地标和电影 / 棚拍感，并逐项核对照片类型、主体、菜名、天气、时段与非人物参考资料。审查器没有接入、失败、低把握或遗漏必须字段时失败关闭。

质量门只返回是否通过和中文短原因，不执行批准、发送或重新生成，也不把模型错误原文带进状态或日志。

运行时适配器把通过本地结构检查的字节编码为与实际格式一致的 `data:` URL，并要求视觉模型只返回固定字段的裸 JSON。Markdown 围栏、额外字段、宽松数字/布尔类型、缺少当前照片所需的菜品/天气/时段/参考匹配字段都会失败关闭；模型原文不进入异常、日志或状态。时段按世界账的 `Asia/Shanghai` 时区计算，不依赖服务器本地时区。

视觉一致性资料只允许 `cat`、`desk`、`tableware`、`view` 四类。状态文件只保存内容 SHA-256、供应商引用 ID、种类和登记时间，不保存图片、文件路径、人脸描述或其他自由文本。调用方必须明确确认资料不含人物；引用 ID 中带人物、人脸、自拍等含义的内容直接拒绝。

## 后续接线

生图草稿链路在写入待审核区前调用质量门；生成时只把对应类别的少量引用 ID 交给支持参考图的供应商。Koishi 控制台展示质量结论和中文原因，但不能绕过质量门直接批准失败图片。
