# 0242：AI 生活照先过质量门，只登记非人物视觉参考

日期：2026-11-04

## 背景

生图接口返回了图片文件，不代表这张图适合进入审核区。常见问题包括文件损坏、分辨率过低、画面突然出现人物或手、招牌乱码、水印、著名地标、过强的棚拍感，以及菜品、天气、时段和当天世界事实不一致。土豆、书桌、餐具和窗景如果每张都换样子，也无法形成连续的生活环境。

## 决定

图片进入人工审核前先经过两层质量门：

1. 本地按实际文件签名和格式结构解析 PNG、JPEG、WebP 的尺寸；拒绝损坏文件、短边不足 512 像素、异常比例、超大尺寸和超过 12 MB 的文件。
2. 可注入的视觉审查器检查人物、人脸、手、可读文字、水印、著名地标和电影 / 棚拍感，并逐项核对照片类型、主体、菜名、天气、时段与非人物参考资料。审查器没有接入、失败、低把握或遗漏必须字段时失败关闭。

质量门只返回是否通过和中文短原因，不执行批准或发送，也不把模型错误原文带进状态或日志。运行时适配器在质量拒绝后至多重新生成 1 次；第二次仍不通过就停止。重生成仍经过同一供应商池，所以每次上游调用都会计入 ADR 0244 的每日预算；任何结果都不会自动发送。

运行时适配器把通过本地结构检查的字节编码为与实际格式一致的 `data:` URL，并要求视觉模型只返回固定字段的裸 JSON。Markdown 围栏、额外字段、宽松数字/布尔类型、缺少当前照片所需的菜品/天气/时段/参考匹配字段都会失败关闭；模型原文不进入异常、日志或状态。时段按世界账的 `Asia/Shanghai` 时区计算，不依赖服务器本地时区。

视觉一致性资料只允许 `cat`、`desk`、`tableware`、`view` 四类，每类最多 4 张、总计最多 16 张、单张最多 5 MB。索引只保存内容 SHA-256、逻辑引用 ID、种类、登记时间和固定哈希文件名；原图放在同一状态目录的受控 `files/` 中，随整目录备份，但路径、哈希和原图都不进入控制台响应或日志。读取时重新校验普通文件、内容哈希、真实格式和尺寸；旧版只有外部引用 ID 的索引仍可读，但不会冒充已经能做图像比较。调用方必须明确确认资料不含人物；引用 ID 中带人物、人脸、自拍等含义的内容直接拒绝。

Koishi 控制台提供中文的“视觉参考”页：可登记和删除上述四类资料，但不显示内容哈希、逻辑引用编号、内部编号或磁盘路径。登记要求用户勾选“不含人物”并二次确认；删除也要二次确认。服务端只接受 5 MB 以内、内容签名与声明类型一致的 JPEG、PNG 或 WebP，索引目录、图片目录或文件为符号链接、目录替身或非普通文件时失败关闭。这些操作不会打开 `aiPhotos`、生成照片、批准草稿或发送 QQ 消息。

生图草稿链路在写入待审核区前调用质量门。视觉审查请求把待审核图作为第一张、同类本地参考图作为后续图片交给已配置的多模态看图服务，模型据真实图像给出 `referenceMatches`；不再用一个模型看不到的字符串编号假装完成一致性比较。控制台明确说明参考图会在质量审查时发送到该看图服务，但不会发到 QQ。Koishi 控制台不能绕过质量门直接批准失败图片。
