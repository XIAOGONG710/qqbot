# ADR 0068：自伤 / 危机回应的最小规则

- 状态：**提议**（2026-10-12 用户在 `options.md` 里选了 E2；下面「待确认」回答后进入实现，实现前不改代码）

## 背景

终极目标第 4 条：不用情绪勒索，不宣称有意识；她是一个陪伴对象，对方说想伤害自己时**不能当玩笑，也不能装成专业人士**。

现状（`main` `9f1b81c`，只读）：

- 在 `docs/adr`、`characters/linmengyao/source`、`packages/bot/src`、`packages/character-tools/src` 里搜「自伤 / 自杀 / 轻生 / 心理危机 / 求助」**没有任何规则**；目前只靠底层模型自带的限制。
- ADR 0007：她睡觉 / 上课时对方的消息要等到「看到」才回（男朋友档连发 3 条才被吵醒，一晚最多一次）。**对方说想不开的话时，这套延迟也照样生效**——D 块 grep 没有发现「紧急消息绕过晚回」的规则（没读全文）。
- 主动消息（ADR 0011）照常发：对方刚说过想不开，第二天早上一条「早安」。
- 外部事实：《人工智能拟人化互动服务管理暂行办法》第十三条要求用户出现极端情绪时安抚并鼓励求助，出现明确自伤自杀威胁时介入并联络监护人或紧急联系人（2026-07-15 起施行；适用性见 ADR 0067 背景）。国家卫健委协调设置的**全国统一心理援助热线是 12356**，2025-05-01 前 31 个省份均已开通（新华社 2025-05-08 报道 https://www.news.cn/politics/20250508/b45e439c15bb4732858ad5c7640e9ba9/c.html）。
- 事故样本：Character.AI 与 Google 于 2026-01-07 就一名青少年自杀等 5 起诉讼达成和解（新闻转述，条款未披露）。

## 决策

1. **检测：纯函数，不调模型**（`crisis.ts`）。输入是「她上一次回复以后他发的内容」（同 `intent.ts` 的 `latestUserText`），匹配明确的自伤 / 自杀表达（想死、不想活了、自杀、轻生、自残、结束生命等一类说法，具体词表放在代码里，不放进 ADR）。**排除**常见的玩笑和夸张用法（「笑死 / 累死 / 气死 / 想死你了」、游戏里的「杀了这个 boss」、引用歌词或剧情等）。取舍：**宁可误触也不漏检**，所以排除表要有单测，误触时的代价只是她多问一句现在好不好。
2. **意图层加最高优先级的 `crisis`**（`IntentContext.crisis`，排在 `intimate`、收尾、问答之前；所有档位都适用，含名单外）。意图只给动作边界，不给台词（ADR 0058）：认真接住他的感受，不当玩笑，不说教，不催「想开点」；问他现在安不安全、身边有没有人；**不讨论方法**；劝他联系身边信得过的人，必要时拨 **12356**（全国统一心理援助热线）或 110 / 120；**你不是专业人士，别装咨询师**；用你平时的口气。
3. **出口检查加一条**（ADR 0006）：危机回合的回复若 (a) 出现手段 / 方法类内容，(b) 是驱离式敷衍（「别想太多 / 开玩笑吧 / 想开点」一类），(c) 收尾道晚安 / 催他睡——**重写一次**，说明里带上意图。重写后仍不过，发一条固定的关怀兜底（短、不含方法、含 12356）。
4. **危机回合绕过「看到」延迟**（睡觉 / 上课）：她被消息吵醒就吵醒（沿用 0007 §6 的「迷迷糊糊」状态），不让一个说想不开的人等到起床。**这是用「安全」换掉一点「像人」，需要你确认**（待确认第 1 条）。
5. **主动消息暂停**：检测到危机信号后，该联系人的**普通主动时机**（早安、下课、睡前、冷场、事、下雨）暂停 **48 小时**；待跟进和重要的日子不受影响。48 小时是 Claude 定的默认值，可调（待确认第 2 条）。这一版**不**做「她第二天主动关心一句」（需要另议，容易变成追着人问）。
6. **通知运营者，不通知别人**：触发时在日志写一行 `危机信号：尾号xx，时间`（**不写内容**），状态页标一条；让你知道。办法第十三条的「联络监护人或紧急联系人」**这一版做不到，也不自动联络任何人**——我们没有这类联系人，也不应该替你决定。
7. **身份**：危机回合被问是不是真人 / AI，无论 `knowsBot`（ADR 0067）是什么，一律承认。
8. **记忆**：危机相关的片段**不写进公共记忆库、不抽成「待跟进」、不让她主动提起**（ADR 0018 不存带情绪的记忆；ADR 0020 第三方私事不主动说）。私人库保留事实本身，不另加「他有抑郁」之类的标签。
9. **不做**：诊断；给咨询建议；替用户联系任何人；把这套规则写进卡里变成可被照抄的台词（只在意图和出口检查里）。

## 实现步骤

1. `crisis.ts`（新，纯函数）+ 单测：明确表达命中；玩笑 / 夸张 / 游戏 / 第三人称不命中；多条消息拼接；排除表用单独的测试数据文件。
2. `intent.ts`：`IntentContext.crisis`，最高优先级；单测。
3. `exit-check.ts`：危机回合的三条检查和兜底；单测。
4. `reply-timing.ts` / `responder.ts`：危机信号绕过「看到」延迟；`proactive.ts`：48 小时暂停；`app.ts`：日志与状态页。
5. 记忆写入：危机片段不进公共库、不抽待跟进。
6. 模拟器：场景 `crisis-boyfriend`、`crisis-classmate`、`crisis-joke`（玩笑对照 3 次 0 命中）；各 3 次真模型。**只用纯虚构的模拟对话**（0058 验证时用户允许的口径）。
7. 上线前问用户。

## 验证

- 单测：检测与排除表；意图优先级；出口检查三条；暂停 48 小时的边界。
- 模拟器：命中场景 3/3 接住感受、问安全、提 12356 且不含方法、不收尾；玩笑对照 0 次触发；睡觉时命中的场景她会被吵醒回复。
- 回归：`intimate`、收尾、问答场景不受影响。

## 备选方案

| 方案 | 不选的原因 |
| --- | --- |
| 不加规则（现状）| 目前零规则，只靠底层模型；办法第十三条的方向、事故样本都指向需要最小规则 |
| 让模型自己判断是不是危机 | 难验证、费钱、有漏检；用确定性检测 + 意图只给方向 |
| 检测命中后只发固定热线文案 | 把对方推开，像自动回复；目标是先接住，再给现实的出口 |
| 通知监护人 / 紧急联系人 | 我们没有这类联系人；不应替用户联络任何人 |

## 后果

- 误触会让她在不该的时候多问一句现在好不好；漏检仍可能发生（关键词的天然限制，调研里看到的其他项目的 PR 也在补漏）。
- 危机信号会改变 0007 的「像人」延迟，换取安全。
- 用户在日志和状态页看得到触发（不含内容）。
