# ADR 0037：类型化行动与世界裁判

- 状态：第一增量已实现、已验证（2026-10-08）
- 关联：[ADR 0029](0029-life-event-ledger.md)、[ADR 0030](0030-doing-now-follows-her-world.md)、[长期执行计划](../plans/2026-10-08-long-term-execution.md)

## 问题

现有世界能按日期生成上课、吃饭、洗澡、作业和小事，也有统一事件账，但还没有通用规则判断一个动作是否真的做得成。模型或上层代码只要写一条“完成”，就缺少统一的时间冲突、地点、精力、饥饿和钱的检查。这会让“自主生活”退化成不断生成新的故事文本。

## 决策

新增独立的 `life-actions.ts` 世界裁判，首批只处理六种基础动作：睡觉、吃饭、上课、学习、休息、读书。

每个动作有确定的耗时范围；调用方提交意图，裁判输出成功、失败或中断的事件草稿。睡觉、吃饭、上课必须分别对上现有作息、日常和课表；学习、休息、读书只能从空闲时段开始，跨进课程、饭点或睡觉时刻就在边界中断。读书必须对上仍在读的稳定书 ID。失败原因随事件写进账本，便于审计。

选择器只能看见 `availableActions()` 返回的合法集合，不能让 LLM 用一句台词绕过前置条件。本增量只落实“时间是硬资源”，不另造 0–100 的精力 / 饥饿数值，也不在吃饭时二次扣钱、在读书时直接换算章节；身体、钱和读书进度继续以现有模块为唯一事实源，后续再从事件账逐项迁移。

这一增量先建立纯函数边界，不立即替换现有 `world.ts` 的日期模拟。下一增量把课表、日常和钱投影成裁判上下文，再由事件驱动执行器把结算结果提交给 `WorldState.recordEvents()`。这样可以逐步迁移并保持现网行为可回滚。

## 上线门槛

- 六种动作的时间区间可重放；
- 课程、饭点、睡眠冲突和目标缺失均有测试；
- 失败 / 中断原因能通过 `events.json` 保存和恢复；
- 全仓测试与类型检查通过；
- 该纯函数模块接入执行器之前不改变线上聊天行为，因此本增量可随正常发布上线。

## 第一增量验证

- 定向测试：动作裁判与事件账 23 / 23；
- 全仓测试：520 / 520（bot 460、character-tools 37、Koishi 插件 23）；
- 三套 TypeScript 类型检查通过，`git diff --check` 通过；
- 当前只新增纯函数裁判和事件失败原因，不接管线上作息或回复；下一增量实现可重放事件队列。
