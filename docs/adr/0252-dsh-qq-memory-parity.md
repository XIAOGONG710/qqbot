# ADR 0252：DSH 与 QQ 使用同一套记忆清晰度

- 日期：2026-11-04
- 状态：已实施
- 相关：ADR 0018、0171、0176、0215

## 问题

QQ 已有清楚、模糊、一提想起、忘记和长期五档记忆，DSH 却只有“30 天内保留、之后按二字词重叠复活”的粗规则。同一条记忆在两个入口表现不同，而且常见词重叠可能错误唤回无关旧事。

## 决策

1. DSH 与 QQ 使用相同核心规则：普通事实 7 天内清楚、30 天内模糊；重复事实、周记和阶段总结期限翻倍；重要、长期和未到期计划保持清楚。
2. 超期事实只在当前话语明确出现该记忆的实体名时“一提想起”，不再使用二字词重叠。
3. DSH 召回请求实体和观察背后的源事实；注入提示词前移除内部【重要】/【长期】标记，并给模糊记忆加自然语言提示。
4. QQ 的 `<<记住>>` 与 DSH 的 `memory_save` 标为【重要】；日记不永久化。
5. 双方都只是纯寒暄或确认时，不向 Hindsight 新增长期文档；跨端最近对话仍照常记录，因此短期衔接不受影响。
6. 不增加第二套夜间整合器。现有 Hindsight observations consolidation 继续负责归纳，避免重复调度和相互覆盖。

## 安全与兼容

- 不迁移、不重写、不删除既有记忆；规则只影响新写入的重要标记和召回展示。
- DSH 仍只读取他的私人 bank、公共库中她自己的文档和旧公共 bank，原隐私边界不变。
- 重要标记在送给模型前剥离，不显示内部代码串。

## 验收

- 契约测试用同一组事实同时调用 QQ 与 DSH 清晰度函数，结果必须一致。
- 覆盖 3/20/45/100 天、重复事实、实体线索、重要标记、日记长期标记和纯寒暄跳过。
- 运行类型检查、记忆/DSH 定向测试、全量测试、发布检查和 `git diff --check`。

## 回滚

回滚本次提交即可恢复旧召回规则；既有 Hindsight 数据无需迁移。
