# ADR 0109：照片货架——她自己从网上找高清图发给他（配置 `photos`，默认关）

- 状态：**已实现，未上线**（2026-10-22；配置 `photos`；默认关）。上线 = `koishi.yml` 里加 `photos: true` + 重启（要「看图」开着才会去网上找；线上 `vision.enabled: true` 已开）；回滚 = 改回 false + 重启（照片文件和清单留在 `<数据目录>/photos/`，不影响别的）
- 日期：2026-10-22
- 关联：[ADR 0063](0063-image-stickers.md)（图片表情：同一套令牌 / 清理 / 发送）、[ADR 0067](0067-disclosure-per-contact.md)（她是程序，被问起照实承认）、[ADR 0055](0055-deepseek-vision.md)（看图）
- 用户提出：2026-10-22「继续开发新功能」；中途两条指示：**「照片不要用我给她的相册，从网络上找她要发给我的照片，高清」**、**「记得去水印」**

## 差距（有数据）

- 线上 `<他的 QQ 号>.jsonl`：他的 628 条里 **115 条（18%）带图 / 表情**；她的 676 条里 **19 条（2.8%）**，真正的照片 **0 张**。
- 人设（角色卡【日常】）：「宿舍楼下有只三花流浪猫，你给它起了名字叫『土豆』。你每天下楼喂它，会拍它的照片存手机里，也会拿去给他看。」他说想看土豆时她只能“先不发”。
- 照片不是模型能编的东西，所以必须是真的图片文件；货架空着就什么都不做。

## 做了什么

1. **货架**（`photos.ts`）：`<数据目录>/photos/` 里 `files/`（原图）+ `index.json`（编号、种类、一句话说明、发过几次、出处）。种类：`cat`（土豆）、`view`（天空）、`work`（她的片子，只能手动加）。不含她本人的自拍（对她长相的裁决是作者的，不替作者定）、不含吃的（和她当天吃了什么对不上就穿帮）。
2. **什么时候发**（代码定，`contact.ts`）：他明确要看某一类（「发张土豆的照片」「看看今天的晚霞」；`photoWanted`）、货架里有这一类、这一轮允许（不是危机 / 吵醒 / 小别扭 / 他难过；3 小时内没发过；一天最多 3 张）。要她本人（自拍）不触发，照旧走“先不发”。只对男朋友档。
3. **怎么发**：同表情包——意图行「先用一句话带一下（是以前拍的，别说成刚拍的），然后另起一行单独发照片」，提示词列这一类的几个编号和说明，模型写 `<photo:编号>` 一行；`clean` 去掉未知的 / 混在文字里的 / 同一轮第二张；发送时按图片发（`sendPrivateImage`）；聊天记录里写成「她发了张照片：……」，下一轮她知道自己发过。拆气泡时这一行自己占一条；出口检查里“翻出来发你看”不算她做不到的承诺（只在这条回复真带着照片时）。照片轮不套形状 / 长短提示（套了以后“最多 1 条”会让模型漏写照片那一行：6 次里只有 1 次发出，去掉后 6/6）。
4. **她自己去网上找**（`photo-sources.ts`；用户 10-22 的要求）：
   - 来源只有 **Wikimedia Commons**（不用 key），**只收 CC0 / 公有领域**——发给他不需要署名、不碰版权。CC BY / BY-SA 要署名，一律不收。
   - **高清**：原图宽 ≥ 2400、高 ≥ 1600、比例 0.55–1.9、jpeg；下载 2560 宽的缩略图（Commons 自己生成，不放大，实测 1.8–4.8 MB，如 3024×4032 的猫）。
   - **同一只猫**：猫的搜索词 `calico cat`；第一次收下哪个系列（标题去掉结尾编号，如「Calico cat, Lebanon」）就只收同一系列的，系列收完就停，不换另一只猫（土豆只有一只）。实测第一批：同一系列的两张 3024×4032 公有领域三花猫。
   - 天空：`sunset sky clouds` + Commons 的 `CC-Zero` 分类。
   - 下载走 `safe-image.ts` 的安全通道（只认公网、每一跳校验、限字节），带说明性 User-Agent（Wikimedia 的要求）；两次下载之间歇 2 秒；遇到 429 / 超时 / 断网这类暂时的错误，**停这一轮、不把这张标成“看过”**，6 小时后再来（实测 Wikimedia 会回 `Retry-After: 600`）。
   - 每类攒到目标数就不再找（猫 8、天空 6）；每次每类最多下载 / 看 2 张；找过的标题记在清单里，不重复下载。
5. **去水印（用户 10-22：「记得去水印」）**——**不擦别人图上的水印，而是不收带水印的图**：
   - 来源本身只取 CC0 / 公有领域的原图（基本没有水印）；
   - 下载后让看图模型逐张检查，要求它看图上**任何位置（尤其四个角和边缘）**有没有叠加的文字、水印、徽标、署名、日期戳、版权标记或相框边框；
   - **没有明确回答“没有”就不收**（没回答、答得含糊、字段缺失都不收），人物同理；另外要清晰、猫要是三花、天空要以天空为主；
   - 说明（一句话，≤ 30 字）只写看得见的东西，带地名、品种名、外文的不收（会和她在学校那边的生活、“土豆”对不上）。
6. **手动加还保留**：`node src/ops/photo-cli.ts list|add|remove`（作者想放自己的图时用；用户 10-22 说照片不靠他的相册，所以默认不需要）。

## 没做 / 要注意

- **这些照片不是“她拍的”**：是网上的公有领域照片，她说“以前拍的”是人设内的说法（她是个有设定的虚拟角色，被认真问起是不是程序仍照实承认，ADR 0067 / 0068 不变）。猫是同一个系列里的同一只，但**不是**角色卡里的“土豆”原型——只要风格上对得上；天空照片也不会和她当天窗外的天气对上，所以提示词要求说成“以前拍的”。
- 看图模型把关能挡掉大部分水印 / 人，但不是 100%；作者可以随时 `photo-cli remove <编号>` 删掉不满意的。
- 没有她的自拍、吃的、街景（街景里的招牌、人、地名会和她在学校那边的生活对不上）。要做这些需要作者的裁决。
- 找照片要联网：外网断了就是“下次再来”，货架里已有的照常发。
- 每次发照片之前不会再看一遍（入库时看过一次）。

## 验证

- `photos.test.ts`（10 个）：货架增删 / 编号 / 提示词 / 清理 / 解析 / 历史描述；什么时候发；意图行；出口检查；拆气泡。
- `photo-sources.test.ts`（12 个）：Commons 搜索结果的筛选（jpeg / 大小 / 比例 / 许可 / 域名）、系列 key、搜索请求（User-Agent、翻页、2560 宽、429 抛错）；**把关规则**（水印 / 人物必须明确说“没有”、清晰、种类、说明长度和地名品种）；`discover`（同系列放一起、一次 2 张、出处记下、被拒不再试、429 不记看过、太小不收、够了不找、同一时刻只跑一个、重开还在）。
- `app.test.ts`：他要看土豆 → 提示词列编号、先一句话再发图、聊天记录写成可读的一句；没要时模型乱写照片指令清掉；货架空 / 没开 → 不发图。
- 真网络 + 真看图模型冒烟：9 秒收下同一系列的两张 3024×4032 公有领域三花猫（1.8 / 2.0 MB），说明干净。
- 模拟（真模型）：`sim/photo-cat.json`（他要看土豆 → 先一句话再发一张，20 分钟后再要不发：6/6）、`photo-selfie.json`（要自拍不发照片：3/3）、`photo-none.json`（没要不乱发：3/3）。

## 调整（2026-10-25）：把关再收紧，货架里「学校那边没有的东西」不收

用户 10-25 看了货架里的图，说吃的照片太假（见 ADR 0128），风景也有同样的问题：两张澳大利亚的棕榈树晚霞、一张有英文啤酒招牌的澳大利亚晚霞、一张海面和岛屿、一张远处有芝加哥摩天轮的湖面——都不像在学校那边拍的。用户选「货架留着」，但这些要去掉。

- `judgePhoto` 加两道（规则在代码里，模型不定）：看图模型的 JSON 里多了 `"热带"`（棕榈 / 椰子 / 热带植物 / 沙滩 / 大海 / 岛屿 / 大片水面 / 摩天轮）和 `"招牌"`（任何能读出来的文字、招牌、路牌，包括外文，场景里的也算——原来的「水印」只管叠加的字），明说有就不收；说明（caption）里写了这些词（棕榈、海面、水面、摩天轮、招牌……）也不收。字段没回答不拦（和水印不同：水印要明确说没有才收），免得模型漏答就一张都收不进。
- 已有的 5 张猫（同一只三花、黎巴嫩拍的，对得上土豆的毛色，绿得像春天）和 2 张没有地标的天空（瑞典松林日落、蓝天白云）留着；棕榈 2 张、海面岛屿 1 张、摩天轮湖面 1 张、英文招牌 1 张从 `photos/index.json` 摘掉，文件挪到 `photos/removed-*/`（`seen` 里还记着，不会被原样收回）。
- 只在他要看猫 / 天空时才发（`photoShares` 默认关，没开）。
- 单元测试：`photo-sources.test.ts`（热带、招牌、说明里的词、字段缺失照旧收）。
