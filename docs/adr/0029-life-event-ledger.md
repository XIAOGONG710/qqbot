# ADR 0029：统一生活事件账与无聊天重放

- 状态：已实现并上线（2026-10-07 23:22，和 ADR 0030、0031 一起）
- 日期：2026-10-07
- 关联：[ADR 0021](0021-her-world.md)（她的世界）、[ADR 0027](0027-world-writeback.md)（说出口的行为回写）、[实施方案](../research/2026-10-07-life-engine/implementation-plan.md)

## 问题

ADR 0027 只有四类“她已经在聊天里声称完成”的动作。它能阻止同一段对话前后矛盾，却不能表示无人发消息时她依然生活，也没有失败和中断。若继续给每个功能单独加状态文件，日记、记忆、世界和未来的自主执行器会各自拥有一份互相冲突的事实。

## 决策

### 1. 事件账是新的事实源

新增 `<dataDir>/world/events.json`。每条事件包含稳定 id、行动者、开放的 kind、按她作息归属的 day、开始/结束 ISO 时间、来源和结算结果；第一版附带 subject、target、seen 以及可选的对话审计线索。

`kind` 刻意保持开放集合：当前世界只认识喂猫、取件、写作业、家庭视频，读书、休息、NPC 互动等未来事件可以先进入同一本账，再逐项增加投影。旧 `actions.json` 不再是权威来源，但仍作为成功世界动作的兼容投影持续写出，方便旧代码回滚。

### 2. 迁移不破坏旧数据

- 启动时同时读取 `events.json` 和旧 `actions.json`，按稳定 id 合并。
- 只有发生第一次新写入时才把合并结果落到事件账；仅启动不会改文件。
- 新事件落盘后继续原子写 `actions.json`。中途失败由上层重试，事件 id 保证幂等。
- 新旧文件同时存在时不会把同一动作迁移两次。

### 3. 结算结果与世界投影分离

事件结果是 `succeeded`、`failed`、`interrupted` 三种。失败和中断也是人生经历，会留在账里，但只有成功且被当前世界认识的事件能投影成 `WorldAction` 并改变世界。

取件、写作业等成功声明仍要经过世界前置条件检查并解析成稳定目标。目标不存在时，内部模拟 / 外部事件会被结算为失败，不能靠调用方一句“成功”凭空改变现实。聊天抽取继续采用 ADR 0027 的保守规则：原话、时间和对象对不上时不写入。

### 4. 模拟器支持无聊天事件

场景新增 `life` 步骤。事件时刻取当前虚拟时钟，id 加运行前缀，来源固定为 `simulation`。它不制造用户输入或模型回复，可以直接验证“三天没人找她，她也发生了什么”。同一个场景、同一个 runId 重放时不会重复执行。

## 后果与下一步

- 这一步建立了统一事实地基，但还没有自主选择器；目前无聊天事件由模拟器或未来外部执行器提交。
- 下一步把睡觉、吃饭、上课、学习、休闲、读书做成带持续时间、资源消耗和打断条件的类型化行动，再让事件队列自主驱动它们。
- `events.json` 目前使用原子 JSON 数组，而不是逐行追加文件。语义上事件只追加；数据量和并发写入达到需要分段时，再迁移存储格式，不提前增加恢复复杂度。
