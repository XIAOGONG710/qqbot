# ADR 0192：删掉危机的最轻一档（strain）

- 状态：**已实现**（没有新开关）；**用户 2026-10-30 的决定**，取代 [ADR 0191](0191-crisis-concern-split.md) 里的 strain 档
- 日期：2026-10-30
- 关联：[ADR 0068](0068-crisis-response.md)（危机最小规则，关切级及以上不变）、ADR 0191（把关切级拆成 strain / concern，现在 strain 已删）、DSH `9eaf9bf`

## 用户的话

我在 ADR 0191 里留了一个问题：最轻的那一档（「撑不下去 / 走不下去 / 熬不下去」）要不要还让她 48 小时不主动找他，我倾向缩到 6 小时或不暂停。用户的回答：**「危机档直接删掉吧，太敏感了。」**

## 做了什么

- **「撑不下去 / 走不下去 / 熬不下去」单独说，不再进危机**：不触发任何危机意图、不重写、不套固定兜底、不记 `crisis.json`、**不暂停主动消息**。她按平常聊天接这句话（卡里的口气）。
- 级别回到三档：`concern`（想消失 / 不想存在了 / 没有我会更好 / 活着没意思 / 活着好累 / 买好了药）、`high`、`imminent`。
- **关切级整个恢复成 ADR 0068 的原样**：意图直接问有没有伤害自己的念头、此刻安不安全、可以拨 12356；固定兜底同样；重写说明也恢复成「认真接住、问他现在安不安全、身边有没有人」。ADR 0191 删 strain 时我发现一个遗留的不一致：关切级的**重写说明**当时还留着 DSH 那版「别追问安不安全」，和关切级自己的意图（直接问安全）相反——这次一并改回。
- **后面直接接想死的仍然命中**：「撑不下去了想死」「撑不下去了，不想活了」照旧是 high。
- **已经落盘的 strain 记录**（ADR 0191 之后、如果 DSH 机器上跑过这版）：读 `crisis.json` 时丢掉，**不抛、不再暂停**；别的联系人的记录不受影响。级别写成别的不认识的词仍然失败关闭（原有的 schema 检查）。
- DSH 的软文案（`CRISIS_STRAIN_INTENT` / `CRISIS_STRAIN_FALLBACK`）随之删除。**请 DSH 不要再把「轻一档」加回来**；如果以后觉得「撑不下去」要接得更好，改卡里她的口气，不要在危机流程里加档位。

## 这件事的边界（要说清楚）

- 这是**用户对最轻一档的决定**。我没有动关切级及以上的任何一条：想消失、没有我更好、活着没意思 / 好累、买好了药仍然是关切级，仍然直接问安全、仍然暂停主动消息 48 小时。危机红线（ADR 0068 / 0067）在代码里，没有变。
- 代价（我愿意让用户知道）：他真的是在说撑不住、却没有用上面那些词时，她不会进保护流程，只靠她平常的口气去接。这是用户明确选的取舍（「太敏感」）。如果以后发现漏了真的信号，要加的是**具体、少误报的词**进关切级，而不是恢复一个宽泛的轻档。
