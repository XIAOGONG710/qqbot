# ADR 0159：跨渠道统一的近期时间线（timeline）

- 状态：**已实现，默认关，未上线**（分支 `claude/continuity`；开关 `timeline`）
- 日期：2026-10-26
- 关联：[ADR 0029](0029-life-event-ledger.md)（生活事件账本）、[ADR 0089](0089-bilibili-account.md)、[ADR 0148](0148-device-control.md)、[ADR 0160](0160-web-lookup.md)
- 用户提出：2026-10-25「跨渠道统一时间线」（清单：「你在 B 站回复评论后，另一个聊天窗口可能毫不知情。不同工具、窗口和实例应共享可访问的事件记录，记下时间、操作与实际结果」）

## 现状

- QQ 聊天有聊天记录；QQ 空间说说和签名她本来就知道（`presence.ts` 的 `describeSelf` 放进了提示词）；世界账（生活事件）有 ADR 0029。
- **缺的**：她在 B 站评论 / 回复 / 发私信 / 看视频、替他操作设备、上网查东西、设定被改、休眠——这些在 QQ 聊天里她完全不知道。他问「你刚才在 B 站干嘛了」她只能编。

## 做法

`timeline.ts`：一个小的 JSONL（`runtime/bot/timeline.jsonl`），每行 `{ at, channel, kind, summary, ok? }`。`summary` 只写「做了什么、结果如何」的一句话（≤80 字），**不记评论、私信、网页的原文**。渠道：`bilibili / device / web / identity / dormancy / people / tastes`（`qzone` 保留）。文件超过 2000 行时留最近 1500 行。

接线（都是包一层，不改原模块的行为）：

- **B 站**：`timelineAccount` 包住账号对象——`postComment / postReply / sendDm / subtitle` 成功或失败（失败标「没做成」，错误照抛）各记一行；
- **设备**：`DeviceServiceOptions.onAudit`，只有真的 `executed / failed` 才记（待批准、被拒、限流、重复、试运行不算「做过」）；
- **上网查**：`WebLookup.onDone`；**设定改动 / 休眠 / 醒来 / 新发现的口味**：app.ts 里直接记。

放进聊天提示词：最近 24 小时里 QQ 以外的最多 5 条——「你最近在 QQ 聊天以外做过的事（这是你自己的经历，聊天里没说过）：今天 08:30 在 B 站看了一条视频（BV1…）……。他问到才说，自然带过，别念清单；没记在这里的就是没做过，别编」。只给男朋友档。

## 测试

`timeline.test`：记 / 读 / 窗口 / 截断；设备只记真执行的；B 站账号成功失败都记且评论 / 私信原文不进时间线；`app.test`：时间线里的条目出现在提示词里，查资料记进时间线。

## 没做 / 限制

- Qzone 说说不重复记（她本来就知道）；QQ 聊天本身不记（有聊天记录）。
- B 站目前暂停（用户 10-24），所以 B 站那几条在恢复前不会有内容。
- 「多个窗口 / 实例共享」目前只有一个进程；要多实例得换成带锁的存储，这次没做。
- 上线 = 合并 + `timeline: true` + 重启；回退 = 删掉那一行。

## 真模型检查（只放角色卡 + 时间线那一行，每种抽 5 次）

- 他问「你刚才在 B 站干嘛了」：5/5 都说看了视频；第一版提示词下她会编内容（「看到一个还挺好玩的」「看完还愣了一会儿」）；加了「没写的细节别编，他追问就说记不太清」之后 3/5 直接说「具体啥内容记不太清了」，其余只说看了视频。
- 他问「你今天有没有在 B 站评论别人的视频」（时间线里没有）：5/5 老实说没评论。
- **残留的毛病**：时间线里 09:30 看了视频、10:05 查了「量子纠缠」两条互不相干的记录，被问到查东西时 5/5 都会把它们接成一个因果（「刷到个视频讲这个，就自己去搜了」）——这是模型替两件事补的“理由”，记录里没有。提示词里写了「两件事之间的联系别编」但压不住；要根治得让每条记录自带“为什么”，这次没做。
