## 一、四条来源分别是什么

| 来源 | 公开描述 | 我们的对应物 |
| --- | --- | --- |
| **qqbot-selfcheck（人格自检 skill）** | 聊久了模型会慢慢变成「通用助手腔」；用设定文件逐条对照最近十条回复；检查结果不发群，改就行 | 有 `exit-check`（出口检查，运行时）、`humanness` / `rough-edges`（度量）、`consistency`（对账），**缺一个「十条对照设定」的入口** |
| **评论区（Zal 的大肥鱼 / token 像流水）** | 8000 条群消息：中位 7 个字、九成句子没主语；超过 5 秒的命令转后台；主动接话交给独立小模型算概率；「不想回就显式沉默」 | 长度目标已有（`shape` / `shortReplies`）、`moody` 就是「看心情不回」；「独立小模型算概率」跟我们 `proactive-planner` 的规则层是两种路线 |
| **bili-cli（kukemc）** | 「为 AI Agent 设计的哔哩哔哩命令行工具：扫码登录、看视频、评论、私信、发动态、投稿，全部 JSON 输出」 | 我们自己的 `bilibili-account.ts` + `bilibili-comment/replies/dm` 已经做了同类事，且有自己的风控、熔断、开关 |
| **astrbot_plugin_memewiki + retcon-form** | 梗百科：6600+ 条梗离线、倒排索引、自动识别、解释「怎么用 / 什么场合」、LLM 工具先查再回；retcon-form：写记忆时只检查一件事——这条有没有写「什么情况下它是错的」 | `memes.ts` 是「从 B 站热榜学 + 本地库」，条目少、依赖 B 站；记忆侧刚有 `identityLedger` / `memoryAudit`，还没有「可证伪」的硬要求 |

## 二、采纳与不采纳

### 1. 人格自检：做成只读工具（本 ADR 的代码）

`packages/bot/src/selfcheck.ts` + `ops/selfcheck-cli.ts`：

- **规则层**（不花 token）：这一档禁用词、助手腔套话（「首先」「希望对你有帮助」）、句号结尾过多、超过 25 字、问句占比、开头重复；
- **模型层**：`buildJudgePrompt(card, replies)` 生成「拿设定卡逐条判断这十条像不像她」的提示词，要它回 JSON（逐条 ok / why + 一句整体 drift）；
- **只读**：命令行读聊天记录和角色卡，例子截短、只取她的话；默认不进任何日志、不发群、不改运行时；
- 用法：`node src/ops/selfcheck-cli.ts --tier boyfriend --limit 10 [--prompt]`。

### 2. 「中位 7 字、九成没主语」：不新做代码

我们已经有 `rough-edges` / `humanness` 两把尺子，量的是气泡长短、标点、功能词。这批数据说明的是同一件事（短、口语、少主语），**再做一个统计脚本是重复**；值钱的是「每改一版就拿最近 30 条复量」这个动作，写进周报流程即可。

### 3. 梗百科：采纳方向，等数据

它比我们强的地方是**离线**（6600 条、16 MB）和**「先查再回」的工具化**。我们 `memes.ts` 的库是她自己从热榜学的，条目少、B 站静默时就不长。**方案**：把梗百科的数据当外部词库导入 `memes.json`（词、一句话意思、用法示例、来源），并保留我们的敏感词过滤和 45 天过期。**没做**：数据集要用户提供（本机下载不到），导入格式得先看一眼真数据。

### 4. bili-cli：不引入

它和我们的 `bilibili-account` 是同一层的竞品，而且更全（能投稿）。不引入的理由：
- 引入它等于把她的 B 站号交给一个外部 CLI，它会自己存 cookie、自己发请求，我们的风控 / 熔断 / 开关全部绕过；
- 我们现在的 B 站线是**全静默**状态（10-24 起），恢复都要用户点头，不适合再叠一层外部工具；
- 可以借鉴的只有它的**接口形态**（所有动作 JSON 输出、Agent 可调用），这一点我们 `scripts/*.ts` 已经是了。

### 5. retcon-form：采纳到记忆账本，下一步

「写记忆时必须写清它在什么情况下是错的」是可证伪性约束，和我们 `identityLedger` / `memoryAudit` 天然互补。**没做**：要改记忆写入 schema 和旧条目迁移，属于下一版；先记为候选，不动现在的记忆。

### 6. 显式沉默 / 5 秒转后台：已有 / 不适用

- 「不想回就显式沉默」= `moody` + `readReceipts`（看到不回），已有；
- 「超过 5 秒的命令转后台」：我们没有这种命令入口（长任务本来就在 `scripts/` 里单独跑），不适用。

## 三、验证

- `selfcheck.test.ts` 4 项：取最近十条（跳过他的话与非文字）、六类规则各报一条、干净十条不报、提示词逐条编号且不带他的话；
- 类型检查（bot）干净；`modules.test.ts` 覆盖新文件；全量套件没跑（只跑受影响的）。

## 四、没做 / 注意

- 规则层只是线索，不是判决：短句、问句、句号在具体语境里都可能是对的，报告要人看；
- 模型层要自己贴提示词（本工具不调模型、不计费），以后可以接 `--model`；
- 梗百科数据、retcon 的记忆可证伪、独立小模型判「要不要接话」都还开着，见第二节的「没做」。
