# ADR 0126：会追问（配置 `curious`，默认关）

- 状态：**已实现，未上线**（2026-10-23；配置 `curious`；默认关）。上线 = `koishi.yml` 里加 `curious: true` + 重启；回滚 = 改回 false + 重启（不存任何状态）
- 日期：2026-10-23
- 关联：[ADR 0116](0116-ask-opinion.md)（问问他的意见——`ask` 时机）、[ADR 0091](0091-reply-shape.md)（顺着说）、[ADR 0098](0098-already-told-and-topic-pick.md)
- 用户提出：2026-10-23「现在她不回主动发问，就算问了也是一些极小的无关问题，是否可以让她发问」

## 问题（有数据）

量了线上 10-08 → 10-23 她的 700 多条：
- **问句率没有低**：12.3%（上线“形状”以前）→ 12.0%（以后），和真人样本（10–16%）持平。
- **问的不对**：十几天里她的问句几乎全是口头语和反问（「睡吧？」「好了吧」「至于乐成这样吗」「你定吧」），真正问他生活、问他刚说的那件事的，只有三四句（「山东博物馆？拍啥呢」「忙去了？」）。
- **原因在提示词**：他说自己的事时，意图行（`intent.ts` 的 `saysOwnThing`）写着「别急着追问细节，真要问也只问一两个字」——为了治“每轮都以问句收尾”（ADR 0019 以来的教训）；顺着说的轮次又写着「别用反问句」。两句合起来，她只会问一两个字的小问题。

## 做了什么（`curious.ts`）

**1. 聊天里：他说了件有细节的事，她问一个关于这件事本身的问题。**
- 条件（全是代码，不额外调模型）：他这一句够长（≥ 6 字）、有事件 / 人 / 计划的细节（去了哪、见了谁、买了什么、面试 / 考试 / 项目 / 同事 / 家人……；只有累、困、烦这类感受的不算——那是接情绪）、不是问句、不是收尾；她最近 4 条里没问过（带问号的）；再按他那句话取哈希，约 60% 触发（同一句每次一样）。
- 意图行 `CURIOUS_INTENT`：「回应他刚说的那件事——先有个真实的反应，然后问一个你真想知道的问题，问的是他刚说的这件事本身：谁、在哪、怎么回事、后来怎么样、他当时怎么想、接下来怎么打算，挑你最想知道的一个；一个问题就够；别问和这件事无关的（在干嘛、吃了吗、你呢），也别问他已经说过的；真好奇，不是客套，更不是反问」。不给台词。
- 排在难过 / 生病 / 危机 / 亲密邀约 / 吃醋 / 他在问她 / 收尾之后（它们先接走），只对男朋友档。
- 说话形状（`shape.ts`）：追问的轮次按“认真接话”算（至少中等长度，留得下一个问题）、不走废话 / 情绪轮 / 带自己的事、不加「顺着说，别用反问句」。

**2. 主动：`ask` 时机换成“想多了解他一点”。** `withCurious`（自带 `ask`，不开 `proactiveAsk` 也有）：一周最多 2 次、隔 ≥ 2 天、下午到 21:00、他没回不催、他说过去忙 / 累就不问——都是 ADR 0116 同一套闸。提示词让她问**他自己的事**：从聊天和她记得的他的事里挑一件他提过但她还不知道细节、或者不知道后来怎么样的（学习 / 工作、朋友同事、爱好、家里、最近在忙的、计划或烦心事），没有合适的就问他这几天的安排；不编他没说过的事、不问客套、不问她自己的事。ADR 0116 原来的“问他对她小事的意见”在 `curious` 开着时被它取代（两个都开，以追问为准）。

## 没做 / 要注意

- 问什么由模型看他的话挑，质量要看真模型模拟（`sim/curious.json`）——外网恢复后跑；今天只有单元测试。
- 只管“追问”这一类。她的生活太单调、没什么可分享的，是另一个问题，另外处理。
- 判断靠关键词，漏判时她还是不问（不坏）；误判（把别的话当成有细节的事）会多问一句，代价小；最近 4 条里问过就不问，不会连着盘问。
- 一周最多 2 次的主动发问是我拟的，嫌少可以调 `ASK_MAX_PER_WEEK`。

## 验证

`curious.test.ts`（10 个）：约 60% 触发且同一句每次一样；太短 / 问句 / 收尾 / 只有感受 / 没有细节都不追问；她最近问过就不再问、隔 4 条以后可以；意图行：开了触发、没开 / 不是男朋友档仍是原来的“别急着追问细节”，每条底线都写着，计入“认真接话”；难过 / 他在问 / 收尾让路；形状：600 轮没有极短 / 废话 / 情绪 / 带自己的事 / 顺着说；主动：`withCurious` 自带 `ask` 并标记、提示词是问他自己的事、原来的问意见保持。
