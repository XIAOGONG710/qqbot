# ADR 0110：她主动发照片——喂完土豆拍了一张（配置 `photoShares`，默认关）

- 状态：**已实现，未上线**（2026-10-22；配置 `photoShares`，要 `photos` 和主动消息开着；默认关）。上线 = `koishi.yml` 里加 `photoShares: true` + 重启；回滚 = 改回 false + 重启
- 日期：2026-10-22
- 关联：[ADR 0109](0109-photo-shelf.md)（照片货架）、[ADR 0057](0057-her-news.md)、[ADR 0064](0064-her-own-events-as-reasons.md)（她那边的事成为开口理由）、[ADR 0106](0106-everyday-life.md)
- 用户提出：2026-10-22「把 A 全部做完」（A2）

## 差距

照片货架（ADR 0109）只在他开口要看时才发。真人是会自己发的：喂完猫随手拍一张就发过去。线上 676 条她的话里照片 0 张，主动开口里也没有“发图”这一类。

## 做了什么

1. **世界账里多一类“她那边的事” `cat_photo`**（`world.ts` 的 `newsCatPhoto`，`proactive.ts` 的 `NEWS_KINDS`）：当天喂了土豆且**见到**它（`seen`，ADR 0034 的猫），其中约 35% 的天（`CAT_PHOTO_CHANCE`，按日期取哈希，同一天每次一样）她拍了张照片；了结的时刻 = 喂完之后 8–25 分钟。没见到、没去喂、还没去、不去、没有猫的天都没有。
2. **运行时叠加，不改角色卡**（`withCatPhoto`，`app.ts` / 模拟器）：加上 `news` 时机和 `cat_photo` 这一类。`app.ts` 的 `news` 现在按叠加后的设置取事件类。
3. **提示词**（`occasionNote` 的 `cat_photo`）：「你刚下楼喂了土豆，还拍了它一张照片，想发给他看：先用一句话带一下（喂它这件事看「你那边」土豆那一行，没写的细节不编），然后另起一行单独发照片；不要他回应，别问他想不想看」。
4. **照片怎么进回复**：`InitiateRequest.photo = 'cat'` → 回复器 → `contact.ts` 的 `photoNow`（主动那条的意图在 `initiate.note` 里，不再加“他想看”的意图行）→ 货架提示词 + 清理允许一行 `<photo:编号>`；照片轮不套形状 / 长短提示（ADR 0109）。
5. **发之前再查一次**（`blockReason`，`photoReady`）：货架里没有土豆的照片、3 小时内发过、今天发够了，就不发这一条（免得说了“拍了张照片”却发不出来）；那之后聊过也不发（ADR 0057 调整的老规矩）。
6. **不带进别的主动里**：“没说成的事”（`untoldNews`）不包含 `cat_photo`——早安 / 睡前里说一句“今天给土豆拍了张照片”却没有照片会穿帮。

## 没做 / 要注意

- 一周约两三次，不是天天；每天主动上限（`dailyMax`）和“上一条主动他没回就停”的闸照旧管着它（它不是“日子”）。
- 照片是货架里的猫（ADR 0109：同一系列的同一只），不是“当天拍的”；提示词要求别说“现在拍”。
- 货架空着或没连上网，这一类就不会发（`photoReady` 为假）。

## 验证

- `photo-shares.test.ts`（6 个）：200 天里约 35% 有、时间 8–25 分钟、同一天每次一样；没见到 / 没喂 / 还没去 / 不去 / 没有猫 / 没开这一类都没有；`withCatPhoto` 不动原来的；说明和到点再查；不带进睡前；计划器发这一条时 `initiate.photo = 'cat'`。
- 模拟（真模型，`sim/photo-share.json`，4 次，世界账里 10-26 傍晚有这件事）：「刚下楼喂土豆，它今天挺给面子，没躲我」＋单独一条 `<photo:…>`；他问“是你拍的吗”她答“我拍的 / 刚下楼喂它随手拍的”，不再发第二张。
