# ADR 0173：她没回他的时候，总要让他知道原因（silenceNotice）

- 状态：**已实现，默认关；本机要在 `koishi.yml` 里设 `silenceNotice: true` 并重启才生效**
- 日期：2026-10-29
- 关联：[ADR 0007](0007-schedule-and-reply-timing.md)（作息与回复时机）、[ADR 0013](0013-old-project-advice.md)（决策 4：看心情不回）、[ADR 0157](0157-identity-ledger.md)（运维提示通道：以「（」开头、不进聊天记录）、[ADR 0165](0165-net-alert-helpers.md)（整个机器人掉线时的断网通知）
- **用户决定（2026-10-29，当前会话）**：在被问「要让她有真正的自主，包括有时选择不回你，你接受吗」时答：「**接受，但是连续发消息不回时总该让我知道原因**」。

## 背景

真人的自主里包括「有时不回」。但被晾着的人想知道的是：是忙、是睡了、是不想回，还是**坏了**。对他来说，「是她自己的决定」和「是故障」是完全两回事：前者是她的自主、该尊重，后者要他去修。

现在她不回的理由还不多（作息、冷场、收尾后的附和、看心情不回、模型连不上）；往后「有后果的自主」会让理由越来越多（自己的事、没消的气、答应了别人……）。所以先把**每一次没回都有一个记在账上的原因、并且说清是谁的决定**做成通用的，之后任何新的「不回」理由只要说出自己的原因就能接进来。

响应器本来就知道原因（`ResponderStatus` 里有等待原因 / 跳过原因 / 失败原因），只是只给控制台状态页、只留最近一次、不告诉他。

## 决策

1. **归成三种「谁的决定」**（`social/silence.ts`）：
   - **作息**（`schedule`）：睡觉、上课、在忙、冷场慢一点——「这是作息，不是故障」，带上几点看到；
   - **她自己**（`her`）：她已经收尾、他后面只是附和；看心情没回；以后新增的「不想回」——明说「这是她自己的决定，不是故障」，并告诉他怎么办（隔一分钟再发一条一定回 / 换个新话题）；
   - **系统**（`system`）：回复失败（连不上模型 / 网络）、休眠、工作模式、正在生成——故障要明说「这是故障，不是她不想回」，还会不会重试、几点再试。
2. **查不到原因就老实说查不到**：她没在等、也没在生成、没有失败记录时，说「我这边查不到她没回的明确原因……已经过了十分钟还没动静，很可能掉线了」，**不编一个原因**。
3. **逐条记账**：响应器加一个可选回调 `onSilence`，在四处调用——等到点才看到、看到了决定不回、失败重试、失败放弃（放弃时实际失败了 重试数 + 1 次）。只是旁观，不影响回复。记在 `<数据目录>/silence/<QQ>.jsonl`（同类同原因一分钟内不重复；超过 60 KB 且 300 行只留最近 300 行）。
4. **什么时候主动告诉他**（每分钟看一次，只看男朋友档那位）：他在她最近一次回复之后**连着发了 ≥ 2 条**、**第一条过了 ≥ 8 分钟**还没回，就用「（」开头的运维提示说一次。**一串同一种原因只说一次；原因变了才再说（比如从「在忙」变成「连不上模型」），一串最多 3 次**；新的一串重新算。「说过了」记在 `<数据目录>/silence-notices.json`，重启不重复。这条提示**不冒充她说话、不进她的聊天记录**（和 `/设定`、`/休眠` 的提示同一通道）。
5. **随时问**：他发 `/为什么`（纯文字、只认男朋友档）：有没回的就说现在的原因（不看条数和时间门槛）；没有就说「都回过了」，有记录的话带上上一次没马上回是什么时候、为什么。这条命令和别的斜杠命令一样「命中的算处理完」，**不进聊天记录、不交给她**——否则它自己会被算成一条没回的消息。开关关着时 `/为什么` 就是一句普通的话。

## 没做

- **她自己的口气里的「我先不回了」**：真人决定不理人时有时会先说一句。现在只有运维提示（不冒充她）。等「有后果的自主」把真正的「选择不回」做出来，再让她在**决定那一刻**用自己的话说一句；这条不在这版里。
- 给别的联系人发提示：他们不是运维，只有男朋友档那位。
- **整个机器人掉线时**（NapCat 断了、VM 停了）发不出提示：那是断网通知（ADR 0165）管的事。
- 阈值（2 条 / 8 分钟 / 3 次）是常量，没做成配置；用了一阵觉得吵或太迟再改。

## 验证

- `silence.test.ts` 18 项：原因归类（含用 `moodySkip` 真正产生的那句话防文案漂移）、谁的决定、连着没回的判定、通知时机（8 分钟、同一串同一原因一次、原因变了再说、最多 3 次、新的一串重算）、每种说明的措辞（作息 / 她的决定 / 故障 / 查不到 / 休眠 / 工作）、由响应器状态定当前原因的优先级、记账（去重、坏行、修剪）、watcher（重启不重复）、`/为什么`。
- `runtime.test.ts` 4 项：响应器回调——失败重试 / 放弃（次数 1、2、3，`retryAt` 精确）、等到点才看到、看到了不回（且真的没回）、不传回调时照旧。
- `app.test.ts` 1 项：开关关着时 `/为什么` 当普通话交给她；开着时是命令、不交给她、不进聊天记录；同学档发同样的字不是命令；启动日志写明「开」。变异检验：把命令处理关掉，这条变红。
- `tsc`（bot + 插件）干净。

## 怎么开 / 回滚

`koishi.yml` 里 `silenceNotice: true`，重启。回滚：删掉这一行（或设 `false`）重启；账和状态文件留着不影响。
