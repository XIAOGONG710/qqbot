# ADR 0091：形状控制——按他说的长短定她每条最多几个字；加上一把「像不像真人」的尺子

- 状态：**已实现，未合并、未上线、未开启**（分支 `claude/bilibili-account`；配置 `shape`，默认 `false`）
- 日期：2026-10-21
- 关联：[ADR 0024](0024-expression.md)（表达层：长短不一、`shortReplies`）、[ADR 0041](0041-candidates.md)（挑候选）、`exchange/research/2026-10-real-chat/findings.md`（真人聊天的形状基准）
- 用户提出：2026-10-21「现在的 ai 味还是比较浓，我已经不知道该如何降低了，感觉盲评测试也没什么作用，还有什么其他的方式吗？」；我给了方案后：「做，先做 1 和 2」（1 = 硬控长度和形状，2 = 做一把「像不像真人」的检测器）。

## 背景：用数字看，问题在哪

2026-10-20 / 21 用 `exchange/tools/chat-audit.mjs` 重算她的聊天记录（只出数字）：每个气泡中位 16 字，几乎全在 13–19 字之间，1–4 字的占 0%（真人：中位 6–7 字，1–4 字约三分之一，长短不齐的重尾）；他发 7 个字，她回 15 个；句末标点 96% 没有。盲评帮不上忙：要用户给孤立的一句话打 1–5 分，噪声大于信号，也只能比「开不开某个开关」，说不出“该改什么”。

**为什么 `shortReplies` 一直压不下来**（这次找到的）：它只是提示词里一句“回短一点”的软话，而且被两处挡掉了：①「认真接话」名单 `ENGAGED_INTENT` 把最常见的意图行“回应他刚说的那件事”也算进去，10-21 模拟里 104 轮有 72% 落在名单里，不加短话；②`lengthHint` 用“意图行里有没有‘收尾’两个字”判断收尾，而亲近那条意图行里写着“他真要收尾时回应后顺着收尾”，亲近的轮次整轮被当成收尾——35 轮一轮形状也没有。

## 做了什么

**`shape.ts`（形状控制，配置 `shape`）**：每一轮按他这一轮说了多长，定她每条最多几个字、最多几条，写进提示词（具体数字，不举例句），出口再强制执行。
- 字数档 5 个：极短 ≤4、短 ≤8、中 ≤14、长 ≤24、宽 ≤40。基线权重 ≈ 真人每条的分布（≤4 字约四分之一、≤8 字过半、≤14 字约八成）；按他这一轮的字数挪：他只发 ≤3 个字多半极短 / 短，他发一大段放宽。一轮几条：真人 1 条 51–65%、2 条 22–28%、3 条以上约 15–20%；极短的一档多半一条。
- 不一刀切：他在难受、报好事、等她解释（`SUBSTANTIVE_INTENT`）、被打回（`WORRIED_TEXT`）、问起她认识的人时只用后三档（不会只回两个字）；亲近 / 撒娇只用短、中、长（真人这时也是“抱抱”“想你”，但不回“嗯”）；收尾（只认“顺着他的话收尾”）用最短两档为主、最多两条；心情安静 / 身体不舒服往短里挪；他明着让她讲、主动找他、危机回合不用（走原来的 `lengthHint` / 危机流程）。
- 强制执行（出口检查之后）：有一条超过上限（给 35% 的余地，8 字的上限放到 11 字）或条数超了 → 带说明（只说数字，不带上一版的原话）重写一次；还超就**只在分句处**截断、去掉多出的条数，找不到分句处就原样留着（不拦腰截断一个词）。图片表情的指令行不占条数名额。
- 抽签的种子是“他最后一条的时间 + 内容”（同一句话每次一样，和 `lengthHint` 同一个办法）。

**`humanness.ts` + `ops/humanness-cli.ts`（尺子）**：只看写法（长短、标点、语气词、连接词、逗号和分句、收尾），不看内容词；逻辑回归，没有依赖。真人样本 = 聊天记录里他自己发的话（同一个场景里最真的真人）+ `exchange/research/2026-10-real-chat` 里 43 段的 602 个气泡；“她” = assistant 的话。输出 5 折交叉验证的 AUC、去掉字数特征后的 AUC、**字数配平**后的 AUC、最露馅的特征、她的话被判成真人的比例。`--save` 存模型（只有权重），`--model … --score <聊天 jsonl>` 用同一把尺子给别的聊天记录里她的话打分（模拟器的输出在 `runtime/sim/…/chats/*.jsonl`，格式相同），改前改后才能比。

**模拟器**：`npm run sim -w @qqbot/bot -- … --shape` 对所有场景打开形状控制；场景文件里可以写 `"shape": true`。

## 量出来的

尺子（她 434 个气泡 vs 真人 1150 个，2026-10-06 起）：区分得开，AUC 0.84；去掉字数特征 0.83；**字数配平后 0.73**。最露馅的写法：一个气泡里带逗号 / 多个分句（她平均每条 1.0 个逗号、2.1 个分句，真人 0.3、1.3）、句末几乎不带任何标点（98% vs 80%）、从来不用“～”“…”“哈哈”。她的话被判成真人的只有 21%（真人自己的 79%）。

真模型 A/B（7 个男朋友档的对话场景 × 5 次，不带记忆，`shortReplies` 开着，和线上一样；每组约 190 轮）：

| 项 | 基线（线上现在的样子） | 形状控制 |
| --- | --- | --- |
| 每条中位 / p25 / p75 / p90 字数 | 11 / 8 / 16 / 24 | **8 / 5 / 13 / 20** |
| ≤4 字的占比 | 8% | **23%** |
| ≥15 字的占比 | 31% | **17%** |
| 一轮只回 1 条 | 56% | **68%** |
| 尺子打的“像真人”的比例（P>0.5） | 29% | **41%**（平均 0.38 → 0.45） |

遵守程度：模型对数字上限基本照做（极短档每条平均 3.3 字，每个档平均都在上限内的占 97–100%），超了的靠重写 / 截断兜住。没有形状的轮次只剩他明着让她“讲讲”的（该长）。**第一版只有 28% 的轮次落在极短 / 短两档（该有一半多），就是上面两处挡掉造成的**——这次的对比里这两处已经改了。

读了一批她的话：从“山楂树什么山楂树，我就是想赶紧写完”“晚安，明天汇报别紧张，加油”变成“哪山楂了”“可算到了”“去几天啊”“那就歇着”“行啊”，更像随手打的。也有一两条显得生硬（“他：嗯 → 她：懂了吧？”），这类要看真聊天里的比例。

## 10-21 用户改写校准（内容层）

用户 10-21 对 10 条“他真实说的话 → 她现在的回复”改写了 5 条：
「在干嘛？」→「研究相机呢，怎么啦？」；「5 个小时到学校那边」→「zdjd，这么快」；「别吃成芝麻酥那样，小心压穿地球」→「芝麻酥不肥！恶语伤酥心～」；「什么，竟然不理我，我真要哭了」→「不哭不哭」；「爱你」→「我也爱你，mua，抱抱」。其余 5 条（嗨啥呀、惨、这就幸福了？、嗯什么呀困了？、破财消灾嘛）留着没改。
共同点：她的版本冲、绕、爱追问，用户的版本暖、接得住、玩得起来、对事实先有反应、用他自己的缩写。落实成五处（`intent.ts`、`shape.ts`）：
- **爱你 / 喜欢你 / 想你**（不是“想不想我 / 爱不爱我”这类能逗一逗的）→ 直接温柔回应（我也爱你、mua、抱抱，叠词也行），不吐槽肉麻、不反问、不损他；抱抱 / 亲亲 / 问句式的才保留一点嘴硬（ADR 0058 其余不变）。
- **句首感叹不当提问**：「什么，竟然不理我，我真要哭了」里的“什么”被当成疑问，先哄（care 意图）被“先直接回答他刚问的”顶掉，她回「哭什么」。现在先剥掉句首的“什么，/ 怎么，/ 我去，”再判断；care 意图加“撒娇式的呜呜、要哭了就直接哄（叠词哄），别反问他哭什么”。
- **他逗她**（胖、吃成、压穿、小猪、笨蛋……，男朋友档，他说自己的不算）→ 新意图“陪他玩：装委屈、撒娇式不服、护着自己的东西，别板着脸顶回去”。
- **他说自己的事** → “先对这件事本身有个反应，别急着追问细节，真要问也只问一两个字”（原来是“真有想知道的细节再随口问”）。
- **顺着说**的提示里加“他用了网络缩写（zdjd、xswl 这类）你也可以顺着用”。

验证：①用户那 10 句重放 4 次，爱你 → 「我也爱你，抱抱」「我也爱你 mua」「我也爱你，超爱」；要哭了 → 「来了来了，不哭不哭」「抱抱抱抱」；5 个小时 → 「真的假的，你别吓我」；压穿地球 → 「芝麻酥多可爱，我就吃」「你才芝麻酥，我这叫匀称」（还有点顶嘴）。②用户真实发的 180 句重放：追问 / 反问 9% → 6%（真人 11%）、应一声 11% → 19%（真人 13%）、带笑 2% → 4%（真人 3%）、驳回开头 8% → 9%（真人 3%，没动）；长短不变。③盲评鉴别员 72 对 63%（此前 54–59%）——那批样本里几乎没有这几类场景，噪声也大，看不出这次改动，不当依据。

## 局限（别当成“她已经像人了”）

- 尺子只看**写法**。字数配平后 AUC 还有 0.73 说明字数之外还有差别（逗号、标点、没有“～”“…”）；但**语义层面的 AI 味**（太会安慰、什么都接、没有自己的议程、不会敷衍）它读不出来——这要靠用户举例 / 改写。
- 模拟器不等于线上：场景里他的话比真实的长（真实中位 7 个字、模拟约 9–10），线上的“极短 / 短”两档会更多；模拟里一轮 2 条的比线上多（线上最近一周 96% 是 1 条）。真实效果要上线后用同一个脚本重算（`chat-audit.mjs` 和 `humanness-cli.ts --score`）。
- 样本不大：每组 190 轮、她的真实基线 434 个气泡，当方向，不是结论。

## 上线 / 回滚

`koishi.yml` 里 `shape: true`，重启一次 Koishi（要用户一句话）。回滚：改回 `false` 重启，或回滚到上一个提交；`shape: false` 时 `lengthHint` / `shortReplies` 的老路径一点没动。`lengthHint` 里“有没有‘收尾’两个字”的毛病**没有顺手改**（它影响现在线上的短话抽签，是单独的一个行为变化）；开了 `shape` 之后适用的轮次不再走它。

## 没做

用尺子挑候选（同一句话生成几条、挑 P(真人) 最高的）；按尺子反过来调字数档的权重；给用户一份“改写 10 句”的包（改写比打分信息多）；微调模型。
