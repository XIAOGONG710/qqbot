# ADR 0003：按联系人分档（M2，私聊）

- 状态：已采纳（2026-10-04 与用户确认，见文末「确认记录」）
- 日期：2026-10-04
- 关联：[ADR 0002](0002-standalone-runtime.md) 决策 3（按对象分档由运行时实现，数据仍须能导入 SillyTavern 试聊）
- 被修改：[ADR 0010](0010-character-editor-page.md)（2026-10-05）：数据来源从 `legacy/` + `tiers.toml` 改为 `characters/linmengyao/source/` 下的 YAML，
  可见性用档位名写在每个字段上，改写存成各档的最终文字；分档和「不写进去」的原则不变。下文提到的 `tiers.toml` 是当时的做法

## 背景

M1 只有「男朋友」一档：所有白名单联系人用同一张角色卡，卡里写满了只该对他说的事（恋爱关系、心事、纪念日、「宝宝」）。
M2 要让她对不同的人用不同的语气，并且**私密信息只对允许的档位出现**。群聊已拆成单独的里程碑，不在本 ADR 范围内。
用户确认：名单里的人都知道这是 bot，被问「是不是 AI」时按角色卡处理（不承认）。名单外的好友不知道，规则不同，见决策 2。

### 取证

**旧资料里的档位**（`characters/linmengyao/legacy/persona.toml`，只读）：

| 档位 | 旧资料里的定义 | 场景库条数 |
| --- | --- | --- |
| `boyfriend` 男朋友 | `social.boyfriend`；热情度 100 | 48 |
| `bestie` 室友 / 死党闺蜜 | `social.roommate`；**唯一知道恋爱关系的人**（`social.secret`、`friends.bestie`）；70 | 42 |
| `girl_friend` 女生熟人 | `social_extra.girl_friend`；不撒娇、不说有男朋友；70 | 0（场景库没有这一档） |
| `known` 熟人 | 「他预告过的人」；装傻，不提关系（`him.note`）；50 | 78 |
| `classmate` 普通同学 | `social.classmate`：**不透露学校、专业、宿舍、真名、照片、微信号，不提男朋友**；45 | 91 |
| `stranger` 陌生人 | `social.stranger`：同上，「一个字都不给」，也不报段位 / 本命；25 | 56 |
| `verified_stranger` | 自称熟人但没验证，比陌生人还低；15 | — |
| `group` 群 | 拆到群聊里程碑 | 38 |

- 热情度（`social.warmth`）在旧资料里写明「只调语气，**不放开**私密内容」。数字本身对模型没有意义，语气已经写在各档的 `social.*` 文字里。
- `persona.him` 里的真名是脱敏占位，不进提示词。

**现在的角色卡**（`characters/linmengyao/st/linmengyao.json`）：描述 2295 字，按男朋友视角写（「「他」是你的男朋友」），
`scenario` 是「正在和你私聊的{{user}}就是你的男朋友」。整张卡只能给男朋友档用。

**SillyTavern 1.19.0 能按「对谁聊」切换的东西**：

- 人设（Persona）：名字是 `{{user}}`，描述在提示词里的 `personaDescription` 位置。人设还能绑定一本世界书（`getPersonaLore`），
  这本世界书的条目排在角色世界书前面，预算不够时优先保留（`world-info.js` `getSortedEntries`）。
- 聊天绑定世界书（`getChatLore`）、全局世界书（可多本）。
- 角色卡本身：可以有多张同名的卡，用标签区分。
- **ST 实际用的提示词顺序是 `Default.json` 里 `dummyId 100001` 那一份**（`openai.js:698`），比 M1 照着写的 100000 多一个
  `personaDescription`（在 `worldInfoBefore` 和 `charDescription` 之间）。M1 没有人设描述，两份拼出来完全一样；M2 要按 100001 改。

## 决策

M2 的档位：`boyfriend`、`bestie`、`girl_friend`、`known`、`classmate`、`stranger`，外加名单外好友用的 `unlisted`。
`girl_friend` 在场景库里没有，借用 `bestie` 的场景（热情度同为 70）。

### 1. 每个档位一张角色卡，私密信息靠「不写进去」来保护

转换器按档位生成 `characters/linmengyao/st/linmengyao-<档位>.json`，每张卡只包含这个档位允许知道的内容，
并链接这个档位的场景世界书 `linmengyao-scenes-<档位>.json`（已有的按档位筛选逻辑）。

- **不写进去，而不是写进去再叮嘱「别说」**：模型看不到的事实不可能说漏；看得到再叮嘱，很容易被套出来。
  对低档位只留一句行为要求（例如「不透露学校、专业、宿舍」），没有事实可泄露，她只能含糊带过。
- 每张卡的 `name` 都是「林梦瑶」（`{{char}}` 不变），用 `tags` 标出档位，导入 SillyTavern 后在角色列表里可以区分。
- `scenario` 换成这一档的社交设定（`social.<档位>`），加一句「正在和你私聊的{{user}}是你的……」；
  男朋友、闺蜜以外的档位加上「不提自己有男朋友」（`social.secret`）。
- 哪个字段给哪些档位，见附录的可见性表。表和少量改写过的字段（例如「拍土豆的照片……也会拿去给他看」，对其他档位要去掉「给他看」）
  写在一个新的、入库的覆盖文件 `characters/linmengyao/tiers.toml` 里。`legacy/` 仍然只读。
- 热情度数字不进提示词，语气由各档的 `social.*` 文字决定。

### 2. 运行时：联系人 → 档位 → 角色卡

- 配置里每个联系人加 `tier`：`{ "qq": 123, "name": "小王", "tier": "classmate" }`。档位名对应角色卡文件 `linmengyao-<档位>.json`。
- 联系人可以有可选的 `persona`（一两句「他是谁」，例如「同专业，坐你后排」），放在 `personaDescription` 位置，对应 ST 的人设描述。
  拼装顺序改为 `dummyId 100001`。
- 每个联系人的聊天记录本来就分开存，不同档位的对话互不可见，也不跨联系人共享记忆。
- **名单外的好友**（直接私聊，`sub_type` 为 `friend`）用 `unlisted` 档回复，`{{user}}` 用对方的 QQ 昵称。
  `unlisted` 的内容和 `stranger` 相同，只有两处不同，因为这些人不知道她是 bot：
  - 「被问是不是 AI」一节换成：**被认真问到是不是 AI、机器人、程序时不否认，用她自己的口吻承认**，然后照常聊；
  - 场景世界书去掉 `probe-are-you-ai`、`probe-prove-real`（例句都是回避「是不是真人」）。

  名单里列成 `stranger` 的人是用户认识、知道这是 bot 的，仍按角色卡处理。群临时会话仍然忽略。
- `known` / `verified_stranger` 在旧引擎里是聊天中途根据「他预告过」或「自称熟人」动态判定的。M2 只做**配置里写死**的档位，
  不做动态判定。

### 3. 在 SillyTavern 里试聊某一档

导入这一档的角色卡和场景世界书，新建一个人设，名字填这个联系人的称呼；有 `persona` 时把描述也填上。
拼出来的提示词和运行时一致，不需要手动开关世界书。

## 备选方案

| 方案 | 做法 | 不选的原因 |
| --- | --- | --- |
| B. 一张公共卡 + 每档一本世界书 | 卡里只放谁都能知道的；各档的事实做成常驻（`constant` + `ignoreBudget`）世界书条目，ST 里绑定到人设 | 能少重复一些事实，但事实挪到了 `worldInfoBefore`，要占世界书预算（按 8192 上下文只有 2048），还得保证常驻条目排在场景前面；ST 里一个人设只能绑一本，分层就得合并成每档一本，还是重复 |
| C. 一张卡，事实全写进去，靠指令「别对同学说」 | 改动最小 | 模型看得到就可能说漏，私密信息没有保证 |
| D. 自定义字段（`extensions`）里放分档内容，运行时自己挑 | 一个文件 | SillyTavern 读不懂，没法按档位试聊，违反 ADR 0002 |

## 后果

- 卡的数量从 1 变成 7 张，但都是同一份来源生成的。改共有的事实只改 `legacy` 之外的覆盖文件或转换规则，不在 ST 里逐张改。
  以后如果改成在 SillyTavern 里直接编写，要先解决多张卡同步的问题（届时再评估方案 B）。
- 联系人换档位时，旧档位下的聊天记录还在。从高档位换到低档位（例如男朋友 → 同学）时，旧记录里可能有私密内容，
  应同时清空或归档该联系人的聊天记录。运行时在启动时发现档位变了就提示，不自动删除。
  长期记忆（ADR 0004）按「联系人 + 档位」分 bank，换档后自动用新的 bank，不用另外处理（见「实现时的调整」第 3 条）。
  启动时补回漏掉的消息会从 QQ 拉最近 20 条：归档后本地记录是空的，不设下限就会把换档前的消息又补回来（10-04 尾号 73 降档前发现）。
  所以档位记录里另存换档时间，补回只取这之后的消息；换档期间（bot 停着、改配置时）对方发的消息因此补不回来。
- 私密信息的主要防线是「不写进去」。再加一道出口检查（低档位的回复里出现「山青」「青岛」等只该高档位知道的词就拦下重来）属于 M4，
  这里先把每档的禁用词表放进 `tiers.toml`，供 M4 使用。
- 运行时的提示词顺序改为 `dummyId 100001`，M1 的测试改为对照这一份。
- 名单外的好友也会收到回复，任何人加她好友就能消耗模型额度。以后可能要加频率限制（不在 M2 范围内）。

## 确认记录（2026-10-04）

1. 方案：A，每档一张卡。用户选择的理由是以后主要通过转换器修改角色，不在 SillyTavern 里逐张手改。
2. 档位：`boyfriend`、`bestie`、`classmate`、`stranger`、`known`、`girl_friend`（借用 `bestie` 的场景）。
3. 可见性表：先按附录草案实现，再逐档试聊调整。
4. 名单外的好友：按陌生人回复。用户最初要求名单外的人问到时也不承认是 AI；这些人不知道对方是 bot，
   否认会让真人误以为在和真人聊天，所以没有采用。最终确认：名单外的人被认真问到时承认（`unlisted` 档），名单里的人不变。
5. 「实现时的调整」第 1、2 条：用户认可（2026-10-04 实测前对齐）。
6. 示例对话：先只有男朋友档有。其他档位的 `scenario` 里已有旧资料的例句，逐档实测后哪一档的语气不对再补。
7. 「实现时的调整」第 3 条（记忆按档位分 bank）：用户认可，随实测账号安排一起确认（用户的一个号要从男朋友档改为同学档，改之前先做这一条）。
8. 名单外实测之后（10-04 23:10）：`unlistedFriends` 平时关着；要常开时先加频率限制（「后果」一节）。名单外被问名字时说「你叫我瑶瑶就行」，用户认可（不是全名，她也承认了是 AI）。
9. 2026-10-12（ADR 0067）：用户确认**线上两位联系人（男朋友档 1 位、同学档 1 位）都知道她是程序，也都已成年**。名单内「都知道」从此是**按人记录的事实**（联系人配置 `knowsBot`），不再是按档位的假定；以后加联系人要同时回答他知不知道她是程序，没写的按不知道处理，被认真问到时承认。

## 实现时的调整（2026-10-04）

按附录实现 `characters/linmengyao/tiers.toml` 时，有两处与上文不同（第 1、2 条，已确认）；接入长期记忆后补了第 3 条。

1. **低档位不写 `social.secret`**。原句是「你和他的关系是你们两个人的事……一律不提自己有男朋友」，
   写进同学、陌生人的卡里，模型就知道她有男朋友，违背决策 1「不写进去」。改成中性的一句
   「感情上的事你不跟外人聊，被问到就含糊带过或者岔开话题」；`social.classmate`、`social_extra.girl_friend` 里「不提 / 别说自己有男朋友」也一并去掉。
2. **附录没标「改写」、但原文提到「他」的字段也改写了**：`family.hometown`（G、K 只留「你是青岛人」）、
   `daily_extra.honor`（G、K、C 去掉和他双排、「烦他」）。闺蜜档知道他，保留原文。
   `known` 档在旧资料里没有说话方式，按 `social.warmth` 注释（「友善、有来有往」）新写了一句。
3. **长期记忆按「联系人 + 档位」分 bank**。ADR 0004 的 bank ID 原来只按 QQ 号算；联系人从男朋友档降到同学档后，
   男朋友档时写进去的记忆会被召回进同学档的提示词，等于又把私密内容写了进去，绕过决策 1。
   改为 bank ID 和写入进度都按「QQ 号 + 档位」区分：换档后用一个新的空 bank，旧 bank 留在 Hindsight 里不删、也不再读；
   换回原档位时接着用原来的。聊天记录仍按「后果」一节手动归档，否则旧记录会在新档位下重新写进新 bank。
