# ADR 0253：DSH 跨端短上下文事务提交

- 日期：2026-11-04
- 状态：已实施
- 相关：ADR 0248、0249、0252

## 问题

手机、QQ 和显式 DSH 咨询共享 `memory/dsh-recent.json`。此前提交成功问答时先修改进程内上下文，再写入磁盘；若磁盘已满、文件被占用或原子替换失败，用户会收到失败提示，但下一轮仍可能看到这次没有完成持久化的“幽灵问答”。离线状态检查也只确认该文件是合法 JSON，不能提前发现运行时会隔离的错误角色、超长内容或非法时间。

## 决策

1. 提交前统一清理问题和回答：去除首尾空白、拒绝空文本，并把单条内容限制在 4000 字符以内。
2. 拒绝非有限或负数时间，保证本轮写出的数据一定能被下次启动重新读取。
3. 先以原子写入保存完整的新快照，成功后再替换进程内数组；写盘失败时内存和旧文件都保持在上一份已确认状态。
4. `state-check` 对 `dsh-recent.json` 调用与运行时相同的读取器和 schema，而不是只做 JSON 语法检查。检查仍在数据目录副本上运行，不移动或修改线上原文件。

## 验收

- 模拟 `ENOSPC` 原子替换失败，确认当前进程和重新加载都只包含上一份成功问答。
- 覆盖空文本、负时间和超长内容边界。
- 向状态检查提供语法正确但角色非法的文件，确认报告“会被隔离”且原目录不动。
- 运行类型检查、DSH/状态定向测试、全量测试、发布检查和 `git diff --check`。

## 回滚

回滚本次提交即可恢复旧顺序；状态 schema 和协议版本未改变，不需要迁移数据。
