# ADR 0083：她在 QQ 上「有个人在」——已读、在线状态、表情回应、点赞、签名、说说

- 日期：2026-10-19
- 关联：[ADR 0075](0075-reply-rhythm.md)（她什么时候「看到」）、[ADR 0013](0013-old-project-advice.md)（看心情不回）、[ADR 0079](0079-poke.md)、[ADR 0077](0077-typing-status.md)（同样的 NapCat 扩展动作）、[ADR 0055](0055-deepseek-vision.md)（看图）
- 用户授权：2026-10-19 10:50「在线状态，表情回应，资料卡点赞，个性签名，QQ空间说说啥的都可以加上」；11:20 补充「QQ 现在有一个新功能叫空友爱看，可以模仿那里的进行发送说说」。做和测；**上线（开开关、重启）仍要用户在场点头，每个开关单独、满 48 小时。**

## 背景

翻 NapCat 的动作清单（约 200 个，群管理、文件、相册那些她用不上）时发现，除了「收消息、发消息」，还有几样**对方在自己 QQ 上看得见**的、真人账号天然会有的东西，而她现在全都是「机器人默认值」：

- 他发的消息下面显示「已读 / 未读」，NapCat 收到消息**不会自动标已读**（源码里只有显式调用 `setMsgRead`），所以她回了话、那条也可能一直显示「未读」；
- 联系人列表里她 24 小时「在线」，凌晨四点也是；
- 资料卡的签名永远不变、空间里一条说说都没有、从不给他点赞；
- 她「看心情不回」的时候，什么也看不出来（真人至少会点个表情）。

## 决策（六件事，各一个开关）

| 开关 | 做什么 | NapCat 动作 |
| --- | --- | --- |
| `readReceipts` | 她「看到」他的消息的那一刻（`untilSeen` 返回的时刻，睡着 / 上课时是起床 / 下课后）标已读；「看心情不回」就成了真的「已读不回」 | `mark_private_msg_as_read` |
| `reactions` | 她看到了却不回（看心情不回、她已经道了晚安他只回「嗯嗯」）时，给他最后一条点个表情回应：笑的点笑哭，亲密的点爱心，其余赞 / 爱心；戳一戳那种合成消息不点 | `set_msg_emoji_like` |
| `onlineStatus` | 睡着或说过「睡了」→ 离开；上课 → 忙碌；空闲活动里有「听歌」→ 听歌中；其余在线。状态变了至少隔 10 分钟才改；**下课后一小时内「忙碌」不改回在线**（睡下的「离开」不受限） | `set_online_status`（码取自 NapCat 文档：10 在线 / 30 离开 / 50 忙碌 / ext 1028 听歌中） |
| `profileLikes` | 约 80% 的日子，12:00–21:30 里某个时刻给男朋友档的人点 1–5 个赞；睡着、上课时不点 | `send_like` |
| `signature` = off / dryRun / on | 隔 3–5 天换一条；节日当天是祝福（平安夜快乐…），下雨天有雨天的，不和上一条重复。`dryRun` 只写草稿 | `set_self_longnick` |
| `qzone` = off / dryRun / on，`qzoneVisibility` = friends / public | 一周两三条说说，见下 | `send_qzone_msg`（`ugc_right`：4 好友可见 / 1 所有人） |

所有时刻、概率都按日期哈希定（同一天每次一样，重启不重来）；已经做过的记在 `<数据目录>/presence/presence.json`；失败的动作同一件事只记第一次日志，成功了再记一次。一个开关都没开就不起这个循环；没有作息（`herDays` 关或卡上没有）不起。

### 说说（模仿「空友爱看」）

「空友爱看」是 QQ 空间新加的推荐池：把陌生人的优质说说混进好友动态流（搜到的报道：以风景美图、自拍、生活碎片、梗图为主，用户主动投稿或被平台邀请收录，不显示好友）。所以说说往这个风格靠：**图文为主、配文一两句、随手发、不讲道理、不写长文**；话题是天空 / 天气、食堂和饭、猫、学习的小抱怨、发呆、小确幸。

- **图**：只用你放进 `<数据目录>/presence/photos/` 的图（jpg / png / gif / webp），一张只用一次。有图就让看图模型先描述（要开「看懂图片内容」），再围着描述写一句；**看不成图就写成纯文字、不把图发出去**。不用别人的图冒充她拍的，不生成「她的自拍」。
- **谁来写**：最低隐私档（陌生人档，读不了就同学档）的角色卡——名字、资料、性格、**这一档的禁用词**——写说说，所以男朋友档才知道的事（买相机、他、纪念日…）不会写进谁都可能看到的地方；「现在在干什么」也用这一档自己的作息，不用男朋友档的。试过一次：用男朋友档的作息时，模型满篇「新相机」，被陌生人档的禁用词 8 次全拦下；换成这一档自己的作息就没再写到。
- **检查**（`cleanQzoneText`）：不超过 60 字；没有网址、@、六位以上的数字（电话、QQ 号）、方括号；不带这一档的禁用词；没有助手腔；不和最近发的重复。三次都不合格这天就不发了。
- **频率**：约 36% 的日子发（一周两三条），工作日晚上 17:30–22:30、周末 11:00–22:30，距上一条至少 20 小时、一周最多 3 条，睡着、上课时不发。
- **可见范围**：`qzoneVisibility` 默认 `friends`（仅好友）。改成 `public` 会让陌生人看到，也可能被「空友爱看」收录并收到好友申请——**这是你的决定，我默认不开**。
- **先看草稿**：`dryRun` 照常生成，但只存在 `presence/drafts.md` 里（连配图是哪张），不真发；签名同理。

## 验证

- 规则与循环：`presence.test.ts` 12 项（状态映射；点赞概率 / 时间 / 次数；签名节日 / 雨天 / 不重复 / 3–5 天；表情；说说概率 / 时间；文字检查；选图；循环：状态只在变了才改、点赞一天一次到点才点、签名试运行不改 / 开着隔 3 天 / 失败只记一次、说说试运行不发不用图 / 开着带图好友可见 / 所有人可见 / 写不出就这天不发）；`qzone.test.ts` 4 项（说明里的「不要」、没图 / 有图 / 看图失败 / 没开看图、不合格重写、模型出错）。
- 接进应用：`app.test.ts` 3 项（开着 `readReceipts` 她看到的那一刻标已读、关着不标；她已道晚安他只回「嗯嗯」→ 不回但已读 + 点表情、关着 `reactions` 只已读；`onlineStatus` 第一次连上按此刻状态设、没开关 / 没作息不起）；插件配置 1 项（旧配置全是关、开了照样传、写错的模式报错）。
- 真模型（陌生人档，6 个时刻）：「楼下那只三花又蹲在老地方了，估计比我上课还准时」「明天早八，现在还在躺平听歌，算了，随便吧」「跟室友扯到现在，饭都凉了还没决定要不要下楼」「太阳晒进被子了，歌单循环到第三遍，还是不想起。」——短、口语、不提他、不提相机。
- 顺手发现并修了 ADR 0077 的接线漏洞（`typing` 在 contact.ts 被悄悄丢掉，开了也不会触发），见 0077 的补充。

## 没做 / 要注意

- **全都没在真 QQ 上试过。** 动作名和参数是照 NapCat 源码写的；`set_msg_emoji_like` 在私聊里能不能用没验证；`set_online_status` 只有文档里列出的码（没有「睡觉中」「学习中」，所以睡着用「离开」）；`send_qzone_msg` 要 NapCat 能取到 Qzone 的 cookie / 登录态。任何一个失败只记一行，不影响聊天。
- 已读回执要你确认**你那边是不是真的显示已读 / 未读**：不显示的话这一项没有可见效果（无害）。
- 点赞、说说的内容和时刻对外可见，所以每一项都是：先 `dryRun` / 单独开、你在场看第一次的效果。
- 她知道自己在 QQ 上的样子（10-19 补）：现在的个性签名（真改了的，不含草稿）和 3 天内真发的说说（连有没有配图）会作为时间块里的一行给她（`describeSelf`，「[你在 QQ 上的样子……他问起或提到时照这个说，没写的别编]」）；他在聊天里提起「我看到你那条说说了」她接得住，也不会编一条没发过的。一个存在感开关都没开时没有这一行。日志里签名、说说只记字数（`logBody`，和聊天正文同一个开关），完整的在 `presence/presence.json` 和 `drafts.md`。
- 签名的文案池是写在 `presence.ts` 里的 30 句（她的口吻），不在角色卡里；想改直接改那个数组，或以后搬进卡的数据。
- 空友爱看没有对外接口：投稿是客户端里点按钮，机器人投不了；`public` 只是让说说有可能被收录。

## 长跑测试发现的问题（2026-10-19）

`presence-soak.test.ts`：把存在感五项和刷 B 站全开，假时钟每分钟一次走 60 天、每隔几天重启一次，检查跨天的界——点赞同一天只一次（重启也不重复）且在 12:00–21:30 她醒着时；签名隔 3–6 天、第一次不是一开机就改；说说任何 7 天最多 3 条、间隔 ≥ 20 小时、只在她醒着的钟点；刷 B 站任何 7 天最多 3 个、间隔 ≥ 36 小时、不重复同一个视频、只在空闲或课间；在线状态一天最多改 8 次。前几项一次就过；**在线状态没过**：一个满课的日子里，课间十五分钟「忙碌 ↔ 在线」一来一回，一天改了 13 次（00:29 起 … 08:20 忙碌 09:40 在线 09:55 忙碌 11:15 听歌中 12:00 在线 13:40 忙碌 15:00 在线 15:15 忙碌 16:35 在线 18:00 听歌中）。真人不会这样，而且是他在联系人列表上一眼就能看到的。

修法：`BUSY_HOLD_MS` = 1 小时，下课后一小时内忙碌不改回在线（睡下的「离开」不受限）；同一个满课日现在是 00:29 在线 … 08:20 忙碌 → 12:14 在线 → 13:40 忙碌 → 17:34 在线 → 18:00 听歌中，最坏的一天 8 次。先试过「每次变化都隔一小时」，没用——只是把闪的时刻挪到整点，13 次照旧，所以改成了保持忙碌。单元测试和长跑测试在没有这个修法时都是红的。

第二个问题是同一条长跑测试里的「NapCat 的动作一直失败」：改在线状态失败后下一分钟还会再试，60 天里 86400 次（每次都失败，日志只记一次，所以平时看不出来）。点赞、说说是一天一次，签名失败 6 小时后再试，这三项本来就有上限。现在改在线状态失败后越隔越久再试（10、20、40、80 分钟，之后每 2 小时，成功一次从头），60 天最多约 720 次。
