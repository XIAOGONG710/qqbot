# ADR 0125：每顿吃什么（配置 `menu`，默认关）

- 状态：**已实现，未上线**（2026-10-23；配置 `menu`；默认关）。上线 = `koishi.yml` 里加 `menu: true` + 重启；回滚 = 改回 false + 重启（不存会话状态，只有一个“从哪天起”的小文件 `world/menu-from.json`）
- 日期：2026-10-23
- 关联：[ADR 0031](0031-her-routine.md)（午饭 / 晚饭 / 洗澡）、[ADR 0106](0106-everyday-life.md)（`everydayFrom` 同一个办法）、[ADR 0109](0109-photo-shelf.md)（照片货架）
- 用户提出：2026-10-23「菜单每天随机，照片直接找没事博主的那些第一视角的照片就行」（B18）。本条是前一半（菜单）；照片那一半见下面“没做”

## 问题

账上的“吃饭”只有午饭 / 晚饭、在食堂 / 外卖 / 在家、几点——没有“吃了什么”。他问“中午吃的啥”，她就现编（“食堂的黄焖鸡”）：今天说黄焖鸡、明天又说黄焖鸡，前后对不上；更没法让“吃的照片”对上她说的那一顿。

## 做了什么（`menu.ts`）

1. **菜是日期的函数**：每天每顿从一张菜单里按日期取一道，同一天对所有人一样，重启、重放都一样（和作息、小事一个办法），**不存状态**。
2. **一个循环里不重样**：按“块”（菜单有几道就几天）洗牌；块与块交界处，新一块的第一道和上一块最后一道一样时和第二道对调——不会连着两天吃一样的。
3. **通用菜单**（午饭 19 道、晚饭 19 道：黄焖鸡米饭、把子肉饭、麻辣烫、水饺、炒饭、砂锅米线……）：食堂、外卖、在家都说得过去；**不写店名、不写谁做的饭**（那是作者才定的事）。想换菜单：世界书 `routine.menu = { lunch: [...], dinner: [...] }`，不写就用默认。
4. **写进三处**（`world.ts`）：此刻在做的事（“在食堂吃午饭，吃的是黄焖鸡米饭”）；她那边的事实（“吃的：午饭在食堂吃的黄焖鸡米饭；晚饭点的外卖，麻辣烫”，只写已经到饭点的）；复盘某一天（两顿吃了什么）。类型化行动 `eat` 的说法同步（`actions.ts`）。
5. **从哪天起**（`loadMenuFrom`）：第一次开的时候定下“第二天”并存进 `world/menu-from.json`，以后重启读同一个——她以前随口说过什么就是什么，不被新菜单改写。

## 没做 / 要注意

- **照片还没做**（B18 后一半）。设想：用户要的是网上普通博主发的第一视角实拍；做法是给当天那两顿各找一张，由看图把关（人脸、水印 / 文字 / 账号标记、商业精修图、跟菜名对不上的都不收，和 ADR 0109 同一套闸），他问“吃的什么 / 拍给我看看”时发。要联网试来源（小红书需要登录和签名、走不通；B 站她自己的账号、通用图片搜索哪个能用，要实测），所以放到外网恢复以后做，做完是 ADR 0126，单独一个开关。
- **版权**：那些图是别人拍的，只在一对一聊天里用、不转发、不公开；看图把关会挡掉脸和水印。这一点比 ADR 0109（只收 CC0 / 公有领域）宽松，是用户这次的裁决。
- 菜单是我拟的通用一份，不是作者写的她的口味（没有“最爱吃什么 / 不吃香菜”）；那类个人偏好要作者定，之后可以加进 `routine.menu` 或另一份。
- 价格没跟着菜走（账上午饭花多少还是原来的随机价）。
- 开启当天和之前吃的饭没有菜名（从第二天起才有）：那几顿她随口说过什么就是什么，不会被改写。

## 验证

`menu.test.ts`（10 个）：同一天同一顿永远是同一道、都在菜单里；400 天里没有连着两天一样、每个循环每道出现一次；一年里每道都出现；空菜单 / 单道 / 去重 / 自定义 / 写得不对用默认；每道菜名不带店名、人名、标点；“从哪天起”第一次定下第二天、以后读同一个、文件坏了用明天；开了：此刻在做的事、她那边的事实（还没到的饭点不写）、复盘都写菜名且与账上同一顿同一道，没开和原来一样；外卖 / 在家的说法；from 之前的日子不改。真模型模拟（10-23，`sim/menu.json`）：4 次 × 21 项检查全过，她说的就是账上那一道（兰州拉面 / 牛肉面），问两遍说的一致。
