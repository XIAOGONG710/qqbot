# ADR 0045：精力、饥饿、压力先成为可重放的事实投影

- 状态：第二步已在影子模式上线（纯投影、版本化锚点和宽阈值选择；仍不进提示词）
- 日期：2026-10-09
- 关联：[长期执行计划](../plans/2026-10-08-long-term-execution.md) B 阶段、[ADR 0025](0025-her-body.md)、[ADR 0029](0029-life-event-ledger.md)、[ADR 0044](0044-npc-and-project-actions.md)

## 问题

A 阶段已经让她能按作息、世界事实和一天打算行动，但“为什么此刻选这件事”仍主要来自预排文本。B 阶段需要连续的身体与心理动机。直接保存一个 `energy: 63` 会立刻制造第二事实源：事件账说她睡了八小时，状态文件却可能仍是 20；重启、补算和改规则也容易改史。

## 决策

1. 新增 `needsAt(anchor, events, at)`，从一个有明确时刻的锚点、已经落账的行动和时间流逝派生精力、饥饿、压力，三个值都限制在 0–100。
2. 睡眠恢复精力并降低压力；普通清醒时间消耗精力、增加饥饿；上课、学习和项目工作有不同压力速率；休息、休闲、读书和与人来往缓慢恢复。吃饭在成功结束时一次性降低饥饿，失败或被打断的不算吃完。
3. 失败事件没有后果；相同事件 ID 只计算一次；坏账发生重叠时按稳定排序只取一件，结果仍可重放。
4. 第一批不让需要值改变行动选择、状态行、日记或回复。先验证数值轨迹和重启一致，再用下一刀的宽阈值调整候选行动效用；这样不会把未经校准的“饿/累/压力大”直接演给用户看。

## 第二步：只调整柔性行动

2026-10-09 用真实规则选择器跑满 14 天后接入：

1. 第一次启用时在运行目录写 `world/needs-anchor.json`，包含 `needs-v1` 规则版本和起点。重启复用同一个锚点；以后改速率必须先把旧规则投影到切换时刻再换锚点，版本不一致时拒绝静默重算历史。
2. 精力不高于 25 时，原本的读书、休闲、学习或项目行动先改成休息；压力不低于 75 时只暂缓摄影项目，不盖掉普通学习。
3. 上课、饭点、NPC 明确约定和已进入截止时间冲刺的作业仍先于需要值。饭本来就是硬日程，因此不会因低精力或高压力跳过；不新增“凭空吃零食”的事实。
4. 需要值只改变影子行动账。状态行、日记和回复仍不读取这些数字，也不让模型把数字翻译成台词。

## 验收

- 单元场景覆盖睡眠、上课、吃饭、学习、失败事件与重复 ID。
- 14 天确定性行动账每 6 小时取样：三个值始终在 0–100，且不会每天瞬间重置为同一组固定值。
- 同一段两周生活一次推完，与第 7 天用当时投影作为新锚点后继续推，最终结果完全一致。
- 真实选择器从 2026-10-12 08:00 连续跑到 10-26 08:00：167 件行动；每 30 分钟取样 673 次，精力范围 29.09–100、饥饿 0–49.033、压力 0–37.883。
- 取样钉在边界的次数：精力 100 为 91 次（13.5%），饥饿 0 为 1 次（0.1%），压力 0 为 237 次（35.2%）；都低于 45%，且三条轨迹都有超过 12 个不同值。
- 同一 14 天在第 7 天重启，事件 ID、结束时间、结果、对象和目标逐项相同。正常锚点没有触发额外休息；专门的低精力 / 高压力用例会休息，饭点和课程仍优先。
- 首次线上启动发现旧队列里的行动可能早于新锚点；复核锚点前的旧行动现沿用旧选择规则，不向过去反推需要。回归提交 `b3ca53f` 后，旧修片行动只结算一次，插件正常启动。

## 后续

1. 影子观察至少两个正常生活日，核对锚点只建立一次、重启后没有重复行动、需要触发不会挤掉课程 / 饭 / 约定。
2. 加入课程项目、相机基金和读书 / 摄影成长三个长期项目的下一步、期限与阻碍，再让效用选择在项目之间做可解释权衡。
3. 压力当前有 35.2% 取样在 0；等真实选择器出现更多截止时间和项目负荷后再决定是否调速率。若调整，必须升规则版本并迁移锚点。
4. 需要值何时、以什么措辞影响说话，另做自然度 A/B；默认不把数字交给模型。
