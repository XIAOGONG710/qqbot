# ADR 0222：真人式连续数值从事实投影，不另造第二事实源

- 状态：第一步已实现，默认只做日志审计，不把原始分数交给模型
- 日期：2026-11-03
- 关联：ADR 0028、0045、0102、0113

## 问题

项目已经有可重放的精力、饥饿、压力，也有关系阶段和短期心境，但它们分散在不同模块里，没有一套能回答“她现在大概是什么状态”的连续数值。直接新增一个会被不断写入的 `intimacy: 83` 又会产生第二事实源：聊天记录、生活账和数值文件可能互相矛盾。

## 决策

1. 新增 `humanValuesAt`，从现有 `NeedsSnapshot`、聊天记录、生活事件和当前时刻计算：
   - 身体：精力、饥饿、压力；
   - 身心：心情、健康、孤独、信心、好奇、无聊、动机、社交电量、自尊、开放程度、满足感、舒适度、挫败感；
   - 关系：亲密、信任、熟悉、依恋、摩擦。
2. 所有维度限制在 0–100，关系值按联系人档位提供基线，之后只由稳定互动、温暖 / 修补信号、冲突和沉默缓慢调整。
3. 不保存“当前分数”；需要值继续由 `needs-anchor.json` + 事件账投影，关系和心理值继续由聊天 / 事件重算。这样重启、回放和规则升级都可审计。
4. 行动事件是数值变化的唯一入口：吃饭在事件结束时降低饥饿，睡觉 / 休息恢复身体，社交降低孤独，学习 / 项目完成提高信心，成功 / 失败 / 被打断留下短期心情余波；这些效果都按事件时刻衰减。
5. 第一阶段在回复日志里记录一行无原文的数值摘要；回复提示词只接收“有点累 / 有点饿 / 想找人说话”等自然语言底色，不接收原始分数。高负荷底色可以让回复更短，但不改变危机、课程、饭点和明确约定的优先级。
   Koishi 状态页在自主生活开启且存在需要锚点时显示一份不含联系人关系值的全局摘要，方便观察精力、饥饿、压力、心情、健康、动机和孤独的变化。
6. 生活行动选择器只读取不带联系人原文的全局状态投影：动机过低时把可推迟的学习 / 项目 / 看书换成休息，无聊过高且身体尚可时把继续躺着换成低负荷休闲；课程、饭点、明确约定、危机和截止任务仍由硬规则优先。孤独和关系值继续只进入联系人回复，避免把“想找男朋友”误算成“她应该去做一件生活行动”。

## 后续

- 继续观察动机 / 无聊回流到柔性行动后的 2–3 个真实生活日分布，再校准阈值；低精力、高饥饿和高压力仍只通过需要值进入选择器，不覆盖课程、饭点、约定或危机规则。
- 为每个值增加离线轨迹报告：范围、变化速度、重启一致性和触发的行动数。
- 关系值需要和现有 `relationship` 开关做一次 A/B；没有校准前不让精确数字直接影响台词。
