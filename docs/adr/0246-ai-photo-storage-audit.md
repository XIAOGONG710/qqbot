# 0246：AI 照片存储先只读审计，清理必须另行确认

日期：2026-11-04

## 决定

`ai-photo-drafts` 和 `ai-photo-references` 作为普通状态目录的一部分，已经被每日 `her-state.zip` 递归备份；各自索引和 `files/` 会一起进入归档。备份发现逻辑继续排除 `logs`、`secrets` 和配置，但不排除 AI 照片目录。恢复时必须整目录恢复，不能只恢复索引或只恢复图片。

新增只读存储审计：检查索引结构、索引与文件名绑定、缺图、孤立图、非普通文件和符号链接。`state-check` 在数据目录副本里执行该审计，不修改线上目录。

被拒绝超过 30 天的草稿和安全的孤立普通文件只进入“清理预览”。当前不提供 `--apply`，不执行真实删除；未来若增加应用步骤，必须同时更新索引和文件、先有可用备份、再次明确确认。未知文件、符号链接和不符合固定哈希命名的文件永远不列入自动清理候选。

文件级恢复演练使用 `npm run restore:drill -- --backup runtime/backups/<日期>`：它只接受带完整标记和精确制品大小的备份，只会解压到 `runtime/restore-drills/` 的新空目录，检查符号链接、敏感目录、AI 照片草稿，以及视觉参考的索引、文件哈希和孤立文件，默认检查后清理演练目录。它不会覆盖在线数据、不会重启服务，也不会把 `hindsight.sql` 导入当前数据库；数据库导入必须另用隔离 PostgreSQL 演练，不能把“压缩包能解开”写成“记忆数据库已经可恢复”。

审计结果只暴露数量、问题代码、内容哈希式编号和固定文件名，不暴露绝对路径、提示词、世界上下文、模型密钥或供应商响应。
