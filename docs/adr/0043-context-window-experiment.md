# ADR 0043：最近若干轮原文 + 更早聊天要点

- 状态：离线实验已实现并完成首轮真模型 A/B；线上保持最近 80 条原文，不启用
- 日期：2026-10-09
- 关联：[ADR 0036](0036-conversation-naturalness.md) P2-8、[ADR 0017](0017-long-term-memory-like-a-person.md)、[长期执行计划](../plans/2026-10-08-long-term-execution.md) N3

## 背景

最近 80 条原文能阻断无限增长，却仍会把大量旧模型措辞带回提示词，让她继续模仿「去吧去吧」「写完跟我说」等旧习惯；窗口边界也按消息条数突然移动。只依赖 Hindsight 又不够：长期记忆负责可召回事实，不负责保存当前片段里每个承接点。

`long-context-memory` 用三天 96 条事先聊天和 13 轮后续对话同时检查：窗口外的面试、耳机和家人来访能否说对，窗口内的电饭锅事件能否接住，同一句收尾说三遍时会不会照抄旧回复。

## 实验方案

1. 保留最近 N 轮用户—助手原文，而不是固定 80 条消息；首轮取 `N = 10`。
2. 更早的当前聊天由同一个聊天模型整理成带日期的事实要点，只写明确发生、计划、承诺和人物关系，不写语气评价，不补事实。
3. 摘要切口每 4 轮才前移一次；切口没变时复用摘要，避免每来一条消息就重新总结并产生漂移。
4. 摘要只补充当前片段连续性；Hindsight 仍负责跨片段长期记忆，两者同时出现时以最近原文为准。
5. 只在模拟器通过 `--context-turns N [--context-step K]` 开启。线上 `contact()` 没有传这个选项，行为仍是最近 80 条。

## 实现

- `context-window.ts`：按完整轮次找稳定切口、生成事实要点、限制摘要输入和输出。
- `contact.ts`：可选地把摘要放在最近原文之前，并在日志中写被省略的条数。
- 模拟器：命令行开关、结果元数据、报告里的摘要与 token 估算。
- 单测：不从助手半句话切开；切口按步长稳定；摘要失败时安全退回 80 条策略；不把摘要文字再送去循环总结。

## 摘要事实审计第一步（2026-10-09 下午，Claude 复核）

`lct10` 那批的 11 条要点逐条核过：日期、星期、主语都对。但 `long-context-memory` 里没有凌晨说的话、没有改口、没有第三个人，测不到上线门槛里点名的「日期、主语、否定」。
另编了 10 条较早聊天专踩这几处（10-07 他说周六宿舍爬千佛山，10-08 说下雨不去了、她回「那正好在宿舍躺着」；10-09 00:40 他说「我明天上午有个面试，九点」、00:45 说室友老周下周一回家；
19:30 她说「我今天没去成图书馆，下午一直下雨」，他说「哈哈你是猪吗」，她回「你才是猪，我明天去」），只调 `summaryRequest`，真模型各 3 次：

| 检查 | 改前 | 改后 |
| --- | ---: | ---: |
| 取消了的计划没有单独留一条「要去」 | 0 / 3 | 3 / 3 |
| 凌晨说的「明天上午面试」写成 10-09，不是 10-10 | 1 / 3 | 3 / 3 |
| 「那正好在宿舍躺着」没记成她自己在躺 | 2 / 3 | 3 / 3 |
| 回家的是老周，不是他 | 3 / 3 | 3 / 3 |

改法（`summaryRequest`）：共用待跟进和她答应的事的凌晨规则（`MIDNIGHT_RULE`，ADR 0011 调整 12）；改了、取消了、没做成的合成一条只写最后结果；每条写清是谁的事，顺着对方的话说的是对方。
改后的一条样子：「阿明宿舍原定10月10日周六去爬千佛山，10月8日周四阿明说因下雨不去了。」

## 上线门槛

- 至少覆盖日常闲聊、亲密、情绪、收尾、冲突和久别重聊的 A/B；固定事实与隐私检查不得退化。
- 摘要必须有超时、失败回退、缓存和成本指标；摘要失败不能阻塞回复。
- 对摘要做事实一致性审计，尤其是日期、主语、否定和「计划」不能被写成「已经发生」。
- 用匿名混排做人工盲评；自动检查变好但真人感没提升，不上线。
- 先做独立配置开关和单联系人灰度，再决定是否替换 80 条默认值。

## 后果

- 好处：提示词更短、旧模型措辞更少，较早事实仍有连续承接。
- 代价：每次切口移动多一次模型调用；摘要本身可能误写事实，所以不能直接进入事件账或长期记忆。
- 当前决定：保留离线能力和证据，线上不变；下一批优先做摘要事实审计与更广 A/B，而不是立即打开。
