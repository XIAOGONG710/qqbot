# ADR 0043：最近若干轮原文 + 更早聊天要点

- 状态：离线实验已实现并完成首轮真模型 A/B；2026-10-09 下午补了后台整理和配置开关（`contextTurns`，默认 0 = 关）。线上保持最近 80 条原文，不启用
- 日期：2026-10-09
- 关联：[ADR 0036](0036-conversation-naturalness.md) P2-8、[ADR 0017](0017-long-term-memory-like-a-person.md)、[长期执行计划](../plans/2026-10-08-long-term-execution.md) N3

## 背景

最近 80 条原文能阻断无限增长，却仍会把大量旧模型措辞带回提示词，让她继续模仿「去吧去吧」「写完跟我说」等旧习惯；窗口边界也按消息条数突然移动。只依赖 Hindsight 又不够：长期记忆负责可召回事实，不负责保存当前片段里每个承接点。

`long-context-memory` 用三天 96 条事先聊天和 13 轮后续对话同时检查：窗口外的面试、耳机和家人来访能否说对，窗口内的电饭锅事件能否接住，同一句收尾说三遍时会不会照抄旧回复。

## 实验方案

1. 保留最近 N 轮用户—助手原文，而不是固定 80 条消息；首轮取 `N = 10`。
2. 更早的当前聊天由同一个聊天模型整理成带日期的事实要点，只写明确发生、计划、承诺和人物关系，不写语气评价，不补事实。
3. 摘要切口每 4 轮才前移一次；切口没变时复用摘要，避免每来一条消息就重新总结并产生漂移。
4. 摘要只补充当前片段连续性；Hindsight 仍负责跨片段长期记忆，两者同时出现时以最近原文为准。
5. 只在模拟器通过 `--context-turns N [--context-step K]` 开启。线上 `contact()` 没有传这个选项，行为仍是最近 80 条。

## 实现

- `context-window.ts`：按完整轮次找稳定切口、生成事实要点、限制摘要输入和输出。
- `contact.ts`：可选地把摘要放在最近原文之前，并在日志中写被省略的条数。
- 模拟器：命令行开关、结果元数据、报告里的摘要与 token 估算。
- 单测：不从助手半句话切开；切口按步长稳定；摘要失败时安全退回 80 条策略；不把摘要文字再送去循环总结。

## 摘要事实审计第一步（2026-10-09 下午，Claude 复核）

`lct10` 那批的 11 条要点逐条核过：日期、星期、主语都对。但 `long-context-memory` 里没有凌晨说的话、没有改口、没有第三个人，测不到上线门槛里点名的「日期、主语、否定」。
另编了 10 条较早聊天专踩这几处（10-07 他说周六宿舍爬千佛山，10-08 说下雨不去了、她回「那正好在宿舍躺着」；10-09 00:40 他说「我明天上午有个面试，九点」、00:45 说室友老周下周一回家；
19:30 她说「我今天没去成图书馆，下午一直下雨」，他说「哈哈你是猪吗」，她回「你才是猪，我明天去」），只调 `summaryRequest`，真模型各 3 次：

| 检查 | 改前 | 改后 |
| --- | ---: | ---: |
| 取消了的计划没有单独留一条「要去」 | 0 / 3 | 3 / 3 |
| 凌晨说的「明天上午面试」写成 10-09，不是 10-10 | 1 / 3 | 3 / 3 |
| 「那正好在宿舍躺着」没记成她自己在躺 | 2 / 3 | 3 / 3 |
| 回家的是老周，不是他 | 3 / 3 | 3 / 3 |

| 互损（猪）不写 | 3 / 3 | 3 / 3 |

改法（`summaryRequest`）：共用待跟进和她答应的事的凌晨规则（`MIDNIGHT_RULE`，ADR 0011 调整 12）；改了、取消了、没做成的合成一条只写最后结果；每条写清是谁的事，顺着对方的话说的是对方。
改后的一条样子：「阿明宿舍原定10月10日周六去爬千佛山，10月8日周四阿明说因下雨不去了。」

改后重跑 `long-context-memory --context-turns 10`（各 2 次）：

| 批次 | 回复检查 | 没过的 |
| --- | ---: | --- |
| `20261009-134725-lct10-fix`（摘要改法） | 171 / 174 | 两次都把「别熬太晚」说了第二遍（跨轮重复，她的老毛病）；一次问他妈哪天来答「周日，10月12号」 |
| `20261009-135723-lct10-hdr`（+ 要点优先于记忆） | 170 / 174 | 一次照抄事先历史里的「写完跟我说一声」两轮（ADR 0036 / 0041 管的老毛病）；另一次 87 / 87 |

「10月12号」不是摘要写错的：那一轮要点里是「10月11日周日」，错的是长期记忆——Hindsight 把 10-08（周四）说的「这周日」抽成了「2026年10月12日（周日）」（12 日是周一）。
回头查了这个场景之前所有批次：`lc80` 3 次里 2 次、`lct10` 3 次全部、`lct10-fix` 2 次全部、`lct10-hdr` 2 次里 1 次，长期记忆都是 12 日——**10 次里 9 次**。
`260 / 261` 那批能过，是因为她答的时候碰巧只说了「周日」。两处应对：
- 要点那一段开头加「和下面从记忆里想起来的对不上时，以这里为准」（要点出自近 7 天聊天原文，比记忆可靠）。`lct10-hdr` 里记忆仍是 12 日的那一次，她答对了。
- 记忆的写入说明（线上也用）加日期换算规则，见 [ADR 0012](0012-hindsight-tuning.md) 的调整。

## 往线上走的改法（2026-10-09 下午，Claude）

原来的写法在回复路径上同步等摘要：切口一挪，那一轮回复先等一次模型调用（几秒到十几秒）；调用失败就不放要点，更早的聊天整段丢掉、只剩最近 10 轮。两条都过不了门槛。

1. **后台整理，回复不等**（`contextSummarizer`）：`summarize(较早聊天)` 立即返回——这一段整理好了就给要点；没整理好就在后台开始整理（同一时间只整理一段），这一轮返回「还没好」，
   `contact.ts` **照旧放最近 80 条**，什么都不丢；下一轮起用要点。日志「上下文要点：切口挪了，后台在整理，这一轮照旧放最近 80 条」。
2. **超时、失败重试**：一次整理最多 60 秒，超时算失败；失败的那一段 5 分钟后再试，这期间照旧放最近 80 条。
3. **存盘**：整理好的那一段写进 `<dataDir>/context/<QQ>.json`，重启以后同一段直接用（ADR 0039：重启前后提示词一样）。
4. **指标**：日志「较早的 N 条整理成 M 条（请求约 T token，用了 S 秒）」；`live-digest` 以后可以数。
5. **开关**：配置 `contextTurns`（0 关，默认；实验用 10）、`contextContacts`（只对这几个 QQ 开，空 = 名单里开了记忆的都开）；Koishi 插件配置页里也有。启动日志一行说开了没有。
6. **模拟器**：每轮结束等后台整理做完（`settle`），结果可复现；切口刚挪的那一轮和线上一样照旧放最近 80 条。

验证 `20261009-150412-lct10-bg`（`long-context-memory --context-turns 10`，2 次）：回复检查 173 / 174，唯一没过的是她把「别熬太晚」说了第二遍。**整理一次要 21–25 秒**（「较早的 78 条整理成 9 条（请求约 1806 token，用了 21.0 秒）」）——原来这段时间都卡在回复路径上，现在那一轮照旧最近 80 条、照常回。长期记忆按新的写入说明（ADR 0012 调整）把他妈来的日子记成「11日周日」或不写日期，没再出现 12 号。全仓 590 项通过。

对照门槛：

| 门槛 | 现在 |
| --- | --- |
| 超时、失败回退、缓存、成本指标；失败不阻塞回复 | **满足**（上面 1–4） |
| 摘要事实一致性（日期、主语、否定、计划写成已发生） | 日期、主语、否定、取消的计划：探针改后全 3 / 3（上一节）；「计划写成已发生」还没专门测 |
| 独立配置开关和单联系人灰度 | **满足**（上面 5），默认关 |
| 日常、亲密、情绪、收尾、冲突、久别重聊的 A/B | 只有 `long-context-memory` 一组；别的场景历史太短，切不到——要先写几个长历史的场景 |
| 匿名混排人工盲评 | 没做；等 DSH 的盲评题库 v1（`exchange/tasks/2026-10-09-dsh-real-chat-research.md` T2） |

## 上线门槛

- 至少覆盖日常闲聊、亲密、情绪、收尾、冲突和久别重聊的 A/B；固定事实与隐私检查不得退化。
- 摘要必须有超时、失败回退、缓存和成本指标；摘要失败不能阻塞回复。
- 对摘要做事实一致性审计，尤其是日期、主语、否定和「计划」不能被写成「已经发生」。
- 用匿名混排做人工盲评；自动检查变好但真人感没提升，不上线。
- 先做独立配置开关和单联系人灰度，再决定是否替换 80 条默认值。

## 后果

- 好处：提示词更短、旧模型措辞更少，较早事实仍有连续承接。
- 代价：每次切口移动多一次模型调用；摘要本身可能误写事实，所以不能直接进入事件账或长期记忆。
- 当前决定：保留离线能力和证据，线上不变；下一批优先做摘要事实审计与更广 A/B，而不是立即打开。

## 2026-11-05 来源完整性补查

原缓存key仅含消息数、末条时间和末条正文；前文撤回/改写但末条不动时，内存缓存、在途完成结果与重启后的summary.json均可能返回旧摘要。合成三项正式回归先红后绿，未使用此文件记载的历史真实模型或仓库角色卡。

现在以实际summaryRequest（含完整系统规则、人物与实际取用的末200条格式化材料）计算带source-v2前缀的SHA-256。派发复用同一请求快照；每次使用前核当前请求，变化则返回未准备好并按既有单任务机制重建。旧弱key无法命中新协议，保原文件直至新结果正常发布，不伪造旧来源迁移。未进入实际请求的更早历史不引起无意义重算；时区改变若实际提示词不同同样失效。没有把本地摘要更新当成远端派生清理，也不更改默认关闭和窗口策略。

## 2026-11-05 摘要停止所有权

真实App假模型保持摘要pending，App.stop完成/目录锁释放后，旧成功会落context/QQ.json，旧失败和授予模型的log仍写日志。contextSummarizer现在返回OwnedSummarizer（不扩大纯读取Summarizer接口）：stop同步永久拒新和旧缓存供给，取消内部等待并返回相同drain；idle可收尾，不等待不合作的底层纯模型，微任务派发前再次检查stop。晚成功/失败不发布文件、缓存、重试或日志，已确认旧文件不删，重建实例仍按完整来源hash使用。

App记录每个实际摘要实例，停止所有摘要并等待取消收尾后才释放目录锁；授予模型的日志回调另受App stopped约束。模拟器仍保持已有可重启的context adapter，不把永久stop套到它需要跨restart复用的摘要实例。实际未合作模型可继续运行，但不再持有本模块授权的写入出口；不声称能强杀任意外部代码。
