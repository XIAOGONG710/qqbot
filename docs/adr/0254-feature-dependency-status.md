# ADR 0254：控制台区分“已打开”与“真正生效”

- 日期：2026-11-04
- 状态：已实施
- 相关：ADR 0120、0197、0202、0203、0216

## 问题

Koishi 控制台过去只读取开关本身。一个功能即使缺少必要的前置能力，也会显示绿色“已启用”。例如“她那边的事有后续”必须同时开启“日常小事”和“日子里的小起伏”；单独打开后实际上不会运行，但页面会让用户误以为已经生效。语义深思、扩展事实检查和回忆情绪也有同类问题。

## 决策

1. 依赖关系写入现有功能总表，不在控制台另维护一份映射。
2. 当前纳入明确、稳定的依赖：
   - 她那边的事有后续 → 日常小事、日子里的小起伏；
   - 回忆带着当时的感觉、聊完回想 → 心境；
   - 事实检查多查他 → 逐条事实检查；
   - 语义路由 → 深思。
3. 开关打开但依赖缺失时，状态返回“已配置但未生效”和缺少的中文能力名；不暴露配置键或内部代码值。
4. 控制台用黄色提示，并在功能总数和分组中单独标出未生效数量。能力概览只统计真正生效的功能。
5. 这只是只读状态解释，不自动修改配置，也不批量开启权限。

## 验收

- 功能总表测试保证依赖项存在、不能依赖自身。
- 覆盖缺一个、缺多个和依赖齐全三种状态。
- 控制台纯函数验证简短中文标签、原因提示和生效计数。
- 运行 Koishi 插件全量测试、全仓类型检查、发布检查和 `git diff --check`。

## 回滚

回滚本次提交即可恢复仅按开关值展示；不涉及持久状态、协议或配置迁移。
