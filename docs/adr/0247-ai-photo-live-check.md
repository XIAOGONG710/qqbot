# 0247：真实生图验收必须区分预检与付费调用

日期：2026-11-04

## 决定

`npm run ai-photo -w @qqbot/bot -- preflight` 只检查生图供应商角色、视觉审查是否配置和每日调用上限，不访问供应商，不读取或显示 URL、模型名、密钥和提示词，也不触碰草稿状态。

真实闭环使用 `smoke --confirm-live`。调用者还必须提供当前时间、全新事件键、照片种类和可见事实；缺少 `--confirm-live`、事件已经过期或事件键已经生成过时，必须在供应商调用前失败。这样不会把一次旧草稿命中误报为“真实服务已经跑通”。

冒烟链路依次经过供应商预算、最多一次质量重生成、视觉审查、草稿落盘和草稿重新读取。成功结果固定停在 `pending_review`，不自动批准、不进入照片货架、不发送 QQ。终端只显示种类、格式、字节数、有效期和当天剩余额度。

不同事件如果生成出与已有草稿完全相同的图片，草稿仓库明确拒绝，不再返回旧条目。否则新事件键不会落盘，后续请求会反复付费，并可能把旧图冒充成当前照片。

当前开发机没有配置生图服务端点或密钥，因此本次提交只运行了不联网预检和注入假供应商的自动化测试，不能把它写成真实模型已经通过。配置服务后应使用全新事件键执行一次 `smoke --confirm-live`，再由 Koishi 或手机人工审核。
