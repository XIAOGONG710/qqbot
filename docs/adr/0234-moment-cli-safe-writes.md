# ADR0234：作者事件命令入口的日期、隐私与跨进程写入

日期：2026-11-05

## 证据

心境审查的真实 CLI 合成回归确认：无效 `--at` 在校验前调用 toISOString 抛栈；不存在日期自动滚动，四位本地日期偏移可输出五位 UTC 年；坏 JSON 解析错误回显作者正文；缺少选项值静默使用默认值；增删丢未知顶层字段。另在两个独立 CLI 的 JSON rename 前设 barrier，两者同时进入发布区，可丢掉一件已确认新增的事件。修前均有失败回归，不把读写原子 rename 当成完整读改写事务。

## 决定

选项先解析：缺值、重复、未知选项以及多余位置参数明确退出2，不回退默认私有目录。日期接受既有 now、四位 ISO 日期与本地日期时刻/明确偏移；校验真实日历、时钟、有限瞬时及四位 ISO 持久格式后才序列化。本地不存在的 DST 时刻拒绝，重叠时刻保留原生选择。坏文件保留原字节，错误不带正文或堆栈；读取失败不当空白重建。增删保留未知顶层和条目字段。

仅 CLI 写作者事件，bot 的 momentsReader 只读。CLI 使用 Node 内置 SQLite 的 `moments.coordination.sqlite` 作进程间 OS 写锁；50ms 是争锁预算，明确忙时提示稍后重试。持锁后重读有效 JSON、应用本次增删、原子发布，最终 ROLLBACK/close。SQLite 不存事件，JSON 是唯一事实源；坏协调文件不能降级为无锁写，也不自动重建。发布后报告异常时同锁读回确认，避免把已应用结果误判为失败。短命 CLI 退出时 OS 回收连接，释放异常不重放成功操作。

## 验证与边界

11项正式 CLI 回归覆盖坏日期/缺值/坏 JSON 脱敏、扩展字段与0099年、双写者互斥及忙后重读、发布前后强杀恢复、发布前后 IO 异常、坏协调库原字节与纽约 DST。双进程测试最初使用 Windows路径作为 --import 失败；已改 file URL，并在隔离的旧版 CLI 上重新确认两个写者同时进入发布区的真实红灯，不把测试夹具错误当缺陷证据。其余新增测试使用临时合成文件与原生进程，不访问私有运行时。

上线前须统一使用新 CLI，运行时不可删除或替换协调文件；外部手工写 JSON、旧 CLI、网络文件系统及恶意文件替换不在互斥保证内。坏库须停止写者人工检查，不凭 PID/超时删除锁。图片模块已有同类 OS 锁决策见 ADR0233；这里只协调作者文件，不引入对视觉模块的依赖，也不将只读 bot 变成作者事件写者。没有新增总量配额、保留期或断电 fsync 保证。

锁语义依据 [SQLite 事务](https://www.sqlite.org/lang_transaction.html) 与 [SQLite 文件锁](https://www.sqlite.org/lockingv3.html)，本机 Node 24 独立进程验证。
