# ADR 0069：稳定性与隐私基线

- 状态：**已实现，待审查与上线**
- 日期：2026-10-13
- 关联：[ADR 0003](0003-contact-tiers.md)、[ADR 0008](0008-koishi-runtime.md)、[ADR 0016](0016-people-she-knows.md)、[ADR 0068](0068-crisis-response.md)、[Hindsight 运维](../hindsight.md)

## 背景

项目已经有数百项测试和较完整的行为证据，但安全默认值、联系人数据定位、持续集成和线上版本识别落后于功能增长：

- `unlistedFriends` 默认打开，任何好友都能触发模型，而且没有频率限制；
- 同一联系人数据散在聊天、记忆进度、承诺、主动消息、状态、日志、生活账和 Hindsight 中，删除前没有统一清单；
- 全量测试只在本机手动执行；
- “线上跑哪个提交”靠 ADR 和操作记录判断，状态页看不到实际工作树。

本 ADR 只做可在一个批次内验证、不会迁移线上数据的基线，不在高风险改动里顺手重构 `app.ts` / `world.ts` / `long-term.ts`。

## 决策

1. `unlistedFriends` 默认改为 `false`。已有配置显式写 `true` 时继续回复，不暗改用户选择。
2. 明确打开名单外好友后，固定限制为：单个联系人 10 分钟 30 条、全部名单外联系人 10 分钟 100 条。超出的消息不进聊天记录、不调用模型，只记不含正文的日志；名单联系人不受影响。
3. 新增只读 `privacy-audit`：输入数据目录和 QQ 号，输出直接文件、混合文件引用数量、私人 Hindsight bank、公共库文档和个人模型的精确标识。报告不输出聊天正文，也不执行删除。
4. 审计报告必须写出不能机械归属的范围：公共日记 / 周记 / 阶段总结、NapCat、Koishi、模型供应商和系统备份。没有覆盖这些范围前，不宣称“一键彻底删除”。
5. GitHub Actions 在 Windows + Node 24 上对 `main` 推送和所有 PR 执行锁定依赖安装、类型检查和全量测试；不加载生产密钥，不初始化上游子模块。
6. 两个正式启动脚本读取 Git commit、分支和工作树是否有未提交改动，运行状态与 Koishi 状态页展示这些字段和启动时间。读取失败时显示 `unknown`，不阻止服务启动。

## 不在本批次做

- 自动删除联系人数据：必须先补 Hindsight 精确删除客户端、混合日志保留策略、公共总结人工复核流程和可恢复备份；仓促实现会造成漏删或误删。
- 大文件拆分：先以接口和依赖图另开重构批次，不能与线上安全默认值混在一次上线。
- 自动清理 Git 分支 / 工作树：其中有未合并实验和历史证据，删除需要逐项确认。

## 验证

- 限流纯函数覆盖个人、全局、窗口恢复和拒绝不占额度；编排测试确认第 31 条不进聊天记录、不触发模型。
- 隐私审计使用虚构数据验证直接文件、混合引用、私人 bank、公共文档和个人模型；断言报告不含正文。
- 运行版本解析覆盖完整环境变量和缺失回退。
- 全仓类型检查、测试和 `git diff --check` 通过后才能提交。

## 上线与回退

- 合并后重启 Koishi 才会在状态页显示运行版本，需用户当次同意。
- `unlistedFriends` 线上若已经显式为 `false`，行为不变；若配置缺省，重启后从“默认回复”变为“不回复”，这是本 ADR 的预期安全变化。
- 回退代码即可恢复旧行为；本批次不迁移、不删除任何线上数据。
