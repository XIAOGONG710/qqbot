# ADR 0052：他发的语音和图片，她「听得到、看得到字」

- 状态：**已上线**（2026-10-10 13:28，`main` = `integration` = `1e86548`（`release-1010b`），用户同意后重启 Koishi；日志确认插件加载、真实天气和听语音看图为「开」、NapCat 就绪）
  用户 10-10 13:27 定：上课时转出了字的语音照字回（不藏）；看图模型暂时不接。
- 日期：2026-10-10

> 10-10 晚调整：DSH 实测并由官方文档确认 `deepseek-flash` 已能看图，不需要新供应商或新 key；实现见 [ADR 0055](0055-deepseek-vision.md)。本 ADR 里“DeepSeek 不能看图 / 还没有提供方”的说法只保留为当时的历史背景。

## 背景

他发语音，她只看到「[语音]」；发照片、截图只看到「[图片]」（表情包是它的名字，如「[动画表情]」）。转文字在 `onebot.ts` 的 `segmentsToText`，
Koishi 插件走的是同一个函数：中间件把 NapCat 的原始事件（`session.onebot`）原样交给 `app.receive`，补回也是原始的 `get_friend_msg_history`（ADR 0008 试验之后的调整 6）。
真人女朋友会点开听、点开看。模型是 DeepSeek，不能看图；接看图模型要用户给 key、选一家，不在这次，只把接口留好。

### 取证（10-10，NapCat 4.18.28）

**源码**（`vendor/NapCatQQ/packages`，只读）：

- `fetch_ptt_text`（`napcat-onebot/action/msg/FetchPttText.ts`）：参数只有 `message_id`。先在 NapCat 内存里的消息 id 表（`MessageUnique`，最多 5000 条）找到这条消息，
  取出语音元素，调 QQ 内核的 `translatePtt2Text`（QQ 自带的语音转文字，和手机上点「转文字」是同一个），再读一次这条消息拿 `pttElement.text`。
  三步各有 `baseTimeout`（默认 10 秒）的上限，最坏 30 秒。失败的样子：`消息不存在`（id 表里没有，NapCat 重启后要等这条被推送或拉历史时重新登记）、
  `消息中不包含语音`、`获取语音转文字结果失败`（转完没有字）、`获取语音转文字结果失败: PromiseTimer…`（超时）。源码里没有时长限制，QQ 语音本身最长 60 秒。
- OCR：`ocr_image` / `.ocr_image`（`napcat-onebot/action/extends/OCRImage.ts`）：参数 `image` 是本地路径、http(s) URL 或 `base64://`，远程的先下载到 NapCat 的临时目录；
  调 QQ 内核的 `wantWinScreenOCR`，说明写着「仅 Windows 端支持」。返回 `ret.result`，源码没写形状（示例写的是 `{ texts: [{ text, coordinates }] }`）。
- 收到的消息段（`napcat-onebot/api/msg.ts`）：语音 `record` 只有 `file`、`path`（本机文件）、`url`、`file_size`，**没有时长**（`pttElement.duration` 没转出来）；
  图片 `image` 有 `summary`、`file`、`sub_type`（`picSubType`，0 是普通图片，1 是收藏的表情……）、`url`、`file_size`。

**线上只读调用**（临时 WebSocket 客户端，只调 `get_version_info`、`get_status`、`ocr_image`、`fetch_ptt_text`；推来的事件直接丢掉，不打印不保存；每次几秒到两分钟就断开）。
图都是自己画的（PowerShell 的 System.Drawing），没有用真人的图：

| 调用 | 结果 |
| --- | --- |
| `get_version_info` / `get_status` | NapCat.Onebot 4.18.28，在线 |
| `ocr_image` 有字的图（PNG、JPEG、带招牌字的「照片」、4000×3000 的大图、1080×2400 的 30 行长截图；base64、本地路径、本机 HTTP 三种传法） | 第一次连着调 4 张**全部超时**（每张等 20 秒）；几分钟后再调都在 0.28–0.55 秒回来，长截图 1.1 秒。返回是数组 `[{ text, pt1…pt4, charBox, score }]`，一行一项，字认得全（空格会被吃掉：「高等数学11月12日上午9:00」） |
| `ocr_image` 没字的图（纯色块 PNG、噪点「照片」） | **一直不回**：等 8、10、20 秒都没有回应；不挡后面的调用（紧接着的有字的照样 0.3 秒回来） |
| `ocr_image` 下载 404 / 不认识的写法 | 0.02 秒报 `下载文件失败: Not Found` / `image字段可能格式不正确` |
| `fetch_ptt_text` 假 id / 不带参数 | 2 毫秒报 `消息不存在`（retcode 1200）/ 参数校验失败（1400） |

线上的聊天记录里他没发过语音（现在两份记录 0 条语音、0 张图片，归档里 3 张图片），所以没有真的语音可试：语音按源码实现，用假数据测；上线后看日志里「听语音」那几行确认。

## 决策

1. **在 `segmentsToText` 前面加一层**（`media.ts`）：消息里有语音、或者不是表情包的图片时，先听一听、看一看，读过的段换成一段文字，`segmentsToText` 照常拼成一行
   （`segmentsToText` 本身没改，转文字的规则仍只有一份）。两个入口把 NapCat 的这两个调用传进来（`AppOptions.media`）：`main.ts` 用自写的 OneBot 客户端，
   Koishi 插件用 adapter-onebot（`ocr_image` 它有现成的方法，`fetch_ptt_text` 没有，用通用的 `_get`）。
2. **语音**：`[语音 8秒：……]`，冒号后面是转出来的字（换行、方括号去掉，最多 300 字）；转不出来是 `[语音 8秒]`；秒数也不知道就是老样子 `[语音]`。
   秒数：OneBot 的消息段里没有，从本机的语音文件（`data.path`）数帧——QQ 的 SILK（开头 `#!SILK_V3`，每块 20 毫秒）或 AMR-NB（`#!AMR`，每帧 20 毫秒）；文件不在、认不出来就不写秒数。
3. **图片**：照片、截图跑 OCR，有字是 `[图片，上面写着：……]`（多行用空格连起来，截到 80 字加「…」；零星一两个字符算噪点，不算有字），没字是 `[图片]`。
   写「上面写着」而不是只写字：她知道这是图上的字、图里别的东西看不清。表情包（`sub_type` 不是 0，或者 `summary` 是名字）照旧用名字，不跑 OCR；一条消息里最多看 3 张。
4. **上限**：语音转文字、OCR 各等 5 秒（看图 8 秒），超时、出错都退回老样子，日志写一行（「听语音：没转出来（超时 5 秒）」「看图：没认出字（超时 5 秒）」）。
   没字的图 NapCat 不回，所以没字的照片总要等满 5 秒——真人点开一张照片看一眼也要几秒，这个代价接受；NapCat 那边会留一个不回的调用（adapter-onebot 一分钟后自己放掉）。
   刚启动第一次 OCR 可能要一分钟以上，同样按超时算。
5. **顺序和不重复**：读是一收到就开始读；同一个人的消息按收到的顺序一条条进聊天记录（图片在读的时候后面来的话排在它后面）。
   聊天记录就是缓存：进了记录的消息（按 QQ 消息 id）不再转，重启后补回拿到同一条也不转；同一条正在读的（实时收到的和补回的撞上）共用一次调用，读完再按 id 查一遍记录才记。
   补回的消息也先读再记（`backfill.ts` 的 `findMissed` 拆成前后两半：`newerThanStored` 挑出漏掉的原始记录，读完再 `toStored`）。
6. **回复节奏：听完才回**（`reply-timing.ts`）：这一串里有语音，看到之后一条条听，每条从它到了之后开始听，听完才算看到；
   时长按记录里写的秒数，只有字按每秒 4 个字（最少 2 秒），都没有按 6 秒，最多 60 秒。在上课不加（看转出来的字，或者让他打字）。日志「正聊着，听完语音（9 秒），20:06:12 看到」。
   附和（她收尾以后对方只回附和就不回，ADR 0007 决策 7）看语音里说的话：「[语音 2秒：嗯嗯]」是附和，「[语音 5秒：我还有个事]」不是；
   **没转出来的语音、照片不算附和**（以前「[语音]」「[图片]」去掉方括号就空了，被当成附和）：不知道里面是什么，照样回。表情包照旧算。语音照旧不算「反应」（看心情不回不挡语音）。
7. **卡上一段**（`persona-to-card.ts` 的输出规则，所有档位）：方括号行是什么；转出来的字可能有错字，按意思理解；只有 `[语音 8秒]` 的，这会儿听不了（上课、图书馆、宿舍有人睡觉，看她此刻在干什么）就像真人那样让对方打字，
   能听的时候就当听过了，顺着前后说的接，别编语音里说了什么；只有 `[图片]` 的，问一句「这是啥」或者就着对方的话接，不假装看见了；她自己只打字，不写方括号。
8. **出口检查**：行首照抄 `[语音`、`[图片` 的写法（假装发语音、发图）带说明重写一次，还在就删掉那一行（和做不到的事一样）。句中提到的（「你发的[语音]我在上课听不了」）不算。
   做不到的事里「发语音」前面三个字以内有「你」的不算（「你发语音干嘛，我这没戴耳机」说的是他发的）；「给你发语音」照旧由「给你发」拦。
9. **看图只留口子**：`media.ts` 的 `ImageDescriber`（给图片 URL，返回一两句话的描述），配了就和 OCR 一起跑，写成 `[图片：一只橘猫趴在窗台上；上面写着：……]`。
   配置 `vision`（`provider`、`model`、`baseUrl`、`timeoutMs`）有这一节才看图；还没有实现任何提供方（`VISION_PROVIDERS` 是空的），现在配了会报错「还没有接任何看图的模型」。
   接的时候：实现一个 `ImageDescriber`（key 从环境变量 `QQBOT_VISION_API_KEY` 读），名字加进 `VISION_PROVIDERS`，`app.ts` 按名字建，插件表单再加一组。
10. **开关**：配置 `media`（默认开；插件表单「联系人」组的「听语音、看图上的字」）。关了和以前一样，什么都不调。
11. **模拟器**：`say` 里一条可以写 `{ "voice": "转出来的字", "seconds": 8 }`（空串 = 没转出来）、`{ "image": "图上的字" }`（空串 = 没字），按上面的写法变成一行。新场景 `media-boyfriend`。

## 遗留

- **线上默认仍看不到图里画的是什么**：ADR 0055 已接好 `deepseek-flash`，但开关默认关、尚未在虚拟机上线；打开前照片仍只认 OCR 的字。
- 语音没在线上真试过（他没发过语音）；`fetch_ptt_text` 要 NapCat 的 id 表里有这条（实时推来的、补回拉过的都有），NapCat 重启之前的旧语音补回时会先被拉历史登记上。
- 秒数靠本机的语音文件：NT QQ 收到语音时不一定马上把文件下到本地，下没下要上线后看；没下就只是不写秒数，听的时间按字数估。
- 没字的照片每张多等 5 秒、NapCat 那边留一个不回的调用；照片多了要看 NapCat 的内存。
- 视频、文件、转发的聊天记录照旧是占位符。

## 留给用户定的

1. **是否在线上打开看图**（用户 10-10 13:27：暂时不接；晚些时候的实现见 ADR 0055）：现在不再需要新 key，打开后每张普通图片会多一次 DeepSeek 调用，图片会发到 DeepSeek 服务器。
2. **在上课时转出了字的语音**（用户 10-10 13:27：**照字回**，不藏）：现在她直接按转出来的字回（像在课上点了「转文字」）；如果更想要「上课不听，让他打字」，可以在上课时把转出来的字藏起来。
3. **没字的照片多等 5 秒**：要更快可以把 OCR 的上限调短（有字的本机 1 秒内回来），代价是网慢时大图的字认不出来。
