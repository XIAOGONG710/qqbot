# ADR 0257：提示词预算先保住当前这一句

- 状态：已实现
- 日期：2026-11-04
- 模块：说话（第 1 个模块，第二轮深挖）
- 关联：[ADR 0256](0256-speaking-direct-answer.md)、[ADR 0049](0049-chat-day-markers.md)、[ADR 0190](0190-learn-from-real-chat.md)

## 发现

`buildPrompt()` 原来先从上下文预算中扣掉全部角色卡、运行时背景和末尾指令，剩余空间才给聊天记录。控制台功能越开越多时，召回记忆、世界事实、连续性和当轮说话规则会一起增长；一旦固定部分占满预算，刚收到的最后一句也可能完全进不了模型。

`pinExamples` 开启时，示例对话还会先于聊天记录占预算，同样可能挤掉当前消息。此时模型虽然拿到很多“该怎么说”的规则，却看不到正在回答什么。

## 决策

1. 固定部分算完后，先为最新一条聊天及其日期标记预留空间。
2. `afterHistory` 的既有顺序同时作为预算优先级：前面是较泛的历史背景，后面是更贴近当前轮次的规则。
3. 从后向前保留一个连续的高优先级后缀；某段放不下时，它以及更早、更泛的段落全部省略，不拿低优先小段填缝。
4. `pinExamples` 仍然优先保留示例，但示例不能使用最新聊天的预留空间。
5. 运行时只记录省略段数，不记录被省略的记忆、事实或聊天内容。

## 边界

- 不截断单段文字，避免把规则截成相反或残缺的意思。
- 不改变预算充足时的提示词内容和顺序。
- 如果角色卡和世界书这些固定内容本身已经超过整个上下文，仍需要单独缩减固定内容；本 ADR 只解决运行时背景和示例挤掉当前聊天的问题。
- 不修改模型、回复长度、安全闸门或状态 schema。

## 验收

- 运行时背景超过预算时，最后一条聊天仍在提示词中。
- 靠后的当前轮次规则优先保留；中间高优先段放不下时，不用更早的低优先段填空。
- 置顶示例无法挤掉最后一条聊天。
- 最终提示词仍不超过可用上下文预算。
