# 0248：手机伴侣接入 QQ / DSH 共用的短期上下文

日期：2026-11-04

## 问题

手机伴侣虽然复用了同一个 DSH 接口、状态和语气，但短期对话只保存在每台设备自己的内存里。刚在 QQ 说过的事，切到手机后看不到；手机上完整成功的一问一答，回到 QQ 的显式 DSH 咨询也接不上。

## 决定

伴侣适配器新增可选 `sharedConversation` 接口：宿主负责读取跨端最近上下文，并在一轮回复完整成功后提交 `{ question, reply, askedAt, repliedAt }`。qqbot 将它接到已有 `DshConversationContext`，因此：

- 手机请求会带入最近 QQ 消息和显式 DSH 咨询；
- 手机成功的一问一答会被下一次手机或 QQ 显式 DSH 咨询继续使用；
- 使用共享上下文时不再额外拼接设备本地副本，避免同一句出现两次；
- 模型失败、空中撤销配对或旧会话失效时不提交半截上下文；
- 解除手机配对只清理设备会话和媒体，不擅自删除宿主的跨端上下文。

没有提供 `sharedConversation` 的独立使用者保持原行为：各设备最多保存有限轮数，并按设备数量淘汰，不形成隐式跨设备共享。

这一步解决的是当前进程内的即时连贯。长期记忆仍由 owner bank / Hindsight 负责；本 ADR 不把手机原文写进公共库，也不扩大 DSH 的读取权限。

自动化验收按同一个时间线覆盖“QQ 最近消息 → 显式 DSH 问答 → 手机接着聊 → 下一次 QQ / 手机咨询读回”，同时验证共享上下文不会再与设备本地缓存重复拼接。
