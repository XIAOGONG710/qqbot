# ADR0237：记忆状态、审计链与恢复的失败边界

状态：接受。2026-11-05。

背景：记忆模块合成故障注入确认了坏状态被当作空白、归档副本恢复不符、错误泄密，以及账本追加掩盖旧断点等问题。证据见当日记忆审查报告。

决策：

- 撤回与休眠控制状态损坏时保留原件并失败关闭；封存内容核对异常仍按 ADR0161 醒来并报告，不将两类故障混同。确认休眠的归档副本必须含可直接恢复的 dormant 状态；live 状态等完整归档成功后发布。
- 异步商量使用随机提议令牌回填，只能修改同一仍有效的提议；确认、取消或替换使旧回调失效。档位屏障确认持久发布后才更新内存。
- 账本写入先按实际 JSON 表示规范化元数据，并在锁内重读、验链、追加、发布 head。SQLite 仅作 OS 协调锁，JSONL/head 是事实源；禁止把协调文件当数据源或运行中删除/替换。所有写者须统一升级。
- JSONL 与 head 的两文件窗口发生故障时保留证据并拒绝继续追加，不能自动重放、重算 head 或截去坏行来“修复”。50ms 是争锁预算；不承诺网络文件系统、断电 fsync 或外部非合作写者的事务性。
- Hindsight 每个 HTTP 请求具有包含读取正文的 deadline，成功响应运输上限8 MiB（不是记忆保留策略或服务器 token 配额）；异常仅输出安全类别和 HTTP 状态，不输出响应正文或带身份的路径。超时会取消 reader，忽略 abort 的实现也不能阻塞调用方；尚未实现整个多页/多请求业务的统一 deadline。
- 隐私恢复资料用独立原子目录预留，旧公共库仅凭可证明的标准 bank 哈希归属清理。无法证明的范围写明局限。归档/遗忘仍没有跨本地文件与外部 API 的全局事务，也没有覆盖 bot 并发启动的全程操作锁，继续审查。

不改变危机、披露、换档、记忆变淡周期和留存产品策略；不访问真实私密数据验证。
