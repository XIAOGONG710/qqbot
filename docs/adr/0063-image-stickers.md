# ADR 0063：她自己的图片表情收藏

- 状态：已实现，默认关；真 QQ 单图技术冒烟已通过，尚未完成 collect 描述核对、未上线
- 日期：2026-10-12

## 背景

ADR 0051 让她能发送 QQ 自带小黄脸，ADR 0052 / 0055 让她能读取普通图片；但图片表情仍只会以 `[动画表情]` 进入聊天记录，她既看不到具体内容，也不能把喜欢的保存下来再用。角色卡还把所有图片一概写成“发不了”，与新增能力冲突。

用户希望图片表情有真实来源，而不是模型临时编一个名字：她可以自己找，也可以遇到别人发来的、自己喜欢的表情后下载收藏，以后在合适语境里发送。

## 决策

1. 新增独立的本地收藏库 `dataDir/stickers/`：图片文件以内容 SHA-256 的前 12 位作为稳定编号，`index.json` 记录客观描述、短标签、来源、收藏时间和使用次数。PNG、JPEG、GIF、WebP 单张最多 5 MB；同内容只留一份。库最多 80 张，满了以后淘汰最久没用的，不再因为到顶而停止学习新表情。
2. 第一阶段只对 `boyfriend` 档工作：只有这个档位收到的表情会进入候选，只有这个档位会看到收藏清单并可能发送。`classmate` 等其他档位既不收藏也不读取全局清单，避免把男朋友发来的亲亲、抱抱、想你类表情转发给别人。后续若扩档，必须先给条目增加并验证 `audience`，不能直接共享全库。
3. 五种候选来源：
   - 启动后及之后每小时，从持续更新的 ChineseBQB 公开目录抽取当天固定、按安全类别轮换的网络候选；目录缓存一周，只保存过滤后的元数据。类别必须在代码白名单内，时政、疫情等类别即使误加白名单也会被第二道规则硬拒绝；
   - 从 NapCat `fetch_custom_face` 返回的 QQ 自定义表情池继续看没看过的候选；
   - `dataDir/stickers/inbox/wechat/` 和 `inbox/web/` 里的本地 PNG/JPEG/GIF/WebP，可放微信导出的表情和从浏览器保存的图片；
   - `dataDir/stickers/inbox/urls.txt` 中一行一个 `http/https` 图片直链，供其他网站或人工找到的候选导入；
   - 男朋友档联系人实时发来或停机期间补回的图片表情。其他档位和名单外联系人不触发收藏。
   导入箱、网络目录和 QQ 自定义表情共用“每小时最多审看 3 个”的预算，优先级依次是本地文件、人工直链、公开网络候选、QQ 自定义表情；收到的表情不占定时发现预算，但仍在同一后台队列串行处理。
4. 候选后台串行处理，不延迟收消息和回复：先由已配置的看图能力得到客观描述，再用一段固定、简短的收藏偏好判断是否喜欢。收藏判断只收到图片描述和 QQ 摘要，不收到聊天原文或完整角色卡。广告、二维码、政治、色情、猎奇血腥、私人照片、只有大段文字或看不清的候选不收。
5. 已看过的候选 URL 或本地文件签名只保存哈希，最多 500 个。无论收没收藏，重启后都会继续向候选池后面翻；短期 URL、rkey 和本机导入路径不进提示词、聊天记录和日志。导入箱里的原文件不删除，收藏的是按内容哈希命名的副本。
6. 回复时只把最多 12 个本地存在的收藏列给模型。发送协议是单独一行 `<sticker:编号>`：编号必须在清单中，不能夹在文字里，一轮最多一个。未知编号、混排指令和第二个图片表情直接清掉；不允许模型传 URL 或本地路径。没有发送权限的档位也会清掉模型幻觉出的内部编号和 `[表情包……]` 文字占位符。最近 8 条她的回复里已经发过图片表情时不再给清单，因此不会连续发，也不会高频刷图。
7. 发送走 OneBot `image` 消息段，`file` 是已经下载的本地文件，两个运行入口行为一致。发送成功后，聊天记录不保存内部编号，而保存 `她发了个表情包：<客观描述>`；这让提示词、长期记忆、日记/周记、上下文摘要、重复检查和统计读到的是可理解事件。模型直接生成同形文字会被清掉，只有真实图片发送成功后才能写入这种记录。发送成功还会增加使用次数；选择清单优先展示用得少、较早没用过的，避免固定刷一张。
8. 他直接提问、说自己的事或好消息、认真难过、生病、很累、聊考试/工作/家里/钱等正事、要照片、或她刚被消息吵醒时，都不向模型展示图片表情清单；即使模型硬输出有效编号也会删除。普通照片、相册图片、语音、电话和视频仍然做不到，只有运行时明确列出的收藏图片表情例外；对方要照片的轮次不能拿表情包糊弄。
9. 配置项 `stickers` 是三档而不是布尔值：`off`（默认）完全关闭，`collect` 只看图、判断、下载并写日志，绝不进回复提示词或发送，`send` 才允许男朋友档使用。需要先在 `collect` 核对至少前 20 个真实候选的描述，再经用户当场授权完成一次真 NapCat 发图，才可切到 `send`。

## 同步进 QQ 账号的「收藏的表情」（2026-10-12 用户要求：「能不能让她直接放在 QQ 的表情收藏中」）

- 用 NapCat 的 `add_custom_face`（本地文件加进收藏）和 `fetch_custom_face_detail`（列出收藏：md5、resId、url）。10-12 在她的真号上试过一次：加 1 张 → 列出来能看到大写 md5 和 resId（试完用 `delete_custom_face` 删掉了，没有留在收藏里），各步 retcode 都是 0。
- 收藏库每收一张就同步加进 QQ 收藏（串行、隔 2 秒一个，失败只记日志、本地收藏不受影响）；**只加不删**（用户 10-12：「可以进 QQ 应该就不需要删除了，存着就行」）：本地收藏满 80 淘汰时 QQ 收藏里仍然留着。补同步时一批里有一张失败（比如 QQ 收藏满了）就停掉这一批，不每小时刷同样的失败。上线前就收了的存货，每次发现（启动和每小时）补同步最多 10 张。`index.json` 的每一项多一个 `qq: { md5 }`。
- 因为 QQ 收藏池现在装着我们自己同步进去的，`discover` 改用 `fetch_custom_face_detail` 并跳过已知 md5，别处加进来的才当新候选。
- 它让这个号的 QQ 客户端「收藏的表情」面板和她的收藏一致，但**发送链路不变**：仍然是本地文件作为 image 消息段发出（已在真 QQ 验证过）。QQ 收藏一般有数量上限（普通账号 300 个）；只加不删的话，每天 3 张加他发来的，大约几个月会碰到上限，到时只会记失败日志、本地收藏照常，需要的话那时再清。
- 没验证：GIF 加进收藏的表现（只在真号上试了一张 JPG）；上线后看第一批同步的日志。

## 当前边界

- “自己找”当前包括 QQ 账号已有表情和持续更新的 ChineseBQB 目录。公开目录按周刷新缓存、每天换一批，能跟随上游新增类别，比写死一组旧梗更接近当前网络；它不是实时热榜，不能保证每张都是当日热门。没有稳定、授权的热榜 API 时不抓搜索引擎页面；以后可替换 `trendDiscover`，不改收藏和发送协议。
- ChineseBQB 的 README 明确发布开放数据源，但仓库当前没有许可证文件；所以这里只按用户请求用于本机私人聊天、图片不进本仓库也不二次分发。若以后商业使用或公开分发，必须先取得清晰授权或换成有许可证的来源。
- 收藏判断和实际图片内容都依赖 ADR 0055 的外部看图接口，因此只有用户明确打开 `vision` 并把 `stickers` 设成 `collect` 或 `send` 后才工作。GIF 当前只能依赖看图端实际支持的帧，带字图也可能误读；`collect` 阶段就是为真实校验这些风险。
- 暂不自动把图片加入 QQ 客户端的云收藏；机器人会把本地收藏作为 QQ 图片消息发送，因此她在聊天里可以使用，但不会出现在 QQ 客户端“收藏的表情”面板。这样能跨重启复用，也避免依赖 QQ 收藏写接口的版本差异。

- 七档角色卡重新生成，明确区分“照片 / 普通图片做不到”和“运行时列出的收藏图片表情可以发”。

### 真 NapCat 发图预检（2026-10-12）

- 经用户当场明确授权，只向配置中的男朋友联系人发送一次原创、无文字、无隐私的紫色小猫 PNG；没有改配置、重启或部署机器人。
- 通过当前本机 NapCat 的 OneBot `/api` 调用 `send_private_msg`，消息只有一个 `image` 段，`file` 直接使用 Windows 反斜杠绝对路径，并带 `summary` 与 `sub_type: 1`。
- NapCat 返回 `status: ok`、`retcode: 0`、消息 ID `581292136`。因此当前环境不需要把本地路径改写成 `file:///C:/...`。
- 这只证明真实发送链路可用，不等于图片描述可靠；`stickers` 仍保持 `off`，必须完成前 20 个 `collect` 候选的人工核对后才可考虑 `send`。

## 手工导入方式

1. 保持 `stickers: "collect"`，不要直接开 `send`。
2. 微信导出的表情图片放到 `dataDir/stickers/inbox/wechat/`；网页保存的图片放到 `dataDir/stickers/inbox/web/`。子目录也会递归读取。
3. 只有图片直链时，写入 `dataDir/stickers/inbox/urls.txt`，一行一个；`#` 开头是注释。网页地址、搜索结果页和登录页不是图片直链，不会导入。
4. 机器人连接后立即检查一次，之后每小时再检查；每小时最多看 3 个。看图、收藏判断、内容去重都通过后才进入本地库，原文件保留。
5. 在日志和 `index.json` 核对至少前 20 张真实图片与描述；确认准确后再单独决定是否切到 `send`。
