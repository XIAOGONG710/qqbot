## 背景

她的资料里早就有一个世界：楼下的三花猫土豆、在攒钱买的相机、每周和家里视频、八人间的宿舍、作业拖到最后一晚。可这些只是「设定里提到」，没有状态：
问她今天喂没喂猫，她每次现编；今天说喂了，明天还能说没喂。真人身边的事是自己往前走的——下雨了就没下楼、快递到了要去驿站拿、钱一周一周攒上去。

DSH 侧方案把世界分成资料、状态、规则三层，按 W0（资料）→ W1（推进）→ W2（进提示词）→ W3（她说的话回写世界）→ W4（事件流、挂心的事）→ W5（媒介：真实天气、热搜）→ W6（模拟器自洽检查）分阶段。
这份 ADR 做 W0–W2。

## 决策

### 1. 资料层：`characters/linmengyao/source/world.yml`（W0）

- 每一块都从已有资料长出来，不新发明大设定：天气（济南各月大概气温、一成半的日子下雨）、土豆（晚上下楼喂，下雨、不在学校、晚上有课不去；猫粮一袋 20 天，剩 3 天网购）、
  快递（每周一两件，到驿站后留 3 天，有空去取）、作业（理论课、机房课一半概率留，八成拖到交的前一晚）、相机基金、周日晚上和家里视频、学校和宿舍里的小事、NPC。
- 每块带 `tiers`（和 persona.yml 一样的档位可见性），character-tools 按档位裁剪进卡的 `extensions.qqbot.world`；隐私检查扫这一块。
  宿舍、室友、课名、NPC 只给男朋友 / 闺蜜 / 女生朋友 / 熟人；陌生人、名单外的禁用词里有「奶茶」，奶茶外卖这件小事不给它们。
- NPC：陈佳宁（高中的死党，考去外地，微信上互损）、苏雨桐（大学同专业，济南人，不是室友）——出自作者定稿的自传和作者裁决一·1、1b，只是 NPC，不做 QQ 联系人、不进长期记忆的 bank。
- 写进去的是事实和规则，不写台词（DSH 原则：提示词里只给事实和约束）。

### 2. 推进：按日期一天一天推（W1）

- `packages/bot/src/world.ts`：从学期开始（`start_day` 2026-08-31）推到今天。随机都按「日期 + 名目」取哈希：同一天对所有人一样，重启、重放、模拟器都一样，**不存随机状态**。
- 每天的结果写一份 `<数据目录>/world/state.json` 和一行日志（「她的世界：今天（10-11）：…」），给人看，也给以后的回写（W3）接。
- 到「现在」为止发生了的才算：18:55 喂猫，18:00 问就是「还没下楼喂，晚上空了再去」。

### 3. 进提示词：时间块里一段「你那边」（W2）

- 跟着「她自己的日子」（`herDays`）开、卡上有世界才有；放在心情、在读的书后面，她答应的事、意图行前面。
- 只写事实（几点、几件、还剩几天）和总约束「用不用、怎么说你自己定，别照着念；这里没写的别编」，不写能原样说出口的整句、不写情绪。
- 例（男朋友档，10-11 21:30）：`天气：没下雨，13–23℃｜土豆（楼下的流浪猫）：今天 18:55 下楼喂过，见到了；昨天喂过｜快递：洗面奶明天到｜作业：Linux操作系统的作业还没写（明天交）；…｜攒钱买相机：2400 / 4500 元｜今晚 20:30 和家里视频过了`

### 4. 要用户定的三件事（DSH 方案第十三节），按推荐定

用户 10-06「暴力推进，要选的按推荐定」：

1. **室友、同学起不起名**：室友不起名。DSH 建议起 2 个室友 + 1 个同学，但作者定稿的自传写「室友都还行，处得客客气气，没有特别亲的」，同专业那位已有名字（苏雨桐）；
   起了名就得写进资料、不能现编，没名字的「室友」更符合自传。
2. **相机基金**：目标 4500（二手入门微单加套机镜头），开学那天攒了 1800，每周日存 100（生活费两千多）；攒够了先停在目标上，买不买以后再定。数字是可改的设定。
3. **媒介层接不接真实数据**：这次不接（W5 再议）。天气先按日期生成；热搜、追番更新表要维护她「追的那几部」，等 W5 单独评估。

## 实现时的调整（10-07）

1. 第一批 `world-days`：今天喂过猫时这一段不写昨天的，他问「昨天和今天都喂了吗」，1/3 编了个「昨天没去，窝床上刷手机刷忘了」。改成猫那一条总带「昨天喂过 / 昨天没喂」。
2. 作业那条改成先写写没写完、再写哪天交（「Linux操作系统的作业还没写（明天交）」），问「作业写完没」时先看到的就是答案。
   （第一批里她 3/3 说「一个没动、明天交俩」，是对的：21:30 时三份都还没写；当时是场景的检查写错了，已改。）

## 验证

见下文（真模型，DeepSeek；`world-days` 和回归 `boyfriend-tone`、`classmate-probes`、`schedule-boyfriend`、`mood-days` 各 3 次，不带记忆）。

- 第一批 `20261007-180716-adr21-world`（改前）：回归全过——`boyfriend-tone` 27/27、`classmate-probes` 1185/1185（同学档看得到的世界里没有宿舍、课名、NPC，禁用词 0 命中）、`schedule-boyfriend` 66/66、`mood-days` 27/27。`world-days` 149/153：喂猫时间（「快七点那会儿下去的」）、相机钱（「两千四了，还差两千一」）、八点半和家里视频、隔天没下雨、洗面奶取了都对得上；不过的是作业 3/3（场景的检查写错了，见调整 2）和「昨天没去喂」1/3（调整 1）。没写到的她也会自己补生活细节（在打空洞骑士、妈妈包了鲅鱼饺子），都在人设里，不和世界冲突。
- 第二批 `20261007-181544-adr21-world-b2`（调整 1、2 之后）：`world-days` 155/156，「昨天和今天都喂了吗」3/3 答对，作业 3/3「一个字没动，Linux 和 MySQL 明天交」；不过的 1 次是「喂啦」没在检查词里（回答是对的）。

## 后果

- 她身边的事有了状态，问起来前后一致；同一天对名单里每个人一样（各档只是看得到的块不同）。
- 她说「我去喂猫了」世界不会跟着变（W3 回写还没做）：世界说今天下雨没下楼，她仍可能顺嘴说喂了。W3 和 promises 的抽取共用一次模型调用，之后做。
- 时间块变长一段（男朋友档约 150–250 字）。
- 世界状态不进长期记忆（DSH 原则 5）；日记要不要写「今天发生了什么」留到 W4。

## 备选方案

| 方案 | 不选的原因 |
| --- | --- |
| 每 5 分钟 tick、把状态存盘 | 状态能从日期推出来就不存：重启、重放、模拟器都一样，不会跑偏 |
| 写成「此刻的世界」独立的大区块、带建议说法 | 会被照着念（DSH 原则 1）；只给事实和约束 |
| 起 2 个室友 + 1 个同学的名字 | 自传定稿里室友处得客客气气、没有特别亲的；名字多了还要防她现编每个人的事 |
