# ADR 0223：DSH 连接层

## 状态

已实现连接层和可开关的 Koishi 插件功能，默认关闭、不自动调用。

## 背景

项目里的“DSH”有两个容易混淆的含义：一是她目前已经使用的 DeepSeek OpenAI-compatible API，二是 `DEEPSEEK_HANDOFF.md` 描述的另一个独立审阅 / 接手会话。后者不是本进程可以直接访问的 API 端点，不能把“读过交接文件”当成“已经连上 DSH”。

## 决策

新增 `packages/bot/src/dsh-link.ts` 作为明确的桥接边界：

- `probe()` 发一个最小的 `ping` 请求，验证 API、key、模型、网络和现有重试闸门；
- `advise()` 只接收脱敏问题、状态摘要、当前档位的最小语气档案，以及用户明确发起 `/dsh ask` 时最近最多 6 条 QQ / DSH 对话；输出直接可接回 QQ 的短回复，不直接改普通聊天、关系账或世界账；
- 手机伴侣通过 `packages/bot/src/mobile-companion-dsh.ts` 复用同一 `DshLink`、脱敏状态和语气回调；上下文按 `clientId` 隔离并限长，避免 QQ 与不同手机互相串话；
- 默认不在每轮聊天里调用，避免重复计费、延迟翻倍和无授权外发；
- 在 Koishi 控制台的「DSH」开关中随时启用 / 停用；关闭时 `/dsh` 不会截获消息，也不会发模型请求；
- 复用现有 `QQBOT_LLM_API_KEY`，不新增密钥落盘；
- 问题字段会去掉常见 QQ 号、API key、token 和密码格式，状态只允许数字值、档位和事件类型摘要。

## 使用

在配置和环境变量有效的机器上运行：

```text
npm run dsh:link -w @qqbot/bot -- probe
npm run dsh:link -w @qqbot/bot -- ask "请审阅当前真人式数值的联动风险"
```

运行中的男朋友档也可以显式发：`/dsh probe` 做一次连通性探针，`/dsh ask <问题>` 做一次受控咨询。裸 `/dsh` 仍保留 DSH 原有的工作模式切换语义，避免破坏既有行为。咨询会复用她当前档位的名字、性格和说话方式，并带入最近最多 6 条 QQ 对话，因此 DSH 回复可以直接接回 QQ 语境；它不会自动写回世界账或关系账。

配置形状：

```json
{ "dsh": { "enabled": false } }
```

需要连接独立的 DSH 兼容接口时，可在 `dsh` 下额外填写 `baseUrl`、`model`、`timeoutMs`；不填写就复用主 `llm` 配置。两种方式都只从 `QQBOT_LLM_API_KEY` 取密钥，不在配置文件落盘。

探针失败只说明当前链路没打通，不会修改运行数据。要让 DSH 参与每一轮回复，仍需单独决定它的角色：主模型、深思模型，还是只做外部审阅；在该决定之前不自动把建议注入 QQ 回复。

## 隐私边界

只有用户明确发送 `/dsh ask` 或 `/dsh talk` 时，才读取该用户最近最多 6 条已落盘聊天，并合并本次进程里最近最多 6 条 DSH 问答作为连续性上下文；每条截短并经过凭据 / 身份字段脱敏，不读取更早聊天、日志或 Hindsight 内容。语气档案只取当前卡的名字、描述和性格，不发送世界书、禁用词或长期记忆；不记录 API key。DSH 命令不会污染普通 QQ 聊天记录。
## 手机伴侣配对入口

当 DSH 开关开启且消息来自男朋友档时，`/dsh pair` 生成一个随机 Android clientId 和短期一次性配对码，并只通过 QQ 私聊返回给用户；配对码不写入普通日志、状态页或聊天记录。手机端后续必须使用同一 clientId + 配对码走 CompanionGateway。
