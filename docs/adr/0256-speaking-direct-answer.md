# ADR 0256：说清楚的问题先直接回答

- 状态：已实现
- 日期：2026-11-04
- 模块：说话（第 1 个模块）
- 关联：[ADR 0207](0207-open-questions.md)、[ADR 0202](0202-depth-routing.md)、[ADR 0149](0149-answer-then-continue.md)

## 模块分析

“说话”模块已经形成五层：先理解整轮和指代，再判断轻重与意图，然后决定长短、分条和是否追问，最后做事实与口吻检查，并把他的反馈和她自己的夜间复盘留到后续对话。优点是规则分层、危机路径优先、私人内容不进日志，并且主要行为都有单元或端到端测试。

这轮按“是否会直接破坏对话”排序后，最高优先级缺陷在 `language/reading.ts`：`readingLine()` 对每一轮普通男朋友对话都追加“没把握就问他指的是哪件”。即使这句话没有指代、问题已经完整，这条保险提示仍会与深思、她自己后来想过的内容竞争。ADR 0207 的模拟已经记录到 2/12 次只反问“你指哪件事”而没有回答。

其余待后续逐项处理的风险：

1. 多条说话规则同时进入提示词时缺少统一的冲突优先级和长度预算。上下文预算的第一层保护已由 [ADR 0257](0257-latest-turn-budget.md) 完成。
2. 控制台能看到开关与局部趋势，但还没有一张“直接回答率、无谓澄清率、重复追问率”的说话健康摘要。
3. 真人语料、盲评和线上反馈仍是分散工具，缺少固定的模块验收样本集。

## 决策

将理解提示改成三种明确路径：

1. 没有指代候选：问题已经说清楚就直接回答，不为保险反问。
2. 只有一个候选：优先按唯一候选理解；只有仍存在两种以上合理解释时才确认。
3. 有多个候选：先根据上下文选最可能项；确实无法区分时才简短确认，并先回应已经说清的部分。

三种路径都禁止把整轮只回成澄清反问。这里不让代码替她决定观点，只减少无意义的“你指哪件”。

## 边界

- 不修改危机处理、联系人权限、事实检查或模型选择。
- 不猜测真实指代；多个合理候选无法区分时仍允许确认。
- 不新增开关或状态文件，回滚只需恢复 `readingLine()` 的旧提示。

## 验收

- 无指代的完整问题包含“直接回应”，不再包含“没把握就问”。
- 单候选优先直接理解，多候选仅在确实无法区分时确认。
- `openQuestions` 端到端提示同时带入她自己想过的内容和“直接回应”规则。
