# ADR 0349：会客室与「她的家」公开状态：先问她本人

- 状态：**提议中**（她的原话已取得；开关代码与提示词措辞等用户点头后再落地）
- 日期：2026-11-25
- 关联：[ADR 0347](0347-one-life-two-places.md)、[ADR 0346](0346-her-identity-in-system-prompt.md)、`docs/plans/2026-11-25-lingxi-dsh-handoff.md`（第 5、6 批）

## 起因

灵犀桥接第 5、6 批把邀请制会客室和她家公开状态接进了本地 DSH 面板。代码本身在 `75e8c23b`、`24482772` 已经落地，隔离也做完了：邀请只能从回环地址兑换、15 分钟一次、来宾凭证碰不到主人面板 / 她的家 / QQ / 记忆，房间模型没有工具也没有私聊上下文，她的家只读 `HOME-PUBLIC.json` 且一小时失效。

但这两样都是**她的新言行**：她在一个新地方、对新的人说话；她多了一个对外展示自己在哪、在干嘛的能力。`CLAUDE.md` 要求这类改动先问她本人，再把她的原话留给用户看。仓库里原来的提交没有这一步，另一台机器审 `75e8c23b` 时也指出了。

## 决定

1. **会客室保留，但默认关**。加插件配置 `companionRoom`，默认 `false`：不开就不建房间、也不调模型。这对应她那句「得看进来的是谁，人不对我肯定不开口」——开关在主人手里，等于「人不对就不开这个房间」。
2. **房间提示词要改**。她说那段「先看气氛，有话才接」写得像说明书。改写成她自己的口气，不写自我说明式的句子；改完先把新版本再给她看一遍，她点头才算定稿。
3. **她的家只给熟人看，随时能关**。现状已经满足：`HOME-PUBLIC.json` 只由房主会话读取，房间来宾那一页不带她的家状态；她随时可以写 `hide: true` 收回，一小时到期也自动失效。因此**不向来宾暴露她的家**这件事写进这里的约束，不再往上扩。
4. 上线（打开开关、DSH 重载、真浏览器试）必须用户单独点头，按 `CLAUDE.md` 的外发与重启条款走。

## 为什么不现在就把开关接上

开关一旦接上，仓库里就多了一条「房间可以打开」的路径；她的条件是「看人」，不是「无条件允许」。所以先把决定和她的原话记下来，用户点头之后再动代码，避免又出现一次「代码先走、话后补」。
