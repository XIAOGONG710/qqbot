# ADR 0229：世界账故障恢复与时间前置

- 日期：2026-11-05
- 状态：采用，分工作单元实施
- 证据：[世界账审查](../reviews/2026-11-05-world-review.md)

## 决定

1. 行动队列先原子写盘再发布内存。安排、改期、取消、提前停和删除写失败时，原内存与磁盘共同保留，不能让同 ID 重试返回未持久化的假成功。事件账已经提交但队列清理失败时保留项目，依赖事件 ID 幂等重试；确认事实和死信落盘失败也不得丢计划。
2. events 为权威账，actions 为兼容投影。主账写成功即为事实；兼容写失败必须保留权威内存与 dirty 状态，下一次事件或同 ID 重试均可修复，不能用旧内存覆盖已落盘事实。
3. 持久事件必须有真实日历/时间、非空身份和安全整数财务/联系人数据，ID 唯一。坏文件保留并明确失败，错误不泄漏正文；瞬时 IO 错误仍可重试。
4. 当前投影不能提前消费尚未到时刻的资金、取件补给或课程作业。每顿饭的 NPC 同伴按实际占用匹配，不以全日第一条社交推断另一顿饭。饭后叙事在窗口里随机取钟点，须派生明确 mealKind，不重写历史事件 at，也不能用叙事钟点直接推断饭点。
5. 不合作的天气供应商也必须有独立截止；过期结果没有落盘通路。缓存损坏不作为空文件覆盖。ADR0048 已有历史补观测政策保持不变，回放仍不得读截止时刻之后的观测。
6. 节日合并用可克隆来源标记，只更新本模块生成的未来项，不删除作者资料或改写已开始活动；旧无来源项保守视为作者输入。
7. NPC 月段次数限制 0–31 的有限数，持续范围为 1–14 的有序整数（沿用既有 MAX_SPAN 上限），概率为 0–1；限制用于保证同步工作量有界，不是医学判断。已答应邀请按通知时间和稳定身份协调，不能让多个 NPC 独立占用同一时段。
8. 同名课程的下一课截止修复必须先具备跨披露档稳定分组身份，不能按空课名或课型猜分组，也不能只修高档而引入跨档事实分歧。该依赖完成前保留既有行为并记录 W10 待修。

## 验证

通过合成事件、假供应商、隔离进程和磁盘故障注入验证，再执行相关测试、类型检查和最终全量。正常财务事实锚点保持，不以盲改断言掩盖回归。工作单元与提交见持续进度。
