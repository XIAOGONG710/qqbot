# 0231：本地日历构造与四位年份边界

日期：2026-11-05

## 证据

W22：真实日期 0099-11-01 可通过日历解析，但多处 `new Date(y, m, d)` 将年份加上 1900。只修 world.parseDate 不够，herDay、日界、加日、课表、NPC、钱和直接调用方会再次错误构造。0099→0100 跨年时，提示词和时间线甚至不再把前一日称为昨天。

另有快递和相机的有限日期加法越过 9999 年，输出五位年份，超出事件账采用的四位日历格式。有限 Date 并不等于可持久化日期。

## 决定

共享 localDate 对 0–99 年先在中立日历归一化溢出的日/时钟，再用 setFullYear 与 setHours 构造本地日历，不作 1900 偏移；其他年份直接沿用原生构造，保留 DST、时钟溢出及整日跳过政策。显式 undefined 仍为无效参数。生活、世界与直接调用方使用同一工厂，单参数 Date（时间戳、ISO、克隆）保持原样。四位年份按原公历年份补零，不借修复随意限制年份下界。

配置日期偏移按中立民用日历计算，并校验计算后仍可表达为四位日历日期。不能把实际本地时刻转成 UTC 后的日期误当作本地日期边界。

W23 同时确认课表学期、假期、调休、起床抖动和活动生效日只检查外形、接受不存在的日历日。源与运行时日期入口统一检查公历日真实存在，拒绝错误时不回显输入正文；不借此更改活动排序或猜测重排历史课表。

W24：菜单/日常小事的既有 v1 生效锚点也必须是真实日期。过去对坏 JSON 的自动隔离并重建次日锚点是原有设计，不计作一个新增缺陷；本次有意将这两项历史事实锚点加强为失败关闭。已有坏 JSON、形状或版本保持原路径/原字节并报安全错误，瞬时 IO 错误保持原类型；仅文件不存在才按原规则创建。合法旧锚点（含年末）原样保留。恢复需修复文件，或明确删除后接受重新启用；不静默迁移已有事实。两处旧自动重置断言按这个明确决策更新。

回忆 localIso 同样补齐四位年份；历史时区可能含秒级偏移，而 getTimezoneOffset 只给分钟。如果本地编码不能往返同一整秒时刻，使用 UTC ISO，保持现代正常时间戳的输出。

运行时在订单、选中事件、行程、日常时长、通知、动作与天气缓存写入边界守界；不递归重扫整条历史时间线。仅计算用的内部窗口可短暂超出四位年，外部查询/输出或账本瞬时无法编码时明确拒绝。年 0000 的日期本身合法，但部分本地年初小时对应负的 UTC 年，不能写入现有四位 UTC 账本；同理负偏移时区末年的 UTC 边界。下一课搜索到支持范围外即停止，不制造错误未来课。

检查同根调用方时也修正了语言/B站派生记录的 UTC 日数和补零，以及周报、预览 CLI、模拟器夜间阈值的数字日期构造。这些是日期修复余波，不代表已完成这些模块的全部审查。无真实数据文件或服务被迁移、调用。

## 验证与兼容约束

使用合成数据复现并回归低年份、0000 年闰日、0099→0100、现代闰年、年末偏移与超范围输入；以多个现代年份、月份、日和时钟溢出组合对比原 Date 构造器，补查上海、UTC、纽约 DST 与 Apia 整日跳过。初版两步工厂被 Apia 2011-12-30 回归抓到兼容差异，已通过现代年原生分支修复。既有事件账保持原样，不猜测修复此前错误运行产生的外部历史数据。
