# ADR 0081：他引用她的某句话再回，她看得到被引用的是哪句

- 日期：2026-10-19

- 用户授权：2026-10-19 09:14「继续」——做和测；上线仍要用户在场点头。

## 背景

QQ 的「引用回复」是 `reply` 段，里面只有被引用那条的消息 id，没有内容。`segmentsToText` 一直对它返回空字符串：他长按她下午的一句话、回「为什么啊」，她看到的只有「为什么啊」。聊得久了、她隔了几个小时才回的时候，这很常见。

真模型试过（聊天记录：下午她说「我周三有早八，烦死了」，晚上聊吃饭；他引用那句话回「为什么啊」，6 次）：
- 只看到「为什么啊」：**3/6 答得对**（从下午那句猜出来的），另 3 次答错或带着困惑：「食堂没别的了？」「问我为什么吃饭？饿了呗」「为什么啊——我这是在问啥，吃炒面哪有为什么哈哈哈」。
- 把被引用的话写进去：6/6 都答早八（「八点上课，我七点就得爬起来」）。

## 决策

1. **按消息 id 在本地聊天记录里找被引用的那一条**（她发出去的、他发来的都记着 QQ 消息 id），写成 `[引用你说的：「我周三有早八，烦死了」]为什么啊`（他自己的话写 `[引用他之前说的：「…」]`），再接后面的文字。
2. **找不到就什么都不写**，和以前一样：不是经过机器人收发的、已经不在记录里的、id 不是数字的。不会比现在更差。
3. 被引用那一条自己开头的 `[引用…]` 不再套进来；换行压成空格；超过 40 个字截短加「…」。
4. 实时收到和停机补回都走这一份（`toStored(…, quoted)`）。
5. 没有配置开关：纯输入侧，找不到就等于没有。

## 验证

- 真模型（`sim/quote-read.json`，4 次）：3 项检查全过（回答里提到早八、八点、起床之类）。上面的 6/6 对 3/6 是同一个场景的前后对照。
- 测试：`quote.test.ts` 5 项（引用她的、引用他的、找不到 / id 不是数字 / 没给查找、不套娃、截短、补回、整个应用里存的和给模型看的都带着那句话）；backfill、app、media、runtime、qq-faces 等相关 134 项全过；类型检查干净。

## 没做 / 要注意

- **没在真 QQ 上对过 id**：`reply` 段里的 `id` 是否和 `send_msg` 返回的 `message_id` 是同一个数（NapCat 的短 id），我是按 NapCat 源码和 OneBot 的约定推的，没收过真的引用。对不上的话只是回到「什么都不写」，不会出错。上线后让他引用她一句话回一下，看日志里「收到：N 字」比平时多了十几个字就是对上了。
- 她不会引用回复他（发送侧没做，见 handoff 里的第 3 条）；要做也得在她隔了很久才回时才像人，另开一项。
- 引用的是图片、语音等：被引用那条在记录里就是 `[图片]` 这类，所以写成 `[引用他之前说的：「[图片]」]`，够用。
