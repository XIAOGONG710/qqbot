- 状态：**已实现，未上线**（2026-10-22；配置 `weeklyReport`；默认关）。上线 = `koishi.yml` 里加 `weeklyReport: true` + 重启；回滚 = 改回 false + 重启。也可不开开关，手动：`node src/ops/weekly-report-cli.ts --write`
- 日期：2026-10-22
- 关联：[ADR 0099](0099-too-smooth.md)（用数字而不是感觉）
- 用户提出：2026-10-22「把 A 全部做完」（A11）

## 为什么

10-22 一天上线了十几个改动，效果互相混在一起；要靠数字看趋势，而不是靠某一次聊天的感觉。原来是 `exchange/tools/realness-report.mjs` 手动跑一次（读线上目录）。

## 做了什么

`weekly-report.ts`：把同一份报告搬进机器人本身（读自己的数据目录）。每小时看一眼，**周日 21:30 以后、这周的文件还没有**就写 `<数据目录>/reports/weekly-<周日日期>.md`（按男朋友档；出错只记日志）。**只有数字，没有原话**：聊天内容只用来数长度、占比、间隔，日志只数行（单元测试里放一个“暗号”，报告里不许出现）。

内容：
1. 说话的样子：轮数、每条字数中位 / p90、一轮一条占比、第一条延迟（中位 / p25 / p75 / p90 / ≤15 秒 / >60 秒 / >10 分钟），旁边是真人参考；
2. 表情和语气：他 → 她的图片表情 / 小黄脸 / 「～」/ 哈哈类；她发了几张照片；问句、语气词占比；**以昵称开头：回话 vs 她先开口**（ADR 0108）；
3. 主动：条数、30 分钟内他回的占比、按时机分、内心念头；
4. 她的日子：账上行动、被打断；
5. 日志里数到的：心境、会拒绝、约他、问意见、等下之后回来、陪玩、被打断、小梗、关系阶段、照片收进货架、照片他要看、图片表情抽到、回复失败；
6. 在不在（下限）：回复失败成几次断、合计至少几小时。

## 数据

对线上聊天记录的副本跑（10-15 起 7.7 天）：他 131 条、她 135 条；每条中位 8 字 p90 17、一轮一条 81%、第一条延迟中位 8.9 秒、>60 秒 3%；问句 13%、语气词 29%（真人 18.5%）；她先开口以昵称开头 13%（8 条）；主动 9 条、30 分钟内回 67%；回复失败成 9 次断、至少 9.6 小时。

## 没做 / 要注意

- 没有自动对比“上周”（每周一个文件，人看）。
- 在数据目录里写文件，不发任何消息、不联网。

## 验证

`weekly-report.test.ts`（4 个）：各部分和数字、原话不出现（聊天、念头、她的话）、昵称开头分开数、什么数据都没有不崩；文件名按本周日、21:30 之前 / 周一不出、出了就不再出。
