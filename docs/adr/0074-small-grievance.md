## 背景

隔了很多天再来，她的第一句和第一天没有区别（「在呀，怎么啦」）。用户 10-15 说这不能接受。D2 的原文：只由对方的具体事件触发，强度按时间戳可重算，道歉 / 安慰消减，一次最多动一档，不存跨天情绪标签。

## 决策

1. **只有一个起因**：他的两条消息之间隔了 **≥ 3 天**，而且这段时间里她在回完他最后一句话之后**又发过话**（她主动发的，没人回）。隔了几天按四舍五入说（3 天 23 小时说「4 天」）。
2. **不是被晾着的不算**：他离开前最近三条里说过要消失几天（「考试周」「出差」「没网」「这几天忙」之类）；她那几天什么都没主动发过。
3. **只有一档**：没有升级、没有冷战。他回来后她最多别扭**两轮**：第一轮淡一点、短一点，点一句有来由的小抱怨；第二轮自然回暖、不再提；第三轮起没有。他回来超过 3 小时才说话的，不接着上一次。
4. **修补让它散**：他道歉 / 解释 / 哄 / 说想念（0028 的修补、安慰、亲近三类，加「这几天太忙」「手机没电」「赶论文」之类解释）。他**回来的第一串里就带着**：不别扭（余温交给 0028）。**别扭了一轮之后**才带：这一轮**和好**——软下来，接他解释的事，嘴硬最多半句，他给的理由就信，不拿它酸他，不说他把别的看得比她重要；之后不再有。
5. **不落盘**：每一轮从聊天记录的时间戳和原话重算，重启、过几天之后结果一样；没有「她生气了」这样的字段（0028 的边界守住）。
6. **让路**：危机回合最优先；他难过 / 生病 / 很累、撒娇要她哄时，先关心；他在收尾时「别扭」让路，「和好」不让。主动找他时不给。
7. **意图行只给方向不给台词**（0058）：不翻旧账、不质问、不说教、不让他内疚、同一件事只提一次、不是真生气更不是冷战。
8. **出口检查只在「别扭」这一轮放宽**：「还知道回来」「才想起我」（算账）和「也不说一声」（怪他没说）这类带点抱怨的话，在这一轮不拦；其他的毛病（助手腔、对照酸话、复读、叮嘱重复）照拦；和好那一轮不放宽。
9. **条数**：别扭 / 和好这一轮最多两个气泡。

## 这一版不做的

- **不由「说好的事爽约」触发**：那要靠模型抽取的挂着的事，会误报；先只用时间和她发的话这两个客观事实。
- **不由「他说了难听的话」触发**：玩笑里的「滚」「烦死了」太多，规则判会误报，模型判没有可靠的办法。
- 没有好感度、阶段、心情拨盘（已排除项）。

## 验证

- 单元 `test/grievance.test.ts` 14 个：触发（刚好 3 天算、差一点不算、她没发过话不算、她只回了最后那句晚安不算、事先说过要消失不算、没有时间戳 / 没有待回的话不算、回来就带着修补不算）、过程（第一轮 → 回暖 → 没有；别扭一轮后修补 → 和好一次；和好后不再有；隔 3 小时不接着；重算一致；老的大间隔不影响）、意图行边界（无台词、禁止项齐全、优先级）。
- 应用层 `test/app.test.ts` 4 个：开着时提示词里有意图、日志只记天数和轮次不记内容、「还知道回来呀」在这一轮不被出口检查拦；关着（默认）时同一句照旧被拦；先道歉不别扭、别扭后道歉和好且之后什么都没有；同学档、他难过、危机回合都不别扭。
- **真模型**（虚构对话，`--no-memory`，每个场景 5 次，共 30 次）全部通过：`grievance-return`（第一轮 5/5 都有一句轻轻的点；第二轮不再提）、`grievance-makeup`（和好 5/5 只关心他的事，没有酸话；第一版意图里「嘴上可以还留一点嘴硬」让 3/5 带酸味、1/5 说「论文比我重要呗」，已收紧）、对照 `sad-return`（先问怎么了）、`short-gap`（只隔 2 天不别扭）、`notice`（事先说过考试周不别扭）、`sorry-first`（一回来就道歉，她说「知道啦，道什么歉」）。

## 风险和上线办法

- 最大的风险：**他其实有正当理由消失却没提前说**（生病、手机坏了）。缓冲是：只别扭两轮、只有一档、他一解释就散、意图要求不质问不让他内疚。
- 3 天是个常量（`GRIEVANCE_GAP_MS`），偏短偏长都可以调；也可以改成 2 天或 5 天，**待用户确认**。
- 上线：`grievance: true` 写进 `koishi.yml`（备份）→ 重启 → 日志里出现 `小别扭：` / `和好：`（只有天数和轮次）。一次一个变量，看 48 小时；退回只要改回 `false`。上线前查 `restarts.log`，距上一次行为变化的重启要满 48 小时（`golive-check`）。
