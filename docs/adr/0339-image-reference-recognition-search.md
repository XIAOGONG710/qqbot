# ADR 0339：认图与“搜一下这个”沿用同一张原图

状态：2026-11-17 实施，未上线。

## 背景

用户发一张 Claude 拟人图，接着说“你认一下这个”“你看看能不能搜到”。旧流程先把图片压成一行外观描述；搜索只取上一条用户文字，拿到“你认一下这个”而不是图片。图片描述和检索结果因此脱节。一般视觉描述对该图只给出“身份不确定”，而将人物原图交给 DeepSeek 的服务端搜图后，返回 Claude 娘候选并核对发色、裙子和书本。

## 她的意见与用户决定

按根目录规则，通过 `node scripts/ask-her.mjs` 问她。她愿意改，并要求：先照可见特征猜、明确是猜测；搜索结果是候选，回看图片核对；认不准就说不知道；搜到的事不能说成原本就知道。用户看过原话后回答“可以”。

## 决定

- 普通图片视觉描述保留可见特征，同时允许对动漫、插画、标志提出有依据的身份猜测；不辨认真实人物，不把猜测写成事实。
- 对名单联系人，运行时只在内存里短暂保留最近一张普通图片的原始 QQ URL，最多 15 分钟。聊天记录仍只保存文字描述；重启或 URL 失效后退回文字检索。
- “认一下这个”重新把原图交给视觉模型，并将结果标为看图猜测。“搜一下这个”才声明 DeepSeek `deepseek_web_search`，让服务端按原图搜图。只有响应中真的出现搜图工具调用，才标成“已搜图”；否则退回既有文字检索。接口与用量见 [DeepSeek Web Tools 的 Image Search 节](https://api-docs.deepseek.com/guides/web_tools/#image-search)。
- 文字检索回退时，从最近图片描述组检索词，并把该描述带到资料摘录问题里。所得事实只作为候选，对照图片，不装作她原本就知道。
- 原图辨认或搜图受取消信号与超时限制；不增加 QQ 指令，不自动发起后台搜图，不把原图写入长期记忆。

## 验证与限制

合成测试覆盖图片、指代、搜图调用、候选标签与普通搜索隔离；行为基线不更新。实际人物图探针中，一般视觉描述没有识别身份，原图搜图得出 Claude 娘候选。这证明本例有改善，不代表所有角色图都能识别。搜索结果仍需对照原图，模型判断可能出错。
