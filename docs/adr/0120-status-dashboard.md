## 差距

原来的“状态”页是一列键值：插件在不在跑、NapCat 连没连上、几个老开关。10-22 一天里加了十几个开关，页面上只看得到其中三四个；要知道“现在她开着哪些功能”只能去读 `koishi.yml`。

## 做了什么

1. **功能总表** `bot/src/features.ts`：每个能开关的功能一行（key、中文名、所属模块、ADR 编号、bool / mode）。8 个模块：说话、她的日子、主动找他、照片和表情、B 站、在 QQ 上的样子、记忆和安全、工具。`featureStatuses(config)` 给出此刻每个开关开没开（mode 类带上模式：试运行 / 问候 / 会发）。
2. **漏登记会红**：`dashboard.test.ts` 核对 `DEFAULTS` 里每个布尔 / 模式开关要么在总表里、要么在 `NOT_SWITCHES`（数值 / 对象 / 字符串配置）里——以后加了新开关忘了登记，测试直接失败，页面不会悄悄漏掉。
3. **`AppStatus` 多两项**：`features`（上面那份）和 `extras`（照片货架张数 / 小梗个数 / 最近一份周报的文字，对应功能没开就没有）。
4. **页面**（`client/status.js` + 纯函数 `client/dashboard.js`）：顶上还是原来的摘要；下面多一块“功能开关　已开 N / M”，按模块分组、每组标 `开着的个数/总数`，开着的绿色靠前、关着的灰色，鼠标放上去看 ADR 编号；再下面是货架 / 小梗 / 最近一份周报；最后是原来的联系人表格。页面分组 / 标签 / 汇总的逻辑都在没有任何导入的纯函数里，Node 里直接测。

## 没做 / 要注意

- 人设 / 世界书 / 作息 / 档位 / 心情 / 书这几个编辑页没动。
- 没能在浏览器里看实际渲染（控制台要登录）；页面代码只用了原来就在用的构件（`h`、`tag`、`el-*`），通过 `node --check` 和纯函数测试，渲染要等重启后你打开看一眼。
- 周报文字最多显示前 4000 字。
