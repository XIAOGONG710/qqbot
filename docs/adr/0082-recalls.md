# ADR 0082：他撤回一条消息，她看到的是「撤回了一条消息」

- 状态：**已实现，未上线、未在真 QQ 上验证**（分支 `claude/recall`；配置 `recalls` 默认关）
- 日期：2026-10-19
- 关联：[ADR 0079](0079-poke.md)、[ADR 0080](0080-share-cards.md)、[ADR 0081](0081-quote-reply-read.md)（同类：以前她看不见或看得太多的输入）、[ADR 0068](0068-crisis-grading.md)（危机的话必须看到）
- 用户授权：2026-10-19 09:14「继续」——做和测；上线（打开配置、重启）仍要用户在场点头。

## 背景

他发一条又撤回（打错了、说了又后悔），QQ 里对方看到的是灰字「对方撤回了一条消息」。机器人收到的是原文：NapCat 先推消息，再推 `friend_recall`，而插件只听消息。于是她会**照着他撤回的内容回**——最容易被识破的地方之一：真人只看到「撤回了一条」，只能问「你撤回啥了」。

## 决策

1. **聊天记录读出来时，他撤回的那条是「[撤回了一条消息]」**（`ChatHistory.recall`，`load()` 里换）。文件仍是只追加的 jsonl，原文还在（隐私审计、日审计照旧读得到）；撤回的 id 记在 `chats/<QQ 号>.recalled.json`（最近 200 个）。提示词、长期记忆、日记、承诺等所有读聊天记录的地方一起看到换过的，不用一处处改。
2. **只换她还没回过的那一条**（他发的、之后没有她的回复）：回过的她已经看过，还记得说了什么。
3. **想伤害自己的话撤回了也照样看到**（`detectCrisis` 命中就不换）：安全比像人优先，同 ADR 0068 决策 4。到达时的危机标记本来就在撤回之前记下了。
4. 只理名单里的人，配置 `recalls` 默认关。日志只记「他撤回了一条还没回的消息」，不带内容。
5. 接线：Koishi 插件在 `internal/session` 里认 `session.onebot` 是 `friend_recall`（同戳一戳那一个钩子的写法）；独立运行的 `main.ts` 也接了。

## 验证

- 真模型先试（不改代码，把「[撤回了一条消息]」当他说的话，6 次 × 3 步）：「撤回什么呢」「你撤回了啥」「撤回啥了，藏着掖着」「打错什么了，我都没看见」；连撤两次：「又撤，你今天是手滑专业户啊」。有一次先回「那你在干嘛呢」没提撤回，一次说「撤回了啥，我都看见了」（调侃，不算错）。
- 测试 `recall.test.ts` 6 项：换了、别的原样、原文还在文件里、换个实例还是撤回的样子、同一条不记两次；回过的、她自己的、不认识的 id、危机的话不换；通知认得出；整个应用里（开着：提示词只有占位没有原文、日志那一行不带内容；关着：原文照旧；危机话照样看到）。history、app、runtime、restart、backfill 共 101 项和插件 30 项过；类型检查干净。

## 没做 / 要注意

- **没在真 QQ 上试过**：`friend_recall` 的 `user_id`、`message_id` 是按 NapCat 源码和 OneBot 约定推的；`message_id` 要和他那条消息的 id 一样才对得上（同引用回复那一项的假设）。对不上就等于没做，不会出错。上线后让他发一条再撤回，看日志有没有「他撤回了一条还没回的消息」。
- 她回之前的这段时间有多长决定了这个功能多常生效：热聊时她 5–10 秒就回了，他撤回得晚就来不及（和真人一样）；冷场时她看到前撤回的才算。
- `recalled.json` 里只有消息 id，不含内容；`privacy-forget` 删某人聊天记录时没有顺带删它（无害，可以手动删）。
- 她自己撤回消息（发错了）没做。
