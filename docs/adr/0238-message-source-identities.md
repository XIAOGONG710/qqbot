# ADR0238：短消息 ID 的来源身份与保守兼容

状态：接受。2026-11-05。关联ADR0082、0237。

证据：NapCat `api/msg.ts` 的 live/历史数据包含 QQ 源秒 `time` 和原始字符串 `real_seq=msgSeq`，而 `message_id`、`message_seq`、`real_id` 都是同一个短 ID。`SendMsg.ts` 的 ACK 仅返回短 ID，`friend_recall` 通知不包含原消息发送时间或序号；其 notice 时间是通知时钟。`get_msg` 仍按短 ID 反查，不能当作无条件权威的身份补全渠道。以上仅只读核对本仓上游源码，未修改或连接真实 QQ。

决策：

- 联系人范围内，明确来源使用角色、短 ID、QQ 源秒及可选原始序号。序号保持规范十进制字符串，包括 `0`，不把大整数转为不精确 Number。已有用户记录的 time 本来就是源时间；补回的助手记录显式增加 sourceTime。双方有序号时必须一致；一方旧记录缺少序号时保留源秒兼容，不能声称消除了同秒碰撞歧义。
- 本地助手发送 ACK 的 time 仍表示本地完成时间，绝不伪造成 QQ 源时间。ACK-only 助手保留显式弱 ID 匹配，避免跨秒 ACK 被重复补回。它仍可能漏掉后来合法重用的助手短 ID；M20未全部解决。
- 实时入口三处去重、媒体读取后复核、补回、设备 capture 回传与 responder 持久化统一携带明确来源。全局共享媒体读取器还必须按联系人隔离，不能仅靠短 ID/源秒/序号跨人共用解析。
- 新撤回状态 version2 记录当前未答用户条目的具体来源及内容哈希。哈希用于区分缺序号时相同元数据的不同正文，确保逐条 keep（危机例外）不会被另一候选穿透；不保存原文。通知不能区分多个候选时，对当时的非 keep 候选集合占位并记固定诊断，不猜其中一条，不将该标记扩展到后来新发生的消息。
- 旧 number[] 标记只冻结当前 raw history 已被隐藏的用户条目，先原子发布再允许新追加；发布后异常可读回确认。找不到原条目的孤立旧 ID 保留保守 wildcard，不猜测其目标，因此该兼容边界仍可能遮盖未来同 ID。迁移保留原有隐藏事实，状态坏文件仍失败关闭。
- 仍按最近200个不同短 ID 维护撤回标记的保留次序。一个 ID 可有多个发生条目及歧义候选，不能将其描述为固定总200条元数据或固定内存上限；不擅自截掉同一批候选造成撤回泄漏。
- 原始撤回通知缺失发生身份，无法保证任意迟到/重复通知在短 ID 再次复用后都能准确归属；媒体尚在解析时先到的撤回也需要进一步贯通。仅接受短 ID 的下游操作/语音转写/引用接口仍需继续核查，不能把本地强身份包装称为上游全链唯一身份保证。

不部署、不改变危机保留和披露权限，不声称所有短 ID 重用问题已解决。
