## 问题（有数据）

线上 10-22 这一天他一整天没回：早安 ✔、催他 ✔、催他 ✔、冷场 ✔ ——正好用满每天 4 条（`dailyMax`），然后「随口说件事」「下课」「睡前」全是“今天的条数留给了别的时机”。**连晚安都没说成**。10-14 到 10-22 的记录里，「随口说件事」一次都没发出去过。

## 做了什么

不加催他的次数、不提高总数，只改“数法”（`ProactiveSettings.room`，`withRoom` 运行时加，不改角色卡）：
1. **睡前那句晚安不占名额**：一天的收尾，不该被前面的催挤掉。它自己的闸照旧——聊着的时候 20 分钟内不发、他没回的闸、今天没聊过不发、已经道过晚安不发。
2. **别的时机最多占 `dailyMax - 1` 条**，留一个给“随口说件事”（它本来一天只有一次）。
总条数：不超过 `dailyMax` + 睡前一条。计划（`planFrom`）和到点再查（`blockReason`）用同一套数法；`usedOn` 带上设置才排除睡前。

## 没做 / 要注意

- 没提高 `dailyMax`：她被冷落时已经催得不少（我的意见），这里只是让名额更合理地分配。
- 想让她更少催，是 `proactiveReach` 的事（ADR 0100），不在这里。
- “随口说件事”是否真的发出去，还取决于它自己的条件（距上次聊天 ≥ 2.5 小时、14:00–21:30 的窗口、没有未回的主动消息挡着）。

## 验证

`proactive-room.test.ts`（5 个）：`withRoom` 只加标记、睡前不占名额（有 room 才这样）；已经用了 3 条：没开时“冷场”还能占最后一个名额，开了以后“冷场”被挡、“随口说件事”有自己的名额；4 条都用满了睡前照发（20 分钟老规矩还在）、没开时被挤掉；计划里开了以后“随口说件事”和睡前都在；总条数不超过上限 + 睡前一条。
