# ADR 0174：灵魂模块止血——主动留话走同一套闸、账本和 SOUL 的写入口、生活引擎的几处错

- 状态：**已实现，没有新开关**（都是收紧，不是新行为）；在 DSH 那台机器上要拉到代码并重启 Koishi + 常驻进程才生效
- 日期：2026-10-29
- 关联：[ADR 0068](0068-crisis-response.md)（危机最小规则，红线第 4 条）、[ADR 0172](0172-work-mode-full-access.md)（整机权限）、[ADR 0171](0171-self-directed-memory.md)（她自己的记忆）、`exchange/reviews/2026-10-29-claude-review-soul-module-and-project.md`（缺陷清单 §1.2，10 项实测复现）、`docs/plans/2026-10-29-autonomy-and-realness.md`（第 3 步：灵魂模块缺陷优先于一切新功能）

## 背景

灵魂模块（`dsh-plugins/dsh-linmengyao-memory`、`scripts/her-life.mjs`、`scripts/her-resident.mjs`，约 1245 行）原来一条测试都没有。10-29 的审查在真实代码上复现了 10 项缺陷。用户要的方向是「她有真正的自主」，而自主要建立在**她自己的状态可信、边界不被绕过**上，所以先止血，再谈新功能。这一版只做不需要设计决定的那些。

## 做了什么（审查 §1.2 的编号）

1. **#6 `outbox_send` 的消费端直通所有闸**（`social/outbox.ts`，`platform/app.ts` 接线）。原来每 30 秒把 `OUTBOX.jsonl` 每一行直接发到他的 QQ：不看危机后 48 小时暂停、不看她睡没睡、不过出口检查、不限条数，发出去的话不进聊天记录，读完就清空（发不出去的行丢了）。现在：
   - 危机暂停 / 睡了 / 休眠：整个文件原样留着，能说话了再发；
   - 每天最多 3 条，两条至少隔 20 分钟，一次只发一条；
   - 出口检查里「硬」的几类（做不到的承诺、禁用词、照抄的语音图片写法、编的对话）命中就不发、记日志；
   - 超过 12 小时的不发；发不出去重试，3 次后丢；
   - 发出去的话记进聊天记录（她下一轮知道自己说过）；
   - 读文件用「先改名再处理」，常驻进程同时再写不会被覆盖；上次中途崩了留下的 `.work` 接着处理。
   - 插件那头 `outbox_send` 同一轮第二条直接拒（原来「每轮最多一条」只写在说明里）。
2. **#1 `ledger_revise` 改错一条且不留痕**。`ledger_read` 现在每条前面带它在整本账里的序号（`4. 2026-10-29：…`），`ledger_revise` 的序号就是这个号；被改掉的原文完整进 `LEDGER.md.history.jsonl`（`.bak` 只有一格，下一次写入就换掉了）。
3. **#2 `soul_update` 无上限、无闸**（SOUL.md 每轮整份注入，她醒来会上网查资料，是持久化提示词注入的落点）。现在：
   - 绊线：内容里有网址、「别让他/宝宝/用户知道」、把文件/密码/密钥发给谁，就不写（**这是绊线，不是边界**：能绕过去；真正的约束是下面三条）；
   - 24 小时内最多写 2 次；
   - 字数上限 6000：最老的追加段落搬进 `SOUL.archive.md`（留着，不再注入），开头「她是谁」和最新一段永远留着；
   - 每次写入记进 `SOUL.md.history.jsonl`。
4. **#3、#4 把倾诉当成冲她的负面**（`her-life.mjs`）。原来 `/烦|滚|讨厌…/` 一命中就怨气 +8，`NOW.md` 随之告诉她「你现在不想哄他：可以顶回去、拒绝他」。现在只认冲着她的话（「你好烦」「闭嘴」「滚开」「不想理你」「讨厌你」……）；「我今天好烦，项目压力大」不再记。同样，「想 / 喜欢 / 陪 / 亲」原来命中就加信任，现在要「想你 / 喜欢你 / 陪我 / 亲亲 / 谢谢 / 晚安」这类冲着她的。**这仍是关键词判断**，只是把最明显的误伤去掉；真正的「气」要有来由、有衰减、要修复，是计划第 4 步（复用 `grievance` / `herFeelings`）。
5. **#5 UTC 日期 / 本地小时混用**：`her-life.mjs`、`her-resident.mjs`、插件的日期戳全改用本地日期（`scripts/her-schedule.mjs` 的 `localDay`）。
6. **#7 睡眠整合 / 醒来不看钟点**（`scripts/her-schedule.mjs`，纯函数）：睡眠整合只在本地 03:00–07:00、每个本地日一次（原来 3 点以后任何时间，含白天，提示词却写「现在是夜里」）；随机醒来夜里（23:00–07:00）不醒、她自己在睡觉时不醒、离开电脑时不醒（原来凌晨三点也 25% 起来用整机权限上网）。
7. **#8 编造关于真人的事**：NPC 里「鸽鸽」是他的真实联系人，原来会生成「鸽鸽发消息说周末可能约饭」。现在是虚构的「同学」。随机数可换（`setRandom`），测试里用固定种子，结果可复现。
8. **#10 写死的路径**：`C:/Users/22601/…` 全部换成 `os.homedir()` 起头（`QQBOT_SOUL_DIR` / `HER_DIR` / `QQBOT_PRIVATE_SCRIPT` / `DSH_BIN` 可以改）；私密日记脚本改指仓库里的 `scripts/private-diary.ps1`；`start-her-resident.ps1` 同理。找不到 dsh 时明说，不再静默失败。有一条测试扫源码，再出现 `Users/22601` 就红。
9. 顺手：`her-life.tick()` 返回的 `changed` 原来恒为 false（赋值后才比较），改成真的反映活动有没有变。

## 没做（要设计决定，或不在这版）

- **#9 两个「她现在在干嘛」来源同时注入**（引擎的 `NOW.md` 和仓库里的作息 / 状态行）：要定谁说了算，属于计划第 6 步「合一个自己」。
- **DSH 库召回对所有联系人生效**（`recallWork`）：要限男朋友档 + 加开关，DSH 来做。
- **`soul_update` 的评分闸门**（他的👍👎决定她能不能改自己）：计划里要换成「频率限制 + 他确认」，不把身份变化绑在他的满意度上；这版没动评分逻辑，只加了和评分无关的闸。
- **`app.ts` 里 outbox 接线本身没有单独的集成测试**：`drainOutbox` 的逻辑有 10 项测试（含 5 个变异检验），接线只有类型检查。
- DPAPI 私密日记是 `CurrentUser`：同一个 Windows 用户下的任何进程都能解。它是「不进提示词、不进聊天」，**不是**「他读不到」。对用户要这样说。

## 验证

- `test/outbox.test.ts` 10 项（变异检验：去掉暂停 / 去掉记账 / 去掉过期 / 去掉每日上限 / 发不出去就丢，每个都让恰好一条测试变红）。
- `test/soul-plugin.test.ts` 15 项：用假的 Cordis 上下文驱动真插件（账本序号、改口留痕、绊线、频率、字数上限与归档、`outbox_send` 每轮一条、本地日期、没有写死路径）。
- `test/her-life.test.ts` 12 项：作息判断、倾诉不记怨气、冲她的才算、同学事件不含「鸽鸽」、固定种子可复现、跨本地午夜、`changed`。
- 变异检验共 15 处，每处都让对应测试变红。

## 怎么回滚

改动都在这几个文件里，`git revert` 这个提交即可；不涉及数据格式变更（新增的 `*.history.jsonl` / `SOUL.archive.md` / `outbox-state.json` 留着不影响）。唯一要知道的行为差别：`ledger_read` 的每一行前面多了序号。
