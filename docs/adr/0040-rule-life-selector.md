# ADR 0040：没人聊天时她一件件过日子（规则自主选择器 v1）

- 状态：已实现（模拟器，影子模式：记账、不进提示词），单元测试、模拟器回归见下（2026-10-09）
- 日期：2026-10-09

## 背景

她的一天现在是「问到哪一刻、按规则算哪一刻」：作息和课表（`stateAt`）、饭点和洗澡、世界里有时长的事（喂猫、取快递、视频、赶作业）、一天的打算（ADR 0034，下雨不出门、作业明天交先赶作业），
都是按日期从开学那天推出来的，不存。类型化行动（0037）和行动队列（0038）做好了，但没有谁去排：没人聊天时，事件账里一件她自己做的事都没有。

还有一个教训（ADR 0035 调整 7，DSH 诊断 2.1）：相机基金按规则从开学推到现在，上线换了规则，过去的数一起变了。**过去要是按规则重新算，改一次规则就改写一次她的过去。**

## 决策

1. **选择器 `chooseAt(at)`：这一刻她该做什么**（`life-selector.ts`）。判断和状态行（`contact.ts`）用同一套规则，顺序：
   - 作息：睡觉 → `sleep`（睡到起床）；正好上课 → `attend_class`（课中间跳到下课）；赶去上课、课间 → 跳过，不记；
   - 饭点 → `eat`；洗澡、下楼喂猫、取快递往回走、和家里视频 → 跳过，不记（世界里已经有，ADR 0030、0031），但算占用，别的事撞上就停；
   - 赶作业那一段（写完之前 90 分钟）→ `study`（某门课的作业）；
   - 空闲：一天的打算这一段实际做的（改了的用改了的）→ 在读的书 `read_book`、作业 `study`、躺着 `rest`、别的（追剧、打游戏、修片子、刷手机……）`leisure`（新的一类，做什么写在 subject，就是状态行那几个字）；
     最多做到这一段结束、下一顿饭、下一件世界里的事、下一节课，哪个先到（裁判再截一次）；短于 10 分钟的空当不记。
   - 世界里喂猫、取快递这些在发生之前，那一刻的世界里只有「打算几点」：占用按她这一天快结束时的世界取。
2. **执行器 `lifeExecutor.fill(now)`**：从她上一件事结束的地方（事件账和队列里 `life:` 开头的行动最晚的结束时刻，不另存）一件件排到 now，交给裁判进队列；最后一件可能还没做完，留在队列里。
   行动 id = `life:<开始时刻>:<种类>`：同一份事件账、同一个时刻推出来的一样，重放、重启都不重复。裁判不收的记日志、往后挪 5 分钟。
3. **挂在读世界之前**：`settlingWorld(world, queue, nowFn, plan)` 先 `plan(now)` 再结算——和 ADR 0038 调整 4 同一个点，模拟器和以后线上一样，没有单独的定时器。执行器读的是不带结算的那一层世界，不会绕回来。
4. **过完的日子落进事件账就不再变**：v1 的行动是从规则推的，和规则推出来的状态行一致；以后规则改了，已经落账的过去不跟着变（相机基金那种事不再发生在这几类事上）。
   ADR 0034「一天的打算不进事件账」在选择器开着时改成：打算本身还是按日期推（往前看的），**照打算做了的那部分**作为行动落账（往后看的事实）。
5. **v1 是影子模式**：事件账里的类型化行动还不进提示词、日记、状态行（`typedOccupation` 还没有调用方，DSH 行动复核 2.4）；场景加 `"autonomous": true` 才开。
   线上装配（功能开关、从开的那天起排、灰度）在 72 小时封板回归 v2 之后，先问用户。

## 不做的（v1）

- 精力、饥饿这些需要（实施方案批次 B）：现在「选择」就是现有规则的选择，选择器只是把它们走一遍「观察—选择—裁判—结算」。
- 状态行从事件账读：要先在模拟器里逐小时比对一阵，确认和现在的规则一致。

## 线上装配（第二增量，2026-10-09）

- 配置 `autonomousLife`（`runtime/bot/config.json` 和 Koishi 插件配置都有），**默认关**。开了以后：`app.ts` 用 `settlingWorld` 包世界，读世界之前排到现在、结算到期的；
  从这次启动那一刻排起（`since`），以前排过的从事件账接着排；没人找她时每 10 分钟推一次，过完的时段尽快落账。启动日志「没人聊天时她一件件过日子：开（……影子模式……）」。
- 还是影子模式：事件账里多了她的行动，提示词、日记、状态行不变。开不开、什么时候开，问用户。
- （ADR 0042 改了：聊天里说过的事改写还没过的，排着的停在那一刻；她说「睡了」就是去睡了。下面是原来的定法。）**聊天里说过做了的事不打断排着的行动**：抽出来的喂猫、取快递是「某一刻」的事（开始 = 结束），通常抽出来时那一段休闲早已落账；
  两者并存就是「刷手机中间下楼喂了趟猫」。代价：世界按聊天改了喂猫的时刻以后，原来按规则在 20:10 截断的那段休闲不再对齐，过去的不改。

## 验证

- 试跑 10-12 08:00 到 10-15 21:00（每小时推一次）：47 件，0 重叠，裁判 0 次不收，1.2 秒。一天大致是：早八 / 9:55 的课、午饭、下午课或修片子、晚饭、晚上赶作业或追剧、22:30 前后洗澡的空当、02:00 睡、没早课睡到 9:30；
  10-12 19:16 和 10-13 18:40 各空出 10 分钟下楼喂猫；10-14 下雨，没有喂猫的空当。
- **查出来一处规则之间对不上**：取快递的时刻（世界 `PICKUP_TIMES` 12:20、17:40）会落在饭点里（10-12 午饭 11:56–12:31，12:20 去取快递）。v1 不改世界的规则（改了会动过去的取件时刻），记下来，等状态行从事件账读的时候一起处理。
- 真模型 `20261008-234850-p1009a`（`58f02ef`，`life-72h-auto` 3 次）：她过的日子 3 次都是 47 件、0 重叠，睡觉 3、饭 8、课 10、学习 10 段（管线自检 33 / 33）；
  问这几天的回答回复检查 70 / 72，两项不过都是检查词误判（「所以我昨天没下楼」含「昨天没下」、「明天要是晴了我就去补上」含「晴」），答的都对——选择器只记账，说的话和不开时一样。
- 2026-10-08 23:55 上线（用户选「现在上线」，`main` 快进到 `9a2bf9e`，重启 Koishi，启动日志无错误）；选择器只有场景开 `autonomous` 才跑，线上没开。
