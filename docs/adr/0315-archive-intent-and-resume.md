# ADR 0315：归档的持久原计划与崩溃续跑

状态：接受，2026-11-05。接续 ADR 0309 及 0313。

原归档只有全过程OS租约，没有崩溃后意图。合成子进程在首份聊天rename后退出时，tiers.since已经更新、聊天已移动、配置仍旧bank；OS锁释放后App仍能进入业务。该事实不同于已修的PID并发问题。

现在任何业务写入前，maintenance/archive-jobs/UUID.json先保存完整不可变计划：原root/prefix/result、顺序copy/move/replace步骤、配置目标、前后size/hash及固定替换文本。逐步发布done，最终complete。App在构造业务前检查未完成/坏job；archive与forget在同一目录租约内互查持久维护屏障，防止遗忘移动归档已完成目标而破坏续跑。

显式--resume UUID只执行原计划，不因文件已移走重新发现空目标，不接受新prefix覆盖原请求。rename或checkpoint异常后按精确目标hash确认事实；原件/目标冲突、坏状态、孤立job临时文件均保原拒绝，不自动覆盖或回滚。不确定的目标内容不能仅靠路径存在就算完成。已完成任务可重复核对，不重做旧移动。

计划的replace文本可能含配置密钥。journal及实际原子写残留一律列共享mixed，不能整份复制到联系人导出或自动遗忘；有效计划精确定位target.archive-UUID-step.tmp，包括配置位于数据目录外的情况。坏记录只报告未知，无法据此推断外部残留位置。运行中不可删换目录协调文件。

测试用真实子进程退出、合成配置/聊天、发布前后IO、多个配置和目标冲突；未读取真实配置/运行时或部署。此为有限原计划前进及启动保护，不是跨文件原子事务、自动rollback、断电fsync或不合作外部写者保证。旧无job的历史中断不能自动追认。
