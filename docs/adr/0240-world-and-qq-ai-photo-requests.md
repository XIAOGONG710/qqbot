# ADR 0240：世界事件与 QQ 当前照片请求只建立 AI 照片草稿

- 状态：已实现，默认关闭（2026-11-04）
- 开关：`aiPhotos: false`
- 关联：[ADR 0239](0239-ai-photo-drafts.md)、[ADR 0110](0110-photo-shares.md)、[ADR 0128](0128-food-photos.md)

## 问题

世界账已经知道“喂完土豆拍了照片”“这一顿拍了饭”，QQ 里也会有人明确问“发一张现在的照片”。以前照片货架只能按种类挑图：即使图是合法的，也可能是旧图，不能把它说成眼前这一刻。

## 决定

增加一层很薄的请求编排，不改变图片审核和发送边界：

1. `cat_photo` / `food_photo` 世界事件到点后，把世界账中已有的主体、菜名、天气和普通场景转换成 `AiPhotoContext`。同一世界事件使用稳定 `eventKey`，重启或轮询不会重复付费生成。
2. QQ 只有在对方明确同时表达“要照片”和“现在 / 刚刚 / 这顿”等当前含义时才走这条链路。普通“看看以前拍的”继续使用照片货架。
3. 新图永远只写入 `ai-photo-drafts` 的 `pending_review`；不自动审核、不自动发送。人工审核通过并得到对应 `shelfId` 后，后续同一当前请求才允许把这一个精确编号交给回复模型。
4. 当前没有已审核匹配图时，回复模型只能如实说此刻发不了；不能从同类别里拿旧图冒充，也不能承诺马上补发。
5. 独立多闸：必须启用 `aiPhotos`、配置至少一个独立生图服务，并配置视觉审查。生图可按本地、主服务、备用服务降级，聊天密钥不作生图回退；没有视觉审查时质量门失败关闭。图片通过 ADR 0242 的结构与视觉一致性检查后，才允许写入待审核草稿。
6. 每日最多自动生成 3 张；同一事件在进程内并发去重；失败后全局冷却 30 分钟。失败日志不写供应商响应正文。
7. 世界事件的自动草稿不等于允许主动发送。现阶段主动照片计划器不会因为生成成功而自动发图，仍需后续明确设计“审核后是否还赶得上事件”的时效规则。

## 数据与回滚

- 草稿索引和图片：`<dataDir>/ai-photo-drafts/`
- 自动请求冷却：`<dataDir>/ai-photo-drafts/auto-state.json`
- 回滚：把 `aiPhotos` 设回 `false` 并重启。已有草稿保留供人工审计，不会被发送。

## 验证

`ai-photo-requests.test.ts` 覆盖世界事件键、当前请求识别、无菜名失败关闭、精确审核编号、每日上限、事件去重和失败冷却。类型检查还验证配置与 QQ 流水线装配。
