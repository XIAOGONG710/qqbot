# ADR 0206：他发来的表情包，她看得懂（`readStickers`）

- 状态：**已实现，默认关，未上线**（分支 `claude/self-pursuits`；全量测试见文末）
- 日期：2026-10-31
- 关联：[ADR 0052](0052-voice-and-images.md)（听语音、看图上的字；一向跳过表情包）、[ADR 0055](0055-deepseek-vision.md)（看图模型）、[ADR 0063](0063-image-stickers.md)（表情包收藏；`STICKER_VISION_PROMPT` 先抄字再说画面）、[ADR 0007](0007-schedule-and-reply-timing.md) 决策 7（收尾之后的附和不回）、[ADR 0013](0013-old-project-advice.md) 决策 4（看心情不回）
- 用户：2026-10-31「做一些新功能吧，你看看可以加什么」；中途补了一句「最好是让她自己决定」

## 背景（线上记录里量到的）

线上聊天记录（VM 上 10-27 之前，只数条数、不看内容）：他的 731 条消息里 **83 条是只发一个表情包**（约 11%）；她 81 条在 5 分钟内回了（98%，和普通文字 96% 一样）。
但进聊天记录的只有「[动画表情]」四个字：`media.ts` 的 `readMedia` 明确跳过表情包，ADR 0063 的看图只服务“收不收藏”，不进回复。所以她回得出话，却不知道图上画的是什么、写了什么字。

模拟器里同一批 8 个“只发一个表情包”的时刻（描述是我编的，不含真实聊天），各跑 2 遍、不带记忆：

| 她看到的 | 她在回什么 |
| --- | --- |
| 只有「[动画表情]」 | 16 条回复里至少 5 条在说“他只发了个表情”（「表情发上瘾了是吧」「你是不是没话了，光发表情」「就发个表情糊弄我」）；那个「想你」的表情她回「你就打算一个接一个发表情撑到睡着是吧」「跟我杠上了是吧」 |
| 读出来的内容 | 0 条在说形式，都在接内容：「想你」→「我也想你～抱抱」/「抱一个，我也想你了」；「好饿」→「刚说撑，现在又饿，你这胃是橡皮筋吗」；「哼，不理你了」→「哟，还生气了」；「晚安」→「晚安～做个好梦」 |

另一个发现（第一版没处理好，见决策 4）：同一批第一次跑，读出来的版本只生成了 5 次——另外 3 个表情包被代码按“她已经收尾、对方只回了附和，不回”直接丢了，**包括「想你」「哼，不理你了」**。`isAck` 对“只有方括号的消息”一律判附和（「只有表情也算附和」），表情包读懂之前这没问题，读懂之后就成了代码替她决定“这句不是话”。

## 决策

1. **开关 `readStickers`（默认关）**：要 `media` 和看图模型（`vision`）开着，只对名单里的人（和看图一样：图会发到看图模型）。名单外的联系人照旧。
2. **怎么读**：没有名字的图片表情（summary 是「[动画表情]」「[表情]」或空）用 `STICKER_VISION_PROMPT`（先把图上的字原样抄下来，再用一句话说画面和情绪）读一次，聊天记录里是 `[动画表情：上面写着「……」；画面……]`（文字 ≤30 字、画面 ≤50 字，方括号换成【】免得提前闭合）。商城表情自带名字（「[是的]」），名字就是意思，不读。一条消息最多读 2 张；读不出来（超时 / 出错 / 没有 url）照旧「[动画表情]」。看图走聊天优先级（`configuredImageDescriber(config, STICKER_VISION_PROMPT, 'chat')`），不排在后台收藏后面。
3. **同一张只读一次**：按 NapCat 的 `file`（内容哈希加扩展名）做缓存，存 `stickers/read-cache.json`（≤300 张，最久没见的先丢，重启还在）。他常发的那几张之后不再花看图调用。日志只写字数，不写图上是什么。
4. **读懂了就不是“附和”（用户：最好是让她自己决定）**：`reply-timing.ts` 新增 `hasReadSticker`，用在**且只用在**两处代码替她决定“不回”的地方——收尾之后的附和（`pendingMessages`）和看心情不回（`moodySkip`）。读懂了的表情包不再被这两处丢掉，她看到内容，自己定怎么回。没读懂的（`[动画表情]`）照旧，因为她什么都看不到，没有什么可定的。`isReaction`/`isAck` 本身、出口检查的“他在认真说事”、`isEndingTurn` 都没动（单独一个表情包仍然算“反应”，行为和以前一样）。
5. **其他地方认得这个写法**：`KNOWN_FACE` 认 `[动画表情：…]`（小黄脸 / 表情统计）；`stickerCued`（“他发了个表情包 → 可以回个表情”）认它；她照抄这一行跟照抄「[语音 …]」「[图片，…]」一样会被出口检查拦下重写（`MEDIA_LINE`）；`speech-check` 的非文字行也认。
6. **提示词里没有新增任何一句**：没有“看到表情包要怎么回”的规矩，没有字数，没有“回个表情”的指示。她看到的就是聊天记录里多了那一行。

## 顺手修的一个旧 bug（单独一个提交，可以单独回退）

`social/stickers.ts` 里“他发了个表情包”的线索写成了 `/[(?:动画)?表情]/`——**没有转义方括号，成了字符类**，任何带 `表 情 动 画 ( ) ? :` 的话都命中：「今天心情不错」「这件事情我想想」「画画好难」「活动在周三」「你在干嘛?」都被当成“他这句话里有明确的反应”（`stickerCued` 为真）。这个 bug 从 ADR 0063 就在（10-27 重构前的 `stickers.ts` 里就是这样），所以线上 `stickers: send` 开着时，发图片表情的抽签比设计宽得多。改成 `/\[(?:动画)?表情[\]：]/`。**线上效果：修了之后 `stickerCued` 变窄，她发图片表情的轮次会比现在少**（设计本来就是“他这句话里有明确的反应才抽签”）；要不要保留这个效果、还是想要原来的宽松，是你的决定——回退只需要还原那一个提交。

## 没做的

- 她**不能在回复里自己选择“这条不回”**：代码里“不回”只有收尾后的附和 / 看心情不回 / 睡着 / 上课这几种，模型没有一个“我这条不想回”的出口（ADR 0173 的“不回要告诉他原因”是反过来的）。读懂的表情包现在一定会交给她，她只能决定回什么。要让她真的能决定不回，需要在提示词里给一个出口——那是 DSH 在改的提示词段，我没碰。
- 只读图片表情；动图只看第一帧（看图模型的限制）；不识别“这是谁的脸”（看图模型本来就不报人名，`STICKER_VISION_PROMPT` 也只要字和画面）。
- 没有用真实表情图在线上跑过：流水线用假看图模型测过（`test/sticker-reads.test.ts`，18 项）；ADR 0063 的 10-12 真图试跑里同一个提示词 14 张抄全了字。上面的对照是模拟器里用我编的描述，不是真看图的结果。
- 他的表情包会发到看图模型的服务器（和他发图片一样）。每个新的表情包一次看图调用（约几秒，最多等 `vision.timeoutMs`），常用的有缓存。

## 开 / 关

- 开：`readStickers: true`（Koishi 插件配置里一个开关；日志第一行会写“看他发的表情包：开”）。先观察：日志里的 `看表情包：读出 N 个字（x 秒）` / `见过这张` / `没读出来` 各几次；`stickers/read-cache.json` 的条数。
- 关：去掉，立刻回到只有「[动画表情]」；已经写进聊天记录的 `[动画表情：…]` 行留着（以后她回看时仍是读懂的版本）。
