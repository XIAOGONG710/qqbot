## 背景：5 条视频教了什么，我们的数据怎么说

用她的 B 站号读了 5 条视频的字幕（`BV1hCPcz2EtJ` 做题式写法、`BV1uQ8E6LE6G` 去 AI 味、`BV1xLn46zEgM` 猫娘草稿法、`BV1QgHN64EUW` 更像人的插件、`BV1NiHn6RExP` 谁最会说人话）。它们的数字都是作者自己的、没有第三方验证。对着我们的真实聊天，值得拿的只有三件：

- **AI 味清单对她没用**：「不是 A 而是 B」、破折号、「稳稳接住」、三段式、服务式收尾，这些是长文章的毛病；她的短气泡里 10-19 起「不是…而是」0.57 / 千字（他 0.54）、破折号 0、服务收尾 0。
- **「毛刺」的思路是对的，但视频的数字不能搬**：「每千字 1.6 个」是别的语料、别的口径。我们用同一把尺子量三份真人（他本人、真人女生样本、真人男生样本）和她。
- **「做题式写法」值得测一下**：视频里把温度压到 0.1 并把上下文打包成「推断最可能的回复」。

## C：毛刺的度量（`rough-edges.ts` + `ops/rough-edges-cli.ts`）

口径写死在代码里，只看写法：一条气泡里有没有 ①句尾挂语气字（吧 / 啊 / 呢 / 嘛 / 哦 / 呀 / 啦；吗不算，单个字的应声不算）②停半拍（嗯 / 呃 / 额 / 唔 / 分句开头的「那个」「就是」）③省略号 ④笑。`node src/ops/rough-edges-cli.ts --chat <聊天> --human <研究样本>…` 出每种占条数的比例。

测量（10-05 起，条数口径）：

| | 他本人 | 真人女生样本 | 真人男生样本 | 她 10-05..18 | 她 10-19 起 |
| --- | --- | --- | --- | --- | --- |
| 句尾挂语气字 | 11.1% | 11.2% | 9.3% | 13.0% | **17.0%** |
| 其中「吧」 | 2.2% | 1.6% | 0.6% | 4.9% | **5.0%** |
| 其中「呢」 | 1.8% | 0.5% | 0% | 4.5% | **5.0%** |
| 其中「啊」 | 4.9% | 2.6% | 4.6% | 2.9% | 6.1% |
| 嘛 / 呀 / 啦 | 约 1% | 约 6% | 约 3% | 约 1% | 约 1% |
| 省略号 | 0.1% | 8.0% | 5.2% | 0.2% | 1.7% |
| 停半拍 | 1.3% | 1.6% | 2.9% | 0.7% | 2.3% |
| 笑 | 0.9% | 0.5% | 2.3% | 0.0% | 0.6% |

读法：
- **她多出来的尾巴几乎全在「吧」和「呢」上**（各是他的 2.5 倍以上）；10-19 之后总占比 17%，对着真人的 11.2% 算 p≈0.03。「啊」在真人范围里；「嘛 / 呀 / 啦」她反而偏少。人味检测器（`humanness.ts`）独立地把 `part_ne`（呢）和 `part_ba`（吧）列进「最露馅的写法」，互相印证。
- **省略号的真人样本（5–8%）和他自己在 QQ 里（0.1%）差得很远**，两个语料口径不同；**停半拍、笑**是个位数，和真人分不出差别。所以**不往她的话里加毛刺**，视频插件「加犹豫 / 语病」的那一半在这里没有依据。

## B：句尾「吧」「呢」封顶（`tailCap`，默认关）

出口检查里新增一种问题 `tail`，走现成的「去掉就解决、不重写」通道（和重复的语气词开头同一条路）：她最近 80 条文字气泡里以「吧」收尾的占比到 3%、以「呢」收尾的到 2.5%（他本人水平略放宽）时，这一轮再用它收尾的就把那个字去掉。

- 不动的：固定搭配（干嘛 / 网吧 / 好吧 / 行吧 / 算了吧 / 走吧 / 是吧 / 对吧 / 别吧 / 随便吧 / 可以吧 / 成吧）、省略问句（你呢 / 然后呢）、少于 5 个字的应声（好啊 / 在呢）、别的字（啊 / 嘛 / 呀 / 啦）。
- 已经有别的问题的那一行不动（去开头 / 重写之后下一轮会重新查）；从前往后数，前面的行占了名额后面的才会被去。
- 最初做成「所有语气字合起来封顶 12%」，回放发现把早期那段压到 8.5%（低于真人的 11%），还会误伤她本来正常的「啊」，所以改成按字封顶。

**离线回放**（假设 10-05 起就开着，把她的真实回复按时间顺序过一遍）：「吧」4.9% → 3.2%（10-05..18）、5.0% → 2.2%（10-19 起）；「呢」4.5% → 2.0% / 5.0% → 3.4%；「啊」等不变；总占比 10-19 起 17.9% → 13.4%；735 条里改了 31 条（约 4%）。人味检测器 P(真人) 均值 0.435 → 0.442，判成真人的占比 40% → 41%——方向对、幅度很小，符合只动一个字的预期，别指望它改变整体观感。被去掉的例子：「你才不要我了呢」→「你才不要我了」，「你自己招的吧」→「你自己招的」（后一类会把试探 / 反问的语气磨平一点，这是代价）。

开关 `tailCap`（要 `speechCheck` 开着），`koishi.yml` 里加一行 `tailCap: true` + 重启；回滚 = 删掉这一行 + 重启。

## A：做题式写法（离线实验，线上没有开关）

**先验证了一个前提：思考模式开着时，temperature 根本不起作用。** 同一个提示词，`deepseek-flash` 思考开、温度 0 与 1.5，各 5 次都是 5/5 种不同输出；思考关掉后温度 0 是 1/5（完全确定）、1.5 是 5/5。线上配置是 `thinking: enabled`、`reasoning_effort: high`，所以视频里「温度 0.1」这一招在我们这套配置上没有杠杆。

实验设计：沿用 ADR 0099 的办法——把 `exchange/research/2026-10-real-chat` 里真人情侣的 72 个回合做成带上文（最多 8 条）的单轮场景，每个变体 2 份不同起点（v0 / v1）各跑一遍，另一次调用按「回复方式」分类，再用人味检测器打分，和真人那一行对照。四个变体（都带 `--shape --agenda --filler --split --feel`，即线上现状）：

- `base`：线上现状（思考开）；
- `solve`：思考开 + 「做题式」提示（`--frame solve`：不让她去想怎么显得像真人、也不演，只推断这个情境里最可能真的发出去的那几条，最普通最不费力的版本，不是最精彩的）；
- `nothink`：关思考 + 温度 0.5；
- `nothink-solve`：关思考 + 温度 0.5 + 做题式提示。

## 没做 / 要注意

- 视频里的数字（1.6 毛刺 / 千字、召回率之类）都没有核实，也没有照搬。
- C 的真人样本只有 188 条女生气泡、172 条男生气泡（偏冲突片段），占比有几个点的误差。
- B 只管「吧」「呢」；「啊」在 10-19 之后到 6.1%，略高于他的 4.9%，但在真人范围里，没封。
- 模拟器里 B 几乎不触发（场景的上文最多 8 条，攒不到 80 条窗口），所以 B 的评估靠真实聊天的离线回放，不靠模拟器。
