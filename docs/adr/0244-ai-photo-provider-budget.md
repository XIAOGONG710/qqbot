# 0244：AI 生图供应商降级与每日预算

日期：2026-11-04

## 决定

生图按“本地服务 → 主服务 → 备用服务”依次尝试。每个服务仍使用兼容 `/v1/images/generations` 的接口，密钥仅来自环境变量，不落盘、不进入日志。

默认每天最多尝试 4 次，失败和降级尝试也计数，避免一个故障事件反复消耗费用。`QQBOT_IMAGE_DAILY_LIMIT` 可以在 1–100 之间调整。统计只保存日期、尝试数、成功数、失败数和供应商角色，不保存提示词、图片、服务地址、模型响应或密钥。

Koishi 的照片审核页有一张只读“运行与费用”卡，只展示功能开关、已配置的供应商角色（本地 / 主 / 备用）、今日尝试 / 成功 / 失败 / 剩余次数和草稿计数。页面不返回模型名、URL、密钥、绝对路径或供应商错误原文；用量文件缺失或损坏时只将该行降级为中文提示，不影响照片审核和其他控制台功能。该卡不能改开关、触发生图或发送消息。

质量门拒绝图片时，运行时最多重新生成 1 次。它不是额外免费额度：第二次生成和其内部的供应商降级都按实际调用继续计数；剩余额度不足时供应商池直接失败关闭。

本地服务由 `QQBOT_IMAGE_LOCAL_BASE_URL` 配置；主服务沿用 `QQBOT_IMAGE_API_KEY`；备用服务需要同时配置 `QQBOT_IMAGE_FALLBACK_BASE_URL` 和 `QQBOT_IMAGE_FALLBACK_API_KEY`。所有服务都没有配置时，生成明确失败，不影响聊天与已有照片发送。

本地服务地址只接受 `localhost`、`127.0.0.1` 或 `::1`，远端主/备用地址只接受不含账号、查询串和锚点的 HTTPS URL，避免把生图密钥发送到意外地址。
