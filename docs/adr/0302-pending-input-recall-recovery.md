# ADR0302：待处理输入的撤回与恢复

状态：接受。2026-11-05。关联ADR0082、0161、0300、0301。

背景：真实App的合成语音、图片在解析held时尚无聊天行，先到的撤回通知找不到目标；释放解析后原文进入历史视图和模型。仅记内存集合不能跨重启恢复，仅依赖QQ最近20条也可能漏掉原消息。

决策：

1. `chats/<QQ>.recalled.json` 的既有version2增加可选pending、kept字段，兼容旧无此字段的状态。待处理条目保存来源、原始消息载荷、随机incomingId、撤回观察，以及可选的首次已准备正文和危机保留决定；对外只给深克隆快照。强来源重复登记复用预约，弱来源不同载荷不擅自合并。
2. 接收缓冲、普通媒体队列、补回和设备捕获异步入口先确认预约持久化。撤回标记绑定当时的待处理候选；写失败时在完整已加载状态上保留并叠加RAM观察，普通读取/准备/追加必须先补提交。首次预约写失败也保留已观察载荷，不能丢掉后来的撤回或让第一笔dirty阻止第二笔观察。
3. 解码完成后先持久保存首次正文、keep决定及精确撤回/保留标记，再允许聊天追加或调度生成。原始正文仍按ADR0082保留在私有JSONL，所有正常读取者只得到占位；危机keep的精确例外优先于孤立legacy wildcard。裸append不能绕过已撤回预约而不作保留判断。
4. JSONL追加确认后才清理预约；完整追加、rename后异常可读回确认。副状态清理失败不能变成重放授权。对已经准备、来源和正文等价的弱token可确认同一既有事实；未准备条目不能仅按弱元数据吞掉。已确认追加的残留预约不得绕过“已回复不遮盖”的规则。
5. 重启先恢复本地待处理条目：已准备正文不重新解码，未准备的才读取持久原载荷，不依赖最近20条。补回用恢复前的尾部界限选候选，再按当前来源去重，避免恢复较晚条目吞掉中间漏消息。恢复与实时处理共享联系人队列；明确消费/拒绝才可取消未撤回预约，处理中异常不能在finally删除它。
6. IO恢复使用有界频率的逐联系人重试，不需用户重投或再发撤回。停止取消媒体与重试，不允许晚回调追加；已确认的待处理事实留给重启。休眠时可以保存此前已开始解码的prepared结果，但不追加/生成、不由恢复重试唤醒；换档前的旧来源不重放进低档上下文，也不因权限变化擅自删除其私有资料。对结果不明的运维/设备命令，本地预约恢复不重新调用命令处理器，不擅自删除原请求；明确成功消费的命令才按原有“不入聊天”规则清理。
7. 预约可能包含私密原文、媒体路径和临时读取URL，属于联系人专属私有数据。隐私审计/导出/遗忘同时覆盖精确QQ的recalled文件及实际格式的临时/隔离残留；归档要搬走只有预约、尚无JSONL的文件。归档前后保留原字节和可按QQ归属的名称，不拆改共享审计链。

边界：从未成功写入的观察在进程崩溃后不能凭空恢复；初始状态无法读取或schema损坏时不能猜空白合并。原媒体URL/缓存失效仍受来源可用性限制，沿既定媒体失败降级处理。不存在QQ、外部模型与本地文件的全局事务，不宣称网络exactly-once、外部旧写者或CLI多文件原子性。所有写者需使用新协议。最近200个不同撤回短ID不是总元数据的固定200行上限，不随意丢弃未处理隐私意图。

验证：全合成App、假语音/OCR/网络、临时目录，覆盖危机、IO故障、重复、停止、休眠、换档、prepared与无QQ历史的重启恢复，以及隐私导出/归档。
