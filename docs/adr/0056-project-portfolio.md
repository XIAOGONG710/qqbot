# ADR 0056：项目组合先成为事实投影

- 状态：已实现事实层与共享选择，14 天模拟通过；线上开关默认关
- 日期：2026-10-10
- 关联：[ADR 0044](0044-npc-and-project-actions.md)、[ADR 0045](0045-continuous-needs.md)、[ADR 0053](0053-buying-the-camera.md)、[ADR 0054](0054-life-ledger-in-prompt.md)

## 问题

生活账已经能记录摄影练习，需要值也能让高压力时暂缓项目；但“项目”仍只有一个硬编码的 `photography_growth`。
课程作业有真实期限、在读书有继续 / 读完 / 放下，相机基金已经完成，这几件事没有统一接口。若选择器现在直接按几个关键词抢空闲时间，
状态行、日记和行动账会各有一套项目状态，也会把已经买完相机的基金继续当成目标。

## 决策

1. `projectPortfolio` 只从已有事实源投影项目，不新增状态文件：
   - 课程作业：`WorldNow.homework` 的课程、期限、完成时刻；
   - 摄影成长：事件账里的 `work_on_project / photography_growth`；
   - 阅读：角色卡既有的日期进度和 `reading / put_down` 状态。
2. 每个项目统一给出稳定 ID、类型、状态、进展、下一步、期限、资源和阻碍。状态先只有 `active / paused / completed`；没有证据时不编“失败”或“放弃”。
3. 活跃项目用纯函数排优先级：过期或 24 小时内课程作业最高，三天内其次；几天没练的摄影略抬高；阅读保持柔性。相同优先级按期限和 ID 排，重启 / 重放不换顺序。
4. 相机基金买完后不再进入项目组合。摄影项目改用已买的索尼 a6100 和套机镜头作为资源；没买时仍能练拍摄和修片，不把它误判成完全阻塞。
5. `chooseProject` 是状态行与生活选择器唯一的项目抢占接口；首个保守规则只允许三天内未完成的课程作业覆盖空闲安排。摄影和阅读仍在原计划选中它们时推进，不能靠“最高优先级”吞掉整天所有空闲。
6. 新配置 `projectChoice` 默认关；打开也要求 `autonomousLife` 真正可用。上课、睡觉、饭点、赴约和世界硬事件仍排在项目之前；模拟器与双向状态审计读取同一开关。

## 验证

- 三类项目来自各自权威事实源，相机基金不会回到活跃列表；
- 已完成作业、放下的书保留为可解释状态，但不进入活跃候选；
- 24 小时内的课程作业压过摄影和阅读；相同输入重复排序一致；
- 开关关闭时选择结果不变；打开后三天内作业在空闲时成为 `study`，状态行与事件账使用同一项目标题；
- 上课等硬事件不会被项目覆盖；
- 打开项目选择跑 14 天，课程作业、摄影和阅读都有真实行动，状态 → 账本与账本 → 状态双向审计均为 0；跨零点进入三天窗口时旧柔性行动会先结束再重选；
- 旧的摄影进展和 `lifeInPrompt` 接口不变。

## 下一步

1. `projectChoice` 继续默认关；先审查线上影子账与部署窗口，再决定是否灰度打开。
2. 给课程项目补稳定作业 ID；现在 `WorldNow` 只暴露课程名和期限，因此投影 ID 暂用两者组合。
3. NPC 改约、拒绝、迟到另做社会生态增量；不能把按日期生成的 NPC 状态直接伪装成对方真的发过消息。
