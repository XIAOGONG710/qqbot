# ADR 0234：把底层能力合成“她此刻的生活”

- 状态：已实现，随 Koishi 控制台页面加载后生效；不增加配置开关
- 日期：2026-11-04
- 关联：[ADR 0120](0120-status-dashboard.md)、[ADR 0222](0222-human-values.md)、[ADR 0232](0232-real-transport-facts.md)

## 背景

项目已经分别展示作息、心情、读书进度、世界事件和二十余项连续数值，但用户要跨多行读取并自行解释。对类似陪伴项目的公开展示进行功能对比后，我们只化用“先让用户看见角色正在经历什么”的产品思路，不复制对方的名称、界面、素材或实现。

## 决策

1. Koishi 状态页新增“她此刻的生活”卡片，把现有状态投影成“现在、身体感受、心情、你们之间、在读、刚发生”六类自然语言。
2. 卡片只读取已经存在的作息状态、世界账、每日心情、读书进度和连续数值，不调用模型、不写运行数据、不根据缺失字段补故事。
3. 身体语言只在宽阈值上出现，例如低精力、高饥饿或高压力；中间区间统一写“状态比较平稳”，避免把微小数字差异演成情绪。
4. 关系摘要只解释亲密、信任和摩擦的投影；完整数字放在折叠区，仍可核验，但不占据首屏。
5. “刚发生”只取世界账已经发生的最新事实。未来计划、模型猜测和聊天原文不进入卡片。
6. 原来的完整功能开关、连接状态和联系人表继续保留；生活卡只负责体验摘要，不成为新的事实源。

## 验证

- `dashboard.test.ts` 覆盖男朋友档优先、身体阈值、心情、关系、读书、最新世界事实和缺失数据降级。
- 测试确认摘要不泄露 ISO 时间、内部字段名或关系数值键。
- `dashboard.js`、`status.js` 通过语法检查，控制台纯函数回归通过。

## 后续

- 实际打开 Koishi 页面检查深色/浅色主题和手机宽度。
- 若生活卡稳定，再考虑把大量技术开关按“生活、记忆、社交、设备”等用户能力包折叠；底层开关仍保持独立，不能用一个总开关隐式扩大权限。
