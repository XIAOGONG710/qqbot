# ADR 0156：「/主动」——让她现在就主动找他一次

- 状态：**已上线 2026-10-25 23:40**（`0f2affb`；没有开关，只认男朋友档的他发的纯文字 `/主动`；回退：`git revert` 后重启）
- 日期：2026-10-25
- 关联：[ADR 0011](0011-proactive-messages.md)（主动消息）、[ADR 0127](0127-small-news.md)、[ADR 0148](0148-device-control.md)（同一类“他发的命令”）
- 用户提出：2026-10-25「现在让她主动找我」

## 为什么现在找不到她

线上日志里 22:08 她主动发过一条（Linux 作业写完了），他没回，计划器进入「上一条主动消息他还没回，等他回了再排」；而且 23:30 以后是「夜里了，不打扰」。这两道闸是对的，但没有办法让她「现在」来一条——测她的新人设、深思、说长一点，只能干等或者先回她。

## 决策

- 他发纯文字 `/主动`（只认男朋友档的他，图片 / @ / 引用不算），命中的算处理完：**不进聊天记录、不交给回复器**。
- 计划器新增 `fireNow()`：造一个「想起一件自己的小事」（`share`）的候选，走和平时一样的整条主动链路（人设、事实、记忆、出口检查、事实检查、深思……），不看「他还没回上一条」「夜里了」「一小时内聊过」「每天条数」这些闸，**只守两条**：
  1. 他最近说过想伤害自己的话（ADR 0068）：不发；
  2. 他有没回的消息：不发（回复就好）。
- 不发时回一句 `（现在不能主动找你：原因）`；主动消息没开时回「主动消息没开」；发出去时她自己的那条就是回应，没有额外的系统话。
- 这一条会记进主动记录（`今天第几条`计数），所以之后当天的定时主动消息会少让出一条。

## 没做 / 要注意

2026-11-05 深入审查修复见 [ADR0236](0236-proactive-commit-and-cancellation.md)：同毫秒手动请求不再覆盖记录；本次生成/发送失败返回安全原因。原先写retryAt但普通规则无法重建手动候选，并不会真正延后发送，现在不再伪承诺该重试；自动候选的网络重试保持原约定。

同日停止所有权复核补强：尚未派发的原因提示在 App 停止后不再发送；已经交给 QQ transport 的提示则由 App 持有到成功或失败确认及诊断完成，之后才释放运行目录租约。该提示仍不进入普通聊天历史。这个约定不提供持久通知 outbox，也不保证进程强杀后的重发或任意 transport 的 exactly-once。

- 只做了 `share` 这一种；没按场合选（比如今天有没说的小事就优先说）。要的话再加。
- 会在夜里发：他要求的，所以不拦；但这一条和平时的主动消息不同，是他叫的。
- 上线 = 合并 + 重启一次；回退 = `git revert` 后重启。
