# ADR 0127：她会主动讲今天的小事（配置 `smallNews`，默认关，要 `everydayLife` 和主动消息开着）

- 状态：**已实现，未上线**（2026-10-23；配置 `smallNews`；默认关）。上线 = `koishi.yml` 里加 `smallNews: true` + 重启；回滚 = 改回 false + 重启（不存任何状态）
- 日期：2026-10-23
- 关联：[ADR 0106](0106-everyday-life.md)（日常小事）、[ADR 0110](0110-photo-shares.md)（`cat_photo`——同一个“news 的新一类”做法）、[ADR 0057](0057-her-news.md)
- 用户提出：2026-10-23「日常对话我能感觉出她的生活很单调，几乎没有什么值得分享的有趣的事情，总是来回重复」

## 问题（有数据）

量了线上 10-08 → 10-23：
- **她自己讲自己的事**：486 条里约 126 句，其中 **「困 / 睡」一类占 18%**（23 句），其次相机、课、吃饭、作业——就是这几样来回说。
- **账上的活动种类太少**：16 天 159 件事，排得上号的只有「熬夜赶作业」13 次、「打独立游戏」12 次、「刷手机」约 13 次、修片 / 研究相机约 20 次；空闲时段的抽签池是卡上的 3–5 条 + 几条后加的。
- **日常小事（ADR 0106，98 条）刚在 10-23 才开始有，而且只有两处会让她说出口**：他问“今天干嘛了 / 有什么好玩的事”时；或“带自己的事”的轮次里 `今天的小事` 只是 5 个候选话题里的 1 个。她自己从来不主动提——所以账里再多小事，聊天里看不出来。

## 做了什么

新的 news 事件类 `small_thing`（`world.ts` 的 `newsSmallThing`，`withSmallNews` 运行时加，不改角色卡）：
- 有小事的日子里按日期取哈希，约一半的天（`SMALL_TELL_CHANCE`）从**当天已经发生的**日常小事里挑一件（按日期取哈希，同一天每次一样），过 10–40 分钟想起来随口发给他；**一天最多一件**。
- **只挑有画面、有来由的几组**：食堂、课堂、手机 / 校园网、宿舍、休闲、同学朋友、土豆、购物、修片。不含天气、身体、学习、家里（天气和身体本来有自己的说法，学习和家里的小事太平）。
- 提示词：「你今天{小事}，想随口跟他说一句：就说这一件（看「你那边」今天的小事那一行），像突然想起来的，一两句，不要他回应，也别铺开讲；那一行里没写的细节不编，也不要借这件事去问他什么」。
- 不勉强：**那之后两人聊过了就不单发**（聊天里多半已经说了）；**没说成的不留到后面的睡前 / 早安里**（小事过了就过了，不像相机那种要补说）；遵守原来的“主动”所有闸（每天条数、没回不催、她难过 / 很累让路等）。只对男朋友档。

## 没做 / 要注意

- 这只解决“有了小事她不提”。**小事本身还是日常尺度**（98 条里 11 条食堂、14 条宿舍……），不是“有趣的大事”。真正的“有趣”要么是更丰富的真实来源（B 站热门、游戏更新、节日和校园活动），要么是跨好几天的小故事线——后者要作者定（她的人生不能我编），见下一条。
- **空闲活动池太小的问题没动**（打独立游戏 / 刷手机 / 熬夜赶作业来回出现）：那是卡上作息的抽签池，扩池是改“她是谁”的边缘，等用户点头再做（能做：在 `schedule.free.later` 里加一批日常尺度的新活动，按“从哪天起”生效，类似节日活动的做法）。
- 效果要看真模型（`sim/small-news.json`）——外网恢复后跑；今天只有单元测试。

## 验证

`small-news.test.ts`（6 个）：120 天里有小事的天约一半有、一天最多一件、同一天每次一样、默认没有这一类；挑的都是能讲的那几组、时间在发生后 10–40 分钟、说的就是账上那句；没开 `everydayLife` 的卡没有；`withSmallNews` 加 news 时机和这一类、不叠；说明里每条底线都写着、不给台词；那之后聊过了不单发、不顺带留到睡前。
