# ADR 0136：引用回复（配置 `quoteReply`，默认关）

- 状态：**已实现，未上线**（2026-10-24）。上线 = 换代码重启 + `koishi.yml` 里加 `quoteReply: true`；回滚 = 去掉这一行（或改 `false`）重启
- 日期：2026-10-24
- 关联：[ADR 0081](0081-quote-reply-read.md)（看得懂他的引用）、[ADR 0086](0086-self-recall.md)（打错字撤回重发）、[ADR 0094](0094-her-own-agenda.md) 起的形状控制
- 来源：2026-10-24 对照麦麦（MaiBot）等相似项目后用户说「123都做」；这是第 1 条（QQ 引用回复）

## 问题（有数据）

她以前一次都没发过 QQ 的“引用回复”（长按一条消息 → 回复，对方那边这条消息上方带着被引用的那句）：代码里只有 `onebot.ts` 的 `quoteText` 能**读懂**他的引用，发送路径里没有这一段。真人在两种时候会引用：

1. 他连着发了几条，其中一条是问题、又不是最后一条——她回答那个问题，不引用的话对方要自己对号；
2. 打错字撤回失败（超过两分钟，ADR 0086）、补一条「*对的词」时，有时引用刚才那条错的。

但也不能多：他自己 654 条消息里只引用过 1 次（0.15%），所以这是**很少出现**的事，不是每次回都带。线上 10-05 到 10-23 的聊天记录（只数条数，不看正文）：

- 她回复之前他连发了两条以上的有 82 次（463 次回复里占 18%）；
- 其中“有一条是明确的问句、又不是最后一条”的只有 11 次（2.4%）。按 60% 的概率引用，约 1.4% 的回合——这 18 天里大约 6–7 次。

## 做了什么

- `quote-reply.ts`（纯函数）：`planQuote` 看他还没回的那一串——至少两条、有一条**明确的问句**（带问号、句尾「吗 / 么」、疑问词加「呢 / 吗 / 啊」；比 `intent.ts` 的 `QUESTION` 严，那条会把“我在想去哪玩”也当问句；「什么 / 怎么」结尾也不算，免得“我不知道吃什么”被引）且不是最后一条，就按 `QUOTE_SHARE = 0.6` 的概率（按消息 id 定，同一串消息重算多少次都一样）引用最晚的那一条。不能引用的：合成的 id（戳一戳、B 站私信的记录 id ≥ 2³²，QQ 会报错）、没有 id、不到 4 个字（「在吗？」）、超过 60 个字、「[」开头的占位符 / 本身就带引用的、他撤回的。
- 提示词多一行：`[你这一轮的第一条是在 QQ 里引用他那句「…」回的：第一条先直接回它，再顺着回他后面说的；第一条里别再把那句话复述一遍]`，让第一条真的是在回被引用的那句。危机回合、他难过（“先接住他此刻的情绪”）、主动找他、只发表情 / 照片的回合不引用。
- 发送：`responder.ts` 的 `send` 多一个 `{ replyTo }`，**只有第一条**带；第一条打错字撤回重发时，打错的和重发的都带，留下来的那条是引用的。撤回失败补「*对的词」时，按 `QUOTE_FIX_SHARE = 0.35` 的概率引用那条错的（`quoteFix`，按那条错消息的 id 定）。
- 传输：`OneBotClient.sendPrivateText(userId, text, replyTo?)` 与 Koishi 插件里的 `sendPrivateText` 在消息最前面放 `{ type: 'reply', data: { id } }`（OneBot 11 标准）。引用发不出去（那条太老 / QQ 不认）就去掉引用再发一次；超时不重发（可能已经发出去了）。图片表情、照片不带引用。
- 开关 `quoteReply`（`config.ts` / `features.ts` / 插件 Schema）；模拟器场景加 `quoteReply`、`quoteShare`（测试和对比用），报告里写成「她（引用「…」）：…」。

## 数据

真模型模拟（`sim/quote-reply.json`，8 次“先问一句、又发一句别的”+ 2 次没有问题的连发，`quoteShare: 1`，2 次，共 20 次生成，约 0.11 百万输入 token）：

| | 次数 | 结果 |
|---|---|---|
| 有明确问句、不在最后一条 | 16 | 16 次第一条直接在回被引用的那句；0 次把那句话复述一遍；后面几条顺着回别的（「那你早点睡呗」「我也快疯了」） |
| 连发里没有问句 | 4 | 0 次引用 |

样本小，而且 `quoteShare: 1`（每次都引）只为了读；线上是 60%。

## 没做 / 要注意

- 没验证过线上 NapCat 对 `reply` 段的反应——协议上是标准的，失败有去掉引用重发的兜底；第一次线上引用要看一眼日志有没有「引用回复没发出去」。
- 主动找他、“说了等下之后回来”（ADR 0112）的那条没有引用（那类要记下被推迟的那条消息的 id，等有数据再说）。
- 没引用她自己的话。
- 单元测试：`quote-reply.test.ts`（挑选规则、回复器里只有第一条带、撤回失败补错字、模拟器里走一遍）。
