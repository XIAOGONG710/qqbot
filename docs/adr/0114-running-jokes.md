## 差距

情侣之间有只有你们懂的玩笑：一个词、一句话反复出现，当时两个人都笑了。她的“记得”是事实（长期记忆），没有“我们的梗”这一层，所以不会过几天自己回头提一句。

## 做了什么

1. **后台抽取**（`jokes.ts` 的 `refreshJokes`，和待跟进、答应的事同一种做法）：每 6 小时看一眼；最近 14 天聊天不少于 40 条、距上次抽取 ≥ 20 小时、比上次多 ≥ 12 条新消息才抽。让模型挑**最多 3 个**反复出现、当时双方在玩的词 / 短句，输出 JSON。
2. **代码硬校验**（`parseJokes`）：梗必须在聊天里**原样出现过至少两条不同的消息**——模型编的、改写的、只出现一次的一律丢；2–12 个字；来历 ≤ 40 字；全是数字 / 像电话号码的不要。旧的梗只要最近两周仍原样出现两次以上就留着。存 `<数据目录>/jokes/<QQ>.json`（读坏了当作没有，原文件不动）。
3. **用的时候**（`jokeLine`）：约 1/4 的轮次（按他最后一句取哈希，同一句每次一样）给她一行：「你们之间有个小梗「X」（来历：…）：这一轮话赶话正好接得上，就顺口提一句；接不上就别提，别解释这个梗，也别每次都提」；她自己 72 小时内说过的梗不再给；他难过 / 危机 / 小别扭 / 主动找他 / 她在想事情时不给。日志只记“放了一个”，不记内容。

## 数据

- 模拟（真模型，`sim/jokes.json`，预置梗「大肘子」，5 次 × 8 句闲聊）：40 句回复里提了 **2 次**，都在他说“我今天吃撑了”时——「大肘子吃多了吧」「大肘子还吃撑了」；没有每句都提、没有解释梗。

## 没做 / 要注意

- 抽取要一次后台模型调用（约 2k token / 20 小时）；没有联网时抽取失败只记日志，用老的。
- 梗的内容在她的提示词里和聊天记录同样敏感，所以存在数据目录里、不进日志。
- 现在没有“梗会随时间消失”的机制，靠“最近两周还出现两次”自然淘汰。

## 验证

`jokes.test.ts`（8 个）：硬校验（编的 / 一次的 / 太短 / 空来历 / 号码 / markdown 围栏）、最多 3 个；聊天太少不抽、抽了存下来且日志不含内容、20 小时 / 新消息不够不再抽、旧的还成立的留着；坏文件当作没有；约 JOKE_TURN_SHARE 的轮次给、同一句每次一样、72 小时冷却、没有梗就没有。

## 2026-11-05：后台停止与在途来源核验（记忆审查第二十一批）

真实合成App证明仅清6小时timer不能取消已派提取：stop释放目录锁后旧模型仍写文件和日志。jokeRefresher拥有所有本地任务，停止同步拒新并取消纯模型等待，drain后App才释放目录租约；构造失败同样登记。晚结果、派发前微任务、授予模型日志均守停止；已确认文件不回滚。取消本地等待不是取消远端服务或其自身副作用，不提供网络exactly-once或强杀事务。

另确认同长度撤回：held提取依据已被替换为撤回占位的消息，仍生成旧梗。生产宿主提供freshHistory，冻结完整角色/时间/正文，派发前及返回后核原前缀；正常追加不失效，来源修改/截短/读取失败不得提交旧结果。独立调用不提供freshHistory只能得到自身快照语义，不声称读取外部来源。

这尚未解决已经保存的旧梗来历：原文件没有可证明每项来历来源的持久manifest，仅重复phrase仍有效不能证明origin有效。合成App已证明撤回来历的唯一来源后重启仍会读旧origin；此项仍待贯通持久来源和读口，不自动猜删全部已回复事实，也不将本批当作所有小梗撤回问题已解决。

## 2026-11-05：已保存来历的持久来源（第二十二批）

真实合成App证实：保存小梗后撤回唯一的来历来源，即使另外两条仍出现同一梗词，重启后旧origin仍进实际提示词。单独按phrase计数无法验证origin。采用整份缓存的保守来源依赖：记录冻结历史完整前缀的条数与role/time/content摘要，绑定实际小梗集合，并保留实际模型请求的摘要；不重复存聊天或提示词原文。请求摘要是本地指纹，不是远端完成回执。读口每次用fresh历史校验；正常尾追加仍匹配，撤回/修改/截短后暂避整份派生内容，不改历史事实。

兼容：旧无来源manifest的文件保原，生产读口不冒充已经验证；显式坏manifest失败关闭，不降级为legacy并覆写。原20小时冷却保留，失效/legacy达到冷却且窗口仍够40条后，可跳过MIN_NEW/cursor门槛重新生成，避免永远等待新增消息。旧origin只有其原来源与集合仍有效时才能保留到新提取结果，扩大后的历史前缀包含旧依赖；失效或无证据旧内容不得借新hash洗白。已回复和危机keep的来源未被历史层遮盖，保持既定策略。

该证明只覆盖本地缓存与当前可读取历史；摘要不能鉴别恶意伪造所有字段，也不提供跨文件全局事务、外部不合作写者或任意历史丢失恢复。模拟器显式预置梗是作者输入，继续走独立接口，不误当成缺证磁盘缓存。现有jokes/QQ.json及精确tmp隐私清单继续覆盖新增指纹，无新增正文副文件。

补充故障边界：除明确ENOENT首次缺文件外，坏JSON、读取EIO、坏schema/manifest均返回不可用来源标记，保原且不自动刷新覆盖。诊断回调抛错不得把这个标记洗成可重建legacy空白；日志不包含解析出的私密正文。实际请求指纹在派发前固定，交给provider的是副本，provider修改参数不会改写本地证据。

## 2026-11-05：重叠刷新不能回退已确认进度（第二十三批）

合成真实文件复现：旧42条提取held，追加至54条并先提交新结果，再释放旧结果，持久source.count/messageCount从54回退42。现派发时冻结原状态摘要，模型返回且来源核验后、保存前重读比较；其它已确认提交改变状态则放弃本次旧结果。新的发布失败不伪造进度，旧请求仍可正常提交。该保护限App目录单写所有权下的本地同步提交段，不宣称对不合作外部进程形成原子CAS，也不消除所有重叠模型调用成本。
