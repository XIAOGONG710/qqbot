- 日期：2026-10-24
- 关联：[ADR 0110](0110-photo-shares.md)（喂完土豆发张照片：本条走同一条“news → 计划器 → 主动消息”的路）、[ADR 0084](0084-bilibili-browsing.md)（B 站分享）、[ADR 0135](0135-proactive-openers.md)（主动消息：事实只能用写了的）、[ADR 0137](0137-fact-check.md)
- 来源：2026-10-24 用户「上线，然后继续开发新功能」。接着想的：她有「听歌中」的在线状态，空闲活动里有「赖在床上听歌」「躺着听歌刷B站」，却从来没有把一首歌发给他过——情侣之间最常见的小事之一，也是现在最缺的一种“她在生活”的痕迹（照片、B 站视频、小事都有了，歌没有）

## 做了什么

- **候选**（`music.ts`）：每天刷一次（`MUSIC_REFRESH_MS` 20 小时、6 小时看一眼）网易云公开榜单（飙升榜、新歌榜、热歌榜、原创榜，各 100 首），挑能播、有歌手、时长 1.5–7 分钟、不是 DJ / 伴奏 / 纯音乐 / Remix / 翻唱 / 现场 / 变速的；逐首读歌词接口，去掉署名行（作词作曲……）和段落标记（verse 2、Chorus），挑**重复最多的相邻两句**（副歌）；歌词里有脏话 / 性暗示 / 危机相关的词的整首不要；歌词不是以中文为主的（俄语、日语、全英文）不要。最多留 12 首，存 `<数据目录>/music/music.json`。榜单是公开接口、只读、一天十几个请求；读不到就当没有候选，不影响别的。
- **什么时候发**：世界账里新的一类 news `music_share`（`world.ts`）：每天约 20%（`MUSIC_SHARE_CHANCE`，平均一周一两次）、晚上 20:30–22:30 之间按日期取一刻，同一天每次一样。计划器照 `photoReady` 的做法多一个 `musicReady`：有候选、上一首发出去满 3 天（`MUSIC_GAP_DAYS`，一周最多两首）才发；没有就跳过；发过的歌 90 天内不再发。属于“轻”的一类（`LIGHT_NEWS`）：他没回她上一条主动的时候不发。
- **怎么发**：先发歌曲卡片（OneBot 11 的 `music` 段，type 163，`OneBotClient.sendPrivateMusic`），隔一秒再发她的一两句话。卡片发不出去（NapCat 不认等）就改发「歌名 - 歌手 + 网易云链接」文字兜底，超时不重发（可能已经发出去了）。聊天记录里卡片写成「[音乐卡片：《歌名》- 歌手]」，她之后知道自己发过什么。试运行不发卡片。
- **她说什么**：提示词里一行事实「这首歌：《歌名》，歌手（网易云飙升榜上的）。歌词里有这几句：……。这些是你知道的全部：歌的故事、歌手的事、你听了多少遍、它陪你过什么，都别编；评价只说你听着的感觉；引歌词最多一句」，加上这次主动的说明：卡片已经先发了，用一两句说这首歌——为什么想发给他（只说真有的感觉）、可以引一句歌词；**这一条只说这首歌，别提别的事**（作业、身体、他在干什么）；别问「好听吗」「你听过吗」，不要他回应；开头别老是同一种。
- **两条出口检查**（`exit-check.ts`，只在发了卡片的轮次）：①「这首发你了」「发你听听」不算做不到的承诺（原来「发你」会被当成要发照片 / 语音拦掉，第一轮模拟里就有一次整条被删）；后面紧跟照片 / 图 / 视频 / 语音 / 红包的还是拦；②**不编听歌经历和歌的细节**：「单曲循环」「循环了好几遍」「听了一晚上」「前奏一起就……」「编曲」「嗓音」这些提示词里都没写，命中就带说明重写一次、还在就删那一行。
- 开关 `musicShares`（`config.ts` / `features.ts` / 插件 Schema，只对男朋友档）；模拟器场景加 `musicShares` + `music: [{title, artist, chart, lyric}]`（预置，不去读榜单），报告里卡片写成一条气泡。

## 数据

- 读榜单（真实、一次，临时文件）：4 个榜共 400 首，过滤后留下 12 首中文歌，每首带两句歌词。读出来才发现的三处：歌词里有「verse 2」这种段落标记被当成歌词；「操场」被脏话规则误伤（规则只认明确的说法了）；俄语 / 日语 / 全英文的歌被挑进来（现在只要中文为主的）。
- 真模型模拟（编的两首歌：一首温柔的、一首伤感的，各 5 次，共约 4 轮 40 次生成，每次只有 1 次生成，约 0.05 百万输入 token 一轮）：
  - 第 1 轮（6 次）：卡片都在文字前面；1 次整条被出口检查删掉（「发你」被当成做不到的承诺）→ 加了第①条；1 次编了「我循环好几遍了」；1 次文字和歌无关（讲生理期、开黑）。
  - 第 2–3 轮（20 次）：加了“这一条只说这首歌”和第②条的前一半后，还有 1/10 编「我听了一遍就单曲循环了」、2/10 编「前奏一起就想发你了」，1/10 文字是「忙完啦？」（没提歌）。
  - 第 4 轮（10 次，第②条加上前奏 / 编曲 / 嗓音）：10/10 都在说这首歌，8/10 引了一句歌词，没有编听歌经历 / 歌的细节；有一句「跟咱两家就隔一道门似的」是把歌词和她的设定（对门邻居）接起来，自然。
  - 样本小（每轮 10 次以内、歌是编的），只能说“这几类毛病没再出现”。

## 没做 / 要注意

- **没验证过线上 QQ 对 `music` 段的反应**：协议上是标准的，失败有文字链接兜底；第一次线上分享要看一眼他那边显示的是卡片还是链接，日志里有没有「歌曲卡片没发出去」。
- 歌来自榜单，不是“她的口味”（不编她爱听谁）；她也没真的听——提示词只给歌名、歌手、几句歌词，她说的“听着”是感觉。网易云的公开接口不是官方 API，可能变；变了就是没有候选，不发。
- 只做网易云；没做 QQ 音乐、没做他点歌 / 她给他放歌。他发来的音乐卡片她原来就看得懂（`shares.ts` 的「[分享音乐：歌名 - 歌手]」），没给那首歌配歌词。
- 偶尔（约 1/20）她的话没提歌——提示词让她只说这首歌，模型有时仍接上一句话题；卡片已经发了，不重试。
- 单元测试：`music.test.ts`（榜单解析、曲目过滤、歌词、候选和发过的记录、刷候选、发卡片兜底、世界账、计划器、回复器里卡片先发、出口检查两条）。
