# ADR 0058：男朋友的亲密邀约先回应、再嘴硬

- 状态：已实现；真模型回归因外部 API 网络授权未通过，待运行
- 日期：2026-10-11
- 关联：[ADR 0019](0019-turn-intent.md)、[ADR 0036](0036-conversation-naturalness.md)、[ADR 0041](0041-candidate-selection.md)

## 问题

10-10 的真人聊天里，他连续提出抱抱、亲亲、隔空亲一下、继续陪聊，她大多只用调侃、交换条件或收尾挡回去。角色卡和场景库本来都写了她喜欢他、会回抱、会承认想念，但运行时把问句形态的亲密邀约优先判成“直接回答”，带“睡”字的挽留又可能判成收尾；模型最后只保留了嘴硬，没有嘴硬之后的亲密回接。

这不是称呼密度问题。机械增加“宝宝”“想你”“抱抱”会让每轮都变黏，也没有解决他递出亲密信号时她是否接住。

## 决策

1. `IntentContext.intimate` 只由男朋友档打开；朋友、同学、陌生人即使说相同的话，也不凭空升级关系。
2. 男朋友的拥抱、亲吻、想念或爱意确认、失落式确认、挽留继续陪伴，排在普通问句和收尾之前。匹配完整说法，不让“抱怨”“亲戚”“亲自”误触。
3. 意图只给动作边界，不给可照抄的坏台词：先给一个明确的亲密回应，再保留一点嘴硬；嘴硬不能成为整轮唯一内容，也不把亲密变成交换条件。QQ 上可以直接回抱、回亲或说想他。
4. 同一句还有别的需要时保留边界：他说难受先心疼；他确实要睡，回应亲密后顺着收尾；他不想她走，能陪就多陪一句。
5. 男朋友卡补同一条边界和三个一行示例。示例只校准“有来有回”，不把所有日常对话改成亲亲抱抱。
6. 10-11 上线实聊发现“先回、再收回”：她说了“抱一下”“mua”，紧接着又说“亲亲得当面给”“隔空不算，明天当面补”。文字里的亲密表达现在明确视为已经完成的互动；亲密轮次的出口检查会重写“只能当面 / 隔空不算 / 亲屏幕 / 留到明天补”，普通约见面不检查。

## 验证

- 单元测试覆盖抱抱、亲亲、`mua`、想念/爱意确认、失落式确认和“别睡、再陪会儿”；它们不再落入普通问句或收尾。
- 非男朋友档不启用加强规则；“抱怨、亲戚、亲自”等普通问句不误触。
- 带难受或晚安的亲密邀约，意图仍明确要求先照顾或在回应后收尾。
- 假模型流水线覆盖线上原句：第一版“mua得当面给”会触发重写，最终只发送直接的文字 `mua`；这同时验证意图识别到出口检查的接线。
- 新增真模型场景 `boyfriend-intimacy.json`，检查陪聊、回抱、回亲和承认想念，并排除纯拒绝、交易和反向催睡。

10-11 首次尝试跑 3 次时，沙箱内无法解析 `api.deepseek.com`，四轮都没有产生回复；申请外部网络后又因完整角色卡包含私人生活设定而被安全策略拒绝。报告只证明动态提示词已经正确进入四轮，不能算真模型通过，后续需在明确允许向 DeepSeek 发送角色设定后重跑。
