# ADR 0084：她刷 B 站，刷到一个真视频，发给他

- 状态：**已实现，未上线、未开启**（分支 `claude/bilibili`；配置 `bilibili` = off / dryRun / on，默认 off）
- 日期：2026-10-19
- 关联：[ADR 0013](0013-old-project-advice.md) 决策 2（分享「刚看到的」会编出视频）、[ADR 0011](0011-proactive-messages.md)（主动找他）、[ADR 0083](0083-presence.md)（草稿档）、[ADR 0080](0080-share-cards.md)（他发来的分享她看得懂）
- 用户提出：2026-10-19 12:00「最近我看见有一个 dsh 刷 B 站视频的插件，可以让 dsh 刷 B 站视频，并 @ 用户账号然后评论，这个我们能做吗？」；「功能先做着，但是暂时不要开启」。

## 背景

搜到的最接近的是 GitHub 上的 [chenluQwQ/bilibili-ai-bot](https://github.com/chenluQwQ/bilibili-ai-bot)：一个**登录了 B 站账号**的 AI 角色，每天随机时间刷推荐 / 关注的 UP 主的视频、看完发评论、决定点赞投币收藏关注、回复评论区；登录靠账号的 Cookie（`SESSDATA`、`BILI_JCT`、`DEDE_USER_ID`），有休眠时段和每天条数上限。没搜到「评论里 @ 用户」的现成做法。

我们这边有一个更早的、没解决的问题：[ADR 0013](0013-old-project-advice.md) 决策 2 写下的教训——让她「分享刚看到的视频」，模型会**编一个具体的视频**，对方要链接时给不出来，所以「冷场」那一档明确禁止提视频、帖子、新闻。**有了真视频，这个禁区就能打开**。

## 能做的两层

### 一、只读（做了）：她刷到真视频，用 QQ 发给他

不用登录 B 站，不在 B 站发任何东西。B 站的热门榜（`x/web-interface/popular`）和热评（`x/v2/reply/main`）是公开接口，这台机器上直接能取（实测：热门榜 3 页都 code 0；`ranking/v2` 被风控 −352，所以不用它）。

流程（`bilibili.ts`）：
1. 每分钟看一眼（和 ADR 0083 同一个套路）：她醒着、在空闲或课间、没说过「睡了」；一天约 30% 的概率（一周两三个），工作日 19:00–22:30、周末 14:00–22:30 里某个哈希定的时刻；距上一个至少 36 小时，一周最多 3 个。
2. 取热门榜（缓存 3 小时，取不到 15 分钟后再试、只记一次日志），挑「她会点开的」：分区在日常 / 搞笑 / 小剧场 / 动物 / 美食 / 音乐 / 影视 / 游戏 / 科普 / 出行 / 摄影等里，20 秒到 12 分钟，标题简介里没有商单、抽奖、新闻、事故、争议等词；没发过的里按日期哈希挑一个。
3. 读前 3 条热评（去掉 @、网址、表情括号、太短太长的）。
4. 用主动找他的方式（`responder.initiate`，和早安、下课同一条路，所以出口检查、拆条、打字节奏、危机暂停都照旧）让她说一句：说明里只给事实（标题、UP 主、分区、分钟数、热评），要求「只说看了之后真实的一句感受或吐槽（可以接热评的梗），视频里没写的内容不编，不说你看到了哪一段、看了多久，链接会自动跟在后面你不用写」。
5. 她说完，程序把**真链接**（`https://www.bilibili.com/video/BV…`）作为下一条发出去，并在聊天记录里记「链接（《标题》）」，她之后知道自己发过什么。
6. `dryRun`：照常生成，但不发，话和链接存进 `<数据目录>/presence/drafts.md`。

### 二、要登录账号（没做）：在 B 站评论区评论、@ 他的账号

这一层需要一个 B 站账号的 Cookie，有四个问题，**每个都需要你决定**：
1. **封号风险**：自动化评论、@ 他人违反 B 站用户协议；新号、低等级号评论常被风控（验证码、−352 / −412）。账号被封是最可能的结局，不是小概率。
2. **公开关联身份**：她在公开评论区 @ 你的 B 站账号，等于公开把「她」和「你」这个账号连起来。她的角色资料含真实隐私信息（见 CLAUDE.md），这条要你拍板。
3. **要账号**：得有一个专门给她用的 B 站号（不是你的），和它的 Cookie（`SESSDATA`、`bili_jct`）放在本机的秘密里，会过期要刷新；还要你的 B 站 UID（@ 要用）。
4. **没必要先做**：第一层已经把「她刷到视频、发给你并附一句评论」做到了，走的是 QQ 私聊，你直接就看得到；第二层只是再多一个公开的出口。

如果你要做第二层，我的建议：先让第一层跑一周，看你喜不喜欢；再决定是否给她开一个专用 B 站号，并且**只评论、不点赞投币关注、一天最多一两条、休眠时段 2:00–8:00**（和上面那个项目的默认一致），@ 你的次数更少。

## 验证

- `bilibili.test.ts` 10 项（热门榜字段 / 坏条目 / code 非 0 / HTTP 错误；热评过滤；合适与否；按日期哈希挑、发过的不挑；说明里的几句；刷不刷的概率与时刻；开着发一个并记下发过的、一天一次、36 小时间隔；试运行写草稿；正聊着 20 分钟后再试、失败今天不再试、睡着不取榜；取榜失败只记一次）。
- `app.test.ts` 2 项（开着：读榜和热评 → 她说一句 → 真链接发在后面并记进聊天记录；关着不碰 B 站；试运行：不发，草稿里有话和链接）。插件配置里 `bilibili`。
- 模拟器新增 `video` 步骤（`sim/bilibili-share.json`），真模型 3 次 × 4 个视频：「刚刷到这个，前面笑得要死后面突然有点感动 热评那个梗我服了」「这个视频看着看着就安静下来了，说不上来」「这个混剪太绝了，赵本山一开口我人没了」「这个最后那波配合是真离谱，我看得一愣」；没有一次写链接、写 UP 主、写标题全名；32 项检查 3 次里 31–32 项过（1 项是我设的「标题」禁词，她直接提了视频里的词）。

## 没做 / 要注意

- 全程**没在真 QQ 上试过**；B 站的接口可能变、可能风控（−352 / −412）——取不到就只记一行日志。热门榜的内容是大众的，她的口味靠分区白名单和黑名单词粗筛，**偶尔会挑到你觉得不对味的**，所以上线先 `dryRun` 看草稿。
- 他发来的 B 站**文字链接**（不是分享卡片）她只看到网址；分享卡片已经读得懂（ADR 0080）。读文字链接要解 `b23.tv` 短链，另开一项。
- 链接发在话的后面，QQ 会不会渲染成卡片取决于客户端；渲染不出来就是一个网址。
- 视频内容她是**看不到**的（没有字幕 / 画面理解），只靠标题、简介、分区和热评；说明里要求「不编视频里没写的内容」，实测她会接热评的梗、说整体感受，不报情节。

## 长跑测试发现的问题（2026-10-19）

`presence-soak.test.ts`（假时钟每分钟一次走 60 天）里加了一条「B 站接口一直取不到」：原来取榜失败固定 15 分钟后再试，被风控（−352）的日子里，从定的钟点起到她睡着，每 15 分钟打一次 B 站，60 天里 226 次。被风控时这样一直敲，只会让风控更久。现在越隔越久：15、30、60、120 分钟，之后每 2 小时，取到一次就从头；同一条测试现在不超过 150 次，日志仍然只记一次。
