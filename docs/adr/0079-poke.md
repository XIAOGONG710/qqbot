# ADR 0079：他戳她一下，她会回

- 状态：**已实现，未上线、未在真 QQ 上验证**（分支 `claude/poke`；配置 `pokes` 默认关）
- 日期：2026-10-19
- 关联：[ADR 0075](0075-reply-rhythm.md)（看到之后她要打字多久）、[ADR 0007](0007-schedule-and-reply-timing.md)（什么时候看到）、[ADR 0042](0042-interrupts-and-chat-rewrites.md)（她说过「睡了」）、[ADR 0077](0077-typing-status.md)（同样是只在真 QQ 上才看得出来的）
- 用户授权：2026-10-19 09:14「继续」——做和测；**上线（打开配置、重启）和第一次在真 QQ 上试仍要用户在场**。

## 背景

QQ 里「戳一戳」是最常见的亲密小动作：他双击她的头像，聊天里出现一行灰字「宝宝 戳了戳 林梦瑶」。真人女朋友一定会有反应（「干嘛」「？」「戳我干嘛」），现在她**完全没有**：插件只挂了消息中间件，`notice/notify/poke` 这个通知被 Koishi 当 `notice` 事件发出去，没人听。他戳了她，什么都不会发生——和已读不回不一样，这是**他看得出来她根本没收到**的那种安静。

## 决策

1. **一次戳 = 一条「[戳了戳你]」**，和「[语音]」「[图片]」一样是占位符，进聊天记录、走原来的整条回复流程（什么时候看到、打字多久、气泡数、出口检查全部照旧）。不单独做「戳回去」的回复器：模型看到这行字自己知道怎么接，比写规则像人。
2. **真模型先试了再接线**（见验证）：直接把「[戳了戳你]」当他说的话，她的反应已经是「戳我干嘛」「戳上瘾了是吧」，不用改提示词、卡、世界书。
3. **算数的戳**才进来（`receivePoke`）：
   - 配置 `pokes` 开着；
   - 戳的人在回复名单里（名单外的好友不理，不占名单外限额）；
   - 通知不是旧的（超过 60 秒的不理：断线后补推等）；
   - **她睡着、在上课时不理**（`stateAt` 是 sleep / class，或她说过「睡了」）。消息会等到起床、下课后看到，但一个戳早上八点才回「戳我干嘛」是怪的——戳是当下的事；
   - 5 分钟里最多算 3 下，第 4 下起不理（日志只记「已经戳过 3 下」，不记次数以外的东西）。她回过一两句「戳上瘾了」就够了。
4. **消息 id**：戳没有真的 QQ 消息 id。聊天记录只收非负的安全整数，NapCat 的真 id 是 32 位，所以用 `2^40 + 时间毫秒 + 序号`。不会撞真 id，同一秒两下也不撞。（测试里第一版用负数，聊天记录拒收，被测试抓到。）
5. **认「他戳了小号」**（`isPokeAtMe`）：NapCat 私聊戳一戳（`OB11FriendPokeEvent`，`vendor/NapCatQQ/packages/napcat-onebot/event/notice/OB11PokeEvent.ts`）里 `user_id` 是这段私聊的对方（不论谁戳的）、`sender_id` 是戳的人、`target_id` 是被戳的人，所以要 `target_id === self_id`；有 `group_id` 的（群里戳）不理；小号戳他（`target_id` 是他）不理。
6. **接线**：Koishi 插件在 `ctx.on('internal/session')` 里认 `type === 'notice' && subtype === 'poke'`，原始数据在 `session.onebot`（同一份消息中间件在用的）；独立运行的 `main.ts` 的 `onEvent` 也接了。

## 验证

- 真模型（`sim/poke-boyfriend.json`，周六下午 15:00，他先发「我到家了」，隔了一个半小时戳一下、说句话、又戳一下）6 次共 15 项检查全过，她的反应：「戳我干嘛」（3 次）、「干嘛戳我」；接着他说「没事 就想戳戳你」：「戳上瘾了是吧」「就为这个戳我？那你得说句好听的补偿我」「你戳我我也不会跑啊」「打游戏呢，有事说事，没事别乱戳」；再戳一下：「戳够没」「手欠是不是」「你不是没事吗，还戳」。没有复述「你戳了我」、没有系统腔、不重复上一句。第一次跑时检查把「戳我」列成禁词，是检查写错了（真人就这么说），已改。
- 测试：`pokes.test.ts`（认得出、变成消息、限频）3 项；`app.test.ts` 3 项（关着不理 / 开着回、聊天记录里是他发的一条、提示词里有「[戳了戳你]」；名单外、旧通知、连戳第 4 下起不理；睡着、上课不理、空闲时算）；插件配置 1 项。bot 包全套并发 1 另见 BOARD。类型检查 bot 和插件都干净。

## 补：戳回去（配置 `pokeBack`，默认关）

- 算数的戳里约 40%（按人和通知时间哈希定，同一下每次一样）她也戳回去一下，隔 1.2–3.5 秒（比文字回复早）；同一个人 5 分钟最多戳回一次。NapCat 的 `friend_poke { user_id }`。她睡着、上课、被限频的戳不算，也就不戳回去。
- 失败（NapCat 的 packet 服务不可用等）只记一行「戳回去失败：…」，文字回复照常。**`friend_poke` 是 NapCat 的 packet 动作，要它的 packet 服务可用；线上 `packetBackend` 是 `auto`，日志里没看到是否真起来了，所以是否能戳要上线后试。**
- 她自己戳他不会再触发「他戳了她」：那条通知的 `target_id` 是他，`isPokeAtMe` 不认，不会循环。
- 测试：`pokes.test.ts` 里概率和延迟范围（2000 个时间里约 40%，延迟在范围内，同一下每次一样）；`app.test.ts` 里开着戳一次、5 分钟里第二下不再戳、关着不戳、失败只记日志文字照回；插件配置 1 项。

## 没做 / 要注意

- **没在真 QQ 上试过**（戳回去同理）。事件字段是照 NapCat 源码和 adapter-onebot 的代码读出来的，没收到过真的戳。第一次要用户在场：开 `pokes`、重启后让他戳她一下，看日志里有没有「[<qq>] 戳了她一下」；没有的话先看 Koishi 日志里有没有收到 notice（可能线上 NapCat 版本不推私聊戳）。
- 戳回去默认关，见上一节；模型有时会说「那我也戳回去」而这一下没有戳（概率 40%），不影响。
- 群里的戳不处理（她不在任何群里）。
- 她睡着、上课时不理的戳不留任何痕迹（不进聊天记录），所以「早上起来看到一个戳」不会发生。要不要有这种可爱的事（一夜之后回「昨晚戳我干嘛」）是另一个取舍；先保守。
- 窗口里 3 下的上限和 60 秒的新鲜度是我定的，没有数据；上线后看日志里「已经戳过 3 下」出现的频率再调。
