# ADR 0330：承诺提取的来源、因果变更与世界事实身份

状态：接受，2026-11-05。关联 ADR0018、0047、0082、0242。

## 证据

M33：未回复的约见确认在提取等待期间撤回，旧结果仍保存约见；同消息数同步和重启不纠正。已完成提取的改期/取消也会丢掉此前有效约定，单纯过滤early条目无法恢复。闭段不等于用户已被答复，闭段结果同样存在合法撤回。聊天缺失时直接撤销所有来源又会把未知日历误当空白。

M34：世界事实先写成功、承诺进度写失败后，重提取结果由`[10]`变为`[20,10]`，旧按数组位置生成的事件ID吞掉20。该证据只涉及合成金额，不改变既有同日去重政策。

## 决定

1. PromiseState保留version1并新增可选sources、attemptSources、promiseVersions、loopVersions、uncertainSources。每次成功提取记录phase、完整来源count/digest及承诺/未了事项的最小before/after变更；尝试进度与成功来源分开，不能用当前摘要冒认旧提取已处理。
2. 提取前冻结来源摘要、称呼及有效pending/loops上下文。成功或失败返回后重新加载可靠来源和有效上下文；当前片段或输入上下文已变，则整次结果不提交、不消费重试次数、不标进度、不执行resolved/world回调。无关新片段不使旧有效提取饥饿；历史及回调输入均隔离别名。
3. 每个受影响记录有因果版本，删除也保留必要tombstone。失效来源只能撤销仍匹配自己version和after像的效果；后来其他来源已接管的记录不回滚。重复同一片段先恢复该片段的有效baseline，保留最初已确认约定的before像，再应用新结果。闭段与早提取共用这一协议，包括改期、取消、resolved及loops；不自动逆改已经实际落入世界的物理事实。
4. describe、openLoops、plans和约见读口都根据fresh来源投影，撤回后无需等待下一次sync才停用失效结果。来源未知与确认无约分开：聊天不可读、活来源消失或截短时，日历/日记来源保持不可确认，不能当空日历继续排程。正常追加不改已提交prefix；已回复消息与危机keep沿ADR0082保留。
5. 合法旧v1/无version状态及未知扩展继续读取。旧状态若有明确撤回但已丢before像，保存uncertainSources，不猜原约定或拼造缺失历史；须可信恢复/核实。没有明确撤回证据时不批量取消旧约。来源/前后像及版本元数据坏形状、同记录同版本被不同来源认领均失败关闭，避免按JSON顺序猜恢复结果。旧合法ID按字面访问版本字典，不把原型继承属性当已有版本。
6. 进度、来源与版本在原专属`promises/<QQ>-<tier>.json`共同原子发布，既有隐私清单覆盖该文件与实际临时残留。裁剪只移除不再支撑有效约定/未了事项的旧证据，版本仍有依赖时保留；不能为了限量丢掉恢复依据。单进程数据目录所有者约定不变，不声称多个外部写者的跨文件事务。
7. 世界事件仅在已有事实验证、目标匹配和语义去重后生成稳定身份。新conversation ID取contact、episode、kind、有效分钟、amount、target、subject的摘要，不依模型数组位置。旧事件ID保留，原同日/同金额/同目标等保守合并规则继续生效；重排、部分成功或进度失败后的重试不会吞掉另一笔不同事实，不回滚既有物理事件。

## 验证及边界

使用真实ChatHistory、PromiseKeeper、App和世界状态配合假提取、临时合成数据，覆盖等待竞态、同长度修订、闭段、跨片段恢复、后续写者、重启、缺失来源、未知旧状态、坏元数据与发布故障。原聊天的实际时间/内容、真实QQ、外部模型和运行目录均未访问，未部署。

JSON进度与世界事件仍非同一事务；稳定事实身份解决本批重试碰撞，不保证所有模型幻觉、外部手工重试或任意跨存储exactly-once。已丢失的legacy before像、强杀前未持久观察不能凭空恢复。M32b自动派生重建与有证据解封仍待实现，ADR0305读取/生成屏障继续保留，不能用本ADR清除guard。
