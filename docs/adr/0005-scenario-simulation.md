# ADR 0005：验收用例先在模拟器里跑（虚拟时钟 + 真模型 + 测试 bank）

- 状态：已采纳（2026-10-04，用户提出并确认，见文末「确认记录」）
- 日期：2026-10-04
- 修改：[ADR 0004](0004-time-scheduling-memory.md) 决策 4（口吻、时间承接类用例「必须在 QQ 上实测」）

## 背景

ADR 0004 决策 4 要求调研方案第 13 节的口吻、时间承接、记忆用例在 QQ 上实测。10-04 晚上按这个做了第一轮（见 roadmap「实测」一节），问题是：

- **太慢**：记忆用例要等一个片段安静 45 分钟才写入；T10、T11 要隔天；调研方案 13.1 要求每个用例至少重复 3 次。一个晚上只能跑完一轮调度用例。
- **有些路径手动测不到**：T09「拆条发送中途插话」，气泡间隔约 1.3 秒，人来不及在两条之间发出消息；T08「生成中纠正」，生成只要 2 秒左右。
- **起始条件不干净**：两个测试号的聊天记录里有语气修正之前的旧回复和另一套引擎发的回复，会被上下文带着走；同一句话也没法在相同的起始条件下重复。
- **要人肉对照**：结果只能靠用户读 QQ、我 grep 日志和 `last-prompt.json`，再对时间。

用户的要求：由我伪装用户消息和时间来测（「这样测试效率太低了，时间跨度太长了，你来伪装用户消息和时间来做测试」）。

### 取证

运行时已经有大部分接缝：

- `responder.ts` 的 `sleep`、`now` 可注入，`whenIdle()` 覆盖等对方说完、生成、逐条发送的全过程；拆条发送调用 `send`，生成调用 `generate`，都能包一层在指定时刻插入消息。
- `LongTermMemory` 的 `now` 可注入，片段是否结束、召回的 `query_timestamp` 都按它算；写入的时间取自消息自己的时间。
- `describeTime(chat, now)` 按传入的 `now` 算时间块。
- 还差：`main.ts` 里每位联系人的接线（召回 → 拼提示词 → 后处理 → 生成 → 清理 → 发送）是写死在入口里的；她发出的消息记的是 `new Date()`。
- Hindsight 0.10.2 有 `GET /banks/{id}/operations?status=`（pending / processing / completed / failed / cancelled），
  可以等后台抽取做完再往下走；`POST /mental-models/{id}/refresh` 可以手动刷新关系概况（T23）。

## 决策

### 1. 模拟器和 bot 用同一条流水线

把 `main.ts` 里每位联系人的接线提到一个模块里，bot 和模拟器都用它，模拟器不另写一份。模拟器只替换三样东西：

| 部分 | bot | 模拟器 |
| --- | --- | --- |
| QQ 收发 | NapCat | 进程内假的：发出的每一条记进报告，可以在第 N 条之后插入对方的消息 |
| 时钟 | 真实时间 | 虚拟时钟 = 真实时间 + 偏移：等连发、气泡间隔照真实时间走（T07–T09 真实发生）；场景里的「过 50 分钟」「过一天」直接加偏移 |
| 数据 | `runtime/bot/` | `runtime/sim/<场景>-<时间>-<第几次>/`，虚构联系人（QQ 10001），每次运行一个临时 bank（前缀 `sim`），跑完删掉 |

模型（DeepSeek）、Hindsight、角色卡、世界书、配置里的 `llm` 和 `prompt` 都和 bot 一样。

### 2. 场景文件 + 报告

- 场景是 JSON：档位、称呼、起始时间，然后一串步骤：说一句、连发几句、在生成中 / 第 N 条气泡之后插话、过一段时间、等记忆写完、刷新关系概况、自动检查。
- 每次运行写一份 `report.md`：每一步的虚拟时间、输入、她发出的每一条、调度事件（合并、重新生成、剩下几条不发）、召回块、时间块、关系概况、检查结果；
  同目录存每次生成的提示词。起始聊天记录为空，只有场景里的对话。
- 能机械判断的自动检查：召回里有没有埋下的事实、时间块里的间隔、某次回复有没有被丢弃、低档位的回复里有没有 `tiers.toml` 的禁用词。
- 口吻按调研方案 13.2 的通过条件由我读报告判断，逐条写结论、引原文，拿不准的标出来给用户抽查。每个场景跑 3 次。

### 3. QQ 实测保留什么

- 端到端冒烟：尾号 37 的号（男朋友档，用户自己也在用，不改档）。
- 只有 NapCat 能走到的路径：补回漏掉的消息、名单外好友（`sub_type` 为 `friend`、用 QQ 昵称）、群临时会话被忽略。
- 低档位：尾号 73 的号先当同学档，再移出名单测名单外（ADR 0003）。

聊天记录和 bank 现在都是测试数据，可以按需归档或重写（先移到 `chats/archive/`，不直接删）。

## 备选方案

| 方案 | 不选的原因 |
| --- | --- |
| 继续 QQ 实测，改测试号的聊天记录时间来「快进」 | 改的是 bot 正在用的数据，要停 bot；Hindsight 里已经写入的片段时间对不上；每次仍要人发消息 |
| 模拟器自己拼一份流水线 | 和 bot 慢慢走样，测的就不是线上的东西了 |
| 假模型 | 只能测机械行为，口吻、承接、记忆用不用得上都要真模型 |

## 后果

- 口吻、时间承接、记忆的结论来自模拟器里的真模型，不再等 QQ 实测；QQ 实测只做冒烟和只有 NapCat 能走到的路径。
  虚拟时钟只影响运行时自己算的时间；Hindsight 内部的处理时间（`created_at`、关系概况的 30 分钟刷新间隔）仍是真实时间，所以 T23 用手动刷新。
- 每次运行要调模型（聊天 + Hindsight 抽取），3 次重复就是 3 倍；场景要写得短而有针对性。
- 模拟的起点是空白聊天记录，和真实使用（几百条历史）不同；需要时可以另写场景先铺一段历史。

## 确认记录（2026-10-04）

1. 用户提出改用伪装消息和时间的方式测试；说明现在的聊天记录都是测试数据，可以按需清除或重写。
2. 起始聊天记录：空白（只有场景里的对话）。
3. 口吻由我按通过条件判断、引原文，用户抽查。
4. 每个场景跑 3 次。
5. 账号：37 保持男朋友档不改；73 做低档位测试号，先同学档、再名单外。
