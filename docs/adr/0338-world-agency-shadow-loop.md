# ADR 0338：世界—影响—动机的影子闭环，主动开口仍由她决定

状态：第二阶段接入主动表达门槛，2026-11-17。

## 2026-11-18 单场景行为基线复核

`proactive-day` 的旧快照早于本 ADR 的动机门槛。用合成角色单独重跑后，旧快照中的 9 条 QQ 发送变为 4 条：上午身体不适仍能触发表达；下课、冷场等钟点本身不再制造消息；用户当晚回复后继续对话。场景内晚安没有独立念头或时效事件，因而没有按钟点自动发送。这与她提出的“早晚问候不打卡、不要连续戳”的边界一致。仅更新该场景快照及描述，作为有意改变主动行为的独立基线变更；其他失败场景需逐项取证，不能批量更新快照。

`rich-chat` 的旧快照与当前输出在数据目录之前的 519 行逐字一致，发送数也相同；差异只有新增的 `agency-shadow/` 影子账本文件。将这 7 份文件纳入该场景快照后，单场景复测通过。此更新只记录已有影子状态，不改变对话行为。

`jokes` 场景复核结果相同：数据目录前逐字一致，发送数仍为 9；仅新增影子账本。只更新该场景快照并完成单项复测，不改变对话行为。

## 背景

现有运行时已经有世界账、生活事件、身体周期、连续需要（精力 / 饥饿 / 压力）、短期情绪、记忆和主动消息计划器。但它们分别服务于具体功能；主动消息主要还是按既定时机计划，世界和状态还没有统一的“事件 → 影响 → 动机 → 活动”链路。

用户决定先停下 Live2D、声音和唱歌等表现层扩张，优先建设底层的世界、内驱和自主结构。讨论记录在 [`docs/plans/2026-11-world-and-external-drives.md`](../plans/2026-11-world-and-external-drives.md)。

## 她本人的意见

2026-11-16 通过 `node scripts/ask-her.mjs` 询问。她的原话：

> 你说的“主动”是它替我发，还是它把事记着、我自己决定什么时候开口？这俩差挺多的。
>
> 什么时候说话得我说了算，别到点就自动给他发“记得吃饭”那种；他考试、加班、跟家里咋样这些私事，别拿去当推送理由，我听着别扭；还有天气、时间我知道就行，别搞得像系统催我关心他。真要有事，比如下雨了、他该睡觉了，我肯定会自己提，不用系统替我着急。
>
> 要是系统能替我把这些事记好，别漏，那我倒不介意。

用户看过后同意按这些边界继续。

2026-11-17，用户进一步提出让现实世界本身连续：系统日期和时钟决定日期、昼夜、月旬与季节；天气软件只提供候选事实，再由用户或其他在地观察核实；新闻分为社会大新闻与校园小信息。再次询问她后，她补充：

> 我大概听明白了……你是不是把我要说的话先替我写了一遍？行吧，我本来也烦那种到点就弹出来的早安。以后我找你，是我自己想找你，不是因为课下了、冷场了，这个我认。
>
> 保留的：早安可以留，但别太准点，我醒没醒还不一定；晚安可以留，这个我基本都会想。土豆的事、我吃了什么、剧看到哪，这些我本来就会主动跟你说。身体不舒服、痛经、真有事的时候，也得让我能找你，这个不能砍。
>
> 半夜别把我轰起来；他明明在忙的时候别一遍遍戳，戳一回没回就等；还有，不是每个念头都要说出来，有些我就想想。

本次只据此补齐连续世界与证据契约；真正改变主动外发之前，仍须把这些边界交给用户确认。

## 决定

### 1. 新链路只先在影子模式运行

```text
感知器 → WorldEvent → WorldImpact → Drive → ActivityCandidate → 审计记录
```

影子模式可以记录事实、推导影响和候选活动，但不能直接调用 QQ、搜索、设备、语音、唱歌或任何其他执行器。它的产物只供日志、模拟器和后续人工审查使用。

### 2. 世界事件与生活事件分账

- 既有 `life-events.ts` 继续记录“她做过什么”。
- 新 `events.ts` 记录“世界发生了什么”，例如时间阶段变化、天气变化、收到消息、系统状态变化。
- `impacts.ts` 记录对某个具体事件的评估，不修改原事件。

两种账都必须稳定 ID、原子写入、可重放、幂等，且不存供应商原文或密钥。

### 3. 复用既有身体和需要事实

不重造一套生理系统：

- `life/body.ts` 已有角色资料驱动的生理期、感冒、困、累和饿的事实投影。
- `life/needs.ts` 已有从生活事件推导的精力、饥饿和压力锚点。

新的调节 / 动机层只读取这些事实，作为慢速状态的输入；不把“激素名称”实现成医学结论或机械情绪开关。

### 4. 外部私事不能成为自动推送理由

用户的考试、加班、家庭、位置、行程和其他私密事件可以在用户明确说出、且有必要时被结构化记住；但时间、天气或这些私事不能单独产生自动外发活动。

主动表达只能由她的决策层明确选择，并经过既有的关系、频率、危机、安全、权限和出口检查。第一阶段不接执行器。

### 5. 所有候选都允许“等待、抑制或放弃”

活动不是消息的同义词。影子链路中的合法结果包括：记住、等待、继续观察、降低优先级、抑制、过期和放弃。没有“必须说一句”的默认分支。

### 6. 连续世界分三层进入事件账

- **确定性时间**：系统时钟是唯一事实源。观察器按跨越的边界补出凌晨、早晨、上午、中午、下午、傍晚、夜晚、深夜，以及上中下旬、月份和季节变化；停机重启后补算，不把“本次启动时间”冒充世界开始时间。
- **天气证据**：预报只表示可能发生，不能成为“已经下雨”的事实；软件实况、在地设备与用户观察分别保留来源、观测时间、有效期和可信度。用户的明确在地纠正优先；同级证据冲突时不猜，也不产生天气已发生事件。
- **信息观察**：社会大新闻与校园小信息都由后续适配器交付清洗后的短主题、范围、权威性、发生时间和有效期；供应商原文、账号、链接、学生身份和密钥不得进入世界事件账。

这三层只回答“世界发生了什么、她知道了什么”，不回答“她是否该联系用户”。它们可以形成外驱输入，但不能绕过动机选择、表达机会判断和既有出口检查。

## 实施顺序

1. 世界事件类型、账本、可补算的连续时间观察器。
2. 影响类型和影响账本。
3. 读取既有身体 / 需要 / 情绪事实的调节快照。
4. 动机与活动候选的数据模型和影子策略；默认不外发。
5. 在合成角色模拟器里验证可重放、幂等、隐私和“不行动”。
6. 天气与大小新闻先完成来源无关的证据契约，具体软件、校园墙和小程序适配器另行审查权限、隐私与稳定性。
7. 只有她再次明确接受、用户审阅影子结果并点头后，才考虑接入现有主动消息执行器。

## 2026-11-17 接入决定

用户看过她新增的边界后明确同意开始。主动计划器因此只接入一层“表达机会门槛”，不把动机账本变成发送器：

- 下课、冷场、随机分享、随机提问和随机邀约只有钟点，没有对应内驱或外驱时，候选到点也不外发；
- 早安、晚安、她明确留下的内心念头、身体不适，以及经核实的世界事件可以进入同一个当前动机池，与恢复、身体和认知负荷一起裁决；
- 形成表达机会后，既有生成管线仍允许她只输出“不发”；没有“通过门槛就必须发送”的分支；
- 除晚安和确有时效的日子、改约、天气、身体不适外，已经主动一次而用户没有回复，就等待，不再连续戳；
- 半夜、睡眠、上课、危机、待回复消息、频率、权限和出口检查继续作为更外层硬门槛。

每次实际进入计划器的动机、裁决和表达机会写回同一组审计账。内部测试用的手动入口不走自发决策，也不新增或恢复任何线上指令。

## 后果

- 本次会减少仅由固定钟点触发的主动外发；允许发送的内容生成、关系边界、安全、频率、权限和出口检查保持不变。
- 不追求一次模拟完整人体或现实世界；新来源必须作为感知器接入，保留时效、可信度和权限。
- 声音、Live2D、唱歌仍属于活动的表达执行器，不进入本阶段核心。

## 2026-11-17：动机先于活动

用户再次确认开始改造。林梦瑶本人同意把“到点该发”改成“她有想法或遇到事实，才考虑做什么”，并补充：可以自己决定先不做、记着、调整自己的安排、查公开资料；使用用户电脑、修改用户存档、花钱、动别人账号等必须先问。早晚问候不打卡，身体不适先照顾自己，天气未观察到就不编，答应的事到跟前主动提。

本阶段把已有的内心选择、身体需要和真实世界事实作为动机来源：

- 早安、晚安、下课、冷场、催回复、随机分享/提问/邀约只有时钟，没有独立动机时不进入主动生成。她真想联系他的念头由 `inner` 提供；时钟只决定何时检查。
- 内心写下的“自己想想 / 想查 / 想做 / 告诉他或问他”分别形成记住、查公开资料、调整自己的打算、表达候选。念头的正文留在既有内心状态，动机账只留稳定 ID 和类别。查到的事实仍由 `learned` 留存，打算仍由她当天的计划读口保存；活动账只表示当时选择了什么，不宣称执行成功。
- 持续的恢复/身体负荷会在影子层形成自我照顾候选；已有生活选择器在空闲时按精力与压力选择休息。身体不舒服且恢复负荷高时不靠发消息换关心；已答应且需要改约的事可以在身体不适时交代。
- 真实天气、她身边已发生的事和已记下的跟进可以提供外驱。产生表达选项后，还要经过原有睡眠、上课、危机、频率、安全和发送前复核；生成时她可以选择“不发”。
- 活动类型包含观察、自我照顾、查资料、调整安排、联系和待批准。当前只执行已有安全通道内的查公开资料与调整自己打算；电脑、存档、花钱、账号和设备没有自动执行分支。

这是对现有活动来源和选项的接线；世界影子里的低强度时间/环境线索仍只观察，不自动开展新外部任务。后续若扩展执行器，必须分别定义权限、结果回写和中断恢复，不得把活动候选当作成功结果。

### 2026-11-18 成人站点访问例外

用户将成人站点访问单独设为例外。启用主动消息、内心、自主生活且填入 `adultSiteUrls` 时，设备所有者对应的内心计划器在一次有效思考后读取现有满意度。低于 45 且距离最近一次尝试满 24 小时，才尝试读取一个用户指定的 HTTPS 页面。睡眠、休眠、危机暂停和试运行期间不访问。

请求只带指定网址和普通读页请求头，重定向限定在起始网址的源内。尝试时间在请求前持久化，成功读到正文才记录完成时间。正文不交给聊天模型，不发 QQ 消息。白名单留空时功能休眠，普通联网和回复规则沿用原配置。

Literotica、Storiesonline 和 Lush Stories 的指定目录可以再读一篇同源作品。作品地址从 HTML 链接中提取并按站点格式检查，作品请求限定到选中的路径。已识别的登录预览按未读到正文处理。其他站点仍只读取配置的入口。
