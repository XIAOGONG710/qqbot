# ADR 0338：世界—影响—动机的影子闭环，主动开口仍由她决定

状态：建设中，2026-11-16。

## 背景

现有运行时已经有世界账、生活事件、身体周期、连续需要（精力 / 饥饿 / 压力）、短期情绪、记忆和主动消息计划器。但它们分别服务于具体功能；主动消息主要还是按既定时机计划，世界和状态还没有统一的“事件 → 影响 → 动机 → 活动”链路。

用户决定先停下 Live2D、声音和唱歌等表现层扩张，优先建设底层的世界、内驱和自主结构。讨论记录在 [`docs/plans/2026-11-world-and-external-drives.md`](../plans/2026-11-world-and-external-drives.md)。

## 她本人的意见

2026-11-16 通过 `node scripts/ask-her.mjs` 询问。她的原话：

> 你说的“主动”是它替我发，还是它把事记着、我自己决定什么时候开口？这俩差挺多的。
>
> 什么时候说话得我说了算，别到点就自动给他发“记得吃饭”那种；他考试、加班、跟家里咋样这些私事，别拿去当推送理由，我听着别扭；还有天气、时间我知道就行，别搞得像系统催我关心他。真要有事，比如下雨了、他该睡觉了，我肯定会自己提，不用系统替我着急。
>
> 要是系统能替我把这些事记好，别漏，那我倒不介意。

用户看过后同意按这些边界继续。

## 决定

### 1. 新链路只先在影子模式运行

```text
感知器 → WorldEvent → WorldImpact → Drive → ActivityCandidate → 审计记录
```

影子模式可以记录事实、推导影响和候选活动，但不能直接调用 QQ、搜索、设备、语音、唱歌或任何其他执行器。它的产物只供日志、模拟器和后续人工审查使用。

### 2. 世界事件与生活事件分账

- 既有 `life-events.ts` 继续记录“她做过什么”。
- 新 `events.ts` 记录“世界发生了什么”，例如时间阶段变化、天气变化、收到消息、系统状态变化。
- `impacts.ts` 记录对某个具体事件的评估，不修改原事件。

两种账都必须稳定 ID、原子写入、可重放、幂等，且不存供应商原文或密钥。

### 3. 复用既有身体和需要事实

不重造一套生理系统：

- `life/body.ts` 已有角色资料驱动的生理期、感冒、困、累和饿的事实投影。
- `life/needs.ts` 已有从生活事件推导的精力、饥饿和压力锚点。

新的调节 / 动机层只读取这些事实，作为慢速状态的输入；不把“激素名称”实现成医学结论或机械情绪开关。

### 4. 外部私事不能成为自动推送理由

用户的考试、加班、家庭、位置、行程和其他私密事件可以在用户明确说出、且有必要时被结构化记住；但时间、天气或这些私事不能单独产生自动外发活动。

主动表达只能由她的决策层明确选择，并经过既有的关系、频率、危机、安全、权限和出口检查。第一阶段不接执行器。

### 5. 所有候选都允许“等待、抑制或放弃”

活动不是消息的同义词。影子链路中的合法结果包括：记住、等待、继续观察、降低优先级、抑制、过期和放弃。没有“必须说一句”的默认分支。

## 实施顺序

1. 世界事件类型、账本、时间观察器。
2. 影响类型和影响账本。
3. 读取既有身体 / 需要 / 情绪事实的调节快照。
4. 动机与活动候选的数据模型和影子策略；默认不外发。
5. 在合成角色模拟器里验证可重放、幂等、隐私和“不行动”。
6. 只有她再次明确接受、用户审阅影子结果并点头后，才考虑接入现有主动消息执行器。

## 后果

- 近期会增加状态账和模拟器测试，但不改变线上表达。
- 不追求一次模拟完整人体或现实世界；新来源必须作为感知器接入，保留时效、可信度和权限。
- 声音、Live2D、唱歌仍属于活动的表达执行器，不进入本阶段核心。
