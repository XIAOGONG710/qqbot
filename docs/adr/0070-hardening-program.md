## 第 1 批实现（网络与媒体安全）

- `safe-image.ts` 是远程图片的唯一入口：只收 http/https，不带账号密码；拒绝 localhost / `.local`、IPv4 私网与保留段、IPv6 本机 / 链路本地 / 唯一本地 / 多播以及内嵌 IPv4 的映射、NAT64、6to4 地址；解析结果里混有任何一个非公网地址就整体拒绝；连接时用同一规则再验一次 DNS（防重绑定）；重定向手动处理、最多 3 跳、每一跳重新检查；`Content-Length` 不可信，边读边限长，超额立即中止并取消；按文件签名认图（GIF / JPEG / PNG / WebP），不信响应头；不读的响应体立即释放。
- 表情收藏和看图都走它：表情「安全下载一次 → 同一份字节识图 → 决定是否保存」；`vision.ts` 的 `describe` 没有回退原始 URL 的路径，传入的 data URL 也先验签。
- 媒体读取（语音转文字、OCR、看图）按联系人先排队（前一条进了聊天队列才开始读下一条），语音 / OCR / 看图各有全局并发上限，停机和超时会把取消信号传到 OneBot 调用。
- 取舍：表情候选现在先下载再判断喜不喜欢，被拒绝的也会下载一次（原来是先问模型再下载）；这些图片都小于 5 MB，且每天候选数有上限。

## 验证

- `safe-image.test.ts`：各种写法的本机 / 内网 / 元数据地址（含十进制、十六进制、IPv6 映射、NAT64、6to4）全部拒绝，公网放行；重定向每一跳重新校验、次数有上限；超额正文被取消；不读的响应体被释放。
- `vision.test.ts`：下载失败不调用模型；模型只收到验过签名的 data URL。
- `media.test.ts` / `app.test.ts`：跨联系人的 OCR 并发不超限；同一联系人后一条媒体在前一条完成前不会启动；停机会取消正在执行的适配器。
- 全仓类型检查、bot 840 / 840、Koishi 插件 29 / 29。

## 第 7 批实现（基础设施：依赖、监听、口令、CI、上线检查）

- **依赖审计门**（第 11 项）：`npm audit` 的 18 个 moderate 条目只对应 2 个公告（`file-type` 16.5.4 的 ASF 死循环、`uuid` 8.3.2 的缓冲区边界），都从 Koishi 传递依赖进来；npm 给的「修复」是把 `@koishijs/plugin-database-sqlite` 降级，不可取。查了调用路径：`file-type` 只在 `@cordisjs/plugin-http` 的 `http.file()` 里用，`adapter-onebot` 只在发出消息时对 `src` 调它，本项目发图走文件 / base64，收到的消息不经过它；`uuid` 由 Koishi 控制台引入，本项目不调用。因此不升级、不覆盖，记进 `docs/security/npm-audit-baseline.json`；CI 新增 `node packages/bot/src/ops/audit-gate-cli.ts`：出现 high / critical、或基线之外的新公告就不通过，拿不到审计结果（退出码 2）也不当作通过。等 Koishi 上游发兼容版本再升级并清空基线。
- **监听检查**（第 12 项）：`ops/listeners.ts` 列出本机我们自己的进程（node / python / postgres / QQ）监听的非回环地址；2026-10-13 实测全部在 `127.0.0.1` / `::1`（NapCat 3001、Koishi 5140、PostgreSQL 5433、Hindsight 8888）。数据库口令：`start-hindsight.ps1` 读 `QQBOT_HINDSIGHT_DB_PASSWORD`，默认仍是 `hindsight`（现有数据目录用它初始化，pg0 的 `-P` 只在新建时生效）；轮换步骤写进 `docs/hindsight.md`，**没有在线上执行**。Hindsight API 没有认证令牌，上游若支持再加。
- **上线前检查**（第 17 项）：`npm run golive-check -w packages/bot -- --live <线上目录>`（只读）：列出线上目录 → 目标的提交，把改动分成角色卡 / 代码 / 脚本 / 文档，卡有改动（等于热加载上线）没加 `--cards-ok` 就挡住，线上目录有未提交改动、有进程监听非本机地址也挡住，最后列出三个要人答的问题（用户当次点头了吗、写重启通知了吗、上一个变量满 48 小时了吗）。CI 现在对所有分支的推送和所有 PR 跑类型检查、全量测试和审计门，不只 `main`。
- 取舍：本批没有把「线上跑哪些开关」做成机器可读清单（capability manifest）；状态页已有提交 / 分支 / 工作树 / 启动时间（ADR 0069），开关仍看 `runtime/koishi/koishi.yml`。
- 验证：`audit-gate.test.ts`、`ops-checks.test.ts`；对真实锁文件跑审计门通过；对线上目录只读跑上线前检查，输出 4 个待上线提交和「代码改动 1 个文件」。
