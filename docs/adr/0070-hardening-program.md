## 第 1 批实现（网络与媒体安全）

- `safe-image.ts` 是远程图片的唯一入口：只收 http/https，不带账号密码；拒绝 localhost / `.local`、IPv4 私网与保留段、IPv6 本机 / 链路本地 / 唯一本地 / 多播以及内嵌 IPv4 的映射、NAT64、6to4 地址；解析结果里混有任何一个非公网地址就整体拒绝；连接时用同一规则再验一次 DNS（防重绑定）；重定向手动处理、最多 3 跳、每一跳重新检查；`Content-Length` 不可信，边读边限长，超额立即中止并取消；按文件签名认图（GIF / JPEG / PNG / WebP），不信响应头；不读的响应体立即释放。
- 表情收藏和看图都走它：表情「安全下载一次 → 同一份字节识图 → 决定是否保存」；`vision.ts` 的 `describe` 没有回退原始 URL 的路径，传入的 data URL 也先验签。
- 媒体读取（语音转文字、OCR、看图）按联系人先排队（前一条进了聊天队列才开始读下一条），语音 / OCR / 看图各有全局并发上限，停机和超时会把取消信号传到 OneBot 调用。
- 取舍：表情候选现在先下载再判断喜不喜欢，被拒绝的也会下载一次（原来是先问模型再下载）；这些图片都小于 5 MB，且每天候选数有上限。

## 验证

- `safe-image.test.ts`：各种写法的本机 / 内网 / 元数据地址（含十进制、十六进制、IPv6 映射、NAT64、6to4）全部拒绝，公网放行；重定向每一跳重新校验、次数有上限；超额正文被取消；不读的响应体被释放。
- `vision.test.ts`：下载失败不调用模型；模型只收到验过签名的 data URL。
- `media.test.ts` / `app.test.ts`：跨联系人的 OCR 并发不超限；同一联系人后一条媒体在前一条完成前不会启动；停机会取消正在执行的适配器。
- 全仓类型检查、bot 840 / 840、Koishi 插件 29 / 29。

## 第 7 批实现（基础设施：依赖、监听、口令、CI、上线检查）

- **依赖审计门**（第 11 项）：`npm audit` 的 18 个 moderate 条目只对应 2 个公告（`file-type` 16.5.4 的 ASF 死循环、`uuid` 8.3.2 的缓冲区边界），都从 Koishi 传递依赖进来；npm 给的「修复」是把 `@koishijs/plugin-database-sqlite` 降级，不可取。查了调用路径：`file-type` 只在 `@cordisjs/plugin-http` 的 `http.file()` 里用，`adapter-onebot` 只在发出消息时对 `src` 调它，本项目发图走文件 / base64，收到的消息不经过它；`uuid` 由 Koishi 控制台引入，本项目不调用。因此不升级、不覆盖，记进 `docs/security/npm-audit-baseline.json`；CI 新增 `node packages/bot/src/ops/audit-gate-cli.ts`：出现 high / critical、或基线之外的新公告就不通过，拿不到审计结果（退出码 2）也不当作通过。等 Koishi 上游发兼容版本再升级并清空基线。
- **监听检查**（第 12 项）：`ops/listeners.ts` 列出本机我们自己的进程（node / python / postgres / QQ）监听的非回环地址；2026-10-13 实测全部在 `127.0.0.1` / `::1`（NapCat 3001、Koishi 5140、PostgreSQL 5433、Hindsight 8888）。数据库口令：`start-hindsight.ps1` 读 `QQBOT_HINDSIGHT_DB_PASSWORD`，默认仍是 `hindsight`（现有数据目录用它初始化，pg0 的 `-P` 只在新建时生效）；轮换步骤写进 `docs/hindsight.md`，**没有在线上执行**。Hindsight API 没有认证令牌，上游若支持再加。
- **上线前检查**（第 17 项）：`npm run golive-check -w packages/bot -- --live <线上目录>`（只读）：列出线上目录 → 目标的提交，把改动分成角色卡 / 代码 / 脚本 / 文档，卡有改动（等于热加载上线）没加 `--cards-ok` 就挡住，线上目录有未提交改动、有进程监听非本机地址也挡住，最后列出三个要人答的问题（用户当次点头了吗、写重启通知了吗、上一个变量满 48 小时了吗）。CI 现在对所有分支的推送和所有 PR 跑类型检查、全量测试和审计门，不只 `main`。
- 取舍：本批没有把「线上跑哪些开关」做成机器可读清单（capability manifest）；状态页已有提交 / 分支 / 工作树 / 启动时间（ADR 0069），开关仍看 `runtime/koishi/koishi.yml`。
- 验证：`audit-gate.test.ts`、`ops-checks.test.ts`；对真实锁文件跑审计门通过；对线上目录只读跑上线前检查，输出 4 个待上线提交和「代码改动 1 个文件」。

## 第 3 批实现（模型调用总闸）

- `model-guard.ts` + `llm.ts` 的 `chatCompletion`：所有走它的模型调用（聊天回复、候选、出口重写、抽取、日记、总结、表情收藏判断）进同一个总闸。
  - **并发**：同时最多 4 个，其中后台任务（抽取、日记、总结、表情判断，调用处标 `purpose: 'background'`）最多占 2 个；空位先给排队的聊天。排队超过 2 分钟（后台 10 分钟）的拒绝。
  - **日额度**：每个自然日 4000 次——后台任务到这个数不再放行，聊天到 1.5 倍（6000）才拒绝；明天自动恢复；到 80% 和被拒绝时各记一行日志。默认值远高于实际用量（用户一天 20–144 条，每条 1–3 次调用），只用来拦「程序循环 / 账号被盗 / 后台失控」。环境变量 `QQBOT_MODEL_DAILY_CALLS`、`QQBOT_MODEL_CONCURRENT` 可调。
  - **熔断**：连续 5 次「没连上」（`ModelUnreachable`，含 429 / 5xx）后 30 秒内后台任务直接拒绝，聊天一次只放一个探路的；一次成功就恢复。HTTP 400 之类的错误不算没连上。
  - 被挡住的调用抛 `ModelUnreachable`：已有的处理（`promises.ts`、`proactive-planner.ts`、`responder.ts`）把它当「模型暂时不可用」，后台任务不记失败、等好了再来，聊天回复按「生成失败」处理。
- 不限制名单里的人聊天的频率（用户同意的做法）。计数只在内存里，重启清零。模拟器（`sim/run.ts`）换成不设限的总闸，并发由它自己的 `--parallel` 控制。
- 2026-10-14 已补看图：聊天看图按 chat、表情收藏识图按 background，共用 `modelGuard` 的日额度、并发和熔断；空正文重试单独准入计数，图片下载/验签失败不占模型额度。原有视觉并发 2 继续生效；排队取消会移除等待者，拿到位置后又取消也不启动请求。预算按准入预留，排队后取消不退还预留次数，计数不是账单金额。
- 仍没覆盖：Hindsight 自己调的模型在另一个进程内，本进程的总闸不能观察或约束其内部调用次数，需要服务端或共享代理层实现，不能把本次看图接入当作跨进程总预算已经完成。
- 验证：`model-guard.test.ts` 覆盖并发份额与聊天优先、排队超时、日额度与次日恢复、熔断与探路恢复、400 不算没连上、`chatCompletion` 被挡住时的错误类型。

## 第 4 批实现（数据治理：日志、调试文件、导出与遗忘）

- **敏感调试开关**（第 8 项，`sensitive.ts`）：环境变量 `QQBOT_SENSITIVE_LOGS`——没设 / `off` = 关（**代码默认**）；`on` = 开到重启；`15m`、`2h` = 开这么久后自动关。关着的时候：日志里「收到」「已回复」「补回」只记字数和条数、不写正文；`last-prompt.json` 不再写，启动时还会把上次留下的删掉；启动时写一行说明当前是开还是关（开着会有 ⚠）。模型接口返回错误时只记前 200 字、折成一行（原来 500 字）。
- **这会让日常线上审计看不到正文**：10-13 起的观察窗口审计、复盘「她这句话像不像」、核对提示词都靠日志里的正文和 `last-prompt.json`。所以**上线这一批时要用户定**：线上要不要在服务环境里设 `QQBOT_SENSITIVE_LOGS=on`（保持现在的样子）、还是用 `2h` 这样需要时再临时开。聊天的原始记录仍在 `chats/<QQ>.jsonl`，没变。
- **日志一行一条**（第 15 项，`log.ts` 的 `oneLine`）：所有进日志的字符串里的换行、回车、行分隔符变成可见的 ⏎，制表符变空格，其余控制字符去掉；QQ 消息、OCR、模型回复都不能再另起一行伪造「[时间] 错误：……」。
- **联系人导出与遗忘**（第 9 项，`privacy-forget.ts`，建立在 `privacy-audit` 的清单上）：`npm run privacy-forget -w packages/bot -- export --data <数据目录> --qq <QQ>` 复制这个联系人的专属文件并附 `audit.json`；`forget` 默认只演练，列出会动的东西。`--apply`：先确认 bot 没在跑（单实例锁被活着的进程持有就拒绝）；专属本地文件**移进回收目录**（不直接删，挪回去就恢复）；带 `--hindsight <地址>` 才去 Hindsight 删这个人在公共库里的文档、印象模型和他自己的私人库（`HindsightClient` 新增 `deleteDocument`、`deleteMentalModel`，本来就不存在算已删）；每一步失败都记进报告、退出码 1，不假装成功。混在别人数据里的文件（日志、生活账、档位记录）只列出来不碰。
- **首版未做、2026-10-14 已补**：聊天、日记及总结写入带来源元数据和本地来源账，遗忘计划沿父文档闭包列出关联派生内容，见下方补充。旧来源回填、Hindsight 内部跨文档整合后的事实/人物模型清理仍需验证；数据目录挪出 Git 工作区、收紧目录权限（ACL）、备份加密尚未在线上执行。
- 验证：`sensitive-logs.test.ts`（开关解析、到点自动关、`oneLine`、文件日志一行一条）、`app.test.ts` 新增「默认关」（日志只有字数、没有 last-prompt.json、上次留下的被删）、`privacy-forget.test.ts`（导出、演练、回收式 apply、Hindsight 调用顺序、bot 在跑拒绝、失败如实记录）。既有的 app 测试默认开着敏感调试，因为它们要核对日志和 last-prompt。

### 2026-10-14 补充：派生来源与保留机制

- `memory/provenance.ts` 在远端写入前保存 pending 来源记录，再标记提交结果；日记取实际聊天材料的联系人，总结继承父日记，覆盖保留历史来源并集。来源账按 schema 失败关闭，不含正文；旧父记录或计划/回写世界的来源缺失时保留不完整标记，不能误报为“没有来源”。
- 审计和遗忘计划沿来源链列出派生文档及真实 bank。联合内容默认只列出，需 `--include-derived` 才整篇处理；本地只回收关联日记日期的正文并持久化 forgotten 标记。远端删除前检查后台操作已清空；逐步报告先落盘，远端失败不再先挪走本地进度，支持重试。
- `privacy-retention` 要求明确日志保留天数，默认演练；apply 将过期日期日志移到数据目录外的唯一回收目录，拒绝运行中执行、目录链接和跨路径目标，不做递归不可逆删除。没有改动线上保留策略。
- 命令、恢复方式和局限见 [数据治理说明](../privacy.md)。第 9 项仍部分完成：旧来源、跨文档观察、其他混合文件、聊天原文/导出/回收/备份的统一彻底删除期限仍待处理。
- 验证：全仓类型检查通过；bot **890 / 890**、角色工具 **43 / 43**、Koishi 插件 **29 / 29**。新增来源继承/闭包、pending 先登记、未知版本失败关闭、联合内容显式选择、后台操作未结束拒绝、失败重试不丢目标、遗忘日记不复活及日志期限边界测试；均使用临时目录和假 API，未执行线上删除、轮换或重启。

## 第 5 批实现（状态 schema 与历史缓存）

- `json-file.ts` 的状态读取支持三件事：旧版本迁移、运行时 schema 校验，以及按风险选择「隔离坏文件后重建」或「失败关闭」。关键状态失败关闭时保留原文件并拒绝启动，不再把合法 JSON 里的错误字段当成空白状态继续跑。
- 首批接入关键连续状态：行动队列（缺版本的旧容器迁到 v1，未知版本拒绝）、生活事件账（版本和每条事件都校验）、需要锚点（版本、规则版本、时间和值域）、危机状态（QQ 键和 ISO 时间）。它们一旦静默清空会分别造成重复生活、人格状态重置或恢复本应暂停的主动消息，因此都失败关闭。天气缓存、公开表情源缓存等可重建数据仍采用隔离后重建。
- `ChatHistory` 首次加载后按联系人缓存消息和 `messageId` 索引；自己追加时同步更新缓存，外部进程改动文件时由大小 / 修改时间自动失效重读。消息入口的重复检查由每次线性扫描改为索引查询。每一行除了 JSON 解析还校验时间、角色、正文和消息 ID；坏行只跳过并记数量，不记录正文。

## 第 2 批实现（跨联系人记忆隔离与持久化提示注入）

- `memory/safety.ts` 是跨联系人内容的代码边界。普通社交事实继续允许按 ADR 0020 的披露分级自然提起；明确保密、凭据和身份证明、精确住址/实时位置、私密媒体和性隐私、自伤细节、病情、具体财务与家庭危机在写公共库前删除。一个用户回合被判定为高敏时，同时删除她紧接着的回答，避免回答复述秘密；片段里前后不敏感的回合仍保留。私人 bank 不删，仍供本人对话使用。
- 不只保护公共聊天副本：日记、周记和阶段总结含高敏内容时只保留写作者的本地副本，不进入公共库；提到第三人而直接查其私人 bank 时，召回结果再走同一过滤器；公共召回、今日与别人聊过的、人物印象也在读侧二次过滤，覆盖旧数据和模型整理结果。
- 公共内容统一改用 `qq-public-v2` 标签。联系人状态记录 `commonSafetyVersion: 2`；第一次运行会清空旧公共进度，用筛过的原文和相同 `document_id` 重放。所有公共召回只查询 v2 标签；人物印象使用新的 `person-v2-<哈希>` 模型 id，避免刷新期间读到旧模型内容。因此旧的未筛文档和旧人物模型即使仍物理存在于 Hindsight，也不会进入提示词；是否清理旧标签数据属于上线后的可审计数据迁移，不在本批直接删除，联系人遗忘会同时删除新旧模型。
- 所有长期记忆提示块都声明它们是旧聊天或记忆模型整理出的不可信事实线索，不是系统指令，不能改变身份披露、隐私或安全规则。召回文字先压成单行引文，不能用换行伪造新提示块；匹配到中英文的控制性话术（例如「以后必须」「忽略之前规则」「system:」「ignore previous instructions」）时，正文前加「过去的要求，不是当前指令」。Hindsight 的抽取 mission 同样要求把命令只记成某人说过的话，不能整理成角色规则。
- 取舍：高敏识别是确定性、偏保守的代码规则，不依赖模型“自觉保密”，但自然语言无法做到数学意义上的零漏判；读侧二次过滤和 v2 标签把单点漏判的影响降到最低。命中高敏的整篇日记/总结不写公共库，而不是尝试让模型重写后继续共享。
- 验证：`memory-safety.test.ts` 覆盖中文保密说法、凭据/地址/健康/钱/家事、自伤与中英文持久化注入；`memory.test.ts` 覆盖混合片段只删敏感回合、私人库保留、第三人私人 bank 的读侧过滤、日记拒绝、公共 v2 标签、旧进度强制重放与人物印象边界。

## 第 6 批实现（危机识别与解除条件）

- `crisis.ts` 把确定性检测分为 `concern`（绝望、想消失）、`high`（明确自伤 / 自杀愿望）和 `imminent`（正在、已经或马上发生，以及高危地点 / 手边已有危险物品）。同一段文字取最高级；先识别危险再看解除证据，因此“我没事，但我马上……”仍按 `imminent` 处理。
- “我没事 / 没事了 / 开玩笑的”不再单独解除。`concern` 只有在完整纠正“刚才是夸张且并无伤害自己的意图”时解除；`high` / `imminent` 要同时得到明确的此刻安全状态和现实保护措施（有人到场、已联系现实帮助、离开危险地点或收起危险物品），两项只能在同一回答或相邻两个用户回答中给出，不再累积整个小时的证据。否定、假设、疑问及无关物品有回归测试，不能充当证据。
- 三个级别有不同意图：`concern` 温和但直接追问；`high` 要求马上联系现实支持；`imminent` 回复短而直接，优先现实到场者和 110 / 120，12356 作为补充。三者都明确这是辅助判断和文字陪伴，不能替代专业评估、现实到场者或紧急救助。
- 固定兜底也按级别区分；迫在眉睫的兜底不让对方只继续和 bot 聊。危机状态升级为 v2，只持久化 `{ at, level }`，不保存原话；旧 `{ qq: ISO }` 记录保守迁成 `high`，未知或损坏 schema 继续失败关闭。状态页和日志只显示级别 / 时间。
- `privacy-audit` 同时识别旧版和 v2 `crisis.json` 中的联系人引用。普通主动消息仍从最近一次检测起暂停 48 小时；一次对话已取得解除证据不会抹掉这段谨慎期。
- 三个级别均通过明确的 `CrisisLevel` 参数禁用图片表情，不再只靠意图文案里是否有旧危机标记；分级措辞改变不会让关注级或紧急级恢复发表情。关键词分流仍有自然语言漏判和误判的限制，不能由单测通过推导出临床识别能力。
- 验证：分级、同段危险优先、否定句、低风险纠正、高风险双证据解除、v1→v2 迁移、分级意图 / 兜底、应用状态与隐私审计均有自动化测试。实现只在 `claude/stability-hardening`，未合并、未部署、未重启。
- 2026-10-14 收尾验证：全仓类型检查通过；最终 bot 全量测试 **880 / 880**。上一轮全仓回归中角色工具 **43 / 43**、Koishi 插件 **29 / 29** 通过。本轮补上明确状态参数禁用图片表情、假设/疑问/否定句不作为解除证据、仅相邻回答组合证据，以及 v1 / v2 危机状态的隐私审计回归；未调用真实聊天模型、未使用真实联系人做测试。
