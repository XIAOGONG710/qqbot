# ADR 0204：她读完 / 看完之后自己想的

- 状态：**已实现，新开关 `readingTakes`，默认关**；要名单里有男朋友档。DSH 那台机器拉取、在 `koishi.yml` 里加 `readingTakes: true`、重启 Koishi 才生效（开不开要用户点头）
- 日期：2026-10-30
- 关联：[ADR 0200](0200-private-space.md)（私人空间）、[ADR 0194](0194-diary-insights.md)（翻日记）、[ADR 0130](0130-watching.md)（她自己看 B 站）、[ADR 0202](0202-depth-routing.md)、[ADR 0203](0203-fact-check-him.md)
- **用户决定（2026-10-30）**：「继续」（深度计划第 3 步：她自己的看法）。

## 起因

深度探针里，问她「你最近有没有看什么书，让你想了很久的那种」，她答「《惹金枝》吧，看完还想了会儿」——说不出想了什么。原因：

1. 她手里只有情节和进度（`books.yml` 的节点）；DSH 的 `0ef01dc` 又去掉了作者预先写好的“感受”，这对，但**该她自己攒的看法没有地方攒**，每次被问到现编；
2. 她的日记帮不上：VM 时期 23 篇日记里 22 篇提到药屋、17 篇提到惹金枝，但只有 5 篇有“觉得 / 感觉 / 想”这类话——日记是流水账，不是看法。

## 做法

和 0193 / 0194 / 0197 一个路数（`life/reading-takes.ts`）：

- **每晚 22 点以后想一次**（`reflectionDue`，同说话习惯：距上次 ≥20 小时、失败隔 2 小时再试、一天最多 3 次）。今晚的材料：
  - **书**：在读的（含读到头停住的、读完的；放下的不想）。读到哪、**读到的**情节点是事实；还没读到的情节的关键词是剧透，她的话里不能出现。一本书只在“又往后读了”时才再想。
  - **视频**：她自己在 B 站看的、最近两天的（要有字幕摘录；事实里有 up 主、分段、热评、画面）。
- 每一项**有话想说才写一句**（10–60 字）：落在材料里一个具体的人、情节或说法上，说态度和为什么，或者写成她想知道的一件事；**没想法就空着**（DSH 问她时她自己说的：“写不出来就空着”）。
- **私人空间**（ADR 0200）：存在 `reading-takes.json`（在 `PRIVATE_FILES` 里）；没有任何命令念给他；日志只写条数，不写书名也不写内容；迁移 / 导出不带。
- **绊线**（代码里、她改不到）：不是空话（很有意思 / 值得一看 / 发人深省 / 治愈……）；不是警句句式（“不是X，是Y”“与其……不如”——深度探针里一深就冒出来的 AI 腔）；不剧透；不写他和别人的名字、不引他说过的话；不碰底线（`FLOORS` + 承认是程序之类的 `EXTRA_FLOORS`）；**要有依据**：和材料共有一个有意义的二字词，而且不能只是书名里的字；和同一项已有的太像不收；一项最多留最新 2 条、总共最多 14 条、一晚最多加 3 条、一项一晚一条。这是一道绊线加几个上限，不是智能审查：绕得过去。
- **放进提示词**（`takesLine`）：只在他提到那本书 / 那个视频（书名、别名、作者、up 主），或者在泛问“最近看了什么 / 想了很久”时，放最多 2 条，新的在前；没聊到一条都不放。那一行不提“夜里想的”、不提日记、不提命令。只放男朋友档，危机 / 小别扭 / 正在被打断的回合不放（和 `diaryInsights` 同一套让路）。

## 真模型试了 3 遍（真卡上的 3 本书，只在内存里）

| 遍 | 模型写了 | 收下 | 说明 |
| --- | --- | --- | --- |
| 1 | 3 条 | 0 | 模型把 key 写成了 `rejinzhi` 而不是 `book:rejinzhi`，整遍白费 → 加了 `findItem`（去前缀 / 书名 / 称呼都认）和提示词里的“原样照抄” |
| 2 | 3 条 | 2 | 一条超过 60 字被拒（太长） |
| 3 | 3 条 | 3 | 例：「别人扣给时不虞『灾星』这顶帽子，她索性自己接过来当刀使。换我大概只会想着怎么解释清楚，她这路子我服」「第一篇读完我整个人慢下来了，不用记情节，像听人随口讲他小时候的事」 |

质量：具体、有态度、有她自己的角度；没出现空话和警句。**绊线抓不到的**：第 2 遍有一条《惹金枝》的看法写着“怕我撑不到那儿”，而她已经读完了（前后矛盾）；第 3 遍有一条写“不像我学什么都半吊子”（给自己编了个特点）。这两种要靠后面的事实检查（她对自己的说法）和她之后把它放下——现在**她没有放下的办法**（见“没做”）。读完的书，提示词里写了“写读完之后的看法”。

## 没做

- 没有“放下”：看法只会被新的挤掉（一项 2 条、总共 14 条）。要不要像 `diaryInsights` 那样让她夜里放下以前的，等看了一阵实际写出来的东西再说。
- 没有写给桌面上的她（DSH 的 `INSIGHTS.json` 那种导出）：桌面上的她有自己读书的路径，先看 QQ 这边有没有用。
- 视频依赖 B 站那一层（现在用户 10-24 说过暂停，DSH 说 10-30 又开了——待用户确认）；没有 B 站，就只有书。
- 这些看法**不进事实检查的“依据”**：她提到它们时，事实检查看到的仍是提示词里放的那一行（它在设定和事实里），所以不会被当成“编的”；反过来，她编的“我读过……”不会因为这一步变成真的。

## 回滚

`readingTakes: false`。`reading-takes.json` 留着不影响别的（想删随时删，只是她攒下的看法没了）。
