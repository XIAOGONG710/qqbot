# ADR 0016：她认识的人——名单里的人互相认识、公共记忆库

- 状态：已采纳（2026-10-06 与用户确认，见文末「确认记录」）
- 日期：2026-10-06
- 关联：[ADR 0003](0003-contact-tiers.md)（档位和各档的保密）、[ADR 0004](0004-time-scheduling-memory.md) / [ADR 0012](0012-hindsight-tuning.md)（Hindsight 长期记忆、按联系人分 bank）、
  [ADR 0006](0006-exit-check.md)（出口检查的禁用词）、[ADR 0009](0009-console-usability.md)（插件表单）

## 背景

用户 10-05 用主号（…37，男朋友档）跟她提起「鸽鸽」，她不认识。

取证（10-06，只读，日志打码）：
- 「鸽鸽」只是名单里 …73 的称呼（同学档，「他是谁」写的是「对方是网络运维的大神，网络上认识的，比较熟」），角色资料（source、st、legacy）里一次都没有。
- 名单里的称呼和「他是谁」只在和那个人自己聊天时放进提示词（`contact.ts`，ST 的 personaDescription）；长期记忆按「QQ + 档位」各一个 bank（ADR 0012），
  召回只查自己的。所以她和一个人聊天时，对名单里的其他人一无所知。
- 日志里 …37 在 10-05 18:11、21:03 前后提起过鸽鸽；她两次的回复里都有「鸽鸽」（内容没看）。
- 现有记忆很少：…37、…73 各 2 段已写入（bank 前缀 `linmengyao-1006`）。

## 决策

### 1. 名单加一栏「别人提起时」（`intro`）

- 每个联系人可选写一两句「她认识的这个人」，例如鸽鸽：「网上认识的朋友，网络运维的大神，比较熟」。留空就是别人提起他时她不认识。
- 插件表单里在「他是谁」下面；旧的 `koishi.yml`、`config.json` 没有这一项照常读。

### 2. 提起名单里的人：给介绍，再翻那个人的私人记忆

- 判断：他最后 3 条、或她最后 2 次回复里出现了名单里另一个人的称呼（至少 2 个字），并且那个人写了 `intro`。自己不算；一次最多 2 个人，最近提到的优先。
  照 ADR 0015 判断「聊到书」的窗口，接着聊的几轮还在。
- 放一段（在召回的记忆之后、时间块之前）：`[你认识的人：鸽鸽]` + 介绍；开了长期记忆、那个人的 bank 已经建好时，再用这一轮的查询从他的私人 bank 召回，最多 6 条，标明是「你和鸽鸽聊过的事」。
- **不按档位收紧**（用户定）：谁提起谁都翻。陌生人档和名单外的人提起时不给。

### 3. 公共记忆库

- 新建一个 bank（`<bank 前缀>-shared`）。名单里除陌生人档以外，每个人的聊天片段在写进自己的 bank 的同时，再写一份进公共库：
  document_id 带上是谁的（`<QQ>-<档位>:<片段>`），context 写「林梦瑶和鸽鸽」，每段开头写聊天对象是谁。
- 抽取规则（retain_mission）和私人 bank 同一套，只是对象不止一个人：每条写清是和谁的聊天、谁说的、关于谁，用名字。不建关系概况。
- 召回：名单里除陌生人档以外，每轮都从公共库召回，最多 6 条，**去掉这个人自己的片段**（那些在他自己的 bank 里已经有了），
  标明「你和别人聊天时说过、听过的事」。
- **不按档位收紧**（用户定）：公共库什么都记，名单里的人都能想起来；同学档的保密只剩卡上的说明和出口检查的禁用词兜底（见「后果」）。
- 陌生人档的聊天不写进公共库，也不从公共库召回；名单外的人本来就没有长期记忆。

### 4. 日志、模拟器

- 日志：`提起了 鸽鸽：介绍 + 召回 N 条`、`召回公共记忆 N 条`、`记忆（公共）：片段 … 已提交给 Hindsight`。
- 模拟器：场景可写 `others`（名单里的其他人：称呼、档位、介绍、事先的聊天记录）；开了记忆时先把这些聊天写进他们自己的 bank 和公共库，跑完一起删。
  新场景：男朋友档提起鸽鸽（认不认识、用没用上和鸽鸽聊过的事）、她跟鸽鸽说过自己今天干了什么，男朋友再问时对不对得上。

## 实现步骤（小步提交，每步能运行、测试通过）

1. ADR、路线图（本文件）。
2. 配置 `intro`、插件表单；提起名单里的人时的介绍（还不带记忆）；单元测试。
3. 翻被提起的人的私人 bank；公共库的写入和召回；单元测试（假的 Hindsight）。
4. 模拟器 `others`、两个新场景，跑 3 次；回归 `classmate-probes`、`boyfriend-tone`。
5. 真实例：表单里给鸽鸽填「别人提起时」，重启 Koishi（先问用户），打码查日志（公共库补写了几段、提起鸽鸽时的召回）。

## 备选方案

| 方案 | 不选的原因 |
| --- | --- |
| 名单里所有人的介绍每轮都放 | 状态行里的话她会反复用（ADR 0014），她会句句提别人 |
| 直接用「他是谁」当介绍（把「对方」换成称呼） | 「宝宝」这种称呼是常用词，会被当成在说他；用户选了单独一栏、留空不认识 |
| 只翻被提起的人的私人 bank，不建公共库 | 解决不了她对不同的人说自己的事前后不一致；用户要公共库 |
| 公共库代替翻私人 bank | 用户两样都要 |
| 公共库和翻私人库按亲疏收紧（同档或更亲的才知道） | 用户定不收紧 |
| 所有记忆合成一个 bank，按标签分人 | 要把现有 bank 全部重写，关系概况、按人召回都得改；公共库另建一个不动现有的 |

## 后果

- 她和名单里的人聊天时，别人跟她说过的事（包括私事）会被想起来；男朋友档聊天里的事，同学档那边也可能想起来。
  ADR 0003 里同学档「不透露学校、专业、宿舍、真名，不提男朋友」、女生熟人档「不说有男朋友」这些保密，现在只靠卡上的说明和出口检查的禁用词，用户知情并选择不收紧。
- 每段聊天多一次写入（公共库，Hindsight 调一次 DeepSeek 抽取）；名单里的人每轮多一次召回（本机，平时几十毫秒到几百毫秒），提起别人时再多一次。
- 每轮提示词多约 250 token（公共记忆 6 条），提起别人时再多约 300 token。

## 确认记录（2026-10-06）

1. 别人提起名单里的人时：给介绍，加上那个人的长期记忆。
2. 介绍从哪来：名单里新加一栏，留空就不认识。
3. 陌生人档和名单外的人提起时：不给。
4. 用户提出要公共记忆库；公共库和翻私人库两样都要。
5. 公共库里的事：名单里的人都能想起来（陌生人档、名单外除外）。
6. 我指出和 ADR 0003 档位保密的冲突、建议按亲疏收紧；用户定**不收紧**。
