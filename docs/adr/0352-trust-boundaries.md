# ADR 0352：信谁、不信谁——只认他的东西按 QQ 号认，别人写的字先拆标记再进提示词

- 状态：**已采纳**（把 11-26 八份审查里已经落地的修复收成一套规矩；代码在 main，部署后生效）
- 日期：2026-11-26
- 关联：ADR 0016（陌生人档不写不查）、ADR 0003（降档）、ADR 0148（设备控制）、ADR 0179（`<<用电脑>>` 要他亲手打的字）、ADR 0180（她自己上网查）、ADR 0200（她的私人空间）；
  审查 `docs/reports/2026-11-26-{mobile-companion,koishi-console,device-control,web-bilibili,inbound-qq,memory,ai-photo,ops-scripts}-review.md`；要用户定的 `docs/plans/2026-11-26-decisions-for-user.md`

## 起因

11-26 把对外开口的地方审了一遍，同一类毛病反复出现：
- **只该给他的东西按「档位」放行**：`<<执行>>` 在同学档、陌生人档的私聊里也会跑 PowerShell（入站 Q1，修之前线上一直如此）；设备菜单、工作房、`<<用电脑>>`、`<<同意工作>>` 给了名单里每个男朋友档；
- **别人写的字原样进她的提示词**：网页、B 站素材、转发、群公告、图上的字里带着 `<<执行>>` `<<记住>>` `<device:…>`，她照抄一句就成了别人替她下的命令；
- **往外连 / 往里读不设限**：内网地址能绕过、DNS 能重绑定、返回体不限大小、坏页面的正则能卡死整个进程。

每一处单独修了，但以后加新功能的人不知道要守什么。这份 ADR 把规矩写下来。

## 决定

**1. 「他」只有一个定义，按 QQ 号认。**
- 「他」= `ownerOf(config.contacts)`（`platform/config.ts`，名单里第一个男朋友档）。全仓库只在这一处取；`test/owner-of.test.ts` 扫源码，别处不许再手写这种查找。
- **能动这台电脑、他的设备、花钱的外部服务、他的私有数据的**，一律按 `contact.qq === owner.qq` 放行，**不按档位**：`<<执行>>`（cf3a83c6）、`<<用电脑>>` / `<<同意工作>>`（c3b54911）、设备菜单和指令登记（c3c6980b）、工作房记忆（5678c41f）、只给他的指令（原来就按适配器给的 QQ 号认，不看文字）。
- 按档位放的只有她对人的说法和亲近程度（男朋友档的亲密说法、口头习惯等）——那是设计，不是漏洞。
- 名单里有第二个男朋友档时的残余（照片、traces 等）和「排第一个」的隐患：决定单第 28 条，推荐配置校验只允许一个男朋友档。

**2. 她回复里的标记只在该办的地方办，别处只摘不办。**
- 标记（`<<执行>>` `<<用电脑>>` `<<同意工作>>` `<<拒绝工作>>` `<<记住>>` `<device:…>` …）在不该办的聊天里**照样从字里摘掉**（不发出去、不留痕），但不执行、不改状态、不写记忆。
- 陌生人档不写、不查公共库（ADR 0016；5678c41f 补上 `<<查>>` `<<记住>>` 两处漏的）。
- 模块里用「App 给的判断函数」表达（`commands.allowed`、`WorkMarkerHooks.owner`），不给时只看档位——模拟器和行为基线不受影响。

**3. 别人写的字进她的提示词之前，先拆掉标记的样子。**
- 第三方写的：网页摘录、搜图结果（`untrustedText`，`platform/web.ts`）；B 站标题 / 简介 / 热评 / 字幕（1bb48ea3）；转发、分享卡片、文件名、图上的字、表情上的字、群公告（`defuseMarkers`，`platform/untrusted-markers.ts`）。
- 只拆标记的样子（连着的两个尖括号、`<device:` 的开头），单个 `<` `>`、颜文字、平常的字一个不动。**他自己亲手打的话不经过这里。**
- 别人的话不能另起一行冒充他或她：群记录压成一行、撞上「他 / 你 / 男朋友」的昵称写成「群友「…」」「昵称叫「他」的人」；记忆事实压成一行（M6）。
- 还没拆的：长期记忆召回段（决定单第 13 条）。3 分钟命令防线要不要扩大（第 7 条）要先问她。

**4. 往外连只连公网，往里读一律设上限。**
- 她发起的网络请求走 `publicOnlyFetch`（连接时按真正要连的地址再查一次），地址检查用审过的 `publicAddress`（v4 包在 v6 里、NAT64、6to4 都认得）。
- 读进来的东西都有体积上限（网页、搜索商返回 1.5 MB，生图返回约 16 MB，Hindsight 8 MB），解析别人给的文本不用会平方级回溯的正则。
- 发给模型的请求体统一 `toWellFormed`（f1f31ab3）。

**5. 往外发的、花钱的，都要能扛住并发和重启。**
- 用量和上限每次从盘上重读（AI 照片预算 592f5a5a），正在进行的也算进当天数量；同一毫秒的写入不能撞 id（M5）。
- 不确定发没发出去的，宁可不重发（B 站发送本身不重试）；还没处理好的（B3）在决定单里。

## 怎么用

- **加新功能前**：它碰不碰上面五类？碰「能动电脑 / 设备 / 花钱 / 他的私有数据」就按第 1 条按 QQ 号认；它会把别人写的字放进提示词就过第 3 条的函数；它往外连就走第 4 条。
- **审提交时**：按这五条过一遍，比从头想漏洞快。
- 改「只给他」的规则（比如只允许一个男朋友档）改 `ownerOf` 一处。

## 不做的

- 不对他亲手打的字做任何拆改。
- 不把她对别人的说法收紧（同学提到闺蜜时只靠「不能说」标签挡，ADR 0020 的选择，决定单第 31 条）。
- 这份 ADR 不改任何行为：列的修复都已单独提交、各自核过行为基线逐字不变。
