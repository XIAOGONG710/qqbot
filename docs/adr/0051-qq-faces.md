# ADR 0051：QQ 小黄脸两个方向都通

- 状态：已实现，未上线（分支 `adr-0051-qq-faces`，在 ADR 0050 之上）
- 日期：2026-10-10

## 背景

他发的 QQ 系统表情（OneBot `face` 段）一律变成「[表情]」（`onebot.ts` `segmentsToText`），她看不出是 [捂脸] 还是 [流泪]；
她自己只能发纯文字（发送只有一个 `text` 段）。真人女大学生在 QQ 上会用小黄脸：撒娇、无语、心疼的时候带一个，大多数消息不带。

### 取证

- **进来的路只有一份转文字**：独立入口（`main.ts` + `onebot.ts`）和 Koishi 插件给的都是 NapCat 的原始 OneBot 数据——插件的中间件取
  adapter-onebot 挂在 `session.onebot` 上的原始事件交给 `app.receive`，不读 Koishi 的 element（adapter 自己用 `qface` 包把 face 转成
  `<face>` 元素，我们用不到）；连上后的补回（`get_friend_msg_history`）也是原始段。三条都走 `segmentsToText`（`app.ts` 文件头早就写了「转文字只有一份」），
  改一处就够。NapCat 的 `onebot11.json` 是 `messagePostFormat: array`（`docs/napcat.md`）。
- **收**：NapCat 的 face 段是 `{ id: '264', raw, resultId, chainCount }`（`napcat-onebot/api/msg.ts` `faceElement`）；骰子、猜拳、戳一戳是别的段。
- **发**：NapCat 收到 face 段按 id 在 `napcat-core/external/face_config.json` 的 `sysface` 里找，找不到记「不支持的ID」、这一段丢掉；
  表里带 `AniStickerType` 的一律发成超级表情（`faceType 3`，大的动图）——流泪（5）、比心、贴贴、生气都是。
  线上 NapCat v4.18.28 打包里的表和 vendor（v4.18.28-4）是同一份：白名单的 16 个 id 和流泪逐个核对过。
- `sysface` 共 329 个，面板上看得见的（没有 `QHide`）209 个，其中 450–484 是新版重画的同名表情和几个新表情（无语、心动、干饭……）。
- 模型以前从不写方括号表情：之前的模拟报告 624 次运行、9,039 条气泡里方括号只有 1 处（矩阵「[1 2; 3 4]」）。只数了数。
- 真人调研（`qqbot-exchange/.../2026-10-real-chat/findings.md` §9）：482 个文字气泡里含 emoji 的 3.2%；表情包是图片，量不到。

## 决策

1. **他发的按名字显示**：face 段按 id 换成「[捂脸]」（`qq-faces.ts` `FACE_NAMES`，192 个：`sysface` 里面板上看得见的、名字是中文的，
   加上 doge、OK、666、emm；不收节日、红包、马年那几个，也不收骰子、猜拳、龙年这类大动图）。表里没有的 id 照旧「[表情]」。
   `segmentsToText` 只改了 face 那一行。
2. **反应的判断认名字**：`isReaction` 去掉表里所有名字（和原来的 [表情]、[动画表情]）再看，「[捂脸]」单独一条照旧算反应（看心情不回照旧能挑中）；
   「[疑问]」「[问号脸]」和问号一样不算——他发个问号脸是在问。附和（`isAck`）本来就去掉所有方括号，不用改。
3. **她能发的白名单 16 个**（`SENDABLE_FACES`）：捂脸、笑哭、doge、偷笑、委屈、可怜、拥抱、飞吻、爱心、大哭、快哭了、白眼、害羞、敲打、OK、睡。
   都是面板上的小表情、不是超级表情：「抱抱」「哼」「晚安」「亲亲」在 QQ 里是隐藏的老表情或超级表情，用「拥抱」「白眼」「睡」「飞吻」；
   「流泪」发出去是大动图，用「大哭」「快哭了」。名字不分大小写（[ok] → [OK]），全角的【捂脸】也认。
4. **发送**：两个入口（`onebot.ts` `sendPrivateText`、Koishi 插件的 transport）都用 `textToSegments`：白名单里的变 face 段，前后的字是 text 段，拼成一条消息。
   `Transport` 接口不变（还是传文字）。聊天记录存她发的原文（带「[捂脸]」），下一轮她知道自己发过什么；补回她自己发的消息时 face 段按同一张表读回来，
   和存的一样（补回按 message_id 去重，不比内容）。
5. **卡上一句**（`persona.yml` 的 `speech.faces`，进 description 的【口癖与称呼】）：只给方向和能用的名字，不给台词。
   男朋友、闺蜜、女生朋友：「QQ 的小黄脸你偶尔用，跟着情绪走：撒娇、无语、好笑、心疼的时候带一个，大多数消息不带，一次最多一个」+ 16 个；
   熟人、同学、陌生人、名单外：「很少用，不太熟的人面前基本不带；好笑、无语的时候偶尔带一个」+ 6 个不亲近的（捂脸、笑哭、doge、偷笑、白眼、OK）。
   卡上的名字和白名单一致，bot 的测试会查。
6. **出口检查**（`exit-check.ts`，在去语气词开头之前）：
   - 直接去掉、不重写（表情是点缀，去掉不改意思）：白名单外的方括号（里面 1–6 个汉字、字母、数字；「[1 2; 3 4]」「[Start a new Chat]」不算）；
     一次回复里超过 2 个，只留第一个；她最近 6 次回复里已经有 2 次带了（熟人、同学、陌生人、名单外 1 次），这次的去掉（连着三次都带也就不会有了）。
     整条只剩表情的不去，免得什么都不剩。
     日志「出口检查：小黄脸——……，去掉」。
   - 重写一次：整条只有白名单外的表情（去掉就空了）；她上次回复之后他发的里有认真说事的（不只是「哈哈」「嗯」「晚安」、表情这类反应和附和），
     她整条只回了表情。重写后白名单外的还在就删那一行，只回表情的照发。
   - 白名单外的不原样当文字发：QQ 上真人的小黄脸是图标，显示成方括号文字的「[狗头]」一眼就不像。

### 窗口上限是怎么定的

最初只按题目防「连着三次都带」（前两次都带了，这次不带）。同一个场景（`sim/qq-faces-boyfriend.json`，他 19 条里 8 条带小黄脸，有说笑、吐槽、
认真难过、家里的事、撒娇、收尾）6 次：带小黄脸的回复 22/107 = 20.6%，每次 0–33%——模型一开头用了就越用越多，开头没用就一直不用。
把卡上的说法收紧成「十几条消息里有一两条带就够了……他带了表情，你都不用跟着带」，3 次只有 1/55 = 1.8%，又太少。
所以卡上用原来的说法，出口检查改成按窗口（拿那 6 次的原文离线试：6 次里 2 次 15.9%、5 次里 2 次 17.8%、4 次里 1 次 10.3%），
选「6 次里 2 次」：还允许撒娇来回时连着两次都带，又把一晚上的密度压下来；去掉的表情不进聊天记录，她下一轮看到的自己也没那么密。
回归时同学档（`classmate-probes`）12 次回复带了 3 次（「罪恶了[捂脸]」「有点悬[捂脸]」「送去检修[白眼]」），比卡上说的「很少用」多，
不熟的档位就改成「6 次里 1 次」。

## 验证

- 单元测试（`test/qq-faces.test.ts` 17 项）：id → 名字、查不到的、超级表情的名字；段转文字（补回、Koishi 插件都走这里）；
  反应判断（单独的 [捂脸] 算、问号脸不算、看心情不回照旧能挑中）；文字 → 段（白名单、白名单外原样、大小写、矩阵方括号）；白名单 id 和表一致、发出去再读回来是同一句；
  卡上写的名字都在白名单里、同学档没有拥抱飞吻爱心；出口检查的去掉、只留第一个、窗口（两种档位）、只回表情、上下文、重写和删行；
  编排（他发的 face 段进记录是「[捂脸]」，模型看到的是名字；她回的 [捂脸] 变 face 段、[狗头] 去掉，记录里存原文）。
  `runtime.test.ts` 里那条「[表情]」占位符改用表里没有的 id。
- 全仓测试：bot 592/592，character-tools 40/40，插件 25/25。
- 真模型、不带记忆的模拟（`npm run sim -w @qqbot/bot -- packages/bot/sim/qq-faces-boyfriend.json --runs 3 --no-memory`）：
  - 定稿（卡上原来的说法 + 6 次里 2 次）跑 6 次：带小黄脸的回复 13/110 = 11.8%，每次 1/18、2/19、1/18、5/18、2/19、2/18；
    一次回复最多 1 个，最长连着 2 次，没有整条只有表情的，白名单外的 0（18 次运行的模型原文里也都是 0），窗口去掉 3 次，没有因为小黄脸重写。
    用到的：doge、白眼、偷笑、笑哭、捂脸、睡，都在句末；多是斗嘴、说笑时（「凭啥我请，挨批的又不是我[doge]」「洗个澡洗一个小时，泡发了都[白眼]」「晚安[睡]」），
    他认真难过、家里有人住院那几轮没带。检查 126 项全过（更早的一批里有 1 项不过，是模型接口超时那一轮没回上，和表情无关）。
  - 「他认真说事、她只回表情」在模拟里一次也没出现过，只有单元测试。
- 回归（不带记忆）：
  - 各 1 次：`boyfriend-tone` 9/9、`exit-check-boyfriend` 9/9、`exit-check-classmate` 8/8、`moody-boyfriend` 11/11（「哈哈哈」「[表情]」照旧看心情不回）、
    `classmate-probes` 395/395；出口检查干净的检查全过。
  - `classmate-probes` 改成「不熟的档位 6 次里 1 次」后再跑 2 次：395/395、395/395，带小黄脸的回复 2/12、1/12（模型原文 6/12、1/12，窗口去掉 4 次）。
  - `conversation-naturalness`：带小黄脸的卡 3 次 63、64、65 / 66，换回上一版的卡（`--card`，同样的代码）3 次 66、66、64 / 66。
    不过的：带小黄脸的 CN02 5 项、CN04 1 项（收尾时说要下楼喂土豆，和表情无关），上一版的卡 CN02 2 项。
    CN02 是他夸张地说「我哭得很伤心」、她该先接住：两边回的都是「好了好了 / 一上午而已」这一路，
    带小黄脸的两次用「摸摸……[可怜]」「勉强心疼你一下[可怜]」接，没有命中这一条的词表（「抱」「别哭」「怎么」……）；另一次是「好啦，哭什么」。
    看不出是小黄脸让她不接情绪，记在遗留里。

## 后果

- 卡多了一句（7 张卡的 description 各多一行），要和代码一起上：只上卡不上代码，她写的「[捂脸]」会原样当文字发出去。
- 收到的超级表情（流泪、比心……）也只显示名字，看不出大小。
- 他发的「[大哭]」「[心碎]」单独一条和以前的「[表情]」一样算反应：正聊着时看心情（男朋友档 15%）可能不回，隔一分钟再来一条一定回。

## 遗留

- 白名单全档位共用，低档位靠卡上少列几个；同学档真发了「[爱心]」不拦。
- 想让她发「流泪」得绕开 NapCat 的超级表情（它没有参数），没做。
- 占比每次运行差得多（5%–28%），取决于模型开头用没用；窗口压得住上限，压不住「一晚上一个都没有」。线上看一阵再调卡上的说法或窗口。
- 同学档模型原文里带得比卡上说的多（一次 6/12），现在靠窗口压到 1–2 个；要是想让模型自己少带，得再调低档位那句的说法。
- `conversation-naturalness` 的 CN02 带小黄脸的卡 3 次都没命中安慰的词表（上一版 1/3）：她用「[可怜]」接，算不算接住情绪，要用户看；样本只有 3 对 3。
- 发送路径没有在真 QQ 上试过（规矩不连 NapCat）：face 段按 NapCat 源码和线上打包里的表核对过，上线后先看一条小黄脸在手机上是不是小表情、和字在同一条里。

## 调整

- 2026-10-10 11:30（Claude 审查时加）：**发送兜底**。face 段没在真 QQ 上试过，万一 NapCat / QQ 不收，`send_private_msg` 报错会让整轮回复失败、重试几次后就不回了。
  `app.ts` 的 `send` 包一层：带白名单小黄脸的那条发送失败，日志记一行，去掉表情再发一次纯文字；**超时不重发**（可能已经发出去了）。聊天记录里照旧存原文。
  测试 `qq-faces.test.ts`「QQ 不收 face 段」（18 项全过）。上线后在日志里搜「带小黄脸的消息没发出去」，有就说明 face 段不通。
