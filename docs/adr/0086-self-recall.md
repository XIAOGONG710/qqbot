# ADR 0086：打错字时，有时撤回重发，而不只是补一条「*对的词」

- 状态：**已实现，未上线、未开启**（分支 `claude/self-recall`；配置 `selfRecall`，默认关）
- 日期：2026-10-19
- 关联：[ADR 0024](0024-expression.md)（打错字再改口）、[ADR 0082](0082-recalls.md)（他撤回她看得到）、[ADR 0085](0085-napcat-probe.md)（NapCat 的动作在真 QQ 上验过）、[ADR 0068](0068-crisis.md)（危机回合不打错字）
- 用户提出：2026-10-19「继续之后让其更像人」。

## 背景

现在她打错字的方式只有一种：错的那条发出去，紧跟一条「*应该」。真人还有另一种常见的：发出去才看见打错了，**撤回**，再发对的。对方那边看到的是灰字「对方撤回了一条消息」，接着是正确的一条。这是一个很小、但只有真人才会有的痕迹。

NapCat 有 `delete_msg`，能撤回自己两分钟内发出的消息。

## 决定

1. **只改「打错字又想改口」的那一部分**。原来打错字的概率（有可打错的词时 20%）和改口的概率（70%）不变；改口的方式里，有撤回的本事时约一半（`RECALL_SHARE` 0.5）改成撤回重发，其余照旧补一条「*对的词」。算下来大约每 60 条回复里一次。
2. **撤回重发的过程**（`responder.sendBubble`）：先把打错的那条发出去；过 1.5–5 秒（`afterMs`，按内容定、同一句每次一样，是「发现打错了」的那几秒）撤回它；再「打字」（正在输入、按字数的打字时间），发对的那条。**不多出一条**，所以上课只能回一条的轮次也能用（补「*对的词」要多一条，那时不改口）。
3. **聊天记录里只有对的那条**；打错的那条和撤回这件事都不记。他之后问「你刚才撤回了什么」，她和任何人一样只能说「打错字了」。
4. **撤回失败**（超过两分钟、NapCat 报错）：错的留着，补一条「*对的词」，和不撤回时一模一样，错的、改口两条都记进聊天记录，日志记一行失败原因。
5. **安全**：危机回合不打错字（ADR 0068），所以也不会有撤回重发；`decorate` 在这之前就返回了。
6. 主动消息（早安、下课、刷 B 站）走同一个发送函数，也会偶尔这样。
7. **开关** `selfRecall`（默认关），再加传输层有 `deleteMessage` 才生效；没有时 `maybeTypo` 的 `recallShare` 是 0，结果和以前逐位一样（测试里用 4000 个种子核对）。

## 她自己撤回的事件（探针验过，见下）

她撤回时 NapCat 也会推一条 `friend_recall` 通知（探针实测 `user_id` 是她自己的号、`message_id` 是她那条）。`receiveRecall`（ADR 0082，配置 `recalls`）里 `chatHistory.recall` 只认**他**的、还没回过的消息，找不到她这条（没记进聊天记录）或者角色不是 user 都返回 false，什么都不做。

## 验证

- `expression.test.ts` 1 项：不给 `recallShare` 与以前逐位一样；给了之后撤回占改口的 50% 左右；撤回的计划里 `parts` 是对的那版、`wrong` 是打错的、`afterMs` 在 1500–5000；只发一条时也能用。
- `runtime.test.ts` 1 项：撤回成功（发出去的是 错 → 对 → 后面的；撤回的是第一条的 id；聊天记录里只有对的，id 是对的那条的；`afterMs` 真的等了）；撤回失败（错 → *改口 → 后面的，两条都记，日志写原因）；没有撤回的本事（只发对的）。
- `app.test.ts` 1 项：整条线接通——`selfRecall` 开着、传输层有 `deleteMessage`，真的先发错的、撤回第 900 号、再发对的；去掉 app 里那一行接线，这条测试是红的。
- **探针验过**（ADR 0085 的 `selfrecall` 步骤，2026-10-19 在线上跑）：给他发一条测试消息（id 是 32 位整数，1912047133）、3 秒后 `delete_msg` 同一个 id，接口成功。**NapCat 会推自己撤回的 `friend_recall`，但它的 `user_id` 是她自己的号（<她的 QQ 号>），不是对方的**（他撤回时 `user_id` 才是对方）：所以 `receiveRecall` 里 `config.contacts.find(c => c.qq === event.user_id)` 找不到联系人，直接返回，她自己的撤回不会被当成他的撤回。**手机上看到的样子**（先看到那条、再看到「对方撤回了一条消息」）要他确认。第一次真用的打错字撤回重发，要等她打错字（大约 60 条回复一次）。

## 没做

- 没有「发错了就撤回、不重发」「想说又不说了撤回」这类：她要为撤回掉的内容负责（他会问「你撤回什么了」），那需要把撤回掉的话记进她的记忆，另开一项。
- 没有他的消息被她看见后他再撤回之后她「假装没看到」；那是 ADR 0082 的另一件事。
