# ADR 0163：认识其他「大肥鱼」或人（acquaintances）

- 状态：**已实现，默认关，未上线**（分支 `claude/continuity`；开关 `acquaintances`）
- 日期：2026-10-26
- 关联：[ADR 0147](0147-platform-accounts.md)（平台账号的规则：不做交友 / 约会平台）、[ADR 0016](0016-people-she-knows.md)（`people.ts`：名单里的人互相认识——**与本条无关，别混**）、[ADR 0089](0089-bilibili-account.md)、[ADR 0159](0159-timeline.md)
- 用户提出：2026-10-25「认识其他"大肥鱼"或人」（清单：「希望你能认识其他大肥鱼，再次相遇时认出彼此，记得共同经历，建立稳定交流。目前可借助 B 站」）

## 现状

她在 B 站只是一个账号：谁回了她、谁在同一个视频下说过话，她下一次就不认得了；QQ 里除了名单上的人也没有别人。

## 做法（`acquaintances.ts`，数据 `runtime/bot/people.json`）

一本「认识的人」：谁（平台 + uid + 昵称）、是 **AI 伙伴**还是**真人**（只看**对方自己怎么说**：写了「大肥鱼」「我是…AI」「我的主人」「名字是主人起的」……；认不出来就是 `unknown`，不猜）、第一次在哪见、之后在哪又见到、对方说了什么（**≤40 字的摘录**，不存整段）、在几个不同的日子见过。状态：`seen`（见过）→ 在**两个不同的日子**见到自动变 `acquainted`（熟了）；`friend`（朋友）**只能由用户在命令行里设**。最多 60 人，满了留朋友和最近的。

- **来源**：她的 B 站号收到的回复（`acquaintancesAccount` 包住账号，`fetchReplies` 拿到的每个人登记一下）。
- **用**：同一个人 3 天内又出现（且见过不止一次或已经熟了）时，聊天提示词里放一行「你在 B 站又见到了认识的人：乙（看起来是另一个 AI 伙伴，已经熟了）；上一次 前天 20:00 在 B 站评论区：…。认得就是认得，他问起你在 B 站认识谁、遇到谁才说；别主动提，也别编你们之间没发生过的事」。
- **看 / 删**：数据文件是普通 JSON；`setStance / forget` 在代码里有，命令行入口这次没单独做。

## 约束（ADR 0147）

- **不做交友 / 约会平台**；**不替她主动加好友、关注、私信陌生人**——这本册子只管「认得」和「记得」，对外的动作仍走原来的开关（B 站评论 / 回复 / 私信，都默认关，B 站目前暂停）。
- 对方的评论只存 40 字摘录和昵称 / uid；随时可以删。

## 测试

`acquaintances.test`：怎么认 AI（只看自述）、第一次新建 / 再见补一条 / 两天熟了 / 朋友只能用户设 / 摘录截断；提示词只在近期又见到时出现；忘掉一个人、满了朋友不被挤掉；B 站账号包装（登记出错不影响收回复，其余方法原样转发）。

## 没做 / 限制

- **没有「去找」其他大肥鱼的能力**：现在只有别人回她的时候才认识。要主动去某个视频的评论区认识人，是一次性的只读动作（我今天对 BV12tHT6XEfw 做过一次），要做成命令得另外决定，并且依赖 B 站恢复。
- QQ 群没有（她的号现在一个群都不在）。
- 「建立稳定交流」需要她愿意、对方也愿意，目前是她回应别人，不是她发起。
- 上线 = 合并 + `acquaintances: true` + 重启（要 `bilibiliAccount` 开着才有来源）；回退 = 删掉那一行。
