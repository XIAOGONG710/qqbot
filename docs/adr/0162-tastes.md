# ADR 0162：从经历里长出偏好（tastes）

- 状态：**已实现，默认关，未上线**（分支 `claude/continuity`；开关 `tastes`）
- 日期：2026-10-26
- 关联：[ADR 0130](0130-watching.md)（她看 B 站视频形成看法）、[ADR 0104](0104-pursuits.md)（追求）、[ADR 0125](0125-menu.md)（菜单）、[ADR 0159](0159-timeline.md)
- 用户提出：2026-10-25「从经历里长出偏好」（清单：「兴趣、偏好和表达习惯不必全部由提示词预先写死……让个人特征有机会在经历中逐渐形成」「我们希望你记得当时为何选择，以及后来的结果」）

## 现状

她的兴趣是人设里写好的（摄影、独立游戏、王者荣耀……）；生活账里她真做过的事（线上现有 100 件经历：休闲 42、吃饭 29、项目 24、读书 3……）不会反过来改变什么。

## 做法（`tastes.ts`）

每天最多一次「回头看」：

1. 把最近两周的经历列成**带编号的清单**（生活账里的休闲 / 吃饭 / 读书 / 项目，没做成的标「结果不好」；看过的 B 站视频）。
2. 让模型指出**最多 2 条**「看得出来的偏好」（喜欢 / 不太喜欢什么、为什么），格式固定，**每条必须引用清单里的编号当证据**。
3. 代码校验：编号必须是清单里真有的；喜欢至少 2 条证据（不喜欢 1 条就够：一次失败 / 烦也算）；名字 2–10 字、理由 ≤40 字、不带括号；不合格的丢掉。
4. 通过的写进 `runtime/bot/tastes.json`，带证据（编号、时间、一句话）和日期；之后再有**相反**的经历才改——翻转要至少 2 条**新**证据，同方向补证据只会加强。上限 12 条。
5. 用：聊天提示词里放最强 / 最近的 3 条——「你自己慢慢发现的口味（是你真的经历过之后才有的，不是设定）：喜欢…（因为…）。聊到相关的事时可以自然带出来，别硬提，也别当成口头禅」。新发现 / 改变记进时间线。

## 干跑（真模型 + 线上生活账，写到临时目录）

60 件经历里发现两条：**喜欢摄影**（强度 3，「多日反复拍摄、研究设置和修片」，证据：拿新相机去校园里拍 / 研究新相机的设置 / 把新相机拍的照片导出来修 / 修昨天拍的片子）和**喜欢独立游戏**（强度 3，「两天内多次连续打独立游戏」，证据 4 条「打独立游戏」）。机制是通的，但**发现的正是人设里本来写好的两样**——因为生活账里的经历本来就是按这些种子生成的。真正「长出来」的偏好要等经历更丰富（不同的菜、不同类型的视频、不同的活动）才看得到；这条 ADR 做的是**让经历有机会反过来影响她**的那条通路，不是说今天就能看到新口味。

## 没做 / 限制

- 不改人设里写好的兴趣（那是作者的）；不从聊天内容里猜偏好；偏好没有证据就不存在。
- 偏好目前只进提示词，**还没有反过来影响她的选择**（比如菜单更爱点喜欢的、休闲更常选喜欢的）——那会改变她的生活账，要单独决定。
- 模型能被「反复出现」的表象带偏（出现多不等于喜欢）；所以喜欢要求 ≥2 条证据，翻转要求 ≥2 条新证据，但没有更深的校验。
- 上线 = 合并 + `tastes: true` + 重启；回退 = 删掉那一行（`tastes.json` 留着不影响）。

## 真模型检查（角色卡 + 口味那一行，每种抽 5 次）

「周末想玩点什么」5/5 提到独立游戏；「中午吃食堂好不好」5/5 说别点鱼香肉丝、上次没吃完。第一版会编具体的名字（「《空洞骑士》」「卡一个 boss」）；加了「这里没写的细节（具体是哪个游戏、哪道菜、发生过什么）别编」之后基本不再点具体游戏名，但仍会有「回头给你看截图」这类顺口的承诺——口味只管“喜欢什么”，不保证她不顺着聊出新细节。

## 2026-11-05：反思的停止所有权（记忆审查第二十批）

真实合成 App 证明，只清启动/每小时 timer 不能停止已经等待模型的反思：目录租约释放后仍会写 tastes.json、时间线及日志。Tastes 现在拥有每次反思，微任务派发前登记并复查 stopped；永久 stop 同步拒新，取消内部纯模型等待并返回可复用 drain。底层模型不合作也不阻止本体取消，晚成功/失败不得写文件、通知或日志。已完成的偏好文件保持，新实例继续读取并遵守既有间隔。默认关闭、证据门槛与偏好策略不改。

App 构造回滚及正常 stop 均接入所有者，目录释放前等待本体；授予模型的 log、onChange 和迟到 timer 入口另守 App stopped。取消本地等待不表示远端请求被撤销，无法阻止任意自定义模型实现自身的副作用；不提供强杀事务或跨实例写协调。
