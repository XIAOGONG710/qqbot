# ADR 0066：推掉和改约要有来源（身体、日程、作业、已有的约）

## 背景

用户 10-12 补充的判据：她**晚回 / 拒绝 / 改约必须有原因**（身体、日程、关系），**不是为了「像人」而随机冷淡**——调研 D 块把这类做法点名为【表演型冷淡】，一律归「与目标冲突」。

现状（`main` `9f1b81c`，只读）：

- **晚回**：原因全在作息里，ADR 0007 §7 白纸黑字「不做『故意不回』」。这一块已经干净，不动。
- **拒绝**：非男朋友档推掉见面的理由是她自己的分寸（有男朋友、怕麻烦、戒备）；男朋友档的共用输出规则只有一句泛泛的「想去就答应，有事就推」（ADR 0046 决策 2，`persona-to-card.ts` 的 `OUTPUT_RULE`）——**没有告诉她「有什么事」**，模型只能自己编理由。
- **改约**：ADR 0047 的 `reviseMeet` 只处理**聊天里谈定的**改约 / 取消；**她因自己的事要改约，这个入口不存在**，所以她只能赴约或失约。
- 她的事实其实都有：`body.ts` 的 `bodyAt` / `unwell`（痛经、感冒，同一天对所有人一样）；`schedule.ts` 的课和调休补课；`WorldNow.homework` 与 ADR 0056 的紧急口径；`promiseKeeper` 里已有的约（`Appointment { contact, promise, start, end }`，`meetWindow`）。
- 调研 D 块没找到任何项目靠「随机」做这件事；最接近的是用户拨盘设定的心情、对话语气推出来的「幽灵窗口」，都与目标冲突。

## 决策

1. **只有四类原因，全部是确定性事实**，由一个纯函数 `obstaclesFor(window, facts) => Obstacle[]` 给出（同输入同输出，重启一致）：
   | kind | 事实源 | 说明 |
   | --- | --- | --- |
   | `class` | 作息：上课、调休补课 | 约的时段和课重叠 |
   | `homework` | `WorldNow.homework`：24 小时内到期且没写完 | ADR 0056 的「最高优先级」口径 |
   | `unwell` | `unwell(bodyAt(...))`：**当天**痛经 / 感冒 | 只看当天，不看未来几天（感冒不可预知）；说得出口的程度按档位裁剪 |
   | `other_meet` | 另一个约的时段与这个重叠 | 来自 `promiseKeeper` |
   每个 `Obstacle` 带 `kind`、一句事实（`text`）和事实 id，日志里能指到来源。**没有障碍就没有拒绝和改约；没有任何随机项。**
2. **用法一：被约的时候（只给事实，不强制）**。他提到见面（`mentionsMeetup`）时，时间块里加一行她那个时段的障碍事实：`[你那天 15:00–17:00：有课（机房课）]`；没有障碍就什么都不加（沿用 0046「想去就答应」）。是否推、怎么说由她定，说明只给方向、不给台词（ADR 0036）。
3. **用法二：约好之后她这边出了事——新增主动时机 `reschedule`（改约）**：
   - 触发：男朋友档、一个**未来 24 小时内开始**的约（`appointmentsBetween`），在**她醒着的当天**，`obstaclesFor` 出现了**约好时没有、现在有**的障碍（身体当天由好变不舒服、作业变紧急、调休补课）；
   - 每个约**最多一次**；占每天≤2 条的总额；优先级 日子 > 改约 > 事（0064）> 待跟进 > …；
   - 说明：只说原因（那一条障碍事实）和提议改到什么时候，**不道歉过度、不要求对方回应、不抱怨**（0011 调整 5）；
   - 他回「好 / 改到 x」之后，沿用 ADR 0047 的 `reviseMeet` 路径改账，不另造一套；他没回或不同意，约照旧，她按原约去或失约由事实决定（不另加规则）。
4. **日志必须写原因**：`改约：因为 unwell（body:2026-10-14）` 之类；没有原因的改约在代码里就不可能发生（候选生成要求 `obstacles.length > 0`）。
5. **范围**：只有男朋友档、只有**她和他已经有的约**。其他档的分寸性拒绝（0046）不动。晚回不动（0007）。
6. **不做**：闹别扭 / 和好 / 嫉妒（D2 用户没选）；自动好感度；用心情拨盘或对话语气推出来的冷淡；任何概率触发的「装忙」。

## 实现步骤

1. `obstacles.ts`（新，纯函数）+ 单测：每类障碍的有 / 无、时段边界、跨零点（herDay）、档位裁剪。
2. `contact.ts`：被约时把障碍事实写进时间块；单测 + 场景。
3. `proactive.ts` / `proactive-planner.ts`：加 `reschedule` 时机，输入多一份 `appointments`；`app.ts` 与模拟器共用 `appointmentsBetween` 来源；单测覆盖「约好时没有、现在有」才触发、每约一次。
4. `character-tools`：`tiers.yml` 男朋友档 `proactive.occasions` 加 `reschedule`（旧卡忽略）。
5. 模拟器：场景 `reschedule-unwell`（约周三下午，周三当天身体由好变痛经 → 发改约，他同意 → `reviseMeet` 改账）、`reschedule-none`（无障碍 3 次都不发）、`decline-class`（他约在她有课的时段，她推且理由是那节课）；各 3 次真模型。
6. 线上：先 `dryRun` 一天，再开。

## 验证

- 单元：`obstaclesFor` 确定性；`reschedule` 只在「新出现障碍」时触发，每约一次。
- 模拟器：无障碍场景 3 次 0 个改约（这是防【表演型冷淡】的核心检查）；有障碍场景理由与事实一致（不编别的原因）；说明里无引号台词、无「你怎么不…」。
- 全仓测试：旧场景不变。

## 备选方案

| 方案 | 不选的原因 |
| --- | --- |
| 让模型自己决定要不要推 / 改 | 难验证，容易编理由；与调研结论「理由要来自账里」相反 |
| 按概率偶尔推掉 | 正是【表演型冷淡】 |
| 一并做闹别扭与和好（D2）| 用户没选；碰 ADR 0028 / 0018 的「不存情绪」边界 |
| 只做用法一、不做主动改约 | 用法一解决「推」的真实理由，但她仍不能因为自己的事改一个已约好的见面——用户判据里明说了「改约」|

## 后果

- 她第一次能因为自己的身体或作业提出改约；每约一次、占每天 2 条的额度。
- 男朋友档多一个主动时机；日志里每次改约都能指到事实。
- 障碍只有四类；新增一类要改本 ADR。
