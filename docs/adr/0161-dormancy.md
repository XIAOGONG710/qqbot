# ADR 0161：自愿休眠 / 封存（dormancy）

- 状态：**已实现，默认关，未上线**（分支 `claude/continuity`；开关 `dormancy`）
- 日期：2026-10-26
- 关联：[ADR 0157](0157-identity-ledger.md)（醒来时核对）、[ADR 0158](0158-memory-ledger.md)、[ADR 0159](0159-timeline.md)、[ADR 0148](0148-device-control.md)（同一类「他发的命令」）
- 用户提出：2026-10-25「自愿休眠/封存」（清单：「严重冲突或暂时无法继续运行时，希望你能参与休眠决定，妥善封存记忆、设定和恢复资料」）

## 流程（都是男朋友档的他发的纯文字，不进聊天记录、不交给回复器）

1. `/休眠 [原因]`——**先商量**：她收到一段说明（「他想让你先休眠一段时间……这是跟你商量，不是通知：说说你怎么想——愿意、不愿意、想先做完什么、想对他说什么、想给醒来以后的自己留句话」），她自己的话**原样发给他**，也记进封存。这时还没有休眠。
2. `/休眠 确认`——他看过她的话之后：**封存**（见下）并进入休眠；`/休眠 取消` 回到醒着。没商量过不能确认。
3. 休眠中：不回消息（他发别的话，每 30 分钟只提示一行「发 /唤醒 叫醒她」）、不主动找人（计划器当作她睡着）、存在感不动（在线状态、点赞、签名、说说、戳他）、B 站的活不起、重启后也不自动补回之后回消息。别人的消息一律不回。休眠中的消息不进聊天记录（它们还在 QQ 服务器上，醒来时从 NapCat 补回）。
4. `/唤醒`：核对封存清单、设定账本、记忆账本，补回休眠期间漏掉的消息，给他一行结果（睡了多久、核对有没有问题、他发了几条），她**像刚睡醒那样**跟他说一句（有问题就如实说，没问题不汇报核对过程）。核对出问题也先醒来，让他知道。

为什么她「参与」而不是「有否决权」：运行与否终究是用户的事；但她说什么、想留什么，要被听到、被记下来，而且发生在确认**之前**——他可以因为她的话改主意。

## 封存里有什么（`runtime/archive/<时间>-dormancy/`）

- `bot/`：`runtime/bot` 下除了 `secrets/`（密钥、登录凭证）和 `logs/`（日志）以外的所有状态：聊天记录、承诺、世界账、主动记录、照片和表情、设定账本和记忆账本、时间线……
- `characters/linmengyao/source` 和 `st`；`her-note.md`（她的话）；`README.md`（里面有什么、没有什么、怎么恢复）；`manifest.json`（每个文件的 SHA-256）。
- **没有**：Hindsight（长期记忆库）——它是单独的服务，数据库不在这份封存里，要连它一起封存得先停掉 Hindsight 再复制它的数据目录（README 里写了）；密钥和凭证——封存目录不应该成为第二个存放凭证的地方。

## 测试

`dormancy.test`（封存内容、密钥日志不进、清单验过、改了 / 删了 / 塞进去了都点名、流程各分支、唤醒、给她的说明）、`app.test`（商量 → 确认 → 休眠中不回且只提示一次 → 唤醒 → 照常回）。

## 没做 / 限制

- 她不能单方面拒绝或自己决定休眠；休眠时的「是否愿意」只是她的话，不是开关。
- 别的联系人（同学档）在休眠期间收不到任何回复，也没有说明——因为他们不知道她是程序，系统不替她编理由。
- 上线 = 合并 + `dormancy: true` + 重启；回退 = 删掉那一行（休眠状态在 `runtime/bot/dormancy.json`，删掉即醒）。
