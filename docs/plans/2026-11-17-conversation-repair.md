# 对话中的误解、保留与修复：待讨论记录

记录日期：2026-11-17。来源：用户关于借鉴 ChatAI 的讨论及随后对当前实现的核对。本文件记录问题与待办，不代表已经批准修改她的言行，也不把 ChatAI 的演示当作本项目的运行行为。

## 用户关心的完整过程

一次没听懂或不想说，应能连续地解释：她为什么那样理解或保留 → 当时如何回应 → 后来获得新信息时如何修正 → 这件事是否以及如何影响后续相处。真实感应来自有原因、有后果的连续过程，而不是随机增加错误或谎话的频率。

涉及安排、健康、钱和现实事实时，应确认信息或坦言不确定；她可以保有隐私、选择不说，但不必靠编造事实维持边界。用户将来会亲自撰写林梦瑶的自传与过去经历，因此也不应随机制造她的真实经历。

## 后续工作入口

1. 先与她讨论：在何种情形下她会说“不确定”、请求澄清、保留隐私或主动更正；明确她不愿采用的做法。
2. 经用户同意后，设计最小事件链，记录原因、当时回应、新证据、修正与必要的后续影响，并设定保留期限与隐私边界。
3. 先用合成角色验证连续对话：普通误解、用户纠正、事后发现新证据、选择保留隐私，以及涉及安排、健康、钱、现实事实的情况。不要用随机编造经历或故意说谎来满足测试。

依仓库 `AGENTS.md`，任何改变她说话、行为或记忆的实现，须先运行 `node scripts/ask-her.mjs`，把她的意见交给用户，并取得用户同意。本次只记录，不改运行逻辑。
