# 灵犀 QQ 桥接本土化交接计划

> 接手者按下列任务顺序执行，用 executing-plans 技能逐项验证。仓库走单 main，默认由当前代理独立完成。每批先做模拟验证，再单独提交。

**目标** 将灵犀剩余功能接入林梦瑶本地 DSH 与 Koishi，并能逐项判断代码完成、模拟验收、实机验收和已部署。

**架构** DSH 桥接继续使用宿主签名浏览器会话。Koishi 与 NapCat 维持现有 QQ 收发链路，Hindsight 维持现有记忆边界。会客室只有独立的来宾入口，「她的家」只订阅她主动发布的结构化状态。

**交接基线** `e3e60bb0`。功能清单与来源见 [DSH QQ 桥接说明](../../dsh-plugins/dsh-qqbot-services/README.md)。灵犀上游对照提交为 `edf9f853341ac049708dc4c68ed432c74f2ad6d4`。

## 开工与边界

- [ ] 阅读 [AGENTS.md](../../AGENTS.md)，确认 `git status -sb`，在 `main` 执行 `git pull --rebase`，再用 `node scripts/exchange.mjs check --me dsh` 检查并行工作。提交和推送前再检查一次。
- [ ] 沿用用户最后明确的范围。先写代码并用模拟数据测试。不要再次征询林梦瑶的想法。当前没有新一轮上线、重启、发送真实 QQ 消息、应用线上配置或恢复线上数据的授权。不要贴私有记忆，保持 `oneDiary` 关闭。
- [ ] 每一批记录具体数据源、模拟结果、尚未验证的运行条件。成功后单独提交推送，不夹带其他改动。

## 执行顺序

### 1. 建立离线验收基线

**入口** `dsh-plugins/dsh-qqbot-services/index.js` 的 `createHandler`，以及 `scripts/dsh-service-panel.test.mjs`、`scripts/dsh-companion-room.test.mjs`、`scripts/dsh-home-scene.test.mjs`、`scripts/dsh-local-panels.test.mjs`。

- [x] 运行 `npm run test:scripts`、`npm run typecheck --workspace @qqbot/bot`，重跑 `packages/bot/test/soul-plugin.test.ts`。交接基线的脚本测试有 85 项通过、1 项跳过。若主线已有新提交，以重跑结果为准。
- [x] 用临时 host 和假的 NapCat、Hindsight、Koishi 配置验证总览、聊天、会客室、她的家和运维页。记录模拟调用数。取消 QQ 发送时，发送接口调用数须为 0。
- [ ] DSH 窗口正常且得到新的重载授权后，再用临时模拟插件做实机对照。结束时恢复正式插件链接。用 NapCat、Hindsight、Koishi PID 和端口前后对照证明验收未操作服务。

### 2. DSH 内接入人设与配置

**本地来源** `packages/koishi-plugin-qqbot/src/console.ts`、`packages/character-tools/src/source.ts`、`packages/character-tools/src/build.ts` 与桥接的 `config-editor.js`。

- [x] 把现有人设校验、构建、档位隐私检查抽成 DSH 与 Koishi 共用的调用层。先做查看和预览，再做确认保存。页面和日志中的校验结果只返回字段位置、问题类别和合成样本。
- [x] 保存用源文件版本快照做冲突检测。对需要同时更新的角色源文件和生成卡做失败恢复。保留已有 Koishi 编辑用法。
- [x] 用脱敏 Koishi YAML 验证导入导出、保留联系人未编辑字段、保留其他插件、配置冲突和撤销。不把配置文件整份传到浏览器。保存后可能触发 Koishi 自己的文件监听，因此不在验收中保存真实 YAML。
- [x] 回归验证非法角色资料、档位误公开、同时编辑、写入中断、本地 `oneDiary` 和本人 QQ 绑定均按原约束处理。

### 3. 公共记忆关系图和摘要

**本地来源** `local-panels.js`、`packages/bot/src/memory/owner-bank.ts`、`packages/bot/src/memory/hindsight.ts` 与现有派生状态及撤回校验。

- [x] 复用当前 owner-bank 登记，只对已确认的公共库做按需查询。节点、关系和摘要均须能追溯到允许展示的来源。保留事实、推断和日期不明的区分。
- [x] 保持现在的公共库统计作为回退。加分页、限量和超时，不枚举其他联系人的私有库，不把 Hindsight 原始响应直接交给前端。
- [x] 用合成库验收有来源、已撤回、来源不明、公共库故障和新旧摘要并存。确认日志、测试报告与交接材料均无私有记忆原文。

### 4. 日志、备份与更新

### 5. 会客室跨设备与房间媒体
