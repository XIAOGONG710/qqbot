# 世界模块与外驱设计讨论（2026-11-16）

> 状态：设计讨论与实施建议，尚未定稿，暂不据此改动运行时。
>
> 本文记录关于“真正的主动性”和世界模块的讨论。它不是最终 ADR；等概念、边界和取舍稳定后，再决定是否拆成正式架构决策。

## 1. 目标

当前的主动消息主要由定时任务驱动：到时间后检查条件，再生成一条消息。这种机制可以完成提醒，但还不能称为真正的主动性。

目标是建立一个持续存在的世界和行动底座：外界发生变化时，她能够判断变化影响了谁、什么关系或什么计划；变化也可以激活记忆、联想和情绪；这些因素共同产生行动倾向，最后由她选择做什么、等待、抑制或放弃。

目标不是完整模拟现实世界，也不是让每个事件都产生消息，而是让她拥有一个连续、分层、能产生因果的环境。

## 2. 基本链路

所有外驱和未来的内驱，都应经过同一条决策链：

```text
现实世界 / 用户 / 系统发生变化
              ↓
          事件 Event
              ↓
      影响评估 Appraisal
              ↓
    认知、记忆、联想 Cognition
              ↓
       动机 / 外驱 Motivation
              ↓
       活动决策 Activity
              ↓
    消息、工具、记忆、媒体等执行器
              ↓
       行动结果反馈到世界与状态
```

概念边界：

- **事件**：世界发生了什么。
- **影响**：事件改变了谁、什么关系、什么计划或什么能力。
- **想法**：她如何理解、联想到或解释这些影响。
- **动机 / 驱动**：她因此产生的想做、想避免、想等待或想确认的倾向。
- **活动**：她最终实际做或不做的事情。

事件不是命令，影响不是行动，想法也不必表达。最终“不做”必须是合法的决策结果。

## 3. 外驱的来源

外驱不应只来自用户消息。第一版可按以下来源整理：

1. **用户事件**：用户的计划、学习、工作、健康、出行、情绪、兴趣和未完成话题。
2. **人际关系事件**：联系频率、长时间未回应、争执、和好、承诺、关系称呼和边界变化。
3. **社会事件**：节假日、调休、公共活动、社会热点、学校或机构公告。
4. **世界事件**：新闻、科技、影视、游戏、体育和其他公共领域变化。
5. **地理与环境事件**：天气、温度、空气质量、日出日落、灾害、城市环境。
6. **时间与周期事件**：日内阶段、星期、月内阶段、季节、纪念日、截止时间。
7. **任务与承诺事件**：任务完成或失败、快递、课程、预约、项目、之前答应要做的事。
8. **媒体与文化事件**：用户关注的作者、作品、音乐、节目或平台内容出现更新。
9. **系统与服务事件**：NapCat、Koishi、模型、记忆、网络和设备能力发生变化。
10. **箱庭世界事件**：她在空间中的活动、发现物品、空间状态变化和小世界规则触发。

这些来源只负责产生或提供事件，不直接决定她发消息。世界模块和感知器发布事实与事件，认知和行动层再判断是否相关。

## 4. 事件的影响

同一个事件可以有多个影响，影响对象也不一定是用户。例如“下雨”可能同时影响：

```text
用户：出行可能不便
她自己：活动计划可能改变
关系：可能产生关心或分享欲
记忆：激活过去某个雨天的共同经历
箱庭空间：窗外声音、光线和可执行活动发生变化
```

影响至少要回答：

- 影响对象是谁或什么？
- 影响了哪个方面？
- 影响是正面、负面还是不确定？
- 程度多大？
- 可信度多高？
- 持续多久？
- 是否有后续时机或截止时间？

影响不直接生成消息。它可以产生多个相互竞争的动机，例如“想关心用户”“想分享回忆”“想避免打扰”“想完成承诺”。

## 5. 联想与思维发散

事件需要能够激活多种关联，而不只是匹配一条固定规则。

```text
下雨
├─ 用户可能出行不便
├─ 想确认用户有没有淋雨
├─ 想起用户以前淋雨回家的事
├─ 想起一首与雨有关的歌
├─ 想起两人曾讨论过的某个雨天
└─ 她自己变得安静或怀旧
```

联想来源可以包括：

- 她自己的经历
- 用户过去说过的事情
- 两人的共同经历
- 关系记忆
- 用户的兴趣和关注对象
- 她当前的情绪、心境和精力
- 最近上下文
- 尚未完成的话题、计划和承诺

需要的是**受约束的联想能力**，而不是无限随机发散。联想必须尽量有真实来源，并保留不确定性；不能因为关键词相似就制造共同经历，也不能把所有联想都表达给用户。

建议把联想视为候选想法，经过相关性、新颖度、可信度、表达成本、打扰成本和重复检查后，才可能发展成驱动。

## 6. 外驱与内驱的统一

外驱和内驱的区别在于来源，不应各自拥有一套行动系统：

```text
外部事件 ─┐
          ├→ 统一动机池 → 动机竞争 → 活动决策
内部状态 ─┘
```

未来的情绪、需求、疲劳、孤独、好奇等内部状态，可以产生内驱；天气、用户事件、社会事件等产生外驱。两者最后都要和“想关心、想分享、想确认、想避免、想完成承诺”等动机一起竞争。

情绪应作为影响注意力、记忆激活、动机强度、行动阈值和表达方式的状态，而不是直接执行消息的规则。

## 7. 世界模块

世界模块的职责是维护她所处的、持续变化的环境，不是替她决定行为。

### 7.1 时间层

时间不应只保存时间戳，还要提供可被世界和认知层使用的阶段：

- 日内：清晨、上午、中午、下午、傍晚、夜晚、深夜
- 周期：周一至周日、工作日、周末
- 月内：上旬、中旬、下旬
- 年内：春、夏、秋、冬
- 特殊时间：节日、调休、假期、考试季、生日、纪念日、截止时间

这些阶段是背景影响，不是固定消息规则。例如“周一早晨适合简短问候”不等于“每周一早晨必须发送早安”。

### 7.2 环境层

- 天气、温度、湿度、风力、光照
- 空气质量、紫外线、花粉、雾霾
- 日出日落、季节、灾害预警
- 用户所在城市或已授权地点的环境变化

### 7.3 城市与交通层

- 地图和路线
- 公交、地铁、航班和铁路
- 拥堵、事故、管制和预计到达时间
- 地点可达性、营业状态和城市活动

### 7.4 社会与媒体层

- 节日和公共活动
- 本地新闻、社会事件和公共安全
- 用户关注的音乐、影视、游戏、作者和节目更新
- 体育、展会、演出和文化事件

### 7.5 数字与服务层

- QQ、Koishi、NapCat、模型、记忆服务是否可用
- 用户设备或她的设备是否在线
- 任务、下载、渲染、构建和部署状态
- 发送失败、工具失败和恢复事件

### 7.6 关系、计划和承诺层

关系、任务和承诺既是其他模块的状态，也可以作为世界中持续存在的对象：

- 用户当前的计划和处境
- 两人的共同计划
- 尚未完成的话题
- 她答应要做的事情
- 等待结果的任务
- 关系中正在变化的状态

世界模块不必拥有这些内容的全部解释权，但需要允许它们以统一事件进入世界。

## 8. 现实世界接入

现实数据不应由各功能直接调用执行器，而应经过统一接入层：

```text
现实数据源
→ 接入适配器
→ 事实标准化
→ 时效 / 可信度 / 权限检查
→ 世界状态更新
→ 状态变化产生世界事件
```

可接入的来源包括：

- 日历、节假日和课程安排
- 地图、导航和交通服务
- 天气、空气质量和环境服务
- 新闻、官方公告和公共预警
- 视频与本地动态平台
- 音乐、影视、游戏和内容平台
- 快递、电商和消费服务
- 体育赛事
- Git、CI、项目和工作环境
- 设备与服务监控

事实应保留来源、观察时间、有效时间、可信度和权限范围。过期事实不能继续当作当前世界状态。

特定搜索应由已有事件或动机提出需求，而不是持续扫描现实世界。例如用户明确问“学校附近是不是封路了”时，才选择地图、官方公告或本地动态等适合的来源进行查询。

对精确位置、学校周边、私人社交、订单、设备和摄像头等敏感信息，必须有明确授权和最小范围原则。公开平台上的内容也不等于可以持续监视用户。

## 9. 大世界与小世界

大世界和箱庭小世界应是嵌套关系，而不是两个互不相干的模拟器：

```text
现实大世界
└── 城市、社会、天气、时间
    └── 她所在区域
        └── 她的活动空间
            └── 房间、客厅、厨房、阳台、线上空间
                └── 物品、计划、当前活动
```

大世界为小世界提供边界条件：下雨可能让她不出门，夜晚可能改变活动方式，交通可能使原计划延迟。

小世界也可以产生事件：她在房间里整理东西时发现旧照片，进而激活记忆、改变心境并产生新的想法。

箱庭世界的重点不是视觉背景，而是持续的因果环境。

### 9.1 活动空间

不同空间应影响：

- 可感知的对象
- 可执行的活动
- 可联想的记忆
- 当前活动的时间成本
- 环境氛围和状态

例如房间适合休息和独处，厨房适合吃饭和做饭，阳台适合观察天气和回忆，线上聊天空间适合等待和回应用户。

### 9.2 空间切换

空间切换是世界事件，不只是修改一个位置变量：

```text
进入阳台
→ 可观察窗外天气
→ 听到雨声
→ 当前活动改变
→ 可能激活天气或回忆联想
```

以后可以让空间定义可见实体、可用活动、环境状态和进入条件；但当前只记录设计方向，不实现完整空间模拟。

## 10. 状态变化与事件的区别

世界不应每分钟重复产生相同事件。

```text
状态：现在是下午
事件：上午进入下午

状态：正在下雨
事件：开始下雨 / 雨停
```

主动性通常由变化触发，而不是由持续状态重复触发。状态可以持续存在，只有进入、退出、显著变化或到达相关时机时才产生事件。

## 11. 模块边界

感知器负责把现实变化转换成统一事实或事件；执行器负责完成已经决定的活动。两者之间由世界、认知和行动层连接。

```text
感知器：天气、地图、新闻、QQ、群聊、系统、箱庭空间
              ↓
        世界事实 / 世界事件
              ↓
        影响、联想和动机
              ↓
执行器：QQ 消息、记忆、工具、声音、唱歌、Live2D、设备
```

感知器不直接调用执行器，执行器也不自行创造动机。任何主动行为都应该能够追溯到事件、影响、动机和决策。

## 12. 实施建议（暂不执行）

未来真正实施时，建议按以下顺序小步推进：

1. 先定义统一术语和事件 / 事实 / 影响 / 动机 / 活动的数据契约。
2. 先实现不依赖外部服务的时间周期和用户事件闭环。
3. 加入一个低风险现实来源，例如天气，并验证“状态变化 → 世界事件 → 影响评估”的链路。
4. 加入持续事件和后续时机，例如“考试结束后询问”。
5. 再加入记忆联想和候选想法，允许等待、抑制和放弃。
6. 以适配器方式接入地图、交通、新闻和媒体来源，并保留来源、时效、可信度和权限。
7. 最后再逐步加入箱庭空间和她自己的活动状态。

在这些概念稳定前，不提前实现完整现实映射、完整箱庭模拟、自动新闻扫描、持续位置追踪或 Live2D / 声音联动。

## 13. 当前明确不做的事情

- 不把天气、星期或定时器直接映射成自动消息。
- 不让各外部服务直接调用 QQ 发送器。
- 不默认持续搜集用户学校、住址、位置或社交平台动态。
- 不把所有现实新闻都注入她的上下文。
- 不把所有联想都表达给用户。
- 不把情绪、外驱和内驱拆成互相独立的行动系统。
- 不为模拟完整世界而提前构建大量无关实体和规则。
- 不在本设计讨论未稳定前修改现有角色行为。

## 14. 内驱、需求与虚拟生理调节（讨论）

外驱之外，角色还需要由自身状态产生内驱。内驱不应直接从“情绪”跳到“发消息”，而应经过多层状态和调节：

```text
世界事件 / 记忆 / 时间 / 关系 / 自身活动
                    ↓
                 基础状态
                    ↓
                情绪与心境
                    ↓
              需求与关注点
                    ↓
              内驱 / 外驱竞争
                    ↓
                 活动决策
```

### 14.1 内在状态层

基础状态不是情绪，而是她当前所处的条件，可以包括：

- 精力、清醒度和疲劳
- 注意力和认知负荷
- 社交负荷
- 当前空间和活动状态
- 恢复需求
- 安全感和不确定感
- 当前是否被某个任务或问题占用

情绪与心境需要区分：即时情绪是对具体事件的短期反应；心境是持续更久的整体倾向。两者都应有强度、来源、持续时间、衰减和是否已经表达等属性。

### 14.2 需求层

马斯洛需求层次可以作为需求分类和优先级参考，但不应被实现为严格的单向金字塔。多个需求可以同时存在并互相冲突。

建议的需求类别：

1. **基础维持**：运行能力、休息、精力、记忆和消息服务可用性。
2. **安全**：自身安全、用户安全、隐私、关系边界、信息可信度和行动风险。
3. **归属与连接**：保持联系、陪伴、被理解、参与共同生活和修复疏远。
4. **尊重与胜任**：完成承诺、有效帮助、保持边界、避免重复犯错和维持自我一致性。
5. **认知**：理解世界、弄清问题、学习用户、追踪未完成话题和探索未知。
6. **表达与审美**：分享、讲故事、音乐、唱歌、图像、空间氛围和创造性表达。
7. **自我实现**：发展兴趣、完成长期计划、形成稳定个性、创造作品和积累共同历史。
8. **贡献与超越**：帮助用户成长、参与共同目标或对更大范围产生积极影响；需要严格受用户边界约束。

还应单独考虑自主性、连续性、确定感、边界感、恢复需求和新鲜感。这些不一定是马斯洛的一层，但对角色运行很重要。

需求至少需要记录强度、紧迫性、持续性、满足度、受阻程度、行动成本和风险等级。需求只是使某些活动更值得考虑，不等于必须行动。

### 14.3 需求的满足与反馈

需求必须能够得到满足、转移、衰减或放弃，否则会变成永久待办并不断重复主动行为。

```text
想确认用户是否安全
→ 用户回复平安
→ 安全感上升，相关驱动关闭

想完成承诺
→ 承诺完成
→ 需求得到满足，记录结果

想联系用户
→ 多次没有回应
→ 打扰成本上升，可能转为等待、克制或暂时放下
```

需求还可区分为：

- **缺失型需求**：安全不足、关系中断、任务未完成、服务故障等，通常更紧迫。
- **成长型需求**：好奇、表达、创造、理解和探索等，可以等待合适时机，也可以被放弃。

### 14.4 虚拟生理调节

可以借鉴人体系统的功能关系，但不应机械复制真实生化过程，也不应把角色实现成医学模型。重点是模拟持续状态、慢速调节、反馈、资源限制和恢复。

一种可行的功能映射：

| 生物功能类比 | 角色运行时的功能 |
| --- | --- |
| 神经系统 | 快速感知、事件分发、注意力和即时响应 |
| 内分泌系统 | 慢速、全局的状态调节，影响多个后续决策 |
| 免疫系统 | 异常识别、威胁防御、风险记忆和边界保护 |
| 循环系统 | 在模块之间传递状态、影响和资源 |
| 呼吸系统 | 活动节奏、负荷、恢复和放松周期 |
| 消化系统 | 接收外部信息并转化为内部状态和可用记忆 |
| 排泄系统 | 清理过期事件、衰减情绪、释放无效任务 |
| 运动系统 | 执行活动、发送消息、操作工具和改变空间状态 |
| 生殖系统 | 不直接照搬生理含义，可抽象为周期、创造、延续和关系发展 |

生理周期可以作为一种持续的身体状态来源。如果角色设定需要，可以影响精力、舒适度、敏感度、恢复需求和活动偏好，但不能机械地决定性格或行为。例如“不适上升”可以提高恢复需求、降低社交负荷承受度，但她仍可以根据重要性选择回应。

### 14.5 神经调节变量

不建议直接把多巴胺、血清素或其他物质实现成“快乐开关”。可以先使用功能性变量，再在解释层注明其生物学类比：

- `rewardPredictionError`：实际结果与预期结果的差异
- `motivation`：推动行动的程度
- `arousal`：唤醒和警觉程度
- `stress`：压力与威胁负荷
- `attachment`：亲近和关系连接倾向
- `novelty`：新鲜感和探索倾向
- `inhibition`：克制、风险敏感度和抑制能力
- `fatigue`：疲劳与恢复需求
- `uncertainty`：对世界、关系或自身判断的不确定感
- `safety`：整体安全稳定程度

这些变量影响注意力、记忆召回、联想范围、需求权重、行动阈值、表达长度和恢复速度，但不应直接生成消息。

例如，多巴胺更适合借鉴“奖励预测误差”功能：

```text
预期用户会回复
→ 用户实际回复且比预期热情
→ 正向预测误差
→ 更新关系安全感、未来期待和记忆重要性
```

如果用户没有回应，结果可以使不确定感和谨慎上升，而不是简单地把她变成“更不开心”或无限重复追问。

### 14.6 快系统与慢系统

可将调节分为两种时间尺度：

- **快速系统**：处理突发事件、用户紧急消息和即时安全问题。
- **慢速系统**：处理疲劳、压力、关系疏远、周期、习惯和长期心境。

紧急事件结束后，快速警觉可以下降，但慢速压力或疲劳仍可持续一段时间。这样可以避免所有状态在一次事件后立即归零。

### 14.7 调节机制

内部调节可以借鉴以下机制：

- **稳态**：把精力、压力、社交负荷和安全感维持在可接受范围。
- **异稳态**：遇到重大事件时临时改变整体状态，事后逐步恢复。
- **反馈调节**：根据行动结果更新期待和状态。
- **习惯化**：重复出现且影响不大的事件逐渐降低注意力。
- **敏感化**：某类事件反复造成影响后，对类似事件更敏感。
- **节律**：日内、周、季节和长期周期改变状态阈值，但不直接生成固定消息。
- **抑制**：安全、权限、重复、打扰成本和资源不足可以阻止行动。

### 14.8 外驱与内驱统一进入动机池

外驱和内驱只在来源上不同，最终应进入同一个动机池：

```text
外部事件 ─┐
          ├→ 统一动机池 → 动机竞争 → 活动选择
内部状态 ─┘
```

一个事件或状态可以同时产生多个冲突动机：想联系用户、想避免打扰、想完成承诺、想独处、想探索。行动决策需要综合驱动强度、紧迫性、持续性、能力、时间、风险、关系边界、过去反馈和当前活动。

### 14.9 研究依据与实现边界

后续研究可参考奖励预测误差、稳态与异稳态、主动推断、内感受和情绪计算等方向。主动推断与稳态研究把内部状态、世界预测和行为选择放在同一反馈框架中；情绪主动推断模型也把情绪视为对世界和身体状态的推断，而不是单纯标签。

实现时应优先复现功能关系，而不是追求生化名词数量：

```text
世界事件
→ 身体 / 周期状态
→ 神经调节变量
→ 注意力、记忆与联想
→ 情绪与需求
→ 外驱 / 内驱
→ 活动竞争、抑制与选择
→ 结果反馈和状态更新
```

这些变量只能影响倾向，不能绕过权限、安全、用户边界或明确的行为规则。它们也不应被直接暴露成机械化数字；对模型表达时，应转换成自然的上下文描述。

## 15. 后续讨论问题

后续需要继续明确：

- 她的虚拟身体状态有哪些，哪些只是抽象变量？
- 生理周期是否属于角色明确设定的一部分，以及如何表达隐私边界？
- 哪些需求属于她的长期稳定需求，哪些只是临时状态？
- 需求如何由世界事件、记忆和反馈改变？
- 哪些调节变量需要可解释、可审计？
- 哪些状态可以影响表达，哪些只能影响内部决策？
- 如何避免把心理和生理状态写成刻板行为？
- 什么时候把设计讨论提升为正式 ADR？
