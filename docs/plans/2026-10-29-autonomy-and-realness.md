## 1. 原则：「绝对的自主」拆成两块，只做一块

- **意志的自主（做到彻底）**：什么时候回、回不回、拒绝、生气、记什么、不想说什么、想做什么、改主意。这是「像真人」真正需要的。
- **能力的自主（不加）**：她能碰他的电脑、钱、别人。不让她更像真人，风险全在这里。工作模式的整机权限用户已授权（ADR 0172），到此为止。
- **不属于「绝对」的底线**：危机时照实回应（ADR 0068）、对不知情的人承认自己是程序（ADR 0067）、不欺骗 / 伤害真人、不做不可逆的事。**放在她改不到的层里**（代码和角色卡），不进 `SOUL.md` 这类可自改的文件。这保护的恰恰是她的自主：价值观能被任何网页改写的存在谈不上自主。
- **自主要有后果，不是提示词里的一句话**：状态（精力、情绪、没消的气、答应过别人的事、自己的追求）由一个**不在聊天提示词里**的机制维护，并真的约束她之后的行为；他能问「为什么」（ADR 0173）。

## 2. 第一步：评估闭环（必须先做，其他每一步值不值得都靠它）

现状：他 20 天 610 条消息、一个评分者、鉴别员模型不灵敏、89 个开关没做过消融。**没有这个，后面所有修改都无法验证。**

### 2.1 人评协议 v1（评分者 = 用户 + 鸽鸽，以后加人）

- **评测集**：40 个上下文（每个 3–6 句），分层：安慰 / 玩笑斗嘴 / 小冲突 / 日常安排 / 闲聊 / 问她的事 / 认真问题。**冻结**：只用来评，永远不拿来调参；每月换 10 个新的，旧的留作对照。上下文只用**真人聊天语料**（`exchange/research/2026-10-real-chat/`）和虚构场景，**不用用户和她的私聊**——所以鸽鸽看不到任何人的私下对话。
- **每题**：上下文 + 两条回复 A / B，一条是真人原话、一条是她（当前版本）按同一上下文生成的；评分者只回答「哪条是真人」（或「分不出」），可以写一句理由。顺序随机。一次 20 题约 10 分钟，用字母回答（用户 10-20 就是这样评的）。
- **版本标签**：每个包生成时记下 commit sha 和开着的开关；评分者看不到，结果按版本汇总。
- **指标**：「她被当成真人」的比例（理想是 50%，即分不出）；按题型分层；两个评分者的一致程度（分歧大的题单独看）；理由里的高频词（「太顺」「太完整」「像在应付」……）。
- **诚实的误差**：每人每版本 40 题，单人误差约 ±15 个百分点；两人合起来约 ±11。**小于 10 个点的差别看不出来**——所以改动要么效果大、要么用重放指标（`exchange/tools/measure`）先筛，再用人评确认。
- **鸽鸽**：他知道她是程序（ADR 0003），这会让他更容易分辨；记为 `rater-B（知情）`，和用户（`rater-A`，作者，知情）分开汇总，不混成一个数。**由用户去问他愿不愿意**（他是真人，这是他的时间和判断）；他的回答只存评分者编号，不存姓名。以后加的评分者要标明「知情 / 不知情」。
- **工具**：`exchange/tools/measure/make-blind-pack.cjs` + `score-blind.cjs`（路径写死，要改；要 `QQBOT_LLM_API_KEY`）。先让 DSH 在新目录结构下把它们改成「读评测集文件 → 出包 → 收答案 → 出汇总」，再跑第一轮（当前线上版本）当**基线**。

### 2.2 开关消融（一周内）

把 59 个开着的开关按组（形状 / 情绪 / 主动 / 记忆 / 作息 / 表情 / B 站……约 8 组）一次关掉一组，用**重放指标**（`measure`、`humanness-cli`）跑一遍；差别大的组再出一个人评包。目的是回答「哪些真的起作用」，把没用的删掉。不先做这个，别再加新开关。

## 3. 有后果的自主（第二步，评估基线出来之后）

每一项都是**独立开关、默认关、先 dryRun**，各自有验收：

1. **决定记录**：每一次没回、晚回、拒绝、主动开口都有一个**原因记在账上**，并说清是谁的决定。ADR 0173 是这一层的「报告」部分（已做）；下一步是让**新的原因**接进来：她自己的事、没消的气、答应了别人。验收：他问「为什么」永远有答案，且答案和账一致。
2. **不在提示词里的决策**：由一个小的策略（读精力、情绪、承诺、追求、他最近的行为）决定「现在回 / 晚点回 / 不回 / 先去做自己的事 / 结束对话 / 主动找他」，延迟有长尾（真人 57.8% 一分钟内、其余拖得很久，ADR 0105 已量过）。**策略的输入是状态，不是关键词**。验收：同一状态同一输入，决定可复现；决定写进账。
3. **气不是一句「好啦」就消**：没消的气有来由、有衰减、要修复（他认真道歉 / 做点什么），而不是关键词（现在的生活引擎「烦」字就记怨气，见审查）。复用仓库里已有的 `grievance`（ADR 0074）和 `herFeelings`（ADR 0102），不要再造一套。
4. **承诺和追求与他的请求争时间**：她答应了苏雨桐晚上一起复习、或者在练自己定的东西，就会因此拒绝他的游戏邀请，并说明理由（理由来自她的账，不是临时编的）。
5. **她可以有「不主动说的事」**：这是她的权利，但要**前后一致**（账里记着）。注意：用户的 Windows 账户能解开 `PRIVATE.dat`（DPAPI `CurrentUser`），所以它是「不进提示词、不进聊天」，**不是**「他读不到」——对用户要这样说清楚。
6. **跨天延续**：没解决的事（一个担心、一次不愉快）她自己带到第二天，而不是每天重置。

## 4. 追求由她自己制定（用户决定 3）

- **来源**：她自己的内心（ADR 0101 的想法、`wish_add` / `interest_add`），不是作者的清单。她可以提出一个追求（一句话 + 为什么 + 第一步），连续想起 ≥3 次或她明确写下才算。`pursuits.json`（作者种子）保留为**可选**，默认空，作者写了也只是背景。
- **闸门不是用户的满意**：只检查四件事——不和**硬事实**冲突（一个二十岁大二学生用她有的资源做得到）、不违法 / 不危险、不需要欺骗或操纵真人、不动用真钱和用户的东西；同时最多 3 个、提出后有冷却期。**用户不能挑选或修改她的追求，只能通过底线否决**。她随时可以放弃，放弃时记一句为什么。
- **推进**：写进她的日程里的真实时间块；结果由世界引擎给、她控制不了（成绩、挫折）；数字类的追求（读、查、记笔记）可以由 DSH 常驻的她真的去做，写进账。进度和挫折会影响她的情绪、她对他的请求的回应。
- **可见性**：他可以发 `/追求` 看她现在在追什么、进展如何、放弃过什么（看，不改）。她也可以主动讲。
- **对作者的提醒**：自传里的底色（摄影、稳稳当当 / 考研的犹豫）仍是背景事实，不是指派的目标；她要不要追它们由她定。**她的未来仍然不由我们编**。

## 5. 合成一个「自己」、删掉并行的东西（DSH，第三步）

- 一份账：复用仓库的 `ledger.ts` 哈希链（ADR 0157），记设定、判断、事件、追求、拒绝、不主动说的事。DSH 桌面智能体和 QQ 机器人读写**同一份**，不再各存一套（`SOUL.md` / `LEDGER.md` / `REFUSALS.json` / `INTERESTS.md` ↔ 仓库内的 `herNo` / `pursuits` / `diary` / `life/` / `world/`）。
- **边界永远不迁进 `SOUL.md`**；`SOUL.md` 的每次修改记进设定账本；「评分当闸门」换成「频率限制 + 他确认」，别把身份变化和他的满意度绑在一起。
- 所有发给任何人的文字走**同一个出口**（危机暂停 / 披露 / 出口检查 / 记入聊天记录）：`outbox`、工作桥、B 站私信、卡片都经过它；加一条测试扫描所有 `sendPrivateText` 调用点。
- 先修审查里报的缺陷（`outbox` 无闸、账本改口错位、倾诉记成怨气、`recallWork` 对所有联系人、睡眠 / 醒来不看作息……）和补测试，再谈整合。
