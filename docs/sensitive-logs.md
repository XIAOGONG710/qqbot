# 日志里的聊天原文（ADR 0070 第 8 项）

## 一句话

**默认日志里不写聊天原文，也不留 `last-prompt.json`。** 需要查问题时，用环境变量临时打开一阵子，用完自动关。原始聊天本来就完整存在 `runtime/bot/chats/<QQ>.jsonl`，日志不该再多存几份。

## 默认（关着）时日志里变成什么

| 以前 | 现在 |
| --- | --- |
| `[QQ] 收到：<他的话>` | `[QQ] 收到：12 字` |
| `[QQ] 已回复（2 条）：<她的话>` | `[QQ] 已回复（2 条）：15 字`（前缀不变，`live-digest` 照常数） |
| `[QQ] 补回 N 条漏掉的消息：<原文>` | `补回 N 条漏掉的消息：2 条是对方的，1 条是她的（共 38 字）` |
| `主动找他（…）：<她主动发的话>`、试运行里「本来要说」 | 只剩 `（N 字）` |
| `待跟进：记下「<事项>」…`、`她答应的事：记下「<事项>」（日期 时间 地点）` | `「（N 字）」`，日期 / 时间保留，地点也只剩字数 |
| 主动消息的标签里的待跟进事项 | `待跟进的事（问今天14:00的（5 字））` |
| 出口检查：`第 1 行禁用词「<命中的原文>」` | `第 1 行禁用词「…」`（类别词保留，`live-digest` 的出口检查分类照常） |
| 危机回合出口检查命中的片段 | `「（N 字）」` |
| OneBot 收到无法解析的数据：`<前 200 字>` | `（N 字）` |
| 去掉模型冒充图片消息的那一行 | `「（N 字）」` |
| `runtime/bot/last-prompt.json`（完整提示词） | 不写；启动时把上次留下的删掉 |

## 仍然会写进日志的（不算聊天原文，但要知道）

- 时间、QQ 号、字数、气泡数、耗时、事件类别、世界书命中的名字。
- **「这一轮有意图：…」**：意图行是代码写的规则句，个别时候会夹带对话里的一两个词（比如进行中的约、作业名）。它是审计要用的，所以保留。
- 她自己一天的事（虚构人物的生活）、表情包的描述（来自对方发来的图，描述是模型写的一句话）、联系人的称呼。

## 临时打开

在启动 Koishi 的环境里设 `QQBOT_SENSITIVE_LOGS`：

- `on`：一直开到下次重启；
- `15m` / `2h`：开这么久，到点自动关。

启动日志第一行会写明开没开（开着时带 ⚠）。**打开要重启一次 Koishi**（环境变量只在进程启动时读），所以平时不开；要查具体哪句话出了问题，优先看 `chats/*.jsonl`，不开这个开关也能看全。

## 审计怎么办

- 看聊天内容：读 `runtime/bot/chats/<QQ>.jsonl`（时间、角色、正文）。
- 看数字（收到 / 回复 / 气泡 / 延迟 / 出口检查类别 / 意图类别）：`node scripts/live-digest.mjs [日期]`，只靠日志行首前缀和类别词，不受影响。

## 没有改变的

- 已经写下的旧日志文件（`runtime/koishi/data/logs/*.log`）里有当时的原文，这次上线不会改写它们；要不要归档 / 删除由用户决定。
- 聊天记录 `chats/*.jsonl`、Hindsight 里的记忆、日记本来就含原文，不在这个开关的范围内。
- 这个开关只管本程序自己写的日志，**管不到 NapCat 自己的日志**。

## NapCat 自己的日志里也有原文（2026-10-17 查实）

`runtime/napcat/workdir/logs/*.log`：`info` 行写 `接收 <- 私聊 (QQ) <文字>`、`发送 -> 私聊 (QQ) <文字>`（图片、卡片只写 `[图片]`、`[卡片消息]`），`debug` 行把整条原始消息（几千个字符的 JSON，含文字）整个倒出来。当前配置 `runtime/napcat/workdir/config/napcat_<机器人QQ>.json` 是 `fileLog: true`、`fileLogLevel: "debug"`，所以这些都在写。

要关：把 `fileLogLevel` 改成 `"warn"`（掉线、登录失败这些仍然会记，聊天的收发不再记），**NapCat 下次启动时生效**（它启动时才读这个文件，所以改了不用急着重启 NapCat）。`consoleLogLevel` 只影响窗口里滚动的输出，不落盘，可以不动。已经写下的旧日志（到 2026-10-17 共 5 个文件、约 2.3 MB，最早 10-10）里有原文，是否归档 / 删除由用户决定。
